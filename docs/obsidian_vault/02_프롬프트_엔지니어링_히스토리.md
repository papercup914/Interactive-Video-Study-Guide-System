# 프롬프트 엔지니어링 히스토리

본 프로젝트의 AI 튜터가 똑똑하고 친절하게 반응하는 이유는 백엔드(`llm.py`)에 정교하게 설계된 '시스템 프롬프트' 덕분입니다. 

## 1. 동적 페르소나 (Dynamic Persona) 부여 원리
단순히 "이 내용을 요약해줘"라고 명령하지 않습니다. 사용자(Frontend)가 선택한 옵션에 따라 AI의 성격과 어조를 동적으로 주입합니다.

**적용된 핵심 프롬프트 원문 발췌:**
> "당신은 무미건조한 AI가 아닙니다. 위에서 부여된 [AI 튜터 페르소나]와 아래의 [학습자 프로필]을 결합하여 완벽한 맞춤형 지도를 수행하십시오."
> "1. 어조 강제: 튜터 페르소나의 '어조'와 학습자 프로필의 '원하는 튜터 어조'를 조화롭게 섞어 본문 전체에 걸쳐 철저하게 유지하십시오."
> "2. 비유 강제: 어려운 개념을 설명할 때는 반드시 프로필에 명시된 '주요 관심사'와 관련된 메타포(비유)를 하나 이상 들어 설명하십시오."

**설명 및 의도:**
LLM은 '강제(Force)'와 '제약(Constraint)'을 줄 때 성능이 높아집니다. "어려운 개념이 나올 때마다 요리, 식당, 교통 등의 비유를 제시하라"고 명확히 제약함으로써, 전문가용 지식도 누구나 이해하기 쉬운 글로 탈바꿈하게 됩니다.

## 2. 적응형 인지 라우팅 (Adaptive Cognitive Routing)
학습 콘텐츠의 성격(수학인지, 암기인지, 개념인지)에 따라 최적의 학습법이 다릅니다. AI가 스스로 챕터의 성격을 파악하고 XML/JSON 태그를 본문에 삽입하도록 설계했습니다.

**적용된 프롬프트 원문 발췌:**
> "반드시 4가지 중 현재 챕터에 가장 적합한 1가지만 골라 정확한 JSON 구조로 태그를 감싸서 출력하세요."
> 
> 1. 개념 이해 (CONCEPT): `<feynman> { "tag_team_scenario": "...", "concept_summary": "..." } </feynman>`
> 2. 논리/수학 (LOGIC): `<steptracer> { "steps": [ ... ] } </steptracer>`
> 3. 단순 암기 (MEMORY): `<mnemonic> { "story": "...", "flashcards": [ ... ] } </mnemonic>`
> 4. 절차적 작업 (PROCEDURE): `<procedure> { "checklists": [ ... ] } </procedure>`

**왜 XML과 JSON을 섞어 썼는가?**
순수 JSON 렌더링 모드(JSON Schema)를 쓰면 마크다운 본문과 인터랙티브 데이터를 한 번에 받아오기 어렵습니다. 따라서 본문은 자연어로 자유롭게 출력하되, 마지막에 특정 XML 태그(`<feynman>`)로 감싼 JSON을 뱉게 하여, 프론트엔드의 커스텀 마크다운 파서(`react-markdown`)가 이 태그를 인식해 React 컴포넌트로 치환(Hydration)하도록 만들었습니다.

## 3. 수동 마킹 시스템으로의 선회 (Pivot to Manual Annotation)
초기에는 AI가 스스로 중요한 단어에 `<highlight>` 태그를 달아주도록 프롬프트를 설계했습니다.
하지만 AI가 단어의 어미(예: "중요합니다")를 잘못 자르거나, 너무 많은 형광펜을 칠해 시각적 피로도를 유발하는 문제가 발생했습니다.

**의사결정:** 
AI의 자동 태깅 프롬프트를 과감히 삭제하고, 사용자가 드래그하여 직접 형광펜/동그라미를 치는 '수동 주석(Manual Annotation) 시스템'으로 방향을 틀었습니다. 이는 학습의 주도권을 사용자에게 돌려주기 위한 핵심 아키텍처 결정이었습니다.
