# 백엔드 코드 분석

FastAPI 기반의 백엔드는 외부 LLM API(Google Gemini, OpenAI 등)와 소통하며 방대한 텍스트를 가공하는 역할을 수행합니다.

## 1. 폴더 구조
* `backend/main.py`: FastAPI 애플리케이션의 진입점. CORS 설정 및 라우터 연결.
* `backend/routers/guide.py`: 클라이언트의 요청(URL 제출, 폴링, 답변 생성)을 수신하는 HTTP 엔드포인트 정의.
* `backend/services/llm.py`: 외부 AI 모델과 통신하는 핵심 비즈니스 로직.
* `backend/services/db.py`: SQLite 데이터베이스 읽기/쓰기 로직.

## 2. 텍스트 청킹(Mathematical Chunking)과 Map-Reduce
LLM은 한 번에 읽을 수 있는 텍스트의 한계(Context Window)가 있으며, 한도가 높더라도 너무 긴 텍스트를 한 번에 주면 중간 내용을 까먹는 "Lost in the Middle" 현상이 발생합니다.

`llm.py` 내부의 `async_map_reduce_transcript` 함수는 이를 해결합니다.
```python
chunk_size = 5000
overlap = 500
# ... 루프를 돌며 텍스트를 쪼갬 ...
```
문서를 5,000자 단위로 자르되 500자씩 겹치게(Overlap)하여 문맥의 단절을 막습니다.
이후 `asyncio.gather(*tasks)`를 통해 여러 개의 쪼개진 텍스트를 동시에 LLM에 던져 병렬로 요약시킵니다. 이 방식은 대용량 문서를 처리할 때 속도를 기하급수적으로 끌어올립니다.

## 3. 캐싱 메커니즘 전략 (Cost Optimization)
사용자가 같은 영상 URL을 재차 요청할 경우 불필요한 API 비용이 발생하는 것을 막기 위해 철저한 캐싱을 구현했습니다.
* **로컬 파일 캐싱**: `backend/data/` 폴더에 스크립트, 마스터 요약본, 목차 데이터를 `url_hash` 기반으로 txt 및 json 형태로 저장합니다.
* **Gemini Context Cache (BETA)**: 초대용량 파일(PDF 등)의 경우 Google의 Context Cache API를 사용하여, 한 번 업로드된 파일은 1시간(TTL) 동안 캐시 메모리에 올려두고 저렴한 비용으로 재조회(Query)할 수 있게 `get_or_create_document_cache` 함수가 구현되어 있습니다.

## 4. 백그라운드 작업 처리 (Background Tasks)
사용자가 긴 유튜브 영상을 업로드하면 요약에 몇 분이 소요될 수 있습니다. 이를 HTTP 응답을 멈춰놓고(Blocking) 기다리면 브라우저가 타임아웃 오류를 냅니다.
따라서 `guide.py`의 엔드포인트는 즉시 `job_id`만 반환하고, 실제 요약 프로세스는 FastAPI의 `BackgroundTasks`에 위임하여 백그라운드에서 비동기로 조용히 처리하도록 설계되었습니다. 프론트엔드는 주기적으로 `GET` 요청을 보내어 완료 여부를 확인(Polling)합니다.
