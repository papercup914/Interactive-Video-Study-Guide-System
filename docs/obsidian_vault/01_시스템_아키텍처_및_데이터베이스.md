# 시스템 아키텍처 및 데이터베이스

## 1. 시스템 전체 흐름도 (Architecture Overview)
StudyGuide.AI는 Next.js(프론트엔드)와 FastAPI(백엔드)가 결합된 모던 웹 애플리케이션입니다. 사용자 요청은 백엔드의 LLM 파이프라인을 거쳐 정제된 마크다운 데이터로 반환됩니다.

```mermaid
sequenceDiagram
    participant U as User
    participant F as Next.js (Frontend)
    participant B as FastAPI (Backend)
    participant LLM as Gemini/OpenAI
    participant DB as SQLite

    U->>F: 유튜브 URL 또는 문서 업로드
    F->>B: POST /api/guide/generate
    B->>DB: 새 Job 생성 (상태: PROCESSING)
    B->>LLM: 스크립트 추출 및 분석 요청
    LLM-->>B: 긴 텍스트 반환
    B->>LLM: Map-Reduce 요약 및 목차 생성
    LLM-->>B: JSON 구조화된 목차 및 본문 데이터
    B->>DB: Job 완료 처리 및 데이터 저장
    F->>B: 폴링(Polling)으로 완료 상태 확인
    B-->>F: 완성된 스터디 가이드 데이터 반환
    F->>U: 인터랙티브 마크다운 UI 렌더링
```

## 2. 백엔드 처리 파이프라인 (The Generation Pipeline)
텍스트가 길어지면 LLM이 문맥을 놓치거나 환각(Hallucination) 현상을 일으키는 것을 막기 위해, 백엔드는 다음과 같은 다단계 파이프라인을 거칩니다.

1. **추출 (Extraction)**: `youtube-transcript-api`를 통한 자막 추출 또는 오디오 분할(Chunking) 후 Whisper/Gemini 멀티모달 분석.
2. **요약 (Map-Reduce)**: 텍스트가 2만 자를 초과할 경우, 5천 자 단위로 잘게 쪼개어 병렬(asyncio.gather)로 1차 요약을 진행한 뒤 하나로 병합.
3. **구조화 (Outline)**: 병합된 마스터 텍스트를 바탕으로 적절한 분량의 목차(챕터)를 기획.
4. **본문 작성 (Detailing)**: 기획된 목차마다 별도의 LLM 프롬프트를 병렬로 던져, 학습자 수준(Persona)에 맞는 맞춤형 해설과 비유를 작성.

## 3. 데이터베이스 스키마 (SQLite ERD)
핵심 상태와 데이터를 영속적으로 저장하기 위해 SQLite를 사용합니다.

```mermaid
erDiagram
    JOBS {
        string job_id PK "UUID (예: job_123abc)"
        string status "처리 상태 (PROCESSING, COMPLETED, FAILED)"
        string original_url "사용자가 입력한 소스 URL"
        float progress "진행률 (0.0 ~ 1.0)"
        string created_at "생성 시간"
    }
    
    STUDY_GUIDES {
        string job_id PK, FK "JOBS 참조"
        text outline "JSON 배열 형태의 목차 데이터"
        text content "마크다운(Markdown) 본문 데이터"
        string length_preset "요약 길이 (예: '핵심 요약')"
        string analogy_preset "비유 수준 (예: '풍부한 비유')"
        string video_duration "영상 총 길이 (표시용)"
    }
    
    JOBS ||--o{ STUDY_GUIDES : "1:1 매핑 또는 재사용"
```
