# 첫 번째 서브 에이전트 구현: 블로그 플래너(Blog Planner)

자, 이제 이론 공부는 잠시 접어두고 **직접 우리 손으로 '일하는 에이전트'를 하나 만들어 볼까요?** 앞서 우리는 에이전트에게 '어떤 사고방식(패턴)'을 줄지 고민했습니다. 순차적으로 일할지, 상황에 따라 반응할지, 아니면 계획을 짜고 실행할지 말이죠. 이번 시간에는 **'계획형 에이전트(Planning Agent)'**의 대표 주자인 **'블로그 플래너(Blog Planner)'**를 실제로 구현해 보면서, ADK(에이전트 개발 키트)가 어떻게 우리의 생각을 코드로 옮겨주는지 구경해 보겠습니다.

---

## 1. 오늘의 미션: "주제만 던지면 블로그 글이 뚝딱?"

상상해 보세요. 여러분이 **"요즘 뜨는 '생성형 AI'에 대해 블로그 글 하나 써줘"**라고만 말하면, 알아서 **목차(아웃라인)를 짜고 → 본문을 채워 넣고 → 클릭을 유도할 매력적인 제목과 훅(Hook)까지 제안**해 주는 똑똑한 비서가 있다면 어떨까요? 오늘 우리가 만들 **'블로그 작성 에이전트'**가 바로 그 역할을 합니다.

이건 단순히 "글 써줘"라고 한 번 시키는 게 아닙니다. **'계획 → 작성 → 검토 → 수정'**의 과정을 거치는, 제법 복잡한 **멀티 스텝(Multi-step) 작업**이죠. 바로 이럴 때 **'플래너(Planner) 에이전트'**가 빛을 발합니다.

> **💡 개념 돋보기: 플래닝 에이전트(Planning Agent)란?**
> > **여행 가기 전 '일정표'를 짜는 친구라고 생각하세요.**
> > 
> > 즉흥 여행을 좋아하는 '반응형 에이전트'가 "일단 공항 가자! 가서 표 끊고 생각하자!" 스타일이라면, **플래닝 에이전트는 "음, 3박 4일이니 1일차는 여기, 2일차는 저기... 렌터카는 여기서 빌리고, 숙소는 저기 예약하고..."** 라고 **엑셀 시트나 노션에 깔끔한 일정표(계획)를 먼저 짜놓고, 그 순서대로 착착 실행하는 스타일**입니다.
> > 
> > 블로그 쓰기처럼 **"목차(계획) 없이 본문(실행)부터 쓰면 뒤죽박죽 되기 쉬운 작업"**에서 절대적인 강자입니다.

---

## 2. 블로그 에이전트의 내부 구조: '식당 주방'으로 들여다보기

이 블로그 에이전트 안을 들여다보면, **혼자서 다 하는 슈퍼맨이 아닙니다.** 마치 **잘 짜인 식당 주방**처럼, 역할을 분담한 **전문가들(서브 에이전트)**이 팀을 이뤄 일하고 있습니다. ADK 코드를 보며 이 '주방 시스템'을 파헤쳐 볼게요.

### ① 헤드 셰프: 플래너(Planner) 에이전트 = **'총괄 기획자'**
가장 먼저 나서는 친구입니다. 사용자가 "생성형 AI 블로그 써줘"라고 주제를 던지면, 이 친구는 **펜을 들고 종이에 '목차(아웃라인)'를 빽빽이 적습니다.**
*   "1. 서론: AI가 왜 뜨나? 2. 본론: 핵심 기술 3가지 3. 사례: 실생활 활용법 4. 결론: 미래 전망"
*   이게 바로 **'계획(Plan)'**입니다. 이 계획서가 있어야 다음 요리사들이 헤매지 않고 요리할 수 있겠죠?

### ② 라인 쿡(파트별 요리사): 라이터(Writer) 에이전트 = **'본문 작성자'**
플래너가 넘겨준 목차(계획서)를 보고, **"좋아, 1번 서론 파트 내가 맡을게! 2번 핵심 기술은 내가 잘 아니까 내가 쓸게!"** 하며 **실제 글감(본문)을 채워 넣는 친구**입니다.
*   플래너가 "큰 그림"을 그렸다면, 라이터는 "디테일"을 채웁니다.

### ③ 품질 검수팀(QC): 루프 에이전트(Loop Agent) = **'잔소리 많은 수석 셰프'**
여기서 ADK의 마법이 나옵니다. 라이터가 글을 다 썼다고 끝일까요? **"이거 문장이 어색한데?", "목차랑 내용이 안 맞는데?", "너무 짧은데?"** 라며 **자동으로 검사하고, 실패하면 다시 쓰게 시키는 '반복 루프(Loop)' 시스템**이 있습니다.
*   ADK에서는 이를 **'루프 에이전트(Loop Agent)'**라고 부르는데, 이건 **'워크플로 에이전트(Workflow Agent)'**의 일종입니다.
*   쉽게 말해 **"합격할 때까지 무한 반복 시키는 엄격한 수석 셰프"**가 자동으로 붙어 있는 셈입니다.

### ④ 마케팅 팀: 타이틀/훅 제안 에이전트 = **'간판 달기 전문가'**
글이 다 완성되면, **"이 글 제목 뭐로 달까? '생성형 AI 소개'? 너무 재미없어. '월급 3배 오른 비결? 생성형 AI 입문기' 어때?"** 하며 **클릭률 높일 제목과 첫 문장(훅)을 제안하는 친구**도 별도로 있습니다.

## 3. ADK 코드 속 숨은 주인공들: LLM 에이전트, 루프 에이전트, 커스텀 에이전트

영상 스크립트에서 언급된 핵심 기술 용어 세 가지, **"LLM 에이전트", "루프 에이전트(워크플로 에이전트)", "커스텀 에이전트"**가 이 주방에서 어떤 역할을 하는지 비유로 완벽하게 이해해 봅시다.

### ① LLM 에이전트 (LLM Agent) = **'두뇌가 달린 로봇 직원'**
> **💡 개념 돋보기: LLM 에이전트**
> > **거대 언어 모델(LLM, 예: Gemini, GPT)을 '뇌'로 장착한 로봇 직원입니다.**
> > 
> > 그냥 코드 짜맞추기(if-else)가 아니라, **"상황을 이해하고, 추론하고, 자연어를 생성하는 능력"**을 가진 친구들이죠. 우리 주방의 **플래너(기획), 라이터(작성), 타이틀 제안(마케팅)** 모두 이 **'LLM 에이전트'**입니다.
> > 
> > *   **플래너:** LLM 뇌로 "이 주제엔 어떤 목차가 논리적일까?" **추론**
> > *   **라이터:** LLM 뇌로 "이 목차에 맞춰 자연스러운 문장을 생성" **창작**
> > *   **제안자:** LLM 뇌로 "사람들 클릭하게 만들 후킹 멘트 생성" **설득**
> > 
> > 즉, **'모델(Model)'이라는 엔진을 달고, '지시(Instruction)'라는 핸들을 잡아서 목적지까지 운전하는 자율 주행차** 같은 존재들입니다.

### ② 루프 에이전트 / 워크플로 에이전트 (Loop Agent / Workflow Agent) = **'자동화된 공정 관리 시스템'**
> **💡 개념 돋보기: 루프 에이전트 (Loop Agent) & 워크플로 에이전트 (Workflow Agent)**
> > **'자동으로 품질 검사하고, 불량품이면 라인 다시 태우는 컨베이어 벨트 시스템'입니다.**
> > 
> > 라이터(LLM 에이전트)가 글을 써서 내놓으면, **루프 에이전트가 중간에 끼어들어 검사(Validation)합니다.**
> > *   "목차에 있는 '핵심 기술 3가지'가 본문에 다 들어갔나? -> **없음(실패)** -> **다시 라이터에게 '다시 써!' 명령(재시도)**"
> > *   "글자 수 2000자 이상인가? -> **미달(실패)** -> **다시 라이터에게 '더 늘려!' 명령(재시도)**"
> > *   "모든 조건 통과? -> **합격(성공)** -> **다음 단계(제목 제안)로 넘김**"
> > 
> > 개발자가 `while문` 짜서 `try-catch`로 에러 잡고 재귀 호출하고... 그런 **지긋지긋한 '제어 흐름(Control Flow) 코드'를 ADK가 '루프 에이전트'라는 부품 하나로 캡슐화해 준 것**입니다. **"그냥 이 조건 통과할 때까지 돌려줘"**라고 설정만 하면 끝! 이게 바로 **워크플로 에이전트(Workflow Agent)**의 위력입니다.

### ③ 커스텀 에이전트 (Custom Agent / Base Agent 상속) = **'우리 식당만의 특제 소스 만들기'**
> **💡 개념 돋보기: 커스텀 에이전트 (Custom Agent - Base Agent 상속)**
> > **ADK가 제공하는 기성복(LLM 에이전트, 루프 에이전트 등)으로 안 되는, '우리만의 독특한 로직'이 필요할 때 직접 바느질해서 만드는 맞춤복입니다.**
> > 
> > 예를 들어, **"글 쓸 때 우리 회사 DB에서 최신 매출 수치 실시간으로 조회해서 넣어줘"** 라거나, **"특정 금칙어 있으면 무조건 거절하고 로그 남겨줘"** 같은 **LLM만으로는 안 되는 '외부 시스템 연동'이나 '엄격한 결정론적 로직'**이 필요할 때 씁니다.
> > 
> > 파이썬 클래스로 `BaseAgent`를 상속받아 `run_async` 메서드 등을 오버라이딩(재정의)해서 **"내 마음대로 작동하는 새로운 에이전트 종류"**를 정의하는 거죠. **"ADK 레고 블록으로 안 되면, 내가 블록을 하나 새로 찍어내겠다"**는 뜻입니다.

## 4. 전체 흐름 정리: "주제 한 줄 -> 완성된 블로그 글" 여정

자, 이제 이 친구들이 어떻게 협업하는지 **시나리오 하나로 쭉 꿰어 보겠습니다.**

1.  **사용자 입력:** `"주제: 직장인을 위한 생성형 AI 생산성 툴 5가지"`
2.  **🧠 플래너 (LLM 에이전트) 작동:**
    *   생각: "직장인 타겟이니 쉬워야 해. 툴 5개 비교표 필요. 프롬프트 팁도 넣자."
    *   산출물: **구조화된 아웃라인(목차) JSON/텍스트 생성**
3.  **✍️ 라이터 (LLM 에이전트) 작동:**
    *   플래너의 목차 받아서 각 섹션별 본문 작성 시작.
    *   산출물: **초안 블로그 글**
4.  **🔄 루프 에이전트 (워크플로 에이전트) 개입 - 검증 루프 시작:**
    *   **검사 1:** "목차의 '툴 5가지'가 본문에 다 있나?" -> **누락 발견!** -> 라이터에게 "3번 툴 설명 빠져있어, 다시 써" -> **라이터 재작성**
    *   **검사 2:** "어조가 전문적인가? 비속어 없나?" -> **통과!**
    *   **검사 3:** "글자 수 3000자 이상인가?" -> **부족!** -> 라이터에게 "예시 더 들어 늘려" -> **라이터 재작성**
    *   ... (모든 조건 통과할 때까지 무한 반복) ...
    *   **최종 합격!** -> 검증된 최종 본문 확정.
5.  **✨ 제목/훅 제안 에이전트 (LLM 에이전트) 작동:**
    *   최종 본문 읽고 -> **"제목: '야근 삭제! 칼퇴 부르는 AI 툴 5선', 훅: '어제 야근 3시간, 오늘 30분으로 줄인 비법 공개'"** 제안.
6.  **최종 결과물 반환:** 사용자에게 **목차 + 검증된 본문 + 추천 제목/훅** 패키지 전달.

## 5. 왜 이 구조가 대단한가? (비전공자가 알아야 할 핵심)

여러분, 만약 이걸 **ADK 없이 순수 파이썬으로 짠다면** 어떨까요?

```python
# 가상의 순수 파이썬 코드 (악몽 버전)
def write_blog(topic):
    outline = call_llm("plan_prompt", topic) # 1. 계획
    draft = call_llm("write_prompt", outline) # 2. 작성
    
    # 3. 검증 루프 (직접 구현해야 함)
    max_retries = 3
    for i in range(max_retries):
        errors = validate(draft) # 검증 로직 직접 짜야 함
        if not errors:
            break
        # 프롬프트에 에러 내용 덧붙여서 다시 요청
        draft = call_llm("rewrite_prompt", draft, errors) 
    else:
        raise Exception("품질 기준 미달")
        
    titles = call_llm("title_prompt", draft) # 4. 제목
    return outline, draft, titles
```

*   **상태 관리(State Management) 골치:** `outline`, `draft`, `errors` 변수 직접 들고 다니며 관리.
*   **재시도 로직 중복:** 다음에 '유튜브 대본 에이전트' 만들면 또 `for문`, `validate` 복사-붙여넣기?
*   **에이전트 간 소통 규약 없음:** 플래너가 준 목차 형식이 라이터가 기대하는 형식이 아니면 파싱 에러 남.
*   **확장성 제로:** "중간에 이미지 생성 에이전트 하나 끼워 넣자" -> 코드 싹 다 고쳐야 함.

**하지만 ADK를 쓰면?**
*   **플래너, 라이터, 검증기, 제목제안자** 모두 **독립된 '에이전트' 객체**로 정의.
*   **루프 에이전트**가 **'검증 실패 시 자동 재시도'**라는 복잡한 제어 흐름을 **설정 한 줄로 끝냄**.
*   **세션(Session), 메모리(Memory), 아티팩트(Artifact)** 같은 **공통 인프라**를 ADK가 알아서 제공. (대화 기록 저장, 파일 주고받기 등)
*   **나중에 "이미지 생성 에이전트" 추가?** 그냥 `sub_agents` 리스트에 하나 추가하면 끝. **레고 블록 쌓듯 조립 가능.**

## 6. 마무리하며: 여러분의 첫 번째 '에이전트 팀'을 맞이할 준비

지금 우리는 **"블로그 플래너"**라는 **첫 번째 서브 에이전트 팀**을 만드는 문턱에 서 있습니다. 지금까지 배운 내용을 가슴에 새기세요.

1.  **복잡한 일은 '계획(Planner)'과 '실행(Writer)'으로 쪼개라.** (분업의 힘)
2.  **실수할 수 있는 일은 '자동 검증 루프(Loop Agent)'로 감싸라.** (안전장치의 힘)
3.  **각각의 역할은 'LLM 에이전트'로 위임하고, 흐름은 '워크플로 에이전트'로 제어하라.** (도구 선택의 지혜)
4.  **기성품으로 안 되면 '커스텀 에이전트'로 직접 만들어라.** (확장성의 완성)

자, 이제 코드 에디터를 열 차례입니다. 다음 강의에서는 실제로 `LlmAgent`로 플래너와 라이터를 정의하고, `LoopAgent`로 검증 루프를 감싸서, **여러분의 로컬 머신에서 돌아가는 '블로그 자동화 공장'**을 같이 세워볼 거예요.
