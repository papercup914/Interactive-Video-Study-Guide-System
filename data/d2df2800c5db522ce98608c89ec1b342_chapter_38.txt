# 🚀 챕터 6. Streamlit 앱 실행으로 웹 인터페이스 확인 — "내 에이전트에게 얼굴(웹 화면) 달아주기"

자, 드디어 우리가 직접 손으로 두드려 볼 시간이 왔습니다. 지금까지 머릿속으로만 그렸던 **'에이전트(두뇌)'**, **'환경(손발)'**, **'세션(연결고리)'**이라는 추상적인 개념들이, 이제 내 눈 앞에서 돌아가는 **웹 화면**이라는 구체적인 모습으로 나타나는 순간입니다.

이번 챕터에서는 터미널(검은 화면)에 익숙하지 않은 분들도 안심하고 따라올 수 있도록, **'식당 오픈 준비'**라는 친근한 비유로 전체 과정을 풀어서 설명해 드릴게요. 자, 앞치마 두르고 주방으로 들어가 볼까요?

---

## 1. 왜 갑자기 '웹 인터페이스'인가요? — "손님상 차리기"

지난 챕터까지 우리는 `agent.py`라는 **설계도(레시피)**를 작성하고, 필요한 **재료(라이브러리, API 키)**를 다듬고, **주방(가상환경)**을 세팅했습니다. 그런데 아무리 맛있는 요리(강력한 에이전트 로직)를 만들어놔도, **손님(사용자) 앞까지 나가지 않으면** 그 가치를 알 수 없죠?

*   **터미널(CLI):** 요리사가 주방에서 "맛있다!"라고 혼잣말하는 것 (개발자만 볼 수 있음)
*   **웹 인터페이스(Streamlit):** 완성된 요리를 예쁜 그릇에 담아 **식당 홀(Hall)로 내놓는 것** (누구든 브라우저로 들어와 클릭하며 쓸 수 있음)

**Streamlit(스트림릿)**은 파이썬으로 데이터 앱이나 데모 웹페이지를 **HTML/CSS/자바스크립트 한 줄 몰라도** 단 몇 줄 코드로 뚝딱 만들어주는 **'마법의 식기 세트'** 같은 도구입니다. 우리가 `streamlit run app.py` 한 방만 치면, 로컬 컴퓨터(내 노트북)에 임시 웹 서버가 뜨면서 `http://localhost:8501` 같은 주소로 **나만의 에이전트 체험관**이 열리는 거죠.

> 💡 **개념 돋보기: Streamlit이란?**
> > **Streamlit**은 **"데이터 스크립트를 공유 가능한 웹 앱으로 몇 분 만에 변환해주는 파이썬 라이브러리"**입니다.
> > 
> > *   **비유:** 복잡한 웹 개발(프론트엔드/백엔드 분리, 배포 설정 등)을 **'인스턴트 라면 끓이기'** 수준으로 단순화해 준 **'자동 식당 오픈 키트'**.
> > *   **특징:** `import streamlit as st` → `st.title("내 에이전트")` → `st.chat_input()` 몇 줄이면 챗봇 UI 완성.
> > *   **왜 쓰는가?:** 에이전트 로직(백엔드) 검증에만 집중하고 싶을 때, UI 만드는 데 시간 쓰지 않게 해주는 **'개발자용 패스트패스'**.

## 2. 실행 전 체크리스트 — "식당 오픈 전 최종 점검"

영상에서는 강사님이 "자, 이제 다들 레포지토리 클론 하고, 가상환경 켜고, 키 넣고, 요구사항 설치했죠?"라고 빠르게 넘어가십니다. 하지만 입문자 입장에선 이 한 문장 한 문장이 다 **'첫 관문'**처럼 느껴지실 거예요. 하나씩 **'왜 하는지'** 이유와 함께 짚어드릴게요.

### ① 레포지토리 클론 (`git clone ...`) — "프랜차이즈 본사에서 매뉴얼 책자 받아오기"
*   **무엇인가:** GitHub(코드 창고)에 올라와 있는 **완성된 프로젝트 폴더 통째로** 내 컴퓨터로 복사해 오는 것.
*   **왜 필요한가:** 우리가 직접 `agent.py`를 처음부터 치지 않아도 되게, **'정답지(agent_complete.py) 포함 풀세트'**를 주신 거예요.
*   **비유:** 창업하러 가는데, 메뉴 개발부터 인테리어 도면까지 다 들어있는 **'창업 세트 박스'**를 트럭으로 실어다 놓은 상황.

### ② 폴더 이동 (`cd Ship Your First Manage Agent`) — "내 매장 자리에 서기"
*   **무엇인가:** 터미널의 '현재 위치'를 방금 받은 프로젝트 폴더 안쪽으로 옮기는 명령.
*   **비유:** 박스만 현관에 놔두고 거실에서 일하면 안 되죠. **주방(프로젝트 루트)**으로 들어가야 칼(코드)을 쓸 수 있습니다.

### ③ 가상환경 생성/활성화 (`python -m venv venv` → `source venv/bin/activate`) — "위생적인 전용 주방 빌리기"
*   **무엇인가:** 내 컴퓨터 전체(시스템 파이썬)를 더럽히지 않고, **이 프로젝트 전용으로 쓸 깨끗한 파이썬 공간**을 만드는 것.
*   **왜 중요한가:** 프로젝트 A는 파이썬 3.10, 라이브러리 1.0 버전이 필요하고, 프로젝트 B는 3.12, 2.0 버전이 필요할 수 있어요. 섞이면 **'재료 충돌(Dependency Hell)'**로 망합니다.
*   **비유:** **'일회용 위생 장갑 + 전용 도마 + 전용 칼 세트'**를 프로젝트마다 새로 꺼내 쓰는 것. `activate`는 장갑 끼고 "나 지금 이 주방에서 일해!"라고 선언하는 행위.
*   **윈도우라면?** `venv\Scripts\activate` (맥/리눅스는 `source venv/bin/activate`)

### ④ 라이브러리 설치 (`pip install -r requirements.txt`) — "레시피에 적힌 재료 장바구니에 담아오기"
*   **무엇인가:** `requirements.txt`라는 **'필수 재료 명세서'**를 읽고, 인터넷(PyPI)에서 자동으로 다운로드해 내 가상환경(`venv`) 안에 깔아주는 명령.
*   **비유:** "이 요리 하려면 간장, 고추가루, 마늘, 참기름 필요해" 적힌 메모 보고 **마트에서 한 번에 카트 채워오는 일**.

### ⑤ 환경 변수 설정 (`.env` 파일에 `ANTHROPIC_API_KEY` 입력) — "마스터 키(열쇠) 주방 금고에 넣기"
*   **무엇인가:** 에이전트의 두뇌인 **Claude(LLM)를 호출하려면 반드시 필요한 인증 키**를 코드에 하드코딩(직접 적기)하지 않고, 안전한 별도 파일(`.env`)에 보관하는 것.
*   **왜 `.env`인가?:** 이 파일을 `.gitignore`에 넣어 **깃허브에 절대 안 올라가게** 막아놨기 때문. **보안의 기본!**
*   **비유:** 식당 **'금고 비밀번호'**나 **'마스터 키'**를 아무나 보는 메뉴판(코드)에 적어두지 않고, 사장님만 아는 **비밀 수첩(`.env`)**에 적어둔 것. `python-dotenv` 라이브러리가 이 수첩을 읽어와 `os.environ`으로 넘겨줍니다.

> 💡 **개념 돋보기: `.env` 파일과 보안 위생**
> > **절대 하지 말아야 할 일:** `ANTHROPIC_API_KEY = "sk-ant-..."` 를 `agent.py`나 `app.py` 소스코드 맨 위에 적어두기 → 깃허브 푸시 → **해킹당해 수억 원 청구서 받기**.
> > 
> > **올바른 습관:**
> > 1.  프로젝트 루트에 `.env` 파일 생성 (숨김 파일임).
> > 2.  안에 `ANTHROPIC_API_KEY=your_actual_key_here` 한 줄만 적기.
> > 3.  `.gitignore`에 `.env` 추가 확인 (보통 템플릿에 이미 있음).
> > 4.  파이썬 코드에선 `from dotenv import load_dotenv; load_dotenv()` 호출 → `os.getenv("ANTHROPIC_API_KEY")`로 꺼내 쓰기.
> > 
> > **비유:** **'통장 비밀번호'를 포스트잇에 적어 모니터에 붙여두지 말고, 금고(비밀 관리 도구)나 암호화된 수첩(`.env`)에만 보관하라는 것.**

## 3. 대망의 실행 명령: `streamlit run app.py` — "개점 종 치기! 🔔"

모든 준비가 끝났다면, 터미널(가상환경 켜진 상태)에서 딱 한 줄을 칩니다.

```bash
streamlit run app.py
```

이 순간, 내 컴퓨터 안에서 다음과 같은 **'마법 같은 연쇄 반응'**이 일어납니다.

### 🪄 백스테이지에서 벌어지는 일들 (비유: 식당 오픈 10분 전)

| 단계 | 기술적 동작 | 식당 비유 |
| :--- | :--- | :--- |
| **1. 스크립트 로드** | `app.py` 파일을 읽어 파이썬 인터프리터가 메모리에 올림 | **헤드셰프(파이썬)가 오늘 메뉴판(`app.py`)을 읽고 머릿속에 그리는 중** |
| **2. Streamlit 서버 기동** | 내부적으로 **Tornado 웹 서버**가 백그라운드에서 뜸 (포트 8501 기본) | **식당 문(포트 8501) 열고 "영업 중" 네온사인 켬. 손님(브라우저) 맞을 준비 완료** |
| **3. 초기 렌더링** | `app.py` 맨 위부터 순차 실행 → `st.title`, `st.chat_input` 등 UI 요소 생성 | **홀 매니저(Streamlit)가 테이블 세팅: 간판 달고(타이틀), 주문 벨(채팅 입력창) 깔고, 메뉴판(사이드바) 놓음** |
| **4. 브라우저 자동 오픈** | 기본 브라우저가 `http://localhost:8501` 로 접속 시도 | **첫 손님(나 자신)이 문 열고 들어와 자리에 앉음** |
| **5. 이벤트 루프 대기** | 사용자 입력(채팅, 버튼 클릭) 기다리며 **무한 루프 돌림** | **웨이터가 주문받으러 올 때까지 손님 앞에서 대기 중** |

### 🖥️ 터미널에 뜰 반가운 메시지들

명령을 치고 엔터 치면, 검은 화면에 알록달록 글씨가 올라옵니다. 당황하지 마세요. 이건 **'오픈 알림판'**이에요.

```text
  You can now view your Streamlit app in your browser.

  Local URL: http://localhost:8501
  Network URL: http://192.168.x.x:8501   (같은 와이파이 공유기 안 다른 기기에서 접속 가능)
```
*   **Local URL:** **내 컴퓨터에서만** 접속 가능한 주소. 클릭하거나 브라우저 주소창에 복사해 넣으세요.
*   **Network URL:** 같은 공유기 쓴 **내 폰/태블릿/동료 노트북**에서 테스트할 때 쓰는 주소.

> ⚠️ **꿀팁: 포트 충돌 났다면? (Address already in use)**
> 이미 8501 포트를 쓰는 다른 Streamlit 앱이 떠 있거나, 안 꺼진 프로세스가 있다는 뜻.
> *   **해결 1:** `Ctrl+C`로 현재 터미널 정지 → `streamlit run app.py --server.port 8502` 로 다른 포트 지정.
> *   **해결 2:** `lsof -i :8501` (맥/리눅스) 또는 `netstat -ano | findstr :8501` (윈도우) 로 PID 찾아 `kill -9 <PID>` 로 강제 종료 후 재실행.

## 4. 브라우저에서 만난 화면 뜯어보기 — "홀 구경하기"

`http://localhost:8501` 접속 성공! 이제 보이는 화면이 바로 **우리가 만든 에이전트의 '얼굴(UI)'**입니다. 영상 강사님이 "자, 이제 보세요"라고 하시며 보여주실 그 화면, 구성 요소를 **'식당 홀 지도'**처럼 설명해 드릴게요.

### 🗺️ 화면 구성 요소 해부도 (일반적인 `app.py` 구조 기준)

| 화면 영역 | Streamlit 코드 예시 | 역할 | 식당 비유 |
| :--- | :--- | :--- | :--- |
| **페이지 타이틀/헤더** | `st.set_page_config(page_title="My Agent")`<br>`st.title("🤖 Incident Response Agent")` | 브라우저 탭 이름, 화면 최상단 큰 제목 | **간판 & 메인 메뉴판** |
| **사이드바 (Sidebar)** | `with st.sidebar:`<br>`st.selectbox("Model", [...])`<br>`st.text_input("API Key", type="password")` | 좌측 접히는 패널. 설정값, 파라미터 조절용 | **주방장 호출벨 & 특별 주문서** (모델 선택, 온도 설정, 시스템 프롬프트 수정 등) |
| **채팅 기록 영역** | `for msg in st.session_state.messages:`<br>`st.chat_message(msg["role"]).write(msg["content"])` | 과거 대화(유저/에이전트/툴 로그) 순차 표시 | **테이블 위에 쌓인 주문서 & 영수증 더미** (대화 히스토리) |
| **채팅 입력창** | `prompt = st.chat_input("What's the incident?")` | 하단 고정 입력창. 엔터 치면 `prompt` 변수에 문자열 담겨 반환 | **손님 입에서 주문 말로 나오는 마이크** |
| **상태/로그 표시** | `with st.status("Thinking...", expanded=True):`<br>`st.write("Calling tool...")` | 에이전트 내부 동작(툴 호출, 사고 과정) 실시간 스트리밍 | **오픈 키친: 주방장에서 "지금 양파 썰고 있어요~" 실시간 중계** |

> 💡 **개념 돋보기: `st.session_state` — "테이블 위 메모지"**
> > Streamlit은 **스크립트가 위아래로 한 번 쭉 실행되고 끝**납니다(Stateless). 버튼 누르면 처음부터 다시 돌려요.
> > 
> > 그런데 **대화 기록**은 유지해야 하죠? 그때 쓰는 게 `st.session_state`라는 **'세션 전용 딕셔너리(창고)'**입니다.
> > 
> > *   `st.session_state.messages = []` → 처음 접속 시 빈 리스트 생성.
> > > *   유저 말하면 `append({"role": "user", "content": prompt})`
> > > *   에이전트 답하면 `append({"role": "assistant", "content": response})`
> > > *   화면 그릴 땐 `for msg in st.session_state.messages:` 로 순회하며 `st.chat_message`로 뿌림.
> > 
> > **비유:** 손님 바뀔 때마다 테이블 치우는 게 아니라, **이 손님 전용 메모지(세션 상태)**에 주문 내역 적어두고, 손님 나갈 때(브라우저 닫을 때) 버리는 것. **서버 재시작하면 다 날아감**(휘발성).

## 5. 실제 동작 시나리오: "사건 발생! 에이전트 호출" — 첫 주문 넣어보기

화면이 떴다면, 이제 **채팅 입력창**에 이렇게 쳐보세요 (영상 예시 기준).

> **입력 예시:** `우리 데이터베이스 CPU가 100% 찍혔어. 원인 좀 찾아줘.`

엔터 치는 순간, **백엔드에서 벌어지는 숨 가쁜 10초** (Streamlit 화면엔 `st.status` 박스로 실시간 중계됨):

1.  **`app.py` 감지:** `if prompt:` 블록 진입 → `st.session_state.messages`에 유저 메시지 추가 → 화면 즉시 갱신(유저 말풍선 뜸).
2.  **에이전트 세션 생성/재사용:** `client.sessions.create(agent_id=..., environment_id=...)` 호출 → **세션 ID** 확보 (이미 있으면 재사용).
3.  **메시지 전송:** `client.sessions.messages.create(session_id=..., content=prompt)` → **Claude 관리 에이전트 서버(클라우드)**로 요청 날림.
4.  **서버 사이드 에이전트 루프 돌림 (우리가 짠 `agent.py` 로직):**
    *   **두뇌(Claude):** "CPU 100%면 메트릭 봐야지" → **툴 호출 결정** (`query_metrics` 스킬 사용).
    *   **손발(Environment):** 컨테이너 안에서 `kubectl top pods` 또는 프로메테우스 쿼리 실행 → 결과 수신.
    *   **두뇌:** "아, `payment-service` 파드가 문제네. 로그 까보자" → **툴 호출** (`read_logs` 스킬).
    *   **손발:** 컨테이너에서 `kubectl logs payment-service-xxx` 실행 → 에러 스택 트레이스 수신.
    *   **두뇌:** "원인 찾았어. DB 커넥션 풀 고갈이야. 해결책 알려줄게" → **최종 답변 생성**.
5.  **스트리밍 응답 수신:** 서버에서 **텍스트 조각(chunk) 단위**로 날아옴 → `app.py`에서 `st.write_stream` 또는 루프 돌며 `st.empty().markdown()`으로 **타자 치듯 화면 출력**.
6.  **완료:** 최종 답변 `st.session_state.messages`에 어시스턴트 역할로 저장 → 루프 끝 → 다음 입력 대기.

> 💡 **개념 돋보기: 스트리밍(Streaming) vs 논-스트리밍**
> > *   **논-스트리밍:** 에이전트 생각 다 끝날 때까지 **손님 앞에 빈 접시 두고 30초 대기** → 완료된 요리 한 번에 내놓음. (답답함)
> > *   **스트리밍:** 요리사가 **한 입 크기씩 썰어서 바로바로 접시에 올려줌**. 손님은 기다리면서 냄새 맡고 맛보며 기다림. (쾌적함)
> > *   Streamlit에선 `st.write_stream(generator)` 또는 `with st.empty(): for chunk in stream: container.markdown(accumulated)` 패턴으로 구현. **사용자 체감 속도(TTFT, Time To First Token) 극적으로 단축**.

## 6. 화면에서 확인해야 할 핵심 포인트 3가지 — "시식 평가서 ✍️"

단순히 "돌아간다" 말고, **개발자 관점**에서 꼭 봐야 할 포인트입니다.

### ① 사이드바에서 **모델/파라미터 바꿔가며 테스트** 해보기
*   `Model`: `claude-3-5-sonnet-20241022` ↔ `claude-3-haiku` 등 변경 → **답변 품질/속도/비용 차이** 체감.
*   `Temperature`: 0.0(결정적) ↔ 1.0(창의적) → **같은 질문에도 답이 얼마나 달라지는지** 확인.
*   `System Prompt` 수정: "너는 시니어 SRE야. 짧게 대답해." → **페르소나 주입 효과** 바로 확인.
*   **이게 다 `app.py` 재시작 없이 사이드바 조작만으로 된다!** → **Streamlit의 상태 유지 + 즉각 리렌더링 위력**.

### ② **에이전트 사고 과정(Thinking/Tool Use) 투명하게 보이는지** 확인
*   `st.status("Agent is working...", expanded=True)` 박스 안에 **어떤 툴을 불렀는지, 인자는 뭔지, 결과는 뭔지** 실시간으로 뜨나요?
*   **왜 중요?:** 프로덕션 가면 "왜 이 답변 나왔지?" 디버깅하려면 **이 로그(추적)가 생명줄**입니다. 개발 단계에서 **'글래스 박스(투명한 상자)'**로 만들어놔야 함.

### ③ **세션 유지/멀티턴 대화** 되는지 테스트
1.  "CPU 100% 원인 찾아줘" → 답변 받음.
2.  "그럼 그 파드 재시작 명령어 줘" → **이전 맥락(어떤 파드인지) 기억해서** `kubectl restart payment-service-xxx` 내놓는지?
3.  브라우저 **새로고침(F5)** 해도 대화 기록 남아있나? (`st.session_state` 덕분)
4.  터미널에서 `Ctrl+C`로 서버 내렸다 `streamlit run app.py` 다시 올리면? → **대화 기록 날아감**(휘발성 확인) → **나중엔 DB/Redis에 영구 저장 필요**함을 체감.

## 7. 자주 겪는 시행착오 & 해결책 — "주방 사건사고 대처법 🚑"

### ❌ 에러 1: `ModuleNotFoundError: No module named 'anthropic'` (또는 `streamlit`, `python-dotenv` 등)
*   **원인:** 가상환경 **안 켠 상태**에서 `pip install` 했거나, **다른 터미널 탭**에서 실행 중.
*   **해결:** 터미널 프롬프트 앞에 **`(venv)`** 글자 있는지 확인 → 없으면 `source venv/bin/activate` (윈도우 `venv\Scripts\activate`) → `pip install -r requirements.txt` 다시.

### ❌ 에러 2: `AuthenticationError: Invalid API Key` / `Permission denied`
*   **원인:** `.env` 파일에 키 **오타**, **공백 포함**, **따옴표 붙여넣기**, 혹은 **키 자체가 만료/잘못됨**.
*   **디버깅:** `app.py` 상단에 임시로 `print(os.getenv("ANTHROPIC_API_KEY"))` 찍어 터미널에 찍히는지 확인 (찍히면 **즉시 지우고 커밋 금지!**).
*   **확인:** Anthropic Console(console.anthropic.com) 가서 키 유효한지, 크레딧 남아있는지 확인.

### ❌ 에러 3: `Agent not found` / `Environment not found` (404 에러)
*   **원인:** `app.py` 안에 하드코딩된 `AGENT_ID`, `ENVIRONMENT_ID`가 **내 클로드 콘솔에 생성한 것과 다름**.
*   **해결:** 강의 자료/레포지토리 README 에 **'Agent/Environment 생성 후 ID 복사해 넣으세요'** 섹션 있는지 확인 → `.env`나 `app.py` 상단 변수에 **내 것**으로 교체.

### ❌ 에러 4: 화면은 떴는데 **입력창 치고 엔터 쳐도 아무 반응 없음** (무한 로딩)
*   **원인 1:** `app.py`에서 `st.chat_input` 받은 뒤 **에이전트 호출 코드가 동기(Blocking) 방식으로 짜여서** Streamlit 메인 스레드 막힘.
*   **원인 2:** 백엔드(클로드 매니지드 에이전트) 응답이 너무 느림(타임아웃).
*   **디버깅:** 터미널(서버 로그)에 `print("Request sent...")`, `print("Response received...")` 찍어 어디까지 가는지 확인.
*   **해결:** 비동기(`asyncio`) 또는 `threading`/`concurrent.futures`로 백엔드 호출 분리하거나, `st.spinner`/`st.status` 안에 `time.sleep` 없이 논블로킹 호출 보장.

## 8. 마무리하며: "이제 내 손안에 에이전트가 있다" 🎉

자, 여기까지 오셨다면 여러분은 이제:

1.  **코드 한 줄 안 짜고** (클론만으로) **완성된 에이전트 앱을 로컬에서 띄우는 법**을 알았고,
2.  **Streamlit이 어떻게 파이썬 변수(`session_state`)를 웹 화면(채팅창)으로 바꿔주는지** 원리를 이해했으며,
3.  **사이드바-채팅창-상태창**으로 이어지는 **에이전트 UI 3종 세트**를 직접 눈으로 확인했고,
4.  **첫 질문 던져보고, 에이전트가 툴 쓰는 모습(Thinking/Tool Use) 구경하고, 멀티턴 대화까지** 테스트해봤습니다.

이건 단순히 "앱 실행해봤다"가 아닙니다. **'서버 사이드 에이전트 루프(두뇌) + 격리된 컨테이너 환경(손발) + 세션 기반 상태 관리'라는 프로덕션급 아키텍처**가, **내 노트북 위 Streamlit이라는 얇은 창문**을 통해 **내 눈 앞에서 투명하게 돌아가고 있다**는 뜻입니다.

> 💡 **한 단계 더 나아가기 (숙제/심화)**
> 1.  `app.py` 열어서 `st.sidebar` 안에 **'대화 초기화 버튼'**(`st.button("Clear Chat", on_click=lambda: st.session_state.clear())`) 추가해보기.
> 2.  에이전트 답변 아래 **'피드백 버튼(👍/👎)'** 달고, 클릭 시 `st.toast("Thanks!")` 뜨게 하기.
> 3.  `st.session_state.messages`를 **JSON 파일로 저장/불러오기**(`st.download_button`, `st.file_uploader`) 기능 붙여서 **브라우저 새로고침해도 대화 유지**되게 해보기.
> 4.  **배포 체험:** `streamlit deploy` (Community Cloud) 또는 `docker build -t my-agent . && docker run -p 8501:8501 my-agent` 로 **내 에이전트 인터넷에 공개**해보기 (API 키는 Streamlit Secrets 관리 필수!).
