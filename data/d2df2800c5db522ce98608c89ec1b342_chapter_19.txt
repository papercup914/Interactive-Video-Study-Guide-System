# 챕터 3. Environment (환경): 에이전트의 손 - 사고와 실행 공간, 컨테이너 제공

자, 여러분. 지난 시간에는 에이전트의 **'뇌(Brain)'**에 해당하는 **Agent(에이전트)** 자체를 살펴봤습니다. "나는 누구인가?", "어떤 모델을 쓸까?", "어떤 기술(MCP 서버, 스킬)을 쓸까?"를 정의하는 설계도 같은 존재였죠.

그런데 아무리 똑똑한 뇌가 있어도, **몸(손발)이 없으면 아무 일도 못 합니다.** 생각이 행동으로 옮겨지려면 실행할 공간과 도구가 필요하니까요. 바로 이 **'손발' 역할**을 하는 것이 오늘 배울 **Environment(환경)**입니다.

---

## 1. 왜 '뇌'와 '손'을 따로 떼어놨을까? (설계 철학의 비밀)

스크립트에서 강사님이 **"이전에는 에이전트 루프(뇌)와 도구 실행(손)이 한 상자 안에 꽉 묶여 있었다"**고 말씀하셨던 부분, 기억나시나요? 이게 왜 중요할까요? 우리 일상 비유로 먼저 들어가 볼게요.

### 🍳 비유: '만능 요리사' vs '셰프와 주방 보조의 분리'

**옛날 방식 (결합된 구조): '슈퍼맨 요리사 1명 고용하기'**
*   식당을 열었는데, **요리사가 단 한 명**입니다. 이 요리사는 **레시피 연구(생각)도 하고, 재료 손질(도구 사용)도 하고, 불 조절(실행)도 다 혼자 합니다.**
*   손님이 10팀 오면? 요리사 10명을 새로 뽑아야 합니다. (컨테이너 10개 띄우기)
*   요리사 한 명 뽑는 데 30분 걸리면? 손님은 30분 동안 기다려야 합니다. **(지연 시간 Latency 발생)**
*   이 요리사가 **식당 금고 열쇠(자격 증명/Credentials)랑 비밀 레시피책(중요 데이터)**을 다 가지고 다닙니다. 요리사가 한눈을 팔거나 나쁜 마음을 먹으면? **대형 사고** 납니다. **(보안 취약점)**

**Claude Managed Agents 방식 (분리된 구조): '셰프(뇌) + 독립된 주방(손/Environment)'**
*   **셰프(Agent/LLM):** 홀에서 손님 주문 받고, 레시피 짜고, "이제 양파 썰어!", "불 중불로 올려!"라고 **지시만 내리는 두뇌** 역할만 합니다. 금고 열쇠 모릅니다. 칼질 못 합니다.
*   **주방(Environment):** 셰프의 지시를 받아 **실제로 칼질하고, 볶고, 접시 담는 물리적 공간이자 도구 모음**입니다. 여기가 바로 '컨테이너'입니다.
*   손님이 10팀 와도? **셰프는 한 명만 있으면 됩니다.** 주방(Environment)만 10개 빨리 복사해 오면(스핀 업) 되니까요. 셰프는 머릿속으로 생각만 하면 되니 **생각 속도(First Token)가 압도적으로 빨라집니다. (90% 단축!)**
*   **보안:** 셰프는 주방 금고 모릅니다. 주방 담당 매니저(시스템)만 열쇠를 가지고 안전하게 재료(데이터/권한)를 주방에 넣어줍니다. 셰프가 해킹당해도 금고 털릴 일 없습니다.

> **💡 개념 돋보기: '뇌-손 분리(Decoupling)'의 3대 혁신**
>
> 1.  **속도(Time to First Token):** 뇌(LLM 추론)는 무거운 컨테이너 띄울 필요 없이 바로 생각 시작 → **응답 속도 90% 이상 단축 (P95 기준)**.
> 2.  **보안(Sandboxing & Credentials):** 뇌가 직접 파일 시스템/비밀번호 만지지 못함. 손(Environment)이 격리된 샌드박스에서만 놀게 함 → **자격 증명 유출 원천 차단**.
> 3.  **확장성(Scaling):** 세션(Session) 늘릴 때 무거운 뇌+손 세트가 아닌, 가벼운 손(컨테이너)만 복제하면 됨 → **서버 비용 절감 & 안정성 확보**.

## 2. Environment(환경)이란 정확히 무엇인가? - "에이전트의 손, 그리고 작업실"

스크립트에서는 **"Environment는 에이전트의 손(hands)이다. 이전 것이 뇌(생각)라면, 이것은 행동을 취할 공간과 컨테이너를 제공한다"**고 정의했습니다.

조금 더 풀어서 말해볼게요. Environment는 **에이전트가 "생각"을 "현실"로 만드는 물리적(가상적) 작업 공간**입니다.

### 🏗️ 비유: '인테리어 시공 현장'

*   **Agent (설계사/감리):** "이 벽 허물고, 여기 콘센트 옮기고, 페인트 색깔 이걸로 해." (계획, 지시)
*   **Environment (현장 + 인부들 + 도구함):** 실제 **먼지 날리는 현장 공간**, **망치/드릴/페인트통 같은 도구들**, 그리고 **지시를 받아 땀 흘리며 일하는 인부들(프로세스/런타임)** 전체를 통칭합니다.
*   **Container (컨테이너):** 이 현장을 **격리된 하나의 '박스'**로 만든 것. 옆 현장(다른 세션)이 시끄러워도 내 현장은 조용하고, 내 현장에서 불내도 옆으로 안 번집니다.

### 🛠️ Environment 안에 실제로 뭐가 들어있나요? (구성 요소)

우리가 `agent.py` 코드에서 Environment를 정의할 때, 대략 이런 것들을 지정하게 됩니다.

1.  **런타임 환경 (OS, 언어 버전):** "이 작업은 Ubuntu 22.04에서 Python 3.11로 해." (기반 토대)
2.  **설치된 패키지/라이브러리:** `requirements.txt`에 적힌 `requests`, `pandas`, `aws-cli` 등 **연장(도구)들**.
3.  **파일 시스템(작업 디렉토리):** 에이전트가 코드 짜고, 로그 읽고, 결과물 저장할 **책상 위 공간**.
4.  **네트워크/권한 설정:** "외부 인터넷 허용할까? DB 접속 허용할까? 루트 권한 줄까?" → **보안 울타리**.
5.  **상태(Statefulness):** 작업을 하다 껐다 켜도 **중간 결과물(파일, DB, 메모리)이 그대로 남아있는 것**. (이게 세션과의 연결 고리!)

> **💡 개념 돋보기: Environment = "일회용이 아닌, 상태를 가진 나만의 클라우드 워크스테이션"**
>
> *   일반적인 서버리스 함수(Lambda 등)는 실행 끝나면 메모리 다 날라갑니다 (Stateless).
> *   하지만 **Managed Agent의 Environment는 '지속성(Persistence)'을 가집니다.**
> *   에이전트가 3시간 동안 디버깅하며 파일 100개 고치고, DB 마이그레이션 돌리고, 로그 분석해도 → **환경이 그대로 유지**됩니다.
> *   사용자가 노트북 덮고 자고 일어나도, 환경은 클라우드에서 **숨 쉬고 있습니다.** (Durability/Reliability 보장)

## 3. 실습 코드(`agent.py`) 속으로: Environment 어떻게 생겼나?

강사님이 화면 왼쪽에 `agent.py` (미완성), 오른쪽에 `agent_complete.py` (완성본) 띄워놓고 하나씩 복사해 넣으라고 하셨죠? Environment 부분이 어떻게 코드로 생겼는지 상상해 봅시다. (실제 코드는 강의 자료 레포의 `Ship Your First Managed Agent` 폴더 README나 완성본에 있습니다.)

```python
# agent.py (작성 중인 파일) - Environment 정의 부분 추정

from managed_agents import Environment, Agent, Session # 가상의 import

# 1. 에이전트(뇌) 정의 - 지난 챕터에서 함
my_agent = Agent(
    name="Incident Responder",
    model="claude-3-5-sonnet",
    skills=["read_logs", "check_deployments", "query_metrics"],
    # ... 뇌 설정 ...
)

# 2. 환경(손/작업실) 정의 - 오늘의 주인공!
my_environment = Environment(
    name="prod-investigation-env",           # 이 작업실 이름표
    image="my-org/incident-response:latest", # 도커 이미지(사전 세팅된 공구함) 지정!
    # 혹은 직접 스펙 정의 가능:
    # base_image="ubuntu:22.04",
    # python_version="3.11",
    # packages=["boto3", "kubernetes", "datadog-api-client"],
    
    # 🔒 보안/권한 설정 (뇌와 손 분리의 핵심!)
    network_policy="restricted",             # 외부 인터넷 차단? 내부만?
    secrets=["DATADOG_API_KEY", "AWS_CREDS"], # 비밀 열쇠는 '여기'서만 관리! 뇌는 모름.
    persistent_storage=True,                 # 작업 내용 저장할래? (기본값 True)
    
    # 자원 할당
    cpu="2 vCPU",
    memory="4 GiB",
    ttl_minutes=60                           # 1시간 안 쓰면 자동 정리 (비용 절약)
)

# 3. 세션으로 묶기 (다음 챕터에서 자세히)
session = Session(agent=my_agent, environment=my_environment)
```

### 코드 읽어주는 튜터의 해설

*   **`image="my-org/incident-response:latest"`**: **"미리 세팅된 만능 공구함(도커 이미지)을 가져와라"**는 뜻입니다. 매번 `pip install` 하고 `apt-get` 할 필요 없이, 우리 팀이 만든 '사건 대응용 표준 환경'을 1초 만에 복제해 온다는 의미죠. 이게 **'컨테이너 제공'**의 실체입니다.
*   **`secrets=[...]`**: 여기서 **자격 증명(Credentials) 관리의 핵심**이 나옵니다. 뇌(Agent) 코드 어디에도 API 키 문자열이 없습니다. 환경(Environment) 설정에서 "이 환경엔 Datadog 키, AWS 키 넣어줘"라고 **선언적(Declarative)**으로만 적습니다. 실제 키 값은 플랫폼의 비밀 저장소(Vault 등)에 안전하게 있고, 컨테이너 뜰 때 **환경 변수나 마운트된 파일로만 주입**됩니다. 에이전트(LLM)는 이 키 값을 **절대 볼 수 없고, 토큰으로도 출력 못 합니다.**
*   **`persistent_storage=True`**: "이 작업일지(파일 시스템) 버리지 마." → 세션이 끊겨도, 브라우저 새로고침 해도, 노트북 덮어도 **내 작업 공간은 클라우드에 그대로 보관**됩니다. 내일 이어서 할 수 있어요.

## 4. 실전 시나리오: "새벽 3시, 서버 다운 알림 (Incident Response)"

강사님이 **"소프트웨어 엔지니어라면 새벽 3시 온콜(On-call)의 고통을 알 것"**이라며 이 예제를 골랐죠? Environment가 어떻게 '내 손'이 되어 주는지 시나리오로 체감해 봅시다.

### 상황: 새벽 3시, PagerDuty 알림 울림 🚨
> **"[CRITICAL] 결제 API 에러율 50% 초과! 즉시 대응 바람"**

### 과거의 나 (Environment 없이, 로컬에서 직접):
1.  눈 비비며 노트북 켬 → VPN 연결 → 터미널 5개 띄움.
2.  `kubectl logs -f payment-service` (로그 보다 터미널 멈춤)
3.  `datadog` 웹사이트 접속 → 대시보드 찾느라 헤맴.
4.  `github` 배포 내역 확인 → "어제 배포한 PR #402 의심됨".
5.  로컬에서 `git revert` → `kubectl apply` → **손 떨려서 wrong namespace 배포 위험**.
6.  **중간에 네트워크 끊기면? 지금까지 분석한 로그, 띄워둔 터미널 세션 다 날라감.** 멘탈 붕괴.

### Environment 있는 나 (Managed Agent):
1.  슬랙(또는 웹 UI)에 한 마디 입력: **`@agent 결제 API 에러 원인 분석하고 롤백 계획 세워줘`**
2.  **뇌(Agent):** "음, 인시던트 대응 페르소나네. 내 스킬(`read_logs`, `check_deploy`, `query_metrics`) 쓸 수 있겠군. 근데 실제 실행은 내 손(Environment)에게 시켜야지."
3.  **손(Environment) - 백그라운드에서 척척:**
    *   **컨테이너 이미지 `incident-response:latest` 로 3초 만에 기동.** (내 노트북 아님, 클라우드 GPU/CPU)
    *   **사전 주입된 비밀 키로** Datadog API 호출 → 메트릭 뽑아옴. (내가 키 입력 안 함)
    *   `kubectl` 클러스터 접속 → 파드 로그 실시간 스트리밍 받음. (내 로컬 `kubeconfig` 필요 없음, 환경에 설정돼 있음)
    *   GitHub API로 최근 배포 목록 조회 → 의심 커밋 특정.
    *   **작업 디렉토리(`/workspace/incident-1234`)에** 분석 로그, 스크린샷, 롤백 스크립트 **차곡차곡 저장.** (파일 시스템 영속성)
4.  **뇌(Agent):** 손이 가져온 데이터 종합 → "원인은 PR #402의 DB 커넥션 풀 누수. 롤백 스크립트 `/workspace/incident-1234/rollback.sh` 준비했음. 실행할까?"라고 **나(사람)에게 보고.**
5.  나: "응, 실행해." → **손(Environment)이 롤백 스크립트 실행 → 서비스 복구 확인 → 나에게 "완료" 알림.**
6.  나: **다시 이불 속으로 직행 🛌** (Environment는 TTL 다 될 때까지 보관돼서 내일 출근해도 히스토리 그대로 볼 수 있음.)

> **💡 개념 돋보기: Environment가 '손'인 결정적 증거 - "도구 호출(Tool Use)의 실행 주체"**
>
> *   LLM(뇌)은 `{"tool": "kubectl", "args": "get pods -n payment"}` 이라는 **JSON 텍스트(생각)**만 뱉습니다.
> *   이 JSON을 **받아서 실제로 컨테이너 안에서 `kubectl` 바이너리 실행하고, stdout/stderr 받아서 다시 LLM에게 주는 주체**가 바로 **Environment(컨테이너 런타임)**입니다.
> *   즉, **LLM은 "뭐 해줘"만 말하고, Environment가 "어떻게(Where/How)"를 책임집니다.** 이게 분리의 본질입니다.

## 5. 요약하며: Environment 마스터하기 체크리스트

이 챕터에서 여러분이 가져가야 할 핵심 마인드셋 3가지입니다.

1.  **Environment = "격리된 실행 컨테이너 + 영속 스토리지 + 비밀 관리소"**
    *   단순한 '서버'가 아닙니다. **에이전트가 안전하게, 빠르게, 길게 일할 수 있는 전용 작업실**입니다.
2.  **뇌(코드/로직)와 손(환경/자격증명)은 철저히 분리 설계하세요.**
    *   Agent 코드(`agent.py`)에 **절대 API 키, DB 비번, 내부 IP 하드코딩 금지**.
    *   Environment 설정(`Environment(...)`)에서 `secrets`, `network_policy`, `image`로 **선언적으로 주입**하세요.
3.  **이미지(Image)로 '표준 공구함'을 미리 만드세요.**
    *   매 세션마다 `pip install` 기다리지 마세요. `Dockerfile`로 우리 팀 표준 도구 다 깔린 이미지 빌드해 놓고 `image="..."` 한 줄로 1초 만에 띄우세요. 이게 **Production Ready**의 시작입니다.

자, 이렇게 **Agent(뇌)**와 **Environment(손)**이 준비되었습니다. 그런데 이 둘이 어떻게 만나서 **대화(Session)**를 이어갈까요? 뇌가 "양파 썰어"라고 했는데, 손이 "어디서 썰지? 어떤 칼로?" 모르게 따로 놀면 안 되잖아요.

다음 챕터 **<Session (세션): 뇌와 손을 잇는 통로, 이벤트 스트림의 마법>** 에서 이 둘을 결혼시키는 **Session**의 비밀과, **스트리밍(Streaming)**으로 실시간 소통하는 마법을 파헤쳐 보겠습니다.

실습 레포의 `README.md`에 적힌 `streamlit run app.py` 명령어로 데모 앱 띄워보시면서, **"아, 저 웹 페이지 뒤에서는 지금 Environment 컨테이너가 돌아가고 있구나"** 하고 상상해 보세요. 그럼 다음 시간에 뵙겠습니다! 👋
