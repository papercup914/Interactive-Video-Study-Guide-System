# Chapter 02. 명령(Instruction) 프롬프트 엔지니어링: 마크다운 아웃라인 출력 형식 명세(제목, 서론, 4-6개 섹션, 결론)

> **학습 목표:** 이 챕터에서는 **"블로그 글쓰기 에이전트"**를 실제로 만들면서, AI에게 **"결과물을 마크다운(Markdown) 형태의 정해진 아웃라인(제목, 서론, 4~6개 섹션, 결론)으로 내놓으라"**는 **명령(Instruction) 프롬프트**를 어떻게 설계하고, 코드로 구현하는지 기초 공사를 다집니다. 아직 프롬프트 문구 자체를 작성하는 단계는 아니지만, **"어떤 도구(ADK)로, 어떤 구조(에이전트 아키텍처)로 그 프롬프트를 실행할 것인가"**를 정하는 아주 중요한 설계도 그리기 시간이라고 보시면 됩니다.

---

## 1. 큰 그림 그리기: "자동 블로그 공장" 짓기 (고수준 뷰)

영상 초반, 강사님은 **"좋아, 이제 고수준 개요는 끝났고, 실제로 에이전트를 만들어서 이 아이디어가 어떻게 작동하는지 보자"**라고 말씀하십니다. 마치 건축가가 설계도만 그리다가 **"자, 이제 모델하우스를 지어보자"**고 외치는 순간과 같습니다.

우리가 지을 **'블로그 글쓰기 에이전트(Blog Writing Agent)'**의 작업 흐름은 이러합니다.

1.  **입력:** 사용자가 **주제(Topic)**를 던져줍니다. (예: "AI 시대의 프롬프트 엔지니어링")
2.  **1단계 - 기획자(Planner Agent):** 주제를 받아 **구조화된 아웃라인(Outline)**을 만듭니다. 이때 **"제목, 서론, 4~6개 본문 섹션, 결론"**이라는 **마크다운 틀**을 지키라고 **명령(Instruction)**을 내립니다.
3.  **2단계 - 작가(Writer Agent):** 완성된 아웃라인을 보고 **본문 전체**를 써내려갑니다.
4.  **3단계 - 마케터(Title/Hook Agent):** 다 쓴 글을 보고 **대체 제목과 훅(Hook, 독자 낚시 문구)**을 제안합니다.

> **💡 개념 돋보기: 왜 '에이전트(Agent)'라고 부를까?**
> > 우리가 흔히 쓰는 '챗봇'은 사용자가 말하면 그냥 대답만 합니다. 하지만 **'에이전트'**는 **목표(Goal)**를 주면 **도구(Tool)를 쓰고, 계획을 세우고, 여러 단계를 거치며 스스로 일을 완수**하는 '일꾼'에 가깝습니다. 여기서는 "블로그 글 하나 완성해"라는 **큰 목표**를 **기획 -> 집필 -> 마케팅**이라는 **작은 단계들로 쪼개서 각각 다른 전문 일꾼(에이전트)에게 맡기는 구조**입니다.

---

## 2. ADK(에이전트 개발 키트)라는 '최신식 공장 설비' 이해하기

강사님은 **"이게 바로 ADK의 카테고리(분류 체계)가 빛을 발하는 지점"**이라고 강조하십니다. ADK(Google Agent Development Kit)는 에이전트를 만들기 위한 **표준화된 공구함**이자 **공장 자동화 시스템**입니다. 코드를 한 줄 한 줄 뜯어보기 전에, 이 공장 안에 어떤 **'일꾼(에이전트) 종류'**가 있는지부터 알아야 합니다.

### 2-1. LLM 에이전트 (LLM Agent): "생각하는 브레인, 모델이라는 엔진을 단 일꾼"

> **"플래너(Planner) 에이전트와 라이터(Writer) 에이전트는 LLM 에이전트인데, 이들은 모델(Model)에 의해 구동됩니다."**

*   **비유:** **'베테랑 기자(또는 작가)'**를 채용했다고 칩시다. 이 기자의 뇌는 **'거대 언어 모델(LLM, 예: Gemini, GPT)'**입니다.
*   **특징:** 지시만 내리면(프롬프트), 자기 지식과 추론 능력으로 **글을 기획하고(플래너), 글을 씁니다(라이터)**.
*   **ADK에서의 역할:** `LlmAgent` 클래스로 만듭니다. "너는 기획자야", "너는 작가야"라는 **시스템 프롬프트(역할 부여)**와 **"마크다운 아웃라인 형식으로 내놔"**라는 **작업 지시 프롬프트(Instruction)**를 장착시킨 상태입니다.

### 2-2. 루프 에이전트 (Loop Agent) & 워크플로 에이전트 (Workflow Agent): "까다로운 품질 관리 매니저"

> **"이들은 루프 에이전트(Loop Agent)로 감싸져 있는데, 이는 ADK의 워크플로 에이전트(Workflow Agent)입니다. 검증(Validation)에 실패하면 자동으로 재시도(Retry)를 처리해줍니다."**

*   **비유:** 기자가 초안을 쓰면 **'편집장(루프 에이전트)'**이 검사합니다. **"야, 이 아웃라인 섹션이 3개밖에 안 되잖아? 4~6개로 다시 써와!"** 혹은 **"마크다운 문법(## 제목) 안 지켰네? 다시 해!"**라고 **퇴짜(검증 실패)**를 놓습니다.
*   **자동 재시도(Retry):** 사람이 일일이 "다시 해"라고 말할 필요 없이, **ADK의 루프 에이전트가 "통과할 때까지 무한 반복(또는 설정 횟수만큼) 시켜줍니다."** 이게 바로 **워크플로 에이전트(작업 흐름 제어자)**의 위력입니다.
*   **왜 중요할까?** AI는 가끔 헛소리(할루시네이션)를 하거나, 정해진 형식을 어깁니다. 이 **'자동 검증 & 재시도 루프'**가 없으면, 우리가 새벽 3시에 일어나 "제이슨 파싱 에러 났다!"며 고쳐야 합니다.

> **💡 개념 돋보기: 루프 에이전트(Loop Agent) vs LLM 에이전트(LLM Agent)**
> > *   **LLM 에이전트:** **'일하는 사람'** (생각함, 생성함, 창작함).
> > *   **루프/워크플로 에이전트:** **'관리하는 시스템'** (생각 안 함, 조건 검사함, 흐름 제어함, 다시 시킴).
> > *   **핵심:** LLM 에이전트가 **"마크다운 아웃라인(제목, 서론, 섹션 4~6개, 결론)"**을 잘 만들었는지 **코드(Validator)로 검사**하고, 틀리면 **LLM 에이전트에게 "프롬프트 지침 다시 읽고 다시 해!"라고 시키는 자동화 장치**가 루프 에이전트입니다.

### 2-3. 커스텀 에이전트 (Custom Agent / Base Agent 상속): "우리 공장만의 특수 로봇 만들기"

> **"만약 그것(기존 에이전트 종류) 이상의 무언가가 필요하다면, ADK는 베이스 에이전트(Base Agent)를 서브클래싱(Subclassing)해서 커스텀 에이전트를 확장하게 해줍니다."**

*   **비유:** 기성품 컨베이어 벨트(LLM Agent, Loop Agent)로 안 되는 **특수 공정**(예: "실시간 구글 검색 API 연동하며 글쓰기", "이미지 생성 모델 호출하며 레이아웃 잡기")이 필요하면? **직접 로봇 팔을 용접해서 만듭니다.** 그게 `BaseAgent`를 상속받는 **커스텀 에이전트**입니다.
*   **현단계에서는:** 우리는 표준 부품(LLM Agent, Loop Agent)만으로도 **'마크다운 아웃라인 생성'**이라는 목표를 달성할 수 있으니, 커스텀 에이전트는 "나중에 필요하면 쓰지 뭐" 하고 넘어가면 됩니다.

## 3. 개발 환경 세팅: "공장 부지 다지고 전기 끌어오기"

이제 본격적으로 코드를 짜기 위해 **개발 환경**을 만듭니다. 강사님은 매우 구체적으로 두 가지를 명령하십니다.

### 3-1. UV 설치: "초고속 파이썬 패키지 관리자, 신입 사원 온보딩 도우미"

> **"First off, you need to install UV. You can do that by running the command right here."**

*   **비유:** 파이썬 프로젝트 할 때마다 `venv` 만들고 `pip install` 하고 버전 꼬이고... 이 지옥 같은 과정을 **'마법의 지팡이(UV)'** 하나로 끝내주는 도구입니다. **Rust로 만들어져서 미친 듯이 빠릅니다.**
*   **명령어 (터미널에 복붙):**
    ```bash
    # 맥/리눅스
    curl -LsSf https://astral.sh/uv/install.sh | sh
    # 윈도우 (파워셸)
    powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
    ```
*   **왜 쓰냐고요?** 우리가 만들 `agent.py` 안에서 `google-adk` 같은 라이브러리를 **순식간에, 꼬임 없이 깔아주기 때문**입니다. "UV 있으면 `pip`, `venv`, `poetry` 다 필요 없어요."

### 3-2. Google ADK 설치: "우리의 메인 공장 기계 들여놓기"

> **"Secondly, you need to install Google ADK because we need to, obviously use ADK in this."**

*   UV가 설치되었다면, 프로젝트 폴더에서 바로 깔 수 있습니다.
*   **명령어:**
    ```bash
    # 프로젝트 폴더 생성 및 이동
    mkdir blog-agent-project
    cd blog-agent-project
    
    # UV로 가상환경 만들고 ADK 설치까지 한 방에
    uv init
    uv add google-adk
    ```
*   **비유:** `uv init`은 **공장 부지 정리하고 뼈대 세우는 것**, `uv add google-adk`는 **메인 생산 라인 기계(ADK 라이브러리) 들여놓고 전원 연결하는 것**입니다.

### 3-3. `agent.py` 생성: "메인 컨트롤 타워 설계도 첫 장 펴기"

> **"And then let's create a file called agent.py in your IDE. We need to import these key libraries and then we can start building out our very first agent."**

*   IDE(VS Code, PyCharm 등)에서 `agent.py` 파일을 만듭니다. 이 파일 하나가 우리 **'블로그 공장'의 메인 컨트롤러**가 됩니다.
*   **가장 먼저 할 일: 라이브러리 임포트 (수입 신고)**
    ```python
    # agent.py 최상단
    from google.adk.agents import LlmAgent, LoopAgent, SequentialAgent # 일꾼들 데려오기
    from google.adk.tools import google_search # 도구들 데려오기 (나중에 쓸 수 있음)
    from google.adk.runners import Runner # 실행기
    from google.adk.sessions import InMemorySessionService # 세션 관리
    # ... 등등
    ```
*   **비유:** 공장 짓기 전에 **중장비(LLM Agent), 컨베이어(Loop Agent), 제어실(Runner)** 등을 창고에서 꺼내 현장으로 **'수입 신고(Import)'** 하는 과정입니다. 이 줄들이 없으면 "LLM Agent가 뭐야? 먹을 수 있어?" 상태가 됩니다.

## 4. 첫 번째 에이전트 탄생: 플래너(Planner) - "아웃라인 설계자" 정의 시작

강사님은 **"우리가 만들 첫 번째 에이전트는 blo..."**라고 말씀하시며 화면이 끊깁니다. 하지만 문맥상 **`BlogPlannerAgent` (블로그 플래너 에이전트)**임이 확실합니다. 이 친구가 바로 **"마크다운 아웃라인 출력 형식 명세(제목, 서론, 4-6개 섹션, 결론)"**을 **지시(Instruction)받아 수행할 핵심 일꾼**입니다.

우리가 앞으로 `agent.py` 안에서 이 플래너 에이전트를 정의할 때 대략 이런 모양이 될 것입니다 (예상 코드):

```python
# agent.py 내부 (플래너 에이전트 정의부)

# 1. '마크다운 아웃라인 출력 형식'을 정의한 명령(Instruction) 문자열 준비
PLANNER_INSTRUCTION = """
당신은 전문 블로그 기획자입니다. 사용자가 준 주제로 블로그 글의 '아웃라인(개요)'을 짜세요.
반드시 아래 '마크다운 형식'을 엄격히 지켜서 출력하세요. 다른 설명은 절대 덧붙이지 마세요.

# [출력 형식 명세 - 마크다운 아웃라인]

## 제목
(여기에 매력적인 블로그 제목을 작성하세요.

## 서론
독자의 관심을 끌 도입부 핵심 내용을 2-3문장으로 요약하세요.

## 본문 섹션 1: [소제목]
핵심 내용 요약

## 본문 섹션 2: [소제목]
핵심 내용 요약

## 본문 섹션 3: [소제목]
핵심 내용 요약

## 본문 섹션 4: [소제목]
핵심 내용 요약
(필요시 섹션 5, 6 추가 가능. 총 4~6개 유지)

## 결론
핵심 메시지 재강조 및 독자 행동 유도(Call to Action) 문구 작성
"""

# 2. LLM 에이전트(생각하는 브레인) 생성 - 이 지시문을 심장처럼 장착
planner_agent = LlmAgent(
    name="BlogPlannerAgent",
    model="gemini-2.0-flash", # 또는 사용할 모델명
    instruction=PLANNER_INSTRUCTION, # <--- 핵심! 여기에 '명령 프롬프트'가 들어감
    output_key="blog_outline" # 결과물을 이 키로 저장해 다음 에이전트(작가)에게 넘김
)
```

> **💡 개념 돋보기: `instruction` 파라미터 = "명령(Instruction) 프롬프트 엔지니어링의 현장"**
> > 바로 이 `instruction="..."` 안에 들어가는 **긴 문자열**이 이번 챕터의 주제인 **"명령 프롬프트"** 그 자체입니다.
> > *   **"마크다운 아웃라인 출력 형식 명세"** -> `## 제목`, `## 서론`, `## 본문 섹션 1~6`, `## 결론` 등으로 **구조화하여 명시**함.
> > *   **"제목, 서론, 4-6개 섹션, 결론"** -> **"반드시 지켜라(Strictly follow)"**, **"다른 말 하지 마라(No extra commentary)"** 같은 **제약 조건(Constraints)**으로 강화함.
> > *   이 텍스트 한 덩어리가 **LLM(모델)에게 "너는 지금부터 이 틀에 맞춰서만 생각해서 답해라"**라고 **세뇌(Instruction)시키는 주문서**입니다.

## 5. 전체 흐름 정리: "공장 가동 준비 완료"

이번 챕터(스크립트 구간)에서 우리는 **아직 코드를 다 짜지 않았습니다.** 하지만 **가장 중요한 기초 공사**를 마쳤습니다.

1.  **목표 설정:** 블로그 글 자동 생성 파이프라인 구축 (기획 -> 작성 -> 제목 제안).
2.  **아키텍처 이해:** ADK의 **LLM Agent(일꾼)** + **Loop/Workflow Agent(관리자)** 조합으로 **신뢰성(자동 재시도)** 확보.
3.  **환경 구축:** **UV**로 초고속 환경 세팅 -> **Google ADK** 설치 -> **`agent.py`** 진입점 생성 -> **라이브러리 임포트**.
4.  **첫 일꾼 정의 직전:** **플래너 에이전트(기획자)**를 만들 차례. 이때 **"마크다운 아웃라인 형식(제목, 서론, 4-6섹션, 결론)"**을 **`instruction` 프롬프트로 심어줄 준비** 완료.
