# 챕터 3: 에이전트 위임으로 인시던트 자동 대응 또는 완전 자동화 목표

안녕하세요! 지난 챕터까지 우리는 '관리형 에이전트(Claude Managed Agents)'라는 강력한 도구의 개념과 그 내부 구조(브레인, 핸즈, 세션)에 대해 꼼꼼하게 뜯어보았습니다. 이제는 **"이게 내 실제 업무, 내 고통스러운 일상을 어떻게 바꿔줄까?"**라는 가장 중요한 질문에 답할 차례입니다.

이번 챕터의 주인공은 바로 **'새벽 3시의 악몽, 인시던트(Incident) 대응'**입니다. 개발자가 아니라면 '인시던트'라는 단어가 낯설 수 있습니다. 하지만 우리 일상생활에서도 이와 똑같은 상황은 수없이 일어납니다. 자, 함께 그 현장으로 가보시죠.

---

## 1. 개발자의 악몽, '온콜(On-call)' 그리고 새벽 3시의 전화벨

상상해 보세요. 여러분이 **'24시간 운영되는 유명 맛집의 헤드 셰프'**라고 해봅시다. 손님(사용자)들은 밤낮없이 몰려옵니다. 여러분은 교대 근무를 서는 직원들(서버, 데이터베이스, 네트워크)을 관리하죠.

어느 토요일 새벽 3시, 깊은 잠에 빠져 있는데 전화기가 울립니다. **"셰프님, 큰일 났어요! 주방 가스불이 안 켜져요(서버 다운)!"** 혹은 **"냉장고가 고장 나서 재료가 다 상했어요(데이터 손실)!"**

여러분은 잠옷 바람으로 택시를 타고 식당으로 달려갑니다. 도착해서는 손전등을 켜고(로그 확인), 가스 밸브를 돌려보고(메트릭 확인), 어제 새로 들여놓은 오븐(최신 배포 버전) 때문에 퓨즈가 나간 건 아닌지 의심하며 이곳저곳을 정신없이 헤집습니다. 심장이 쿵쾅거리고, 머리는 멍하고, "도대체 왜 지금이야..."라는 한숨만 나옵니다. 이게 바로 소프트웨어 엔지니어들이 겪는 **'온콜(On-call, 당직 근무)'의 고통이자 '인시던트 대응'**의 실체입니다.

> **💡 개념 돋보기: 인시던트(Incident)와 온콜(On-call)**
> > **인시던트(Incident)**란, 서비스가 정상적으로 동작하지 않아 사용자에게 피해를 주거나 줄 수 있는 **'비상 상황'**을 뜻합니다. 서버가 다운됐거나, 결제가 안 되거나, 페이지 로딩이 무한정 걸리는 것들이죠.
> > **온콜(On-call)**은 이 비상 상황에 즉각 대응하기 위해 **'당번을 정해 24시간 대기시키는 제도'**입니다. 주말이든 휴가든 새벽이든, 전화가 오면 무조건 뛰어나가야 합니다. 개발자들의 '워라밸(일과 삶의 균형)'을 무너뜨리는 주범 1호로 꼽히죠.

## 2. 기존 방식: 인간이라는 '느리고 지치는 프로세서'

지금까지 이 문제를 어떻게 해결해왔을까요? **'사람이 직접 다 한다'**였습니다.

새벽 3시에 깨어난 엔지니어(인간 프로세서)는 다음과 같은 순서를 밟습니다.
1.  **상황 인지:** 알림(알람)을 보고 "어? 큰일 났네?" 인지함. (지연 시간: 잠결이라 느림)
2.  **도구 준비:** 노트북 켜고, VPN 접속하고, 모니터링 대시보드(Grafana, Datadog 등) 띄우고, 터미널 열어서 서버 접속함. (준비 시간: 10~30분 소요)
3.  **원인 분석 (탐정 놀이):** 로그 찍어보고, 메트릭 그래프 뜯어보고, 최근 배포 내역 뒤져보고, 동료에게 슬랙으로 "너 뭐 건드렸어?" 물어봄. (분석 시간: 운 좋으면 30분, 나쁘면 몇 시간)
4.  **조치 실행:** 설정 파일 고치고, 서비스 재시작하고, 핫픽스 배포하고.
5.  **사후 처리:** 사고 리포트(Postmortem) 쓰고, 재발 방지 대책 회의 잡음.

이 과정의 치명적인 단점은 **'인간의 한계'**입니다. 인간은 피곤하면 판단력이 흐려지고(실수 유발), 동시에 여러 일을 못 하며(병목), 자야 할 시간에 깨면 다음 날 업무 효율이 바닥납니다. 마치 **셰프가 매일 밤 주방 불을 직접 확인하러 뛰어오는 것**과 같습니다. 셰프가 요리 개발(핵심 가치 창출)을 할 시간이 어디 있나요?

## 3. 에이전트 위임: '초능력 수석 부주방장'의 등장

이번 세션에서 보여주는 **관리형 에이전트(Claude Managed Agents)**는 이 지긋지긋한 루프를 **"셰프(당신) 대신 수석 부주방장(에이전트)이 다 처리하게 만드는 것"**입니다.

영상 속 강연자는 이렇게 말합니다.
> *"우리는 이제 에이전트를 실행시켜 클로드가 이 모든 걸(로그, 메트릭, 배포 조사) 대신 하게 할 겁니다. 그래서 우리가 새벽 3시에 깨더라도 에이전트에게 넘겨버리거나, 어쩌면 클로드가 다 해결해버려서 우리가 아예 깨지 않아도 되게 만들 겁니다."*

이게 바로 **'에이전트 위임(Agent Delegation)'**의 핵심입니다. 단순히 "알림 끄기"가 아닙니다. **조사 → 진단 → 조치 → 보고**라는 **전문가의 인지 프로세스 전체를 AI에게 위임**하는 것입니다.

### 비유: 셰프 vs 수석 부주방장 (에이전트)

| 상황 | 기존 방식 (인간 직접 대응) | 에이전트 위임 방식 (Managed Agent) |
| :--- | :--- | :--- |
| **새벽 3시 알람** | 셰프(당신)가 벌떡 깨어나 택시 타고 출동 | **수석 부주방장(에이전트)이 "셰프님, 주무세요. 제가 다녀오겠습니다"** 하고 출동 |
| **원인 파악** | 셰프가 손전등 켜고 가스관, 전기, 재료 일일이 확인 | 부주방장이 **동시에** 가스 압력 체크, 전기 차단기 확인, 냉장고 온도 로그 분석, 어제 바꾼 레시피(배포) 검토 |
| **조치** | 셰프가 직접 밸브 돌리고, 퓨즈 갈고, 재료 폐기 결정 | 부주방장이 "가스 밸브 고장 확인이요. 예비 밸브로 전환 완료했습니다. 재료는 냉동고로 옮겼습니다." **실행 후 보고** |
| **결과** | 셰프 녹초, 다음 날 요리 못 함 | **셰프는 꿈나라에서 계속 잠듦. 아침에 "해결 완료 리포트"만 읽으면 됨.** |

## 4. 실습 시나리오: '시뮬레이션된 인시던트' 속으로

영상에서는 이 멋진 상상을 현실로 만들기 위해 **스트림릿(Streamlit)**이라는 파이썬 웹 앱 프레임워크로 만든 **시뮬레이션 화면**을 띄웁니다. (`streamlit run app.py`)

여러분이 보게 될 화면은 대략 이렇습니다.
*   왼쪽에는 **에이전트 코드(`agent.py`)**가 보이고(우리가 만들 거임),
*   오른쪽에는 **완성된 정답 코드(`agent_complete.py`)**가 있습니다.
*   중앙에는 **"인시던트 발생!"** 버튼과 에이전트가 실시간으로 생각하고 행동하는 **로그 스트림**이 뜹니다.

이 실습의 목표는 단 하나입니다. **"에이전트에게 '너 이 인시던트 좀 봐줘'라고 시켰을 때, 에이전트가 도구(MCP 서버, 스킬)를 써서 로그도 까보고, 메트릭도 그려보고, 배포 내역도 뒤져서 '원인은 이것이다, 이렇게 고쳐라'라고 답하게 만들자."**

우리는 빈 껍데기인 `agent.py`에 **'페르소나(너는 베테랑 SRE야)'**, **'도구(로그 조회기, 메트릭 조회기, 배포 히스토리 조회기)'**, **'환경(실행할 컨테이너)'**을 하나씩 붙여넣으며 **'완벽한 수석 부주방장'을 조립**할 것입니다.

> **💡 개념 돋보기: 왜 '시뮬레이션'인가? (안전장치의 중요성)**
> > 실제 운영 서버(Production)에 처음부터 에이전트를 풀어놓는 건 **'초보 운전자에게 F1 레이싱 카를 몰아보라 하는 것'**과 같습니다. 브레이크가 어디 있는지도 모르는데 엑셀만 밟으면 대형 사고 납니다.
> > 그래서 우리는 **'연습용 주행 트랙(시뮬레이션 환경)'**에서 가짜 인시던트를 터뜨려놓고, 에이전트가 **헛발질(환각, 잘못된 명령 실행)**을 해도 실제 서비스가 안 망가지게 연습합니다. 이 과정에서 에이전트의 프롬프트(지시문)와 도구 사용 로직을 계속 다듬는 거죠. **'관리형 에이전트'의 세션 격리 환경(Sandbox)**이 바로 이 안전한 연습장이 되어줍니다.

## 5. '완전 자동화(Full Automation)'로 가는 단계적 로드맵

강연자가 말한 **"에이전트에게 넘기거나(Hand off), 아예 안 깨게 만들거나(Full Automation)"**는 두 단계의 성숙도를 의미합니다. 이건 한 번에 되는 게 아니라, **신뢰 쌓기** 과정을 거칩니다.

### 1단계: 코파일럿 (Co-pilot) / 인간 승인 필요 (Human-in-the-loop)
*   **상황:** 새벽 3시 알람 울림 → 에이전트가 **초동 조사(트리아지)** 수행 → **"셰프님, 원인은 A모듈의 메모리 누수인 것 같습니다(확신도 90%). 재시작하시겠습니까? [예/아니오]"**라고 슬랙/이메일로 보고.
*   **인간 역할:** 잠결에 휴대폰 보고 **"예"**만 누르면 됨. 조사 30분 → 1분으로 단축.
*   **비유:** 부주방장이 "셰프님, 가스 밸브가 고장 난 것 같아요. 예비 밸브로 돌릴까요?"라고 **전화로 묻는 것**.

### 2단계: 반자동화 (Semi-auto) / 사후 승인 (Human-on-the-loop)
*   **상황:** 에이전트가 조사 → 진단 → **일시적 조치(재시작, 트래픽 우회 등) 자동 실행** → **"조치 완료했습니다. 상세 리포트 드려요. 영구 조치는 아침에 검토해주세요."**
*   **인간 역할:** 아침에 일어나서 리포트 읽고 "잘했네" 혹은 "이건 좀 위험했네" 피드백.
*   **비유:** 부주방장이 **셰프 허락 없이** 예비 밸브로 돌리고, 냉동고로 재료 옮긴 뒤 **"조치 다 해놨습니다. 주무세요."**라고 문자 남기는 것. (단, '가게 문 닫기' 같은 돌이킬 수 없는 행동은 안 함)

### 3단계: 완전 자동화 (Full Automation) / 인간 배제 (Human-out-of-the-loop)
*   **상황:** 인시던트 발생 → 에이전트가 **감지부터 근본 원인 분석, 영구 조치(코드 패치, 배포 롤백, 설정 변경)까지 모두 수행** → 사후 리포트만 생성.
*   **인간 역할:** **모름(잠만 잠).** 아침에 "어제 밤 3시에 DB 커넥션 풀 고갈 났었는데 에이전트가 쿼리 튜닝하고 배포까지 했네? 대박."이라고 확인만 함.
*   **비유:** 부주방장이 밸브 고치다 발견한 **낡은 배관까지 통째로 새걸로 갈아끼우고, 건강검진(모니터링 강화) 예약까지 잡아놓는 것.** 셰프는 그냥 맛있는 요리만 연구하면 됨.

> **💡 개념 돋보기: '완전 자동화'의 전제 조건 - 신뢰(Trust)와 관측가능성(Observability)**
> > "그냥 다 맡기면 되지 않나요?"라고 묻고 싶으시죠? **절대 안 됩니다.** 에이전트가 **"DB 테이블을 실수로 다 지워버렸습니다(TRUNCATE TABLE users)"** 같은 짓을 하면 회사 망합니다.
> > 완전 자동화를 위해선 두 가지가 필수입니다.
> > 1.  **강력한 가드레일(Guardrails):** "읽기 전용 모드", "승인 없이 배포 금지", "비용 한도 초과 시 정지" 같은 **하드코딩된 안전장치(규칙 기반)**가 에이전트 밖에 있어야 함.
> > 2.  **완벽한 관측가능성:** 에이전트가 **'왜' 그런 결정을 내렸는지(사고 과정, Tool Call 로그, 추론 Trace)** 인간이 사후에 완벽히 감사(Audit)할 수 있어야 함.
> > 관리형 에이전트의 **'서버 사이드 에이전트 루프'**와 **'세션 이벤트 스트리밍'** 기술이 바로 이 **"블랙박스 열어보기"**를 가능하게 해주는 핵심 인프라입니다.

## 6. 코드 레벨에서 보는 '위임의 해부학' (실습 예고)

이제 우리가 `agent.py`에 채워 넣을 코드 조각들이 이 '위임'을 어떻게 구현하는지 살짝 엿보겠습니다. 강연자는 **"완성된 파일에서 조각을 하나씩 복사해오며 원리를 이해하자"**고 했습니다.

### 조각 1: `Agent` 클래스 정의 (페르소나 & 두뇌 장착)
```python
# agent.py 에 들어갈 핵심 코드 조각 (예시)
agent = Agent(
    name="senior-sre-agent",           # 이름: 수석 SRE 부주방장
    model="claude-3-5-sonnet-20241022", # 두뇌: 가장 똑똑한 클로드 모델
    instructions="""당신은 10년 차 베테랑 사이트 신뢰성 엔지니어(SRE)입니다.
    인시던트가 주어지면 다음 순서로 행동하세요:
    1. 관련 로그 조회 (MCP 툴 사용)
    2. 메트릭 대시보드 확인 (MCP 툴 사용)
    3. 최근 배포/변경 내역 확인 (MCP 툴 사용)
    4. 근본 원인 가설 수립 및 검증
    5. 조치 방안 제안 (또는 실행)
    절대 추측만으로 조치하지 말고, 반드시 데이터(로그/메트릭) 근거를 제시하세요.""",
    mcp_servers=[logs_server, metrics_server, deploy_server], # 손(도구) 연결
    skills=[incident_analysis_skill, runbook_execution_skill] # 특기(스킬) 장착
)
```
*   **비유:** 이력서(페르소나/인스트럭션), 자격증(모델), 쓸 수 있는 연장 가방(MCP 서버), 비법 노트(스킬)을 **한 번에 채용 계약서에 적어넣는 행위**입니다.

### 조각 2: `Environment` 생성 (격리된 작업실 제공)
```python
# 안전한 샌드박스 환경 만들기
env = Environment(
    name="incident-response-env",
    # 실제 프로덕션 DB 접속 정보는 여기에 절대 안 넣음!
    # 시뮬레이션용 더미 데이터만 마운트하거나, 읽기 전용 프록시만 연결
)
```
*   **비유:** 부주방장에게 **"여기는 연습용 주방이야. 진짜 칼(프로덕션 DB 쓰기 권한)은 없어. 플라스틱 칼(읽기 전용 조회 툴)만 있어. 맘껏 썰어봐."**라고 안전한 작업장을 주는 것. **'브레인(에이전트)'과 '핸즈(환경)'의 분리**가 바로 여기서 빛납니다. 에이전트(두뇌)가 환자(프로덕션)를 수술칼(쓰기 권한)로 찌르지 못하게 물리적으로 격리시킨 거죠.

### 조각 3: `Session` 생성 및 실행 (위임의 시작)
```python
# 세션 시작 = "부주방장, 지금부터 이 인시던트 맡아줘"
session = client.sessions.create(
    agent_id=agent.id,
    environment_id=env.id,
)

# 인시던트 컨텍스트(알림 내용, 알람 링크 등) 주입하며 시작
stream = client.sessions.stream(
    session_id=session.id,
    messages=[{"role": "user", "content": "인시던트 발생: API 지연 시간 급증 (P99 > 5s). 상세 링크: ..."}]
)

# 실시간으로 에이전트 생각/행동 구독하며 화면에 띄우기
for event in stream:
    print(event) # 스트림릿 화면에 실시간 렌더링
```
*   **비유:** **"자, 여기 인시던트 접수증(컨텍스트) 줄게. 너 연습 주방(환경)에서 네 두뇌(에이전트) 써서 해결하고, 진행 상황 실시간으로 나(스트림)한테 중계해."**라고 **업무 지시(위임)를 내리는 순간**입니다.

## 7. 마무리하며: 여러분이 만들 '미래의 나'

이 챕터의 학습 목표는 단순히 "파이썬 코드 돌리기"가 아닙니다.
**새벽 3시, 전화벨 소리에 심장이 떨어지지 않는 미래**를 코드 한 줄 한 줄로 쌓아 올리는 것입니다.

우리가 실습에서 `agent.py`를 채워나갈 때마다, 우리는 에이전트에게 이렇게 가르치는 겁니다.
*   "로그 보지 말고 **먼저 메트릭부터 봐라** (우선순위 교육)"
*   "에러 메시지만 보지 말고 **최근 배포 내역이랑 대조해라** (상관관계 분석 교육)"
*   "재시작만 하지 말고 **왜 죽었는지 런북(Runbook) 찾아서 근본 원인 고쳐라** (재발 방지 교육)"

이게 바로 **'에이전트 위임으로 인시던트 자동 대응 또는 완전 자동화 목표'**의 진짜 의미입니다. **나의 전문 지식, 나의 직관, 나의 노하우를 에이전트라는 '디지털 분신'에 이식하여, 내가 잠든 사이에도 내 몫의 일을 해내게 만드는 것.**

자, 이제 정말 신나는 시간이 왔습니다. 강연자 말대로 **"코드 속으로 다이브(Dive)해서, 조각을 맞춰보며 우리만의 수석 부주방장을 조립해 봅시다."** 다음 섹션에서는 실제로 `agent.py` 파일을 열어서 첫 번째 조각인 **'에이전트 정의(페르소나와 도구)'**를 심어주는 실습을 진행하겠습니다. 준비되셨나요?
