# 📚 챕터 5: 에이전트 개발 생명주기 완전 정복 — 개념 이해 → 코드 구현 → 로컬 실행 → 검증까지 한눈에

자, 드디어 대장정의 마지막 챕터입니다. 지금까지 우리는 **'에이전트란 무엇인가?'**라는 개념부터 시작해서, **구글 ADK(에이전트 개발 키트)를 설치하고**, **파이썬 코드로 에이전트의 두뇌(Instruction)와 도구(Tools)를 설계하고**, **하위 에이전트(Sub-agent)라는 팀원까지 채용하는** 과정을 모두 배웠습니다.

이제 마지막 퍼즐 조각, **"내가 만든 에이전트가 정말 제대로 작동하는가?"**를 확인하는 시간입니다. 이 챕터는 단순히 '실행 버튼을 누르세요'가 아닙니다. **개발의 전 과정이 하나의 흐름으로 어떻게 연결되는지**, 그리고 **실행 후 어떤 점을 봐야 '성공'이라 할 수 있는지**를 비전공자 눈높이에서 아주 상세하게 짚어드릴게요.

---

## 1️⃣ 개발 생명주기, 왜 '순서'가 중요할까? — 집 짓기와 똑같습니다

에이전트 개발도 **집을 짓는 과정**과 정확하게 닮았습니다. 순서를 건너뛰면 집이 무너지듯, 에이전트도 엉뚱한 소리만 하는 '고장 난 로봇'이 됩니다.

> **💡 개념 돋보기: 에이전트 개발 4단계와 집 짓기 비유**
> 
> | 개발 단계 | 집 짓기 과정 | 핵심 질문 |
> | :--- | :--- | :--- |
> | **1. 개념 이해 (Design)** | **설계도 그리기**<br>"어떤 집을 지을까? 방은 몇 개? 화장실은 어디?" | **"이 에이전트는 무슨 문제를 풀까? 어떤 도구가 필요할까?"** |
> | **2. 코드 구현 (Build)** | **뼈대 세우기 & 벽돌 쌓기**<br>설계도대로 철근 콘크리트 붓고, 벽돌 쌓고, 배관 깔기 | **"파이썬 클래스로 Agent를 정의하고, Instruction(성격)과 Tools(연장)을 코드로 심자."** |
> | **3. 로컬 실행 (Deploy)** | **입주 & 전기/수도 개통**<br>지어진 집에 전기를 연결하고 수도를 터서 실제 사람이 살 수 있게 만들기 | **"`adk web` 명령어로 내 컴퓨터(로컬)에서 에이전트 서버를 띄우고, 브라우저라는 현관문을 열자."** |
> | **4. 검증 (Test & Verify)** | **입주 청소 & 하자 보수**<br>불은 잘 켜지는지, 물은 잘 나오는지, 방음은 괜찮은지 직접 살아보며 체크 | **"'블로그 써줘'라고 시켰을 때, 계획-작성-전달 전 과정을 에러 없이 완수하는지 눈으로 확인하자."** |

이 4단계 중 **어느 하나라도 대충 넘기면 안 됩니다.** 특히 1단계(개념)가 흔들리면 2단계(코드)가 산으로 가고, 3단계(실행)에서 에러가 나며, 4단계(검증)에서 "이게 뭐야?" 하게 됩니다. 우리는 지난 챕터들에서 1, 2단계를 탄탄히 다졌고, 지금부터 3, 4단계를 실전으로 마무리할 것입니다.

---

## 2️⃣ 3단계: 로컬 실행 — `adk web` 마법의 주문, 내 컴퓨터에 에이전트 깨우기

코드 작성이 끝났다면(보통 `agent.py` 파일 완성), 이제 **'정지된 코드 텍스트'를 '살아 숨 쉬는 프로세스'로 깨워야** 합니다. 구글 ADK는 이 복잡한 과정을 **단 한 줄의 명령어**로 해결해 줍니다.

### 🪄 마법의 주문: 터미널에 입력하세요

```bash
adk web
```

> **💡 개념 돋보기: `adk web`이 백그라운드에서 하는 일 (보이지 않는 엔진룸)**
> 
> 이 명령어 하나를 치는 순간, 내 컴퓨터(로컬 머신) 안에서 **엄청난 일들이 순식간에 벌어집니다.**
> 
> 1.  **FastAPI 서버 구동 (백엔드):** 에이전트가 HTTP 요청을 받을 수 있는 **웹 서버**를 자동으로 띄웁니다. (포트 번호는 보통 8000번)
> 2.  **에이전트 로딩 (모델 주입):** 우리가 작성한 `agent.py`를 읽어서, **Gemini 같은 거대 언어 모델(LLM)과 연결**시킵니다. 이때 API 키가 환경 변수(.env)에 잘 들어있는지 확인합니다.
> 3.  **UI 프론트엔드 서빙 (대시보드):** 별도로 리액트(React)나 뷰(Vue) 코드를 짤 필요 없이, ADK가 내장된 **예쁜 관리자 페이지(Admin UI)**를 같이 띄워줍니다.
> 4.  **세션/메모리 관리자 대기:** 사용자와 대화할 때마다 **'세션(Session)'**이라는 대화방을 만들어 주고, 이전 대화 맥락(Context)을 기억하게 해줍니다.
> 
> **비유하자면:** `adk web`은 **"식당 오픈 준비 완료"** 버튼입니다. 주방(모델), 홀서빙(UI), 예약장부(세션), 메뉴판(에이전트 정의) 모두 세팅되고 "손님 받으세요!" 상태가 되는 겁니다.

### 🌐 브라우저에서 확인: `http://localhost:8000`

명령어를 치고 터미널에 `Running on http://0.0.0.0:8000` (또는 `http://127.0.0.1:8000`) 같은 문구가 뜨면 성공입니다. 이제 **크롬, 엣지, 사파리 아무 브라우저나 열어서** 주소창에 `http://localhost:8000`을 치고 엔터를 누르세요.

**짜잔!** 여러분이 코드로만 보던 에이전트가 **시각적인 채팅 인터페이스**로 나타납니다. 왼쪽 사이드바에는 내가 만든 에이전트 이름(예: `BlogWriterAgent`)이 보이고, 가운데는 대화창, 오른쪽에는 **'이벤트 스트림(Event Stream)'** 또는 **'트레이스(Trace)'** 패널이 보입니다. 여기가 바로 **'에이전트의 뇌 속을 들여다보는 현미경'**입니다.

## 3️⃣ 4단계: 검증 — "블로그 글 써줘" 한 마디로 전 과정 테스트하기

이제 진짜 검증의 시간입니다. 단순히 "안녕?"이라고 인사시키는 게 아닙니다. **에이전트의 핵심 능력(계획 → 도구 사용 → 협업 → 최종 산출물 생성)** 이 한 번에 작동하는지 검증해야 하니까요.

영상 스크립트에서 강사님이 **"Top 10 use cases for AI agents(에이전트 활용 사례 톱 10) 블로그 글 써줘"**라고 요청하신 이유가 바로 여기에 있습니다. 이 요청 하나에 **에이전트가 가져야 할 거의 모든 역량**이 담겨 있습니다.

### 🧪 검증 시나리오: 복합 미션 수행 테스트

**입력 프롬프트 (사용자):**
> **"AI 에이전트 활용 사례 톱 10에 대한 블로그 포스트를 작성해줘."**

**기대되는 에이전트 내부 동작 (우리가 코드로 설계한 대로):**

1.  **계획 수립 (Planning - 메인 에이전트):**
    *   "좋아, 블로그 글을 쓰려면 ① 주제 조사 → ② 목차 잡기 → ③ 섹션별 초안 작성 → ④ 검수/윤문 → ⑤ 최종 합치기 단계가 필요하네?"
    *   메인 에이전트는 이 **작업 분해(Task Decomposition)** 계획을 세웁니다.

2.  **하위 에이전트 호출 및 협업 (Delegation & Collaboration):**
    *   메인 에이전트는 **"너, 리서치 에이전트! 'AI 에이전트 활용 사례' 최신 트렌드 좀 찾아와."** (`ResearchAgent` 호출)
    *   리서치 에이전트는 **`google_search` 도구(Tool)**를 써서 웹을 뒤지고, 요약본을 메인에게 보고합니다.
    *   메인 에이전트는 **"너, 라이터 에이전트! 이 자료 바탕으로 10개 섹션 초안 써."** (`WriterAgent` 호출)
    *   라이터 에이전트는 **글쓰기 전용 프롬프트(Instruction)**에 따라 마크다운 형식으로 뚝딱 작성합니다.
    *   (선택) **"너, 에디터 에이전트! 톤앤매너 맞춰서 다듬어."** (`EditorAgent` 호출)

3.  **결과 취합 및 최종 응답 (Synthesis):**
    *   모든 하위 에이전트 일이 끝나면, 메인 에이전트가 조각난 결과물을 **하나의 완성된 블로그 포스트**로 합칩니다.
    *   사용자 채팅창에 **최종 마크다운 렌더링 결과**가 뜹니다.

### 👀 검증 체크리스트: UI에서 '이것'을 확인하세요

브라우저 ADK 웹 화면에서 **단순히 답변 텍스트만 보지 마세요.** 오른쪽 **Event Stream(이벤트 스트림) / Trace(트레이스) 패널**을 유심히 보세요. 여기가 **'검증의 핵심'**입니다.

> **💡 개념 돋보기: 이벤트 스트림(Event Stream) 읽는 법 — 에이전트의 '일기장' 엿보기**
> 
> ADK 웹 UI 오른쪽 패널에는 시간 순서대로 **이벤트(Event)**가 쌓입니다. 이건 에이전트가 **"나 지금 뭐 했어"**라고 기록해둔 로그입니다. 비전공자도 이렇게 읽으세요.
> 
> | 이벤트 타입 (아이콘/라벨) | 의미 | 검증 포인트 (이게 보여야 성공!) |
> | :--- | :--- | :--- |
> | **`user`** | 사용자 입력 | "블로그 써줘" 내 말이 잘 들어갔나? |
> | **`model` (메인)** | 메인 에이전트 생각 | **"Plan: 1. Research 2. Write 3. Edit..."** 같은 **계획(Plan)** 이 찍히는가? (ReAct 패턴의 Thought) |
> | **`tool_code` / `tool_output`** | 도구 사용 | **`google_search`** 호출됐나? 검색 결과(`output`)가 돌아왔나? |
> | **`agent_transfer`** 또는 **`sub_agent_call`** | 하위 에이전트 위임 | **`ResearchAgent`**, **`WriterAgent`** 이름이 보이나? **전달된 입력(Input)**과 **반환된 출력(Output)**이 정상인가? |
> | **`model` (서브)** | 하위 에이전트 생각 | 서브 에이전트도 각자 자기 지시(Instruction)대로 생각하는 로그(`Thought`)를 남기는가? |
> | **`final_response`** | 최종 답변 | 사용자에게 보여줄 **완성된 블로그 마크다운**이 찍히는가? |
> 
> **🚨 검증 실패 신호 (Red Flags):**
> *   `model` 단계에서 **계획(Plan) 없이 바로 답변**하려 함 → **Instruction(지시문) 설계 실패** (1단계 개념/2단계 코드 문제)
> *   `tool_code`에서 **에러(Error) 발생** (예: API Key 없음, 쿼리 형식 오류) → **Tools 설정/환경변수 문제**
> *   `agent_transfer`가 **안 찍힘** (메인 에이전트가 혼자 다 하려 함) → **Sub-agent 정의/등록 코드 누락** (`sub_agents=[...]` 리스트 확인)
> *   서브 에이전트 `output`이 **빈 칸이거나 엉뚱한 소리** → **서브 에이전트의 Instruction 프롬프트 튜닝 필요**

## 4️⃣ 전체 생명주기 복기: 우리는 무엇을 배웠나? (총정리 로드맵)

이번 챕터를 끝으로 '첫 에이전트 만들기' 강의가 끝납니다. 하지만 이것은 **끝이 아니라 시작**입니다. 우리가 지나온 4단계 생명주기를 머릿속에 **'체크리스트'**로 새겨두세요. 앞으로 어떤 복잡한 에이전트를 만들든 이 프레임은 그대로입니다.

### 🗺️ 에이전트 개발 마스터 로드맵 (평생 써먹는 템플릿)

#### Phase 1: 개념 이해 (Concept & Design) — "기획서 쓰기"
*   [ ] **문제 정의:** "무슨 문제를 풀까?" (예: 블로그 자동 작성)
*   [ ] **아키텍처 스케치:** 메인 에이전트 1개 + 서브 에이전트 N개 구성도 그리기
*   [ ] **도구(Tools) 목록화:** 검색? 코드 실행? DB 조회? API 호출? 어떤 연장 필요한가?
*   [ ] **데이터 흐름 설계:** 입력 → (메인 계획) → 서브 위임 → 도구 실행 → 결과 취합 → 출력

#### Phase 2: 코드 구현 (Implementation) — "설계도대로 짓기"
*   [ ] **환경 세팅:** `uv`/`pip` 설치, `.env`에 `GOOGLE_API_KEY` 넣기
*   [ ] **에이전트 클래스 정의:** `Agent(name=..., model=..., instruction=..., tools=..., sub_agents=...)`
*   [ ] **Instruction(시스템 프롬프트) 엔지니어링:** **가장 중요!** 역할, 톤, 단계별 절차, 제약사항을 **자연어로 아주 구체적으로** 적기
*   [ ] **도구(Tools) 바인딩:** `google_search`, `FunctionTool(내_파이썬_함수)` 등 정확히 연결
*   [ ] **서브 에이전트 등록:** `sub_agents=[research_agent, writer_agent]` 리스트에 넣기 (이거 빼먹으면 위임 안 함!)

#### Phase 3: 로컬 실행 (Local Run) — "전기 켜고 문 열기"
*   [ ] **터미널 실행:** `adk web` (또는 `adk run`으로 터미널 채팅 모드)
*   [ ] **서버 헬스 체크:** 터미널에 `Uvicorn running on http://0.0.0.0:8000` 확인
*   [ ] **브라우저 접속:** `localhost:8000` 진입, 내 에이전트 이름 사이드바에 뜨는지 확인

#### Phase 4: 검증 및 반복 (Verification & Iteration) — "살아보며 고치기"
*   [ ] **Happy Path 테스트:** 정상 시나리오(블로그 작성) 한 번에 성공하는가?
*   [ ] **Trace/Event Stream 분석:** 계획 → 도구 → 위임 → 합성 **전 단계 로그**가 정상인가?
*   [ ] **Edge Case 테스트:** "이상한 말 시키기", "도구 없이 답하게 하기", "중간에 끊기" 등 예외 상황 던지기
*   [ ] **프롬프트 튜닝 (Prompt Engineering):** 결과물 퀄리티 낮으면 → **Instruction 수정 → 재실행 → 재검증** (이 루프가 90%임!)
*   [ ] **평가(Evaluation) 자동화:** 나중엔 `pytest` 등으로 "이 입력엔 무조건 이 키워드 포함되어야 해" 자동 테스트 코드 짜기

## 5️⃣ 마무리하며: 여러분은 이제 '에이전트 아키텍트'입니다

영상 마지막에 강사님이 말씀하셨죠?
> *"You've built and run your first AI agent with Google's ADK. We've started from the idea of what agents are, then walked through the code step-by-step and finally saw it come to life in terminal."*

**"여러분은 구글 ADK로 첫 AI 에이전트를 만들고 실행했습니다. 에이전트가 무엇인지 개념에서 출발해, 코드를 한 줄 한 줄 뜯어보며, 마침내 터미널(과 브라우저)에서 살아 움직이는 것을 보았습니다."**

이 말은 단순히 '튜토리얼 하나 끝냈다'는 뜻이 아닙니다. **여러분은 이제:**
1.  **LLM을 '대화 상대'가 아닌 '추론 엔진(Reasoning Engine)'으로 다루는 법**을 알았고,
2.  **복잡한 작업을 '분해(Decomposition)'하고 '위임(Delegation)'하는 아키텍처**를 코드로 구현할 줄 알며,
3.  **눈에 안 보이는 에이전트의 사고 과정을 '트레이스(Trace)'로 가시화하여 디버깅**하는 전문가의 워크플로우를 익혔습니다.
