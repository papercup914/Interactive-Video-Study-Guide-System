# 🐍 Python 가상환경 생성 및 활성화: 나만의 깨끗한 작업실 만들기 (Mac/Windows 완전 정복)

자, 여러분! 이제 본격적으로 **'클로드 매니지드 에이전트(Claude Managed Agents)'**라는 마법의 세계로 떠나기 전에, 우리 손에 꼭 쥐고 가야 할 **'마법의 도구 상자'**를 준비하는 시간입니다. 방금 영상에서 강사님이 "자, 이제 여러분 노트북을 열고 레포지토리를 클론한 뒤, 가상환경을 만들고 켜세요"라고 하셨죠? 

이 과정이 왜 필요하고, 어떻게 하는 건지 **비전공자 입장에서 눈높이를 맞춰** 아주 천천히, 그리고 친절하게 풀어서 알려드릴게요. 자, 따라오세요!

## 1. 왜 '가상환경'이 필요한가? - "내 방을 어지럽히지 않는 나만의 공방"

> **💡 개념 돋보기: 가상환경(Virtual Environment)이란?**
> 
> > **"파이썬 프로젝트마다 독립된 '전용 공방(작업실)'을 만들어주는 기술입니다."**
> > 
> > 시스템 전체(글로벌)에 라이브러리를 설치하면 버전 충돌이 나지만, 가상환경을 쓰면 **프로젝트 A는 공방 A에서, 프로젝트 B는 공방 B에서** 각자 필요한 도구만 딱 갖다 놓고 쓸 수 있어요.

상상해 보세요. 여러분이 **목수**라고 해볼까요?

*   **가상환경 없이 개발하기 (글로벌 환경):** 집 거실(시스템 전체)에서 모든 작업을 합니다. 의자 만드는 톱, 테이블 만드는 대패, 책장 만드는 망치를 **거실 한가운데 다 꺼내놓고** 쓰는 거죠. 그런데 '의자 프로젝트'에는 1번 톱이 필요하고, '테이블 프로젝트'에는 2번 톱이 필요해요. 거실에 1번 톱과 2번 톱을 동시에 둘 수 있을까요? **버전 충돌**이 나서 망가집니다. 게다가 가족(다른 프로젝트)들이 거실을 지나다니다 다칠 수도 있어요.
*   **가상환경으로 개발하기:** 프로젝트마다 **별도의 작은 공방(가상환경)**을 빌려줍니다. '의자 프로젝트 공방'에는 1번 톱만, '테이블 프로젝트 공방'에는 2번 톱만 딱 갖다 놓습니다. 공방 문을 닫으면(비활성화), 거실(시스템)은 언제나 깨끗한 상태 그대로 유지되죠.

**오늘 우리가 할 일:** 'Ship Your First Managed Agent'라는 **이 프로젝트 전용 공방**을 하나 만들고, 거기에 `requirements.txt`라는 **'필요한 도구 쇼핑 리스트'**를 보고 도구들을 싹 채워 넣는 과정입니다.

## 2. 1단계: 레포지토리 복제 & 폴더 진입 - "재료 키트 받고 작업실로 가기"

영상에서 강사님이 제일 먼저 하라고 한 명령어들, 기억나시나요?

```bash
# 1. 레포지토리 클론 (자료실에서 키트 가져오기)
git clone <저장소_URL>

# 2. 해당 세션 폴더로 이동 (작업실로 들어가기)
cd "Ship Your First Manage Agent"
```

*   `git clone`: 깃허브라는 거대한 창고에서 **'오늘 실습 키트(코드 뭉치)'**를 내 컴퓨터로 통째로 복사해 오는 거예요.
*   `cd` (Change Directory): 복사해 온 상자 안에 있는 **'Ship Your First Manage Agent'라는 작업실 폴더**로 쏙 들어가는 명령어입니다. 이제부터 모든 일은 이 폴더 안에서 일어납니다.

> **⚠️ 튜터의 팁:**
> 폴더 이름에 띄어쓰기(`Ship Your First...`)가 있어서 따옴표(`" "`)로 감쌌어요. 터미널에서 `cd Ship`까지만 치고 **Tab 키**를 누르면 자동으로 완성되니 꼭 활용하세요!

## 3. 2단계: 가상환경 생성 - "빈 공방 짓기 (이름: venv)"

이제 본격적으로 **내 프로젝트 전용 공방**을 지을 차례입니다. 영상에서는 "Mac에서는 python 명령어, source 명령어... Windows도 있다"고 하셨죠? 운영체제별로 명령어가 살짝 다릅니다.

### 🍎 Mac / Linux (터미널, zsh, bash 공통)

```bash
# 파이썬 3으로 'venv'라는 이름의 가상환경 폴더 생성
python3 -m venv venv
```

*   `python3`: "파이썬 3짜리 건축가님, 일 좀 해주세요!"라고 부르는 겁니다. (맥에서는 보통 `python`이 예전 버전(2.x)일 수 있어 `python3`을 명시하는 게 안전해요.)
*   `-m venv`: "파이썬 표준 도구 중 **`venv`(가상환경 만들기) 모듈**을 실행해라"라는 뜻이에요.
*   마지막 `venv`: **"만들 공방 폴더 이름은 `venv`로 해줘"**라는 의미입니다. (이름은 아무거나 지어도 되지만, 관례상 `venv` 또는 `.venv`를 많이 써요.)

> **💡 개념 돋보기: `venv` 폴더의 정체**
> 
> > 이 명령어를 치고 나면 현재 폴더 안에 **`venv`라는 새 폴더**가 생깁니다. 그 안을 들여다보면(열지 마시고 눈팅만 하세요) `bin`, `lib`, `pyvenv.cfg` 등이 있는데, 이게 바로 **나만의 파이썬 실행 파일, 나만의 라이브러리 보관함, 설정 파일**입니다. 시스템 파이썬을 복사해 온 게 아니라, **가볍게 링크만 걸어둔 미니 파이썬**이라고 보시면 돼요.

### 🪟 Windows (명령 프롬프트 cmd / 파워쉘 PowerShell)

윈도우는 터미널 종류에 따라 활성화 명령어가 다르지만, **생성 명령어는 똑같습니다.**

**공통 (생성):**
```cmd
python -m venv venv
```
*   윈도우에선 보통 `python` 명령어가 파이썬 3을 바로 가리키도록 설치됩니다. 그냥 `python` 쓰시면 돼요.

## 4. 3단계: 가상환경 활성화 - "공방 문 열고 불 켜기 (진입)"

공방(`venv` 폴더)을 지었으면, 이제 **들어가서 불을 켜야(활성화)** 거기서 작업할 수 있습니다. 이걸 해야 `pip install` 할 때 시스템이 아닌 **내 공방(`venv`)에 도구가 설치**됩니다.

### 🍎 Mac / Linux (터미널)

```bash
source venv/bin/activate
```

*   `source`: "이 스크립트 파일을 **현재 쉘(터미널)에서 실행해라**"라는 뜻입니다. 그냥 `venv/bin/activate`라고 치면 **새로운 하위 쉘에서만 켜지고 내 터미널에는 적용 안 돼요**. 꼭 `source`를 붙이세요! (줄여서 `. venv/bin/activate`도 가능합니다.)
*   `venv/bin/activate`: 방금 만든 공방 안에 있는 **'불 켜기 스위치(활성화 스크립트)'** 위치입니다.

**성공 확인:** 터미널 프롬프트 제일 앞에 **`(venv)`**가 붙으면 성공입니다!
```text
(venv) username@MacBook-Pro Ship Your First Manage Agent % 
```

### 🪟 Windows - 명령 프롬프트 (cmd.exe)

```cmd
venv\Scripts\activate.bat
```
*   윈도우 cmd에서는 `source` 명령어가 없습니다. 그냥 **스크립트 파일 경로를 직접 실행**하면 됩니다.
*   경로 구분자가 `/`(맥/리눅스)가 아니라 **`\`(백슬래시)**임을 주의하세요.

### 🪟 Windows - 파워쉘 (PowerShell)

```powershell
venv\Scripts\Activate.ps1
```
*   파워쉘은 보안 정책 때문에 스크립트 실행이 막혀 있을 수 있어요. 만약 **빨간 글자로 에러(unning scripts is disabled)**가 뜬다면, 아래 명령어로 권한을 풀고 다시 시도하세요.
    ```powershell
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
    ```
    (이건 현재 사용자에게만 스크립트 실행 권한을 주는 안전한 설정입니다.)

**성공 확인:** 역시 프롬프트 앞에 **`(venv)`**가 뜨면 됩니다!
```text
(venv) PS C:\Users\username\Ship Your First Manage Agent>
```

> **💡 개념 돋보기: 활성화(Activation)의 마법 - PATH 환경 변수 조작**
> 
> > `activate` 스크립트가 하는 일은 단순하지만 강력합니다. **내 터미널의 `PATH`(실행 파일 찾는 경로 순서)라는 리스트의 제일 앞에 `venv/bin`(또는 `venv/Scripts`) 경로를 꽂아 넣는 거예요.**
> > 
> > 그래서 내가 `python`이라고 치면 → 시스템 파이썬 대신 **`venv` 안의 파이썬**이 실행되고,
> > `pip install`을 치면 → 시스템 사이트 패키지가 아닌 **`venv` 안의 사이트 패키지**에 설치되는 겁니다.
> > 
> > **비유:** "이제부터 도구 찾을 때 **'내 공방 선반'부터 먼저 뒤져!"**라고 비서에게 지시 내리는 것과 똑같아요.

## 5. 4단계: 의존성 설치 - "쇼핑 리스트 보며 도구 채우기"

공방에 불도 켰으니(`activate` 완료), 이제 영상에서 강사님이 말씀하신 **`requirements.txt`(쇼핑 리스트)**를 보고 도구들을 쫙 깔 차례입니다.

```bash
pip install -r requirements.txt
```

*   `pip`: 파이썬 패키지 매니저(도구 관리인).
*   `install`: 설치해.
*   `-r requirements.txt`: **"이 파일 안에 적힌 목록대로 한 방에 다 설치해"**라는 옵션입니다.

이 명령어를 치면 쫙쫙 라이브러리들이 다운로드되면서 내 공방(`venv/lib/python3.x/site-packages`)에 차곡차곡 쌓입니다. **절대 `sudo pip install` 쓰지 마세요!** (그건 시스템 공방에 설치하라는 뜻이라 권한 문제나 충돌 납니다. 지금 우린 내 공방(`venv`) 안에 있으니까 `sudo` 없이 그냥 `pip install`만 치면 됩니다.)

## 6. 5단계: 환경 변수 설정 - "비밀 열쇠(.env) 챙기기"

영상에서 **"copy over the environment key into your dot m file... put in the Anthropic API key"**라고 하셨죠? 이건 코드 안에 비밀번호(API 키)를 하드코딩하지 않고, **`.env`라는 비밀 수첩에 따로 적어두는 보안 작업**입니다.

보통 리포지토리에 `.env.example`이나 `.env.sample` 파일이 들어있습니다.

**Mac/Linux:**
```bash
cp .env.example .env
# 또는 cp .env.sample .env
```
**Windows (cmd):**
```cmd
copy .env.example .env
```
**Windows (PowerShell):**
```powershell
Copy-Item .env.example .env
```

그럼 `.env` 파일이 생깁니다. **VS Code 같은 에디터로 열어서** `ANTHROPIC_API_KEY=여기에_발급받은_키_붙여넣기` 하시면 됩니다. (QR 코드로 받은 무료 크레딧 키를 넣으시면 돼요!)

> **⚠️ 튜터의 중요 팁: `.gitignore` 확인!**
> 
> 이 `.env` 파일은 **절대 깃허브에 올리면 안 됩니다**(비밀번호 유출!). 보통 파이썬 프로젝트 `.gitignore`에는 `.env`가 기본으로 들어가 있지만, 혹시 모르니 `.gitignore` 파일을 열어서 `.env`가 적혀 있는지 한 번만 확인해 주세요.

## 7. 6단계: 애플리케이션 실행 - "완성된 로봇 작동시키기"

모든 준비 끝! 이제 강사님이 말씀하신 대로 **스트림릿(Streamlit) 앱**을 띄우면 됩니다.

```bash
streamlit run app.py
```

*   `streamlit`: 파이썬으로 데이터 앱/웹 앱을 뚝딱 만들어주는 라이브러리입니다.
*   `run app.py`: `app.py` 파일을 실행해서 웹 서버를 띄워라.

그러면 터미널에 이런 메시지가 뜨면서 **로컬 주소(보통 `http://localhost:8501`)**가 나옵니다. 브라우저에서 그 주소로 들어가면 **'인시던트 대응 에이전트' 웹 페이지**가 짠! 하고 나타날 거예요.

## 8. 마치며: 공방 문 닫기 (비활성화 & 삭제)

실습이 다 끝났거나, 다른 프로젝트 하러 갈 때는 공방 불을 끄고 나와야죠.

### 비활성화 (공방 문 닫고 거실로 나오기)
어디서든(맥/윈도우/파워쉘) 동일하게:
```bash
deactivate
```
그럼 프롬프트 앞의 `(venv)`가 사라집니다. 이제 시스템 글로벌 환경으로 돌아온 거예요.

### 가상환경 완전 삭제 (공방 철거하기)
이 프로젝트 아예 안 쓸 거면, 그냥 폴더째 지우면 됩니다. **가상환경은 폴더 하나(`venv/`)로만 존재하니까, 탐색기/Finder에서 `venv` 폴더를 휴지통으로 보내면 끝!** 별도의 언인스톨 명령어 필요 없습니다. 이게 가상환경의 가장 큰 장점이자 매력이에요.

**자, 여러분!** 이제 `venv`라는 나만의 깨끗한 공방도 만들었고, `requirements.txt`로 도구도 다 채웠고, `.env`로 비밀 열쇠도 챙겼고, `streamlit run app.py`로 에이전트도 깨웠습니다.

터미널에 `(venv)` 불빛이 반짝이고 있다면, 여러분은 이미 **프로 개발자의 첫 관문**을 통과하신 겁니다. 이제 `app.py` 속으로 들어가 에이전트의 뇌(Persona)와 손(Environment)을 어떻게 연결하는지, 다음 챕터에서 같이 뜯어보러 가볼까요? 🚀
