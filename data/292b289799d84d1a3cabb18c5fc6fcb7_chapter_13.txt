# 챕터 3: 프로젝트 구조 생성 및 `agent.py` 파일 생성 - 우리만의 AI 비서 작업실 꾸미기

자, 지난 챕터까지 우리는 **'에이전트란 무엇인가?'**라는 개념을 잡고, **순차(Sequential), 반응형(Reactive), 계획형(Planning/Deliberate)** 이 세 가지 에이전트의 성격 유형까지 살펴보았습니다. 이제 이론 공부는 잠시 접어두고, 직접 손코딩을 하며 **나만의 '블로그 글쓰기 에이전트'**를 만들어 볼 차례입니다.

영상에서 강사님이 **"Okay, that's the high-level view. Now let's actually build an agent so you can see these ideas in action."(자, 개요는 이쯤 하고, 실제로 에이전트를 만들어서 이 개념들이 어떻게 작동하는지 봅시다.)"**라고 말씀하셨죠? 바로 그 순간입니다.

가장 먼저 해야 할 일은 **'에이전트가 일할 깨끗한 작업실(프로젝트 폴더)'을 만들고, 그 안에 '두뇌 역할을 할 설계도(agent.py)' 파일을 생성하는 것**입니다. 비전공자 눈높이에서, 마치 **'나만의 작은 식당을 오픈하기 위해 주방을 세팅하고 헤드 셰프(에이전트)에게 줄 레시피 북을 만드는 과정'**에 비유해서 아주 천천히, 자세히 안내해 드릴게요.

## 1. 작업실(프로젝트 폴더) 마련하기: "빈 가게 계약하기"

코드를 짜기 전에 가장 먼저 할 일은 **프로젝트가 담길 폴더(디렉터리)를 만드는 일**입니다. 이건 컴퓨터 바탕화면에 `my_blog_agent`라는 이름의 **새 폴더 하나를 만드는 것**과 똑같습니다.

> **💡 개념 돋보기: 프로젝트 루트 디렉터리 (Project Root Directory)**
> > 이 폴더는 우리 식당의 **'건물 전체'**와 같습니다. 앞으로 우리가 만들 모든 파일(주방 도구, 재료 장부, 메뉴판 등)은 반드시 이 건물 안으로 들어와야 합니다. 나중에 터미널(명령창)에서 `cd my_blog_agent` 명령어로 이 건물 안으로 들어가는 연습을 하게 될 거예요.

### 🛠 실습: 폴더 만들기 (VS Code 기준)

1.  **VS Code(비주얼 스튜디오 코드)**를 실행하세요. (에디터가 없다면 메모장이라도 상관없지만, VS Code를 강력 추천합니다!)
2.  메뉴바에서 **File(파일) > Open Folder(폴더 열기)**를 클릭하세요.
3.  왼쪽에 뜨는 탐색기 창에서 **바탕화면(Desktop)** 또는 원하는 위치를 클릭한 뒤, **'새 폴더' 아이콘(폴더에 + 표시)**을 누르세요.
4.  폴더 이름을 **`blog_agent_project`** (또는 본인이 원하는 영문 이름)로 입력하고 **생성(Create)** 후 **열기(Select Folder)**를 누르세요.

> **💡 튜터의 팁:** 폴더 이름에 **한글이나 띄어쓰기(공백)**는 피하는 게 좋습니다. 나중에 터미널에서 경로 입력할 때 오류의 주범이 되거든요. `blog_agent_project`처럼 영문 소문자와 언더바(`_`)만 쓰는 습관을 들이세요.

이제 왼쪽 탐색기(Explorer) 패널에 `BLOG_AGENT_PROJECT`라고 덩그러니 빈 폴더만 보입니다. 여기가 바로 우리가 앞으로 채워나갈 **빈 주방**입니다.

## 2. 파이썬 가상환경(Virtual Environment) 만들기: "우리 식당 전용 냉장고 & 조리도구함 준비하기"

폴더를 만들었으니 이제 **'파이썬 가상환경'**을 만들어야 합니다. 이 부분이 입문자분들께는 가장 낯설고 귀찮게 느껴지실 수 있어요. **"그냥 내 컴퓨터에 깔린 파이썬 쓰면 안 돼요?"**라고 물으실 수 있습니다.

### 🍳 비유로 이해하기: 왜 가상환경이 필요할까?

*   **시스템 파이썬 (전역 환경):** **'공용 대형 마트 냉장고'** 같습니다. 누구나 와서 재료(라이브러리)를 넣고 뺍니다. 내가 A라는 요리를 하려고 `requests`라는 재료를 2.0 버전으로 넣어놨는데, 다른 요리(B 프로젝트)를 하는 사람이 "나 이거 1.0 버전 써야 해!"라고 1.0으로 덮어쓰면? 내 요리(A)는 망합니다.
*   **가상환경 (Virtual Environment):** **'내 식당 주방 전용 냉장고 & 개인 칼 세트'**입니다. `blog_agent_project` 폴더 안에 `venv`라는 작은 냉장고를 하나 둡니다. 여기엔 **이 프로젝트에만 필요한 라이브러리(ADK, 구글 라이브러리 등)만 딱 깔아서** 씁니다. 다른 프로젝트랑 절대 안 섞입니다. 버전 충돌 걱정 끝!

### 🛠 실습: 가상환경 생성 및 활성화 (터미널 사용)

VS Code 하단 메뉴바에서 **Terminal(터미널) > New Terminal(새 터미널)**을 클릭하세요. (단축키: `Ctrl + Shift + ` ` 백틱 키)

검은 화면(터미널)이 떴나요? 프롬프트 끝에 `blog_agent_project $` 또는 `PS C:\Users\...\blog_agent_project >` 라고 떠 있으면 **현재 폴더 위치가 맞습니다.**

#### ① 가상환경 생성 (이름은 관례상 `venv`로 많이 씁니다)
```bash
python -m venv venv
```
*   `python`: 파이썬 실행해줘.
*   `-m venv`: `venv` 모듈(가상환경 만들기 도구)을 실행해줘.
*   `venv` (뒤에꺼): **생성될 폴더 이름을 `venv`로 해줘.** (이렇게 하면 프로젝트 폴더 안에 `venv`라는 숨김 폴더가 생깁니다.)

> **⏳ 잠깐!** 3~5초 정도 기다리면 커서가 다시 깜빡입니다. 탐색기(왼쪽 파일 트리)를 보면 `venv` 폴더가 생긴 걸 확인할 수 있습니다. (안 보이면 탐색기 빈 곳 우클릭 > Refresh)

#### ② 가상환경 **활성화 (켜기)** - **가장 중요!**
가상환경을 만들기만 했다고 끝이 아닙니다. **"이제부터 이 터미널은 내 전용 냉장고(venv)를 쓸 거야!"**라고 선언하는 **활성화** 과정을 꼭 거쳐야 합니다.

*   **Windows (PowerShell 기본):**
    ```powershell
    .\venv\Scripts\Activate.ps1
    ```
    *   보안 오류(`running scripts is disabled`)가 난다면? 관리자 권한으로 PowerShell 켜서 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` 입력 후 `Y` 누르고 다시 시도하세요. 혹은 VS Code 터미널을 **Command Prompt(cmd)**로 바꿔서 `.\\venv\\Scripts\\activate.bat` 치셔도 됩니다.
*   **Mac / Linux (bash/zsh):**
    ```bash
    source venv/bin/activate
    ```

**성공 확인:** 터미널 프롬프트 맨 앞에 **`(venv)`** 라는 글자가 생겼나요?
```text
(venv) PS C:\Users\...\blog_agent_project >
```
**축하합니다!** 이제 이 터미널 안에서 `pip install`로 뭐든 설치하면 **전역이 아닌 이 프로젝트 전용 `venv` 폴더 안에만** 설치됩니다.

## 3. 필수 라이브러리 설치: "요리 재료(ADK) 사서 전용 냉장고에 넣기"

활성화된 `(venv)` 상태에서, 우리 에이전트를 구동시킬 **Google ADK (Agent Development Kit)** 라이브러리를 설치합니다. 영상에서 **"This is where ADK's categories comes in."(이게 바로 ADK의 카테고리들이 쓰이는 지점입니다.)"**라고 했죠? ADK가 없으면 시작도 못 합니다.

### 🛠 실습: ADK 설치 명령어

터미널에 아래 명령어를 복사해서 붙여넣고 엔터 치세요.

```bash
pip install google-adk
```

*   `pip`: 파이썬 패키지 설치 도구 (배달 앱 같은 역할)
*   `install`: 설치해줘.
*   `google-adk`: 구글이 만든 에이전트 개발 키트 패키지 이름.

### 📦 설치 과정 구경하기
화면에 `Collecting google-adk`, `Downloading ...`, `Installing collected packages ...`, **`Successfully installed ...`** 같은 글자가 쭉 지나갑니다. 이 과정이 **'재료 배달 트럭이 와서 내 전용 냉장고(venv/Lib/site-packages)에 차곡차곡 넣는 과정'**입니다.

> **💡 개념 돋보기: requirements.txt (나중에 쓰지만 알아두기)**
> > 나중엔 `pip freeze > requirements.txt` 명령어로 **"이 프로젝트에 들어간 재료 목록(버전까지)"**을 텍스트 파일로 저장해둡니다. 나중에 다른 컴퓨터에서 이 프로젝트 열 때 `pip install -r requirements.txt` 한 방으로 똑같은 환경 복원이 가능하죠. 지금은 손으로 한 번 설치해보는 경험이 중요합니다.

## 4. `agent.py` 파일 생성: "헤드 셰프(에이전트)에게 줄 '두뇌 설계도' 첫 장 넘기기"

자, 드디어 **코딩의 시작**입니다. 영상에서는 **"We'll build a blog writing agent... As we walk through the code, notice how the planner and writ..."(블로그 글쓰기 에이전트를 만들 겁니다... 코드를 따라가며 플래너와 라이터가 어떻게...)**라고 하며 본격적인 코드 설명으로 넘어갑니다.

가장 첫 번째 파일, **에이전트의 핵심 로직이 담길 `agent.py`**를 만들어 봅시다.

### 🛠 실습: 파일 만들기

1.  VS Code 왼쪽 탐색기 패널에서 **빈 공간(폴더 이름 `BLOG_AGENT_PROJECT` 근처)에 마우스 우클릭** 하세요.
2.  **New File(새 파일)** 클릭.
3.  파일 이름 입력란에 **`agent.py`** 라고 정확히 입력하고 엔터.

> **⚠️ 주의:** 확장자가 `.py`여야 파이썬 파일로 인식됩니다. `agent.txt`나 `agent`만 치면 안 돼요!

이제 화면 중앙에 텅 빈 `agent.py` 탭이 열렸습니다. 여기에 우리가 배운 **'계획형(Planning) 에이전트'**의 뼈대를 하나씩 채워넣을 겁니다. 아직 코드를 다 쓰진 않을 거예요. **가장 기본적인 '뼈대(Import 및 기본 클래스 정의)'만 먼저 세워두고**, 다음 챕터에서 플래너(Planner), 라이터(Writer) 같은 구체적인 도구(Tool)와 흐름(Flow)을 살을 붙일 예정입니다.

### 🦴 `agent.py` 초기 뼈대 코드 (복사해서 붙여넣기)

```python
# agent.py - 블로그 글쓰기 에이전트의 두뇌 설계도

# 1. 필요한 도구들(라이브러리) 가져오기: 요리 전 칼, 도마, 프라이팬 꺼내놓기
from google.adk.agents import Agent
from google.adk.models.lite_llm import LiteLlm # 필요시 모델 지정용
# from google.adk.tools import ... # 나중에 도구(Tool) 추가할 때 쓸 예정

# 2. 루트 에이전트(Root Agent) 정의: 우리 식당의 '헤드 셰프' 임명장 쓰기
# 이 변수 이름 'root_agent'가 ADK가 "이 프로젝트의 메인 에이전트는 너야!"라고 찾는 공식 이름입니다.
root_agent = Agent(
    # 모델 설정: 어떤 두뇌(LLM)를 쓸지. 여기선 구글 제미나이 플래시 최신 버전 예시
    # model="gemini-1.5-flash-latest", 
    # 혹은 LiteLlm을 써서 다른 모델(오픈AI 등) 쓸 수도 있음: model=LiteLlm(model="gpt-4o")
    
    name="blog_writer_agent",        # 에이전트 이름표 (고유해야 함)
    description="주제를 받으면 개요 -> 본문 -> 제목/후크 제안까지 해주는 블로그 글쓰기 전문 에이전트", # 자기소개
    
    # instruction(시스템 프롬프트): 헤드 셰프에게 주는 '업무 매뉴얼/레시피 북'
    instruction="""
    당신은 전문 블로그 작가 에이전트입니다.
    사용자가 주제를 주면 다음 순서대로 작업을 수행하세요:
    1. 구조화된 개요(Outline)를 작성한다.
    2. 개요를 바탕으로 완성도 높은 본문(Blog Post)을 쓴다.
    3. 클릭을 유도할 대체 제목(Alternative Titles)과 훅(Hooks)을 제안한다.
    """,
    
    # tools=[...]: 셰프가 쓸 칼, 믹서기(도구들) - 다음 챕터에서 채워넣을 예정
    # sub_agents=[...]: 수셰프(하위 에이전트)들 - 플래너, 라이터 등을 여기에 배치 예정
)

# 터미널에서 `adk run` 또는 `adk web` 치면 이 root_agent가 실행됩니다.
```

## 5. 코드 한 줄 한 줄, 비유로 깊게 씹어먹기

방금 붙여넣은 코드가 무슨 뜻인지, **식당 비유**로 완벽하게 소화해 드릴게요.

### ① `from google.adk.agents import Agent`
> **비유:** **"주방장(에이전트) 자격증 틀(클래스) 빌려오기"**
> ADK 라이브러리 창고에서 `Agent`라는 **설계도(클래스)**를 내 작업대(코드)로 가져온 겁니다. 이 설계도가 있어야 `Agent(...)`라고 찍어낼 수 있어요.

### ② `root_agent = Agent(...)`
> **비유:** **"헤드 셰프 임명장 작성 및 벽에 걸기"**
> *   **`root_agent`**: 이 변수 이름이 **엄청 중요합니다.** ADK 프레임워크(실행기)는 프로젝트 폴더를 스캔할 때 **무조건 `root_agent`라는 이름의 변수**를 찾아서 "너가 메인이다!"라고 실행시킵니다. 이름을 `my_agent`나 `chef`로 바꾸면 **에러 나거나 실행 안 됩니다.** 관례이자 규칙이에요.
> *   **`Agent(...)`**: 빌려온 설계도로 **실제 헤드 셰프 객체(인스턴스) 한 명을 뽑아낸 것**입니다.

### ③ `name="blog_writer_agent"`
> **비유:** **"명찰(이름표) 달아주기"**
> 나중에 로그를 보거나 여러 에이전트가 협업할 때 "아, 너가 `blog_writer_agent`구나!" 하고 식별용으로 쓰입니다. 중복 안 되게 유일한 이름으로 짓습니다.

### ④ `description="..."`
> **비유:** **"구인 공고 / 간판 문구"**
> 외부에서 이 에이전트를 들여다봤을 때 "아, 얘는 블로그 쓰는 애구나" 한눈에 알게 해주는 설명서입니다. 사람이 읽는 용도죠.

### ⑤ `instruction=""" ... """` (가장 중요!)
> **비유:** **"헤드 셰프에게 주는 '비밀 레시피 북 & 업무 매뉴얼'"**
> **이게 바로 LLM(거대 언어 모델)에게 들어가는 '시스템 프롬프트(System Prompt)'입니다.**
> *   우리가 `agent.py`를 실행하면, ADK가 백그라운드에서 **제미나이(Gemini) 같은 LLM 모델을 호출**합니다.
> *   그때 **"너는 이제부터 ~~~한 역할을 해. ~~~순서로 일해."**라고 **가장 먼저, 가장 강력하게 지시하는 내용**이 바로 이 `instruction` 문자열입니다.
> *   영상에서 **"These pause to sketch a plan, then execute... booking travel... pick dates, hotels..."(이들은 계획을 짜고 실행합니다... 여행 예약처럼 날짜, 호텔을 정하고 순서를 따릅니다.)"**라고 설명한 **'계획형(Deliberate) 에이전트'의 사고방식**을 이 instruction 안에 **"1. 개요 작성 -> 2. 본문 작성 -> 3. 제목 제안"**이라는 **명시적 순서(Step-by-step)**로 심어준 것입니다.
> *   **핵심:** LLM은 이 instruction을 읽고 "아, 내가 당장 글 쓰지 말고 **먼저 개요부터 짜야지**"라고 **생각(Plan)하는 척(Scratchpad/Chain-of-Thought)하게 됩니다.**

### ⑥ `model="gemini-1.5-flash-latest"` (주석 처리됨)
> **비유:** **"어떤 두뇌(엔진)를 장착할까?"**
> 주석(`#`) 처리해뒀는데, ADK는 기본값으로 구글 제미나이 모델을 쓰도록 설정되어 있는 경우가 많습니다. 명시적으로 쓰고 싶은 모델 버전을 적거나, `LiteLlm`으로 GPT-4o, Claude 등을 꽂을 수도 있습니다. 이건 나중에 `.env` 파일에 API 키 설정할 때 같이 다룰게요.

### ⑦ `tools=[...]`, `sub_agents=[...]` (주석 처리됨)
> **비유:** **"수셰프(하위 에이전트) 채용 공고 & 도구함 열쇠"**
> *   **`tools`**: 파이썬 함수(검색, 계산, 저장 등)를 에이전트가 **직접 호출해서 쓸 수 있게 등록**하는 곳. "셰프가 직접 칼(도구) 쓰는 법".
> *   **`sub_agents`**: **다른 에이전트(Planner, Writer, Critic 등)를 부하 직원으로 두고, 헤드 셰프가 지시만 내리게 하는 구조**. 영상에서 말한 **'계획형 에이전트'의 꽃**이 바로 이 `sub_agents`를 이용한 **위임(Delegation)**입니다. 다음 챕터에서 본격적으로 만들 거예요!

## 🎓 튜터의 마무리 조언 (Troubleshooting & Mindset)

> **Q: `Import "google.adk" could not be resolved` 라고 빨간 줄(에러)이 떠요!**
> **A:** **가상환경(venv)이 활성화된 터미널에서 `pip install google-adk`를 했는지 확인하세요.** VS Code 오른쪽 하단 파이썬 인터프리터 버튼(예: `Python 3.10.1`)을 눌러서 `./venv/bin/python` 또는 `./venv/Scripts/python.exe` (가상환경 안의 파이썬)로 선택되어 있는지도 확인하세요. 이걸 **'인터프리터 설정'**이라고 합니다.

> **Q: `root_agent` 이름을 바꿨는데 안 돌아가요.**
> **A:** ADK 런타임(`adk run`, `adk web`)은 **관례(Convention) > 설정(Configuration)**을 따릅니다. 엔트리 포인트 파일(보통 `agent.py` 또는 `__main__.py`) 안에서 **전역 변수 `root_agent`**를 찾는 하드코딩된 로직이 있습니다. **이름 절대 바꾸지 마세요.**

> **Q: `instruction`에 한국어 써도 되나요?**
> **A:** 네, **한국어로 쓰셔도 LLM(제미나이, GPT 등)은 다 알아듣습니다.** 다만, 프롬프트 엔지니어링 고급 기법(Chain-of-Thought 유도 등)은 영문 프롬프트가 더 안정적일 수 있어 나중에 영어로도 써보시길 권장합니다. 지금은 **한국어로 편하게 작성하세요.**
