## 2. `agent.py` 해부학: 세 가지 핵심 부품 (뇌, 손, 연결고리)

강사님이 화면 왼쪽에 띄워준 `agent.py`(미완성)와 오른쪽 `agent_complete.py`(완성본)를 비교하며, **비어 있는 세 개의 구멍**을 채워야 합니다. 이 세 가지는 에이전트의 **해부학적 필수 장기**와 같습니다.

### ① `Agent` (에이전트) = **🧠 '뇌 (Brain): 당직 팀장의 머리'**
*   **역할**: "어떻게 생각할까?", "어떤 도구를 쓸까?", "내 성격(페르소나)은 무엇인가?"를 정의합니다.
*   **비유**: **수석 셰프의 '레시피 노트'와 '요리 철학'**. "나는 한식 전문이야(페르소나), 칼질은 이렇게 해(도구/스킬), 재료는 여기서 사(모델/MCP)"를 적어둔 설계도입니다.

> **💡 개념 돋보기: Agent (에이전트) - "뇌"의 3대 구성요소**
> > **1. Model (모델): '두뇌 회로'** - 실제 추론을 담당하는 LLM (예: Claude 3.5 Sonnet). "이 로그를 보니 메모리 누수 같군"이라고 생각하는 주체.
> > **2. Skills (스킬): '전문 자격증/비법'** - 에이전트가 할 줄 아는 구체적인 작업 단위. "쿠버네티스 로그 뽑기", "데드락 분석하기" 같은 액션 묶음.
> > **3. MCP Servers (MCP 서버): '외부 도서관/창고'** - 모델이 내부 지식만으로는 부족할 때 꺼내 쓰는 외부 지식/도구 창고. "최신 AWS 문서 찾아봐", "내부 위키 검색해봐" 할 때 연결되는 통로.

### ② `Environment` (환경) = **🤲 '손 (Hands): 당직 팀장의 손발'**
*   **역할**: 뇌가 "이거 해!"라고 명령하면 **실제로 실행**되는 물리적(가상) 공간. 컨테이너, 샌드박스, 파일 시스템, 네트워크 접근 권한 등이 여기 있습니다.
*   **비유**: **주방 (Kitchen)**. 뇌(셰프)가 "양파 다져!"라고 해도, 실제 칼과 도마, 양파가 있는 주방이 없으면 아무 일도 못 합니다. 여기가 바로 **'실행 환경'**입니다.

> **💡 개념 돋보기: Environment (환경) - "격리된 안전한 작업실"**
> > 에이전트가 **`rm -rf /`** (전체 삭제) 같은 위험한 명령을 내려도, 내 실제 노트북이나 프로덕션 서버가 터지지 않도록 **격리된 컨테이너(샌드박스)** 안에서만 놀게 하는 안전장치입니다.
> > *   **Stateful (상태 유지)**: "아까 그 파일 어디 뒀더라?" 하며 이전 작업 내용을 기억함.
> > *   **Ephemeral (일회용)**: 작업 끝나면 싹 치워버리는 깨끗한 방.

### ③ `Session` (세션) = **🔗 '연결고리 (Glue): 뇌와 손을 잇는 신경계'**
*   **역할**: "이 뇌(에이전트 인스턴스)를 저 손(환경 인스턴스)에 붙여서, **실시간으로 대화하게(이벤트 스트리밍) 해줘**."
*   **비유**: **셰프(뇌)와 주방(손) 사이를 오가며 주문서와 완성된 음식을 나르는 '홀 매니저(서빙 직원)'**. 사용자(손님)가 "물 좀요"라고 하면 매니저가 주방에 전달하고, 주방에서 "물 나왔어요" 하면 다시 손님에게 갖다 줍니다.

## 3. 핵심 설계 철학: "뇌와 손을 분리하라" (Decoupling) - 이게 진짜 핵심입니다! 💡

자, 여기서 **강사님이 가장 강조하신 부분**이 나옵니다. 왜 `Agent`(뇌)와 `Environment`(손)를 굳이 따로 만들었을까요? 그냥 하나에 다 넣으면 안 되나?

### 🍳 비유: **'슈퍼 셰프' vs '분업화된 레스토랑'**

*   **구식 방식 (Coupled - 뇌+손 합체)**:
    *   **"만능 슈퍼 셰프 1명"**이 주방도 관리하고, 장도 보고, 요리도 하고, 서빙도 함.
    *   **문제점**:
        1.  **보안 구멍 (Security Risk)**: 이 셰프가 **금고 열쇠(자격 증명, Credentials)**랑 **마스터 키(파일 시스템 전체 접근권)**를 다 목에 걸고 다님. 셰프가 해킹당하거나 실수하면 가게(시스템) 전체가 털림.
        2.  **느린 속도 (Latency)**: 손님(유저) 한 명 올 때마다 **새 주방(컨테이너)을 짓고, 가스 연결하고, 재료 채워 넣는 시간**이 걸림. (Time To First Token 지연)
        3.  **확장성 꽝**: 손님 100명 오면 슈퍼 셰프 100명, 주방 100개 지어야 함. 비용 폭증.

*   **클로드 매니지드 에이전트 방식 (Decoupled - 뇌/손 분리)**:
    *   **뇌(헤드 셰프)**: 본사 별관의 **보안 철저한 '전략 회의실'**에 앉음. 금고 열쇠 모름. 그냥 "저기 냉장고에서 양파 좀 꺼내와"라고 **명령만 내림**.
    *   **손(주방 팀)**: 별도의 **격리된 주방(샌드박스 환경)**에서 일함. 뇌가 시키는 대로만 함. 뇌가 해킹당해도 주방 팀은 자기 구역만 털림(격리).
    *   **세션(매니저)**: 둘 사이를 초고속 전용선으로 연결.

> **💡 개념 돋보기: 뇌-손 분리(Decoupling)의 3대 혁신 효과**
> > **1. 🛡️ 보안 (Security & Sandboxing): "자격 증명은 뇌가 모릅니다."**
> > 뇌(에이전트 루프)는 **자격 증명(Credentials)이나 민감한 파일 시스템에 직접 접근 못 함**. 손(환경)이 대신 접근하고, 뇌는 결과만 받음. 해커가 뇌를 해킹해도 "비밀번호 뭐야?"라고 물어볼 수조차 없음. **최소 권한 원칙(Least Privilege)** 완벽 구현.
> >
> > **2. ⚡ 속도 (Latency & TTFT): "주방은 미리 데워놨습니다."**
> > 뇌(에이전트 루프)는 **서버 사이드에서 항상 켜져 있는 상태(Warm)**로 대기함. 유저가 요청하면 **새 컨테이너 안 띄우고**, 바로 준비된 뇌가 생각 시작. 강사님 말씀대로 **TTFT(Time To First Token, 첫 토큰 생성 시간) P95 기준 90% 이상 단축**됨. "새벽 3초 만에 답장 옴."
> >
> > **3. 🛠️ 신뢰성/운영 (Durability & Managed): "내 노트북 꺼도 에이전트는 일함."**
> > 에이전트 루프(뇌)가 **클라우드 서버 사이드에서 돌아감**. 내 로컬 `agent.py` 돌리다가 와이파이 끊기고, 노트북 덮고, 배터리 나가도 **클라우드에선 뇌가 계속 생각 중**. 세션 상태 그대로 유지됨. 프로토타입 → 운영 전환 시 겪는 '내 컴퓨터에선 되는데 서버에선 안 돼' 지옥에서 해방.

```python
async def create_agent() -> Agent:
    """
    🧠 '당직 팀장'의 뇌를 정의하는 함수.
```

> **💡 튜터의 친절한 설명**
> *   `model`: 어떤 LLM을 쓸지 고르는 건 **'어떤 두뇌를 이식할까?'** 고르는 거랑 같습니다. 최신 모델일수록 추론이 똑똑하지만 비싸요.
> *   `system_prompt`: 이 에이전트의 **'성격/직무 기술서'**입니다. "너는 시니어 SRE야. 절대 추측하지 말고 로그 기반으로만 말해. 답변 형식은 마크다운 표로 해." 같은 지시사항을 여기 적습니다.
> *   `skills`: **'자격증 사본'**입니다. `KubernetesSkill`이면 "kubectl 명령어 치는 법", `LogAnalysisSkill`이면 "grep, awk로 로그 파싱하는 법"이 코드로 짜여져 있는 클래스들입니다.
> *   `mcp_servers`: **'외부 전문가 전화번호부'**입니다. 내 머리(모델 가중치)에 없는 최신 정보(오늘 바뀐 AWS API 스펙, 사내 위키)를 실시간으로 조회하러 갈 때 씁니다.

### Step 2: 손 만들기 (`create_environment` 함수 채우기)

```python
# agent.py 중간 부분

async def create_environment() -> Environment:
    """
    🤲 '당직 팀장'이 일할 작업실(주방)을 준비하는 함수.
    도커 컨테이너 띄우고, 필요한 툴(kubectl, aws cli 등) 깔고, 권한 설정.
    """
    # TODO: 여기를 채우세요
    
    # [강사님 힌트] Environment 클래스 인스턴스 생성
    return Environment(
        # 환경 타입: 도커 컨테이너 기반
        type="docker",
        
        # 컨테이너 이미지: "이미 쿠베른네스, AWS CLI, jq, curl 다 깔린 이미지 써"

        image="ghcr.io/your-org/incident-response-env:latest", 
        
        # 환경 변수 주입: "이 주방에서 쓸 비밀 키(API 토큰)들은 여기서 줌"
        # 주의: 뇌(에이전트)는 이 값을 모름. 손(환경)만 알고 있음 -> 보안!
        env_vars={
            "KUBECONFIG": "/workspace/.kube/config",
            "AWS_PROFILE": "production-readonly",
            # 슬랙 웹훅 등도 여기 넣을 수 있음
        },
        
        # 네트워크/권한 설정: "프로덕션 클러스터 읽기 권한만 줌 (쓰기 금지!)"
        network="host", # 또는 특정 브릿지 네트워크
        # resources: CPU/메모리 제한 걸어서 폭주 방지
    )
```

> **💡 튜터의 친절한 설명**
> *   `image`: **'주방 인테리어 공사'**를 미리 다 끝낸 상태를 이미지로 떠둔 겁니다. 매번 `apt-get install kubectl` 할 필요 없음. **시작 속도(냉시작 지연) 확 줄여줌**.
> *   `env_vars`: **'주방 전용 출입증/열쇠꾸러미'**입니다. 뇌(에이전트)는 "거기 냉장고(쿠버네티스)에 있는 재료(파드 목록) 좀 봐줘"라고만 말하면, 손(환경)이 자기 주머니에서 `KUBECONFIG` 열쇠 꺼내서 냉장고 열고 내용물 읽어옴. 뇌는 열쇠 존재조차 모름. **이게 디커플링의 보안 마법!**
> *   `network`, `resources`: "이 주방은 가스(CPU) 2개, 물(메모리) 4GB만 쓸 수 있어", "외부 인터넷(악성 코드 다운로드) 차단" 같은 **안전장치**입니다.

### Step 3: 뇌와 손 연결하기 (`create_session` 함수 채우기)

```python
# agent.py 하단 부분

async def create_session(agent: Agent, environment: Environment) -> Session:
    """
```

> **💡 튜터의 친절한 설명**
> *   `Session.create`: **'매니저 채용'**입니다. "너(뇌)랑 너(손)랑 짝지어줄게. 일 시작해."라고 매니저(세션 객체) 하나를 뽑는 겁니다.
> *   `max_steps`: **'야근 방지 타이머'**. 에이전트가 "음... 저건 뭐지? 이건 뭐지?" 하며 무한 루프 돌지 않게 **최대 행동 횟수 제한** 거는 거. 50번이면 충분히 복잡한 인시던트도 해결 가능.
> *   `event_stream`: **'실시간 중계 방송 켜기'**. 사용자(슬랙 유저) 화면에 "생각 중...", "kubectl 실행 중...", "로그 분석 완료!" 뜨게 해주는 스위치. 이게 꺼지면 사용자는 답장이 올 때까지 깜깜무소식 기다려야 함.

## 5. 서버 사이드 에이전트 루프 (Server-Side Agent Loop) - "내 노트북은 그냥 리모컨일 뿐"

강사님이 **"이게 제일 중요해!"**라고 하신 부분, 코드엔 안 보이지만 **아키텍처 레벨**에서 작동하는 마법입니다.

```text
[내 로컬 머신 (Laptop)]                          [클라우드 서버 (Managed Service)]
┌─────────────────────────────┐                  ┌─────────────────────────────┐
│  streamlit run app.py       │   HTTPS/WS      │  🧠 Agent Loop (Brain)       │
│  - UI 그려줌 (입력창, 로그)  │ ◄─────────────► │  - 생각(Reasoning)           │
│  - 세션 ID만 가지고 있음    │   API 호출      │  - 도구 선택(Tool Selection) │
│  - 내 노트북 꺼도 상관없음  │                 │  - 상태 관리(State Mgmt)     │
└─────────────────────────────┘                  └─────────────────────────────┘
                                                          ▲
                                                          │ 내부 고속 통신
                                                          ▼
                                               ┌─────────────────────────────┐
                                               │ 🤲 Environment (Hands)       │
                                               │ - Docker Container (Sandbox) │
                                               │ - kubectl, aws cli 실행      │
                                               │ - 파일 시스템 접근           │
                                               └─────────────────────────────┘
```

*   **내 로컬 `agent.py`**: **'설계도(Blueprint)'** 역할만 함. "뇌는 이런 스펙, 손은 이런 스펙으로 만들어줘"라고 **클라우드 API에 주문 한 번 넣는 것**이 끝.
*   **실제 실행**: 클라우드 쪽에서 **뇌(에이전트 루프)가 24시간 켜져 있음**.
*   **장점**:
    1.  **내 노트북 덮어도 됨**: 세션이 클라우드에 살아있으니까 내일 아침 열어서 "어제 그 인시던트 어떻게 됐어?" 물으면 이어서 답함.
    2.  **배포/스케일링 내 알 바 아님**: 쿠버네티스 디플로이먼트, 오토스케일링, 헬스체크... 클로드 팀이 다 해줌. 난 `agent.py`만 잘 짜면 됨.
    3.  **버전 관리**: `agent.py` 고쳐서 다시 `streamlit run` 하면 **새 버전 뇌가 클라우드에 즉시 교체됨**. 무중단 배포.

## 6. 마무리하며: 이제 `streamlit run app.py` 칩시다!

자, 세 구멍(`create_agent`, `create_environment`, `create_session`)을 다 채우셨나요? 저장(`Ctrl+S`) 하시고 터미널에서 마법의 주문을 외치세요.

```bash
# 가상환경 활성화 확인 후
streamlit run app.py
```

브라우저가 열리며 `http://localhost:8501` 페이지가 뜹니다. 이제 화면에 **시뮬레이션 인시던트 버튼**이 있을 겁니다. (예: "결제 서버 500 에러 발생!", "DB 커넥션 풀 고갈")

**클릭해 보세요.**

*   오른쪽에 **에이전트의 생각(Chain of Thought)**이 실시간으로 스트리밍됩니다. ("음, 500 에러면 일단 파드 상태부터 보자. `kubectl get pods` 실행해야지.")
*   **도구 호출(Tool Call)**이 뜹니다. (`kubectl get pods -n payment`)
*   **환경(손)**에서 결과가 돌아옵니다. (`pod-1: CrashLoopBackOff`, `pod-2: Running`...)
*   에이전트(뇌)가 다시 생각합니다. ("CrashLoopBackOff네? 로그 봐야지. `kubectl logs pod-1`")
*   최종적으로 **근본 원인 분석 리포트**가 예쁘게 마크다운으로 렌더링되어 나옵니다.

## 📝 요약 정리: 오늘 배운 '에이전트 조립 3단계'

| 단계 | 코드 함수 | 비유 | 핵심 키워드 |
| :--- | :--- | :--- | :--- |
| **1. 뇌 만들기** | `create_agent()` | **수석 셰프 고용 계약서** 작성 | `Model`, `System Prompt`, `Skills`, `MCP` |
| **2. 손 만들기** | `create_environment()` | **격리된 최신식 주방** 짓기 | `Docker Image`, `Env Vars(비밀키)`, `Network/Resources` |
| **3. 연결하기** | `create_session()` | **매니저(신경계)** 채용해 뇌-손 연결 | `Session.create()`, `max_steps`, `event_stream` |

> **💡 마지막 개념 돋보기: 왜 클로드 매니지드 에이전트인가?**
> > **"프로토타입의 마법을, 운영의 현실로 가져오기 위해."**
> > 로컬에서 `langchain`이나 `autogen`으로 돌려보던 에이전트를 **실제 서비스에 붙이려면?**
> > *   내 노트북에서 돌리면? -> 노트북 켜둬야 함, IP 바뀌면 끊김, 로그 어디 갔지?
> > *   직접 서버에 도커로 올리면? -> 오토스케일링 어떻게? 세션 상태 저장소(Redis?)는? 헬스체크는? GPU/CPU 자원 관리는?
> > **클로드 매니지드 에이전트 = 이 모든 '운영 지옥(Operational Hell)'을 추상화해 준 플랫폼.**
> > 당신은 **`agent.py`라는 '설계도'만 잘 그리면 됩니다.** 나머지는 플랫폼이 책임집니다.
