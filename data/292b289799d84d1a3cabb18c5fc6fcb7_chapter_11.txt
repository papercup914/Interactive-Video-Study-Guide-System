> **알림:** 제공해주신 영상 스크립트 구간은 **'UV 패키지 매니저 설치 방법'**이 아닌 **'AI 에이전트의 3가지 행동 패턴(순차, 반응, 계획 에이전트)'**에 대한 내용입니다. 요청하신 챕터 제목과 원본 스크립트 내용이 일치하지 않으므로, **제공된 스크립트 내용(에이전트 패턴)**을 바탕으로 학습 가이드를 작성해 드립니다. UV 설치 가이드가 필요하시면 해당 스크립트를 다시 전달해 주세요.

# 🤖 챕터: AI 에이전트, 너 도대체 어떻게 생각하니? — 3가지 생각법 완벽 해부

안녕하세요! 여러분의 친절한 AI 튜터입니다. 지난 시간에는 AI 에이전트가 단순히 말을 잘하는 챗봇이 아니라, **'추론하고, 계획하고, 기억하며, 사용자를 대신해 자율적으로 결정 내리는 시스템'**이라는 정의를 내렸었죠? 오늘은 **"그럼 그 똑똑한 에이전트들이 머릿속에서 어떻게 생각을 굴리는가?"** 즉, **에이전트의 3가지 핵심 행동 패턴**을 파헤쳐 볼 거예요.

이건 마치 **'일하는 스타일이 다른 직원 3명'**을 채용 면접 보는 것과 똑같아요. 누가 우리 팀(프로젝트)에 맞을지, 끝까지 읽고 골라보세요!

---

## 1. 첫 번째 지원자: '매뉴얼 대로만 일하는 신입' — 순차 에이전트 (Sequential Agents)

자, 첫 번째 지원자입니다. 이 친구는 **'조립 라인(Assembly Line)'** 방식대로 일해요.

### 🍳 일상 비유: 라면 끓이기 레시피북
상상해 보세요. 여러분이 **'라면 끓이기 매뉴얼 100페이지짜리'**를 손에 쥐고 있다고 쳐요.
1.  **1단계:** 물 550ml를 냄비에 붓는다.
2.  **2단계:** 불을 켜고 물이 끓기를 기다린다.
3.  **3단계:** 면과 스프를 넣는다.
4.  **4단계:** 4분 30초 타이머를 맞춘다.
5.  **5단계:** 불을 끄고 그릇에 담는다.

이 친구는 **1번이 끝나야 2번을 하고, 2번이 끝나야 3번을 해요.** 중간에 "아, 물 좀 덜 넣을까?" 혹은 "스프부터 넣을까?" 같은 **융통성 제로**예요. 그냥 정해진 순서(Step 1 → Step 2 → Step 3)를 **무조건, 기계적으로, 예외 없이** 실행합니다.

> **💡 개념 돋보기: 순차 에이전트 (Sequential Agent)**
> > **핵심 정의:** **정해진 워크플로우(Workflow)대로 단계별로 순차 실행하는 에이전트.**
> > 
> > *   **작동 원리:** `Step 1 완료 → Step 2 시작 → Step 3 시작 ...` (선형 구조)
> > *   **장점:** **예측 가능(Predictable)함.** 버그 찾기 쉽고, 디버깅 편함. "무조건 이 순서대로 해"라는 통제가 가능.
> > *   **단점:** **경직됨(Rigid).** 예외 상황(물이 넘침, 면이 불음)에 대처 못 함. 중간에 사용자가 "그만!" 해도 못 멈춤.
> > *   **비유:** **자동차 조립 라인 로봇 팔, 배치(Batch) 스크립트, CI/CD 파이프라인.**

### 🎯 언제 써먹나요?
*   **"무조건 이 순서대로만 하면 되는 단순 반복 작업"**
*   예: 매일 새벽 3시 DB 백업 → 압축 → S3 업로드 → 슬랙 알림
*   예: 회원가입 → 이메일 인증 메일 발송 → DB 저장 → 환영 메일 발송 (절대 순서 바뀌면 안 되는 플로우)

---

## 2. 두 번째 지원자: '눈치 백단, 즉흥 연기의 달인' — 반응형 에이전트 (Reactive Agents)

두 번째 지원자는 완전히 달라요. 매뉴얼? 그런 거 안 봐요. **'지금 이 순간의 상황(State)'만 보고 즉각 반응**해요.

### 🍳 일상 비유: 주방에서 불 끄는 베테랑 셰프
경력 20년 차 셰프를 떠올려 보세요. 레시피북 안 봐요. 팬에 기름 튀면 **즉시** 불 조절하고, 재료 타는 냄새 나면 **즉시** 뒤집어요. 
*   상황 A: "어? 연기 나네?" → **행동: 불 줄이기** (도구 A 사용)
*   상황 B: "어? 소스 묽네?" → **행동: 전분물 넣기** (도구 B 사용)
*   상황 C: "어? 손님 컴플레인?" → **행동: 새 요리 시작** (도구 C 사용)

이 셰프는 **"다음에 뭐 할까?" 미리 계획 안 짜요.** 그냥 **눈앞의 상태(State)만 보고 "지금 뭘 해야 하지?"** 결정하죠. 엄청 유연하고 빠르지만, **"이거 해서 저거 하고, 저거 해서 큰 그림 그리자"** 같은 **장기 플랜(Plan)은 전혀 없어요.**

> **💡 개념 돋보기: 반응형 에이전트 (Reactive Agent)**
> > **핵심 정의:** **현재 상태(Observation/State)를 보고 즉시 다음 행동(Action)을 결정하는 에이전트. (자극-반응, Stimulus-Response)**
> > 
> > *   **작동 원리:** `상태 확인 → 조건 분기(if/else 또는 LLM 판단) → 도구 호출 → 결과 관찰 → 다시 상태 확인...` (루프 구조)
> > *   **장점:** **유연함(Flexible), 동적 환경에 강함.** 예상치 못한 상황(에러, 사용자 말 바꾸기, 외부 API 변경)에 즉각 대처.
> > *   **단점:** **근시안적(Short-sighted).** "지금 이거 하면 나중에 큰일 나는데..." 같은 **선견지명 없음.** 목표가 복잡하고 단계가 많으면 헤맴(무한 루프, 목표 이탈).
> > *   **비유:** **로봇 청소기(벽 만나면 꺾음), 고전적인 게임 AI(플레이어 보면 공격), 단순 챗봇(입력 오면 즉시 답변).**

### 🎯 언제 써먹나요?
*   **"상황이 시시각각 변하고, 다음 단계를 예측 못 하는 동적 환경"**
*   예: 주식 자동 매매 봇(호가창 보고 밀리초 단위 매수/매도)
*   예: 게임 NPC (플레이어 위치 보고 추격/도주/공격 즉시 결정)
*   예: 고객 문의 분류 봇 (들어온 문의 텍스트 보고 즉시 부서 라우팅)

## 3. 세 번째 지원자: '프로젝트 매니저(PM) 스타일, 큰 그림 그리는 기획자' — 계획/숙고 에이전트 (Deliberate / Planning Agents)

드디어 마지막, 가장 '똑똑해 보이는' 지원자입니다. 이 친구는 **일 시작하기 전에 잠시 멈추고 "자, 계획 좀 짜보자" 하고 머리를 굴려요.**

### 🍳 일상 비유: 해외여행 떠나는 꼼꼼한 여행자
여러분, 비행기 표부터 막 사나요? 아니죠.
1.  **목표 설정:** "일주일 동안 오사카/교토 여행 가자."
2.  **계획 수립(Deliberation/Planning):**
    *   날짜 고르고 → 항공권/숙소 예약 → 교통 패스 구매 → 맛집/관광지 리스트업 → **동선 짜기(1일차: 오사카성 → 도톤보리, 2일차: 교토 기요미즈데라...)** → 짐 싸기 리스트 작성.
3.  **실행(Execution):** 짜둔 일정표 들고 그대로 움직이기. (중간중간 비 오면? → 실내 일정으로 대체하는 **재계획(Re-planning)** 수행)

이 에이전트는 **"생각하는 시간(Thinking Time)"을 따로 가집니다.** LLM에게 "목표는 이거야, 제약 조건은 이거야, 가능한 도구는 이거야. **단계별 계획(Plan) 짜줘**"라고 시키는 거죠. 계획을 다 짜고 나서야 비로소 **첫 번째 단계(Tool 실행)**를 시작해요.

> **💡 개념 돋보기: 계획/숙고 에이전트 (Deliberate / Planning Agent)**
> > **핵심 정의:** **목표 달성을 위해 사전에 추론(Reasoning)하여 실행 계획(Plan/Task List)을 수립하고, 그 계획에 따라 단계적으로 실행하며, 필요시 계획을 수정(Re-planning)하는 에이전트.**
> > 
> > *   **작동 원리:** `목표 수신 → [계획 수립 단계: LLM이 Chain-of-Thought로 Task Graph 생성] → 계획 확정 → [실행 단계: 순차/병렬로 Tool 호출] → 중간 평가(Reflection) → 필요시 재계획 → 완료`
> > *   **장점:** **복잡한 다단계 문제 해결 가능.** 의존성 관리(호텔 예약해야 비행기 탈 수 있음) 가능. 큰 그림 보며 효율적 경로 탐색.
> > *   **단점:** **초기 지연 시간(Latency) 김.** 계획 짜는 데 토큰/비용/시간 듦. 계획이 틀리면 처음부터 다시 짜야 할 수도 있음 (Hallucination 위험).
> > *   **비유:** **자율 주행 자동차(경로 계획 → 주행), AI 코딩 에이전트(아키텍처 설계 → 파일 생성 → 테스트), 여행 플래너 앱.**

### 🎯 언제 써먹나요?
*   **"목표는 명확한데, 어떻게 도달할지 경로가 불확실하고 단계 간 의존성이 복잡한 작업"**
*   예: "이 레포지토리 분석해서 버그 찾아 고치고 PR 올려줘" (코드 분석 → 원인 추론 → 수정 파일 선정 → 수정 → 테스트 → 커밋)
*   예: "경쟁사 분석 보고서 써줘" (검색 계획 → 크롤링 → 요약 → 구조화 → 문서 작성)
*   예: "내일 회의 자료 준비해줘" (일정 확인 → 자료 수집 → 슬라이드 기획 → 작성 → 리뷰)

## 4. 자, 그럼 우리 팀엔 누구를 뽑을까? — 상황별 채용 가이드 (Decision Matrix)

스크립트 마지막에 **"So, which of these is the right one for you? It depends on the problem."** (어떤 게 맞냐고요? 문제에 달렸죠.) 라고 했죠? 면접관 여러분, 이제 결정하세요.

| 문제 유형 (Problem Type) | 추천 에이전트 | 이유 (Why?) |
| :--- | :--- | :--- |
| **단순하고, 예측 가능하며, 순서가 고정된 흐름**<br>(예: 데이터 파이프라인, 정기 백업, 배포 자동화) | 🥇 **순차 에이전트 (Sequential)** | 굳이 비싼 LLM 써가며 생각할 필요 없음. 코드(스크립트)로 짜는 게 제일 빠르고 싸고 확실함. |
| **상황이 실시간으로 변하고, 즉각 반응이 생명인 환경**<br>(예: 게임 AI, 실시간 트레이딩, 로봇 제어, 간단 라우팅) | 🥇 **반응형 에이전트 (Reactive)** | 계획 짜는 시간조차 사치임. "보고 → 바로 쏴야" 함. 상태 머신(State Machine)이나 단순 Rule-based가 짝꿍. |
| **목표는 있는데 길이 여러 갈래이고, 순서/의존성이 복잡한 미션**<br>(예: 여행 예약, 코드 리팩토링, 리서치 리포트, 복합 업무 자동화) | 🥇 **계획 에이전트 (Planning)** | "무작정 돌진"했다간 낭패 봄. 잠시 멈춰서 지도(Plan) 펴고 가야 가장 빠른 길 찾음. LLM의 추론 능력 극대화. |

> **💡 튜터의 꿀팁: 하이브리드가 정답입니다!**
> 실제 프로덕션 레벨 에이전트는 **이 셋을 섞어서 씁니다.**
> *   **최상위 레벨:** **플래너(Planning Agent)**가 큰 마일스톤 계획 짜기.
> *   **중간 레벨:** 각 마일스톤은 **순차 에이전트(Sequential)**로 확실하게 처리 (예: "예약하기"라는 마일스톤 안에서는 항공권 → 호텔 → 렌터카 순차 실행).
> *   **최하위/예외 처리:** 도구 실행 중 에러 나거나 예외 상황 터지면 **반응형 에이전트(Reactive)**가 즉각 "재시도 / 대체 도구 / 사용자 호출" 판단.
> 
> **이게 바로 '에이전트 아키텍처 설계'의 핵심입니다!**

## 📝 마무리 요약 & 다음 예고

오늘 배운 3가지 패턴, 입에 붙게 한 번 더 외워볼까요?

1.  **순차 (Sequential):** **"레시피대로만 해"** — *예측 가능, 경직됨, 단순 작업용.*
2.  **반응 (Reactive):** **"눈앞의 불부터 꺼"** — *유연, 근시안적, 실시간/동적 환경용.*
3.  **계획 (Planning):** **"지도 펴고 경로 짜자"** — *전략적, 초기 비용 큼, 복합/다단계 목표용.*

**다음 시간에는?** 드디어 **"자, 그럼 이제 실제로 에이전트 하나 만들어 볼까? (Now let's actually build an agent...)"** 라며 코드로 들어간다고 합니다. 오늘 배운 **'계획 짜는 에이전트(Planning Agent)'를 직접 구현**해 보면서, LLM에게 "생각해!" 시키는 프롬프트 엔지니어링 비법과 도구(Tool) 바인딩, 상태 관리(State Graph)까지 실습할 예정이에요.

여러분의 '생각하는 머신'을 직접 만들 그날까지, 튜터는 여기서 기다릴게요. 수고하셨습니다! 👋
