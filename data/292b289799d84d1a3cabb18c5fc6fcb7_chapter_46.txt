# 챕터 10. 실전! 내 에이전트에게 첫 미션 주기: "AI 에이전트 탑 10 유스케이스 블로그 써줘"

자, 드디어 기다리던 순간이 왔습니다. 그동안 주방(코드 에디터)에서 레시피(코드)를 짜고, 재료(도구, 프롬프트)를 손질하고, 조리 도구(에이전트 구조)를 세팅하느라 고생 많으셨습니다. 이제 손님(사용자)을 맞이하고 실제 주문(프롬프트)을 받아 요리를 내놓을 시간입니다.

이번 챕터에서는 우리가 만든 **'블로그 작성 마스터 에이전트'**에게 최초로 일을 시키는 현장으로 여러분을 초대합니다. 화려한 이론이 아닌, 터미널이라는 검은 화면 위에서 펼쳐지는 **'실제 작동의 마법'**을 함께 목격해 보시죠.

---

## 1. 레스토랑 오픈 준비: `adk web` 명령어, 그 의미는?

영상에서는 이렇게 말합니다.
> *"Head into your terminal and launch it using this command with ADK web so you can view everything inside a simple UI."*

**비유로 이해하기: '주방 문 열기' vs '홀 오픈하기'**

지금까지 우리는 **'주방(백엔드/코드)'**에서만 일했습니다. 셰프(루트 에이전트)와 보조 셰프(플래너, 라이터 서브 에이전트)를 고용하고, 레시피(지시문)를 벽에 붙여놓고, 칼(도구)을 갈아두었습니다. 하지만 손님이 주문하려면 **'홀(프론트엔드/UI)'**이 열려 있어야 하죠.

*   **`adk run` (이전 방식):** 주방 뒤쪽 문으로만 주문을 받는 '배달 전문점' 같습니다. 터미널에 텍스트로만 입력하고 텍스트로만 받는, 개발자 전용 모드입니다.
*   **`adk web` (이번 방식):** **번듯한 홀과 캐셔, 오픈 키친을 갖춘 정식 레스토랑 오픈**입니다. 브라우저라는 예쁜 식당 공간에서, 마우스로 클릭하고 타이핑하며 에이전트가 일하는 과정을 **눈으로 직접 지켜볼 수 있는 UI(사용자 인터페이스)**를 띄워주는 명령어입니다.

**터미널에서 이 한 줄을 치는 순간:**
```bash
adk web
```
여러분의 컴퓨터 내부에서 작은 웹 서버가 켜지고, `http://localhost:8000` 같은 주소가 생깁니다. 이 주소를 브라우저 주소창에 넣고 엔터를 치면, 짜잔! **'내 에이전트 전용 관리 페이지'**가 열립니다. 왼쪽엔 에이전트 목록이, 오른쪽엔 채팅창이 있는 익숙한 화면이죠.

> **💡 개념 돋보기: ADK Web (Agent Development Kit Web UI)**
> > **ADK가 개발자에게 선물하는 '관찰 창'이자 '테스트 베드'입니다.**
> > 
> > *   **코드 수정 없이 즉시 테스트:** 파이썬 코드를 고치고 다시 실행할 필요 없이, 브라우저만 새로고침하면 최신 코드가 반영됩니다(핫 리로딩 지원 시).
> > *   **내부 동작 완전 공개:** 에이전트가 '생각(Thinking)'하는 과정, 어떤 **도구(Tool)를 호출**했는지, **서브 에이전트에게 위임(Transfer/Call)**했는지, **입력/출력 값(JSON)**이 무엇인지 모든 흐름이 타임라인처럼 보입니다.
> > *   **세션 관리:** 대화 히스토리가 세션 단위로 저장되어, 이전 대화를 이어가거나 새로운 손님(세션)을 받을 수 있습니다.
> > 
> > **한 마디로:** "내 에이전트 머릿속을 투명하게 보여주는 CCTV이자 대시보드"

## 2. 첫 손님 맞이: 프롬프트 입력 "AI 에이전트 탑 10 유스케이스 블로그 작성"

브라우저 창이 떴습니다. 이제 떨리는 마음으로 채팅 입력창에 첫 주문을 넣어봅니다.

> **User:** `AI 에이전트 탑 10 유스케이스 블로그 작성해줘` (또는 영상처럼 영어로 `Generate a blog on the top 10 use cases for AI agents`)

**비유로 이해하기: '손님의 주문서'와 '주방장의 브리핑'**

이 한 줄의 프롬프트는 단순한 문장이 아닙니다. **'주문서'**이자 **'프로젝트 기획안'**입니다.
손님이 "김치찌개 1인분"이라고 주문하면, 주방장은 머릿속으로 이렇게 생각하죠.
1.  **재료 확인:** 김치, 돼지고기, 두부, 양파... (데이터 수집 필요)
2.  **조리 순서:** 고기 볶기 -> 김치 넣고 볶기 -> 물 붓고 끓이기 -> 두부 넣기 -> 간 보기 (플래닝 필요)
3.  **플레이팅:** 그릇에 담고 파 뿌리기 (최종 아웃포맷 필요)

우리 에이전트도 똑같습니다. **"AI 에이전트 탑 10 유스케이스 블로그"**라는 주문을 받자마자, **루트 에이전트(총괄 셰프)**는 자신이 가진 도구함을 훑어봅니다.

> **💡 개념 돋보기: 루트 에이전트의 '도구함'에는 오직 두 개만 있다!**
> > **중요!** 영상에서 강조했듯, *루트 에이전트는 플래너(Planner)와 라이터(Writer)라는 두 개의 '서브 에이전트 도구'만 직접 쓸 수 있습니다.*
> > 
> > *   ❌ 루트 에이전트가 직접 구글 검색 안 함 (`google_search` 도구 없음)
> > *   ❌ 루트 에이전트가 직접 글 안 씀 (`write_blog` 도구 없음)
> > *   ✅ **오직 `planner` 도구 호출 -> `writer` 도구 호출**만 가능
> > 
> > 이게 바로 **'통제된 워크플로우(Controlled Workflow)'**의 핵심입니다. 총괄 셰프는 요리하지 않고, **'기획서 짜는 직원(플래너)'**과 **'글 쓰는 직원(라이터)'**만 관리합니다. 그래서 실수가 없고 예측 가능합니다.

## 3. 오픈 키친 구경: 에이전트의 '생각 과정' 실시간 중계

주문 넣고 엔터 치는 순간, 오른쪽 채팅창이 아닌 **왼쪽/아래 패널(이벤트 스트림/트레이스)**에서 불꽃 튀는 움직임이 시작됩니다. 이게 `adk web`의 백미입니다.

### 단계 1: 기획팀장(Planner Agent) 소환 📋
루트 에이전트가 `planner` 도구를 호출합니다. 화면에 `Function Call: planner` 같은 로그가 뜨죠.

*   **플래너의 머릿속:** "좋아, 'AI 에이전트 탑 10 유스케이스' 블로그를 써야 해. 그럼 목차를 어떻게 짤까? 1. 서론(정의/중요성), 2. 유스케이스 1~10 (각각 제목, 설명, 사례), 3. 비교/선정 가이드, 4. 결론/미래 전망... 이 정도면 좋겠네. 각 섹션별로 어떤 키워드로 검색해야 할지 검색 쿼리도 같이 짜서 라이터한테 넘겨줘야지."
*   **결과물 (Output):** 구조화된 **'블로그 플래닝 문서(Planning Output)'** - 이 안에는 `outline`(목차), `search_queries`(검색어 리스트), `target_audience`(타깃 독자) 등이 JSON 형태로 담겨 있습니다.

> **💡 개념 돋보기: 플래너의 산출물 = '상세 설계도 + 자재 주문서'**
> > 플래너가 그냥 "대충 써"라고 안 하고, **섹션별 키워드와 검색 쿼리까지 구체적으로 짜서 라이터에게 주는 것**이 포인트입니다. 라이터는 이 설계도만 보고 재료(검색 결과) 가져다가 글만 쓰면 되니까, **'할루시네이션(거짓말)' 확률이 확 줄어듭니다.**

### 단계 2: 작가(Writer Agent) 소환 & 검색 도구 난사 🔍✍️
플래너의 설계도를 받은 루트 에이전트가 이제 `writer` 도구를 호출합니다. `Function Call: writer` 로그 등장!

라이터 에이전트는 받은 설계도를 보며 **자신의 도구함(`google_search`)**을 마구 꺼내 듭니다.
*   `google_search("AI agent use cases 2024 customer support")` -> 결과 수신
*   `google_search("AI agent coding automation examples")` -> 결과 수신
*   `google_search("AI agent healthcare diagnosis use case")` -> 결과 수신
*   ... (탑 10 개수만큼, 혹은 섹션별로 반복)

**비유: 도서관 사서가 자료실에 뛰어다니는 모습**
라이터는 **'자료 조사원'**입니다. 설계도(플래너 작품)를 손에 쥐고, 구글이라는 거대한 도서관에서 "이 섹션 쓸 재료 좀 주세요!"라고 요청하고, 검색 결과 스니펫(요약본)을 받아옵니다. 이 과정이 화면에 **주르륵 로그로 찍힙니다.** "아, 지금 '코딩 자동화' 파트 자료 찾으러 갔구나", "지금 '의료 진단' 케이스 공부 중이구나"가 실시간으로 보입니다.

### 단계 3: 집필 및 검수 (Drafting & Checking) 📝
자료 수집이 끝나면 라이터는 본격적으로 **글을 씁니다.** (LLM 내부 추론)
*   플래너가 준 목차 순서대로 섹션별 작성
*   검색해 온 사실(Fact) 바탕으로 내용 채우기
*   마크다운 형식(제목, 볼드, 리스트) 맞추기
*   **자체 검수(Check):** "내가 쓴 글이 플래너 의도랑 맞나? 톤앤매너 괜찮나? 사실 오류 없나?"

### 단계 4: 최종 포장: 대체 제목 3개 + 트윗 훅 2개 🎁
영상 스크립트에 나온 아주 중요한 디테일입니다.
> *"...and finally it adds three alternative titles and two tweet-length hooks."*

단순히 본문만 던져주는 게 아닙니다. **'편집장' 역할까지 합니다.**
1.  **대체 제목 3개 (Alternative Titles):** SEO용, 클릭 유도용, 전문가용 등 다른 앵글의 제목 제안
2.  **트윗 훅 2개 (Tweet-length Hooks):** X(트위터)나 링크드인에 홍보용으로 올릴 한 줄짜리 요약/홍보 문구

**비유: 요리 다 해서 그릇에 담고, '메뉴판 사진'과 '인스타 홍보 문구'까지 찍어주는 셰프**
개발자가 블로그 글 하나 올리려면 본문 쓰기, 제목 고민, SNS 홍보글 쓰기... 별도 작업이잖아요? 에이전트가 **'원스톱 콘텐츠 패키지'**로 다 만들어서 줍니다.

## 4. 완성된 요리, 테이블로 서빙: 최종 결과물 확인

잠시 후(복잡도에 따라 30초~수 분), 루트 에이전트가 라이터로부터 최종 결과물을 받아 **사용자 채팅창에 예쁘게 렌더링**해줍니다.

여러분은 브라우저에서 다음을 보게 됩니다.

1.  **완성된 블로그 본문:** 마크다운으로 깔끔하게 렌더링된 글 (제목, 소제목, 리스트, 볼드 처리 완벽)
2.  **Alternative Titles (대체 제목 3개):**
    *   "2024년 놓치면 후회할 AI 에이전트 활용 사례 10가지"
    *   "비즈니스 혁신을 이끄는 AI 에이전트: 산업별 탑 10 유스케이스 심층 분석"
    *   "챗봇을 넘어선 자율성: 실무에 바로 적용하는 AI 에이전트 베스트 10"
3.  **Tweet Hooks (홍보용 훅 2개):**
    *   "챗GPT만 써봤다면 반쪽짜리! 스스로 일하는 'AI 에이전트'가 바꾸는 업무 혁신 탑 10 🚀 #AI #Agent #Automation"
    *   "개발자, 마케터, 영업... 직군별로 골라 쓰는 AI 에이전트 유스케이스 치트키 공개 🔑 링크에서 확인하세요!"

## 5. 마무리하며: "당신은 이제 에이전트 아키텍트입니다"

영상은 이렇게 끝맺습니다.
> *"And that's it. You've built and run your first AI agent with Google's ADK. We've started from the idea of what agents are, then walked through the code step-by-step and finally saw it come to life in terminal."*

**비유로 이해하기: '자전거 타기'의 첫 성공 순간**

여러분은 지금 **보조 바퀴 뗀 자전거를 처음 혼자 타고 10미터쯤 나아간 아이** 같습니다.
*   **이론(자전거 원리):** 에이전트란 무엇인가, LLM, 도구, 메모리... (챕터 1~2)
*   **설계(자전거 조립):** 파이썬 클래스 구조, Instruction 작성, Tool 바인딩, Sub Agent 위임... (챕터 3~7)
*   **디버깅(넘어지기):** Import 에러, API 키 오류, 프롬프트 수정... (챕터 8~9)
*   **실행(달리기):** `adk web` -> 프롬프트 입력 -> 결과물 확인! (챕터 10, 현재)

지금 이 순간, 화면에 뜬 **'탑 10 유스케이스 블로그'**는 단순한 텍스트 파일이 아닙니다. **여러분이 설계한 '자율적 업무 프로세스'가 살아 숨 쉬는 첫 번째 증거**입니다.

> **💡 개념 돋보기: 이번 실행을 통해 검증된 핵심 아키텍처 3가지**
> > 1.  **계층적 위임(Hierarchical Delegation):** 루트 -> 플래너 -> 라이터 -> 구글 검색. **명령 체계가 명확히 작동함.**
> > 2.  **도구 격리(Tool Isolation):** 루트는 검색 못 함, 라이터는 플래닝 못 함. **권한 분리로 안전성 확보.**
> > 3.  **상태 기반 워크플로우(Stateful Workflow):** 플래너의 출력(State)이 라이터의 입력(Context)이 됨. **데이터 흐름이 끊기지 않음.**
> >
> > 이 세 가지가 터미널 로그 없이, 브라우저 UI만으로도 **'완벽하게 돌아갔다'**는 증명입니다.

| **1. 서빙 오픈** | 개발자 (`adk web`) | 웹 UI 서버 실행, 브라우저 접속 | 레스토랑 홀 오픈, 손님 맞이 준비 |
| **2. 주문 접수** | 사용자 (프롬프트) | "탑 10 유스케이스 블로그 써줘" | 손님 주문서 제출 |
| **3. 기획 수립** | **Planner Agent** | 목차, 검색어, 타깃 정의 (JSON 출력) | 총괄 셰프가 메뉴 구성안 & 장보기 리스트 작성 |
| **4. 자료 수집** | **Writer Agent** | `google_search` 반복 호출 | 보조 셰프가 장보고, 재료 손질 |
| **5. 집필/검수** | **Writer Agent** | 본문 작성, 사실 확인, 포맷팅 | 요리 조리 및 간 보기 |
| **6. 포장/서빙** | **Root Agent** | 대체 제목 3개, 트윗 훅 2개 추가하여 최종 응답 | 플레이팅 완료, 테이블 서빙 + 포장용기(홍보문구) 제공 |

**다음 여정은요?**
이제 여러분은 **'블로그 작성 에이전트'라는 하나의 완성된 프로덕트**를 가지게 되었습니다. 하지만 여기서 끝이 아닙니다.
*   **"이 글 한국어로도 써줘"** -> 멀티링구얼 에이전트 추가
*   **"이미지도 넣어줘"** -> 이미지 생성 에이전트(DALL-E, Imagen) 도구 추가
*   **"워드프레스에 자동 발행해줘"** -> API 연동 에이전트(Function Calling) 추가
*   **"매일 아침 9시에 트렌드 정리해서 슬랙으로 보내줘"** -> 스케줄러(Cloud Scheduler/Cron) 연동

여러분이 방금 터미널에서 `adk web` 치고 브라우저에서 확인한 이 **'기획 -> 조사 -> 작성 -> 포장'** 파이프라인은, 앞으로 만들 모든 복잡한 에이전트 시스템의 **표준 템플릿**이 될 것입니다.
