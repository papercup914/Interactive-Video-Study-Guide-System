## 1. 왜 갑자기 '분리' 이야기부터 할까? - 요리사의 뇌와 손 분리하기

실습 명령어를 치기 전에, 강연자분이 실습 직전에 **"핵심 설계 결정(Key Design Decision)"**이라는 조금 어려운 이야기를 꺼냈습니다. 이게 무슨 소리냐고요? 사실 이 이야기가 **우리가 지금부터 할 실습의 전체 구조를 이해하는 열쇠**입니다.

### 🍳 비유: '뇌'만 있는 천재 요리사 vs '손'만 있는 로봇 팔

*   **기존 방식 (Agent Loop + Tool Execution 결합):**
    *   **상황:** 요리사(에이전트)가 **뇌(판단력)**와 **손(칼질, 불 조절, 재료 손질)**을 **한 몸**에 가지고 있는 경우입니다.
    *   **장점:** 요리사가 "당근 썰어"라고 생각하면 즉시 자기 손으로 썰 수 있으니 빠르고 직관적입니다. (Claude Code처럼 내 컴퓨터 파일 시스템을 직접 만져야 할 땐 이게 편함)
    *   **치명적 단점:**
        1.  **보안 사고 위험:** 요리사가 내 집(파일 시스템, 비밀번호, 신용카드 정보) 구석구석을 자유롭게 드나듭니다. 요리사가 해킹당하거나 실수하면? **내 집 전체가 털리거나 망가집니다.** (Credential/Security 이슈)
        2.  **준비 시간 지연 (Latency):** 손님이 올 때마다(세션이 시작될 때마다) 요리사 전용 주방(컨테이너)을 새로 짓고, 요리사를 불러오고, 도구 세팅을 해야 합니다. "첫 요리 나오는 시간(Time to First Token)"이 끔찍하게 깁니다.

*   **Claude Manage Agents 방식 (Brain과 Hand 분리 - Decoupling):**
    *   **뇌 (Agent Loop / 서버 사이드):** **"레시피 짜고 지휘만 하는 헤드 셰프"**. 안전한 본사(서버)에 앉아서 "이제 당근 썰어", "이제 볶아" 명령만 내립니다. **내 집(로컬 환경) 모릅니다. 내 비밀번호 모릅니다.**
    *   **손 (Environment / 샌드박스):** **"격리된 주방에서 일하는 로봇 팔"**. 헤드 셰프의 명령만 받아서 정해진 격리된 주방(샌드박스)에서만 움직입니다. 내 집 열쇠가 없습니다. 위험한 짓 못 합니다.
    *   **세션 (Session):** **"헤드 셰프와 로봇 팔을 연결해주는 무전기(통신망)"**.

> **💡 개념 돋보기: 왜 '분리(Decoupling)'가 혁신인가?**
>
> 1.  **철통 보안 (Sandboxing & Credential Safety):** 에이전트(뇌)가 내 컴퓨터의 실제 자격 증명(Credentials)이나 파일 시스템에 **절대 직접 접근 못 함**. 로봇 팔(환경)이 대신 일해주고 결과만 줌. 해킹당해도 내 집 열쇠는 안전!
> 2.  **번개 같은 속도 (TTFT 90% 단축):** 매번 주방(컨테이너) 짓고 요리사 불러올 필요 없음. 헤드 셰프(서버 측 에이전트 루프)는 항상 대기 중. 무전기(세션)만 연결하면 **즉시 작업 시작**. P95 지표 기준 **첫 토큰 생성 시간 90% 이상 단축**이라는 기적 같은 성과!
> 3.  **내구성/신뢰성 (Durability/Reliability):** 내 노트북 덮개 닫아도, 브라우저 새로고침해도 서버 측 '뇌'는 살아있음. 내 로컬 환경이 불안정해도 에이전트 작업은 끊기지 않음.

이 설계 철학을 머릿속에 넣고 실습을 시작하면, 우리가 지금 치는 명령어 하나하나가 **"로봇 팔을 내 컴퓨터에 설치하고, 헤드 셰프(서버)와 무전기로 연결하는 과정"**으로 보일 겁니다.

## 2. 실습 재료 준비: GitHub에서 '실습 키트' 복제하기 (Clone)

강연자분이 화면에 띄워준 URL로 가보세요. 그곳이 바로 **'오늘의 실습 재료 창고(GitHub 저장소)'**입니다.

### 🛒 비유: 오픈 마켓에서 '밀키트' 주문해서 내 집 현관 앞에 두기

*   **GitHub 원격 저장소 (Remote Repository):** 거대한 **온라인 식자재 마켓**이자 **밀키트 창고**. "Ship Your First Manage Agent"라는 이름의 완성된 밀키트 박스가 있습니다.
*   **`git clone` 명령어:** **"이 밀키트 박스 하나, 내 집(로컬 컴퓨터) 현관 앞으로 배송해줘!"**라고 주문하는 행위.
*   **로컬 저장소 (Local Repository):** 내 집 현관 앞에 도착한 **실물 밀키트 박스**. 이제 인터넷 안 끊겨도, GitHub 서버 다운돼도 내 박스는 내 손에 있습니다.

### 🖥️ 실전 터미널 명령어 (맥/리눅스/윈도우 공통)

터미널(명령 프롬프트, 파워셸, 아이텀2 등)을 여세요. **내가 작업하고 싶은 폴더(예: `Documents`나 `Projects` 폴더)**로 먼저 이동한 뒤, 아래 명령어를 **복사해서 붙여넣기(Enter)** 하세요.

```bash
# 1. 강연자분이 알려준 URL을 여기에 넣으세요. (예: git clone https://github.com/anthropics/manage-agents-workshop.git)
git clone [여기에_강연자분이_알려준_GitHub_URL_붙여넣기]

# 예시:
# git clone https://github.com/anthropics/claude-manage-agents-workshop.git
```

> **💡 개념 돋보기: `git clone`이 하는 일 상세 보기**
>
> > 1.  원격 서버에서 **폴더 통째로 다운로드** (히스토리, 브랜치, 모든 파일 포함).
> > 2.  내 컴퓨터에 **같은 이름의 폴더 생성**.
> > 3.  `.git`이라는 **숨겨진 관리 폴더**를 만들어 "이 폴더는 Git으로 관리 중이야"라고 표시해둠.
> > 4.  원격 저장소 주소를 `origin`이라는 별명으로 저장해둬서 나중에 `git pull`(업데이트 받기), `git push`(내 변경 올리기) 하기 편하게 세팅 완료.

**성공했다면?** 터미널에 `Receiving objects: 100%... Resolving deltas: 100% done.` 같은 메시지가 뜨고, 탐색기(Finder/윈도우 탐색기)에 방금 클론한 폴더가 생겨있을 겁니다.

## 3. 오늘의 주방으로 입장: `cd` 명령어로 디렉토리 진입하기

박스(폴더)를 현관에 뒀으니, 이제 **박스를 뜯고 요리할 주방(작업 폴더)**으로 들어가야죠.

### 🚶 비유: 대형 쇼핑몰에서 '특정 매장'으로 걸어가기

*   클론한 저장소 폴더 = **거대 쇼핑몰 건물 전체**.
*   `Ship Your First Manage Agent` 폴더 = **그 건물 3층에 있는 '오늘의 요리 교실' 매장**.
*   `cd` (Change Directory) = **"발걸음 옮겨 매장 안으로 들어가기"**.

### 🖥️ 실전 터미널 명령어

```bash
# 1. 먼저 클론한 큰 폴더(쇼핑몰 건물) 안으로 들어갑니다.
# 폴더 이름이 뭐였는지 `ls`(맥/리눅스) 또는 `dir`(윈도우) 쳐서 확인하세요.
cd claude-manage-agents-workshop  # ← 실제 폴더 이름으로 변경하세요!

# 2. 이제 오늘 실습할 'Ship Your First Manage Agent' 폴더(매장)로 들어갑니다.
cd "Ship Your First Manage Agent"
# ※ 폴더 이름에 공백이 있으니 반드시 큰따옴표(" ")로 감싸주세요! 안 그러면 "Ship" 폴더로 가려다 에러 납니다.
```

**확인해보세요:** 터미널 프롬프트 앞부분 경로가 `.../Ship Your First Manage Agent`로 바뀌어 있어야 합니다. `ls` 또는 `dir` 치면 `agent.py`, `app.py`, `requirements.txt`, `README.md` 같은 파일들이 보일 거예요. **여기가 바로 오늘 우리 주방입니다.**

## 4. 요리 도구 세팅: 가상환경 만들고 라이브러리 설치하기

주방에 들어왔으니, 이제 **나만의 깨끗한 도마와 칼(파이썬 가상환경)**을 세팅하고, **레시피에 적힌 재료들(파이썬 패키지/라이브러리)**을 사와야 합니다.

### 🍳 비유: '공용 주방' 쓰지 말고 '내 전용 주방' 빌리기 + 장보기

*   **시스템 파이썬 (Global Python):** 아파트 공용 주방. 누가 이상한 양념(라이브러리 버전 충돌) 쏟아놨는지 모름. 내 요리 망칠 수 있음.
*   **가상환경 (Virtual Environment / `venv`):** **내 방 안에 만든 '개인 전용 미니 주방'**. 여기선 내가 원하는 버전의 파이썬, 원하는 라이브러리만 깔끔하게 쓸 수 있음. **강력 추천! 필수 관문!**
*   **`requirements.txt`:** **"오늘 요리에 필요한 장보기 리스트"**. `pip install -r requirements.txt`는 "이 리스트대로 싹 다 사와서 내 미니 주방 채워놔"라는 뜻.

### 🖥️ 실전 터미널 명령어 (OS별로 다름 - 주의 깊게 따라하세요!)

#### 🍎 Mac / Linux 사용자:
```bash
# 1. 내 미니 주방(가상환경) 짓기. 이름은 'venv'로 통일합시다.
python3 -m venv venv

# 2. 미니 주방 '불 켜기' (활성화). 터미널 앞쪽에 (venv) 뜨면 성공!
source venv/bin/activate

# 3. 장보기 리스트(requirements.txt) 보고 재료들 싹 다 사오기.
pip install -r requirements.txt
```

#### 🪟 Windows 사용자 (명령 프롬프트 cmd 기준):
```cmd
:: 1. 미니 주방 짓기
python -m venv venv

:: 2. 미니 주방 불 켜기 (활성화). 앞쪽에 (venv) 뜨면 성공!
venv\Scripts\activate.bat

:: 3. 장보기
pip install -r requirements.txt
```

#### 💡 Windows PowerShell 사용자라면?
실행 정책 때문에 `activate.ps1`이 안 될 수 있어요. 관리자 권한으로 파워셸 켜고 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` 한번 쳐준 뒤, `venv\Scripts\Activate.ps1` 치세요. 아니면 그냥 `cmd` 창 열어서 위 명령어 쓰시는 게 맘 편합니다.

> **💡 개념 돋보기: `source venv/bin/activate` (또는 `venv\Scripts\activate`)가 하는 일**
>
> > 이 명령어는 **"이제부터 `python` 치면 시스템 파이썬 말고 `venv` 폴더 안의 파이썬 써!"**, **"`pip` 치면 `venv` 안의 `pip` 써!"** 라고 터미널에게 **환경 변수(PATH)를 임시로 바꿔치기** 하는 겁니다. 터미널 창 닫으면 풀리니, **새 터미널 열 때마다 꼭 다시 쳐줘야 함**을 잊지 마세요!

**설치 완료되면?** 쭉쭉 로그 뜨다가 `Successfully installed ...` 메시지들과 함께 프롬프트가 돌아옵니다. 내 미니 주방에 재료 준비 끝!

## 5. 비밀 열쇠(API Key) 넣기: `.env` 파일 설정하기

자, 재료도 다 준비됐는데 **'요리 시작 버튼'을 누를 열쇠**가 없습니다. 바로 **Anthropic API Key**입니다. 강연 초반에 QR 코드로 무료 크레딧 받으셨죠? 그 키를 우리 프로그램만 알 수 있는 **비밀 수첩(`.env` 파일)**에 적어둬야 합니다.

### 🔐 비유: '자동문 열쇠'를 나만 아는 서랍에 넣어두기

*   **API Key:** **"Claude라는 슈퍼 브레인을 쓸 수 있게 해주는 전용 출입증"**. 이걸 코드에 직접 박아두면(GitHub에 올리면) **누구든 내 출입증 복사해 가서 내 돈으로 Claude 씀**. 큰일 남.
*   **`.env` 파일:** **`.gitignore`(깃 무시 목록)에 기본 등록되어 있는 '비밀 금고'**. 깃허브에 절대 안 올라감. 로컬에서만 프로그램(`python-dotenv` 라이브러리)이 읽어감.
*   **`.env.example` (또는 `.m` 파일):** **"이 금고엔 어떤 열쇠를 넣어야 하는지 적힌 설명서"**. 우리는 이걸 복사해서 `.env`라는 진짜 금고를 만들고, 거기에 내 열쇠를 채워 넣을 겁니다.

### 🖥️ 실전 터미널 명령어

```bash
# 1. 설명서(.env.example 또는 .m 파일) 복사해서 진짜 금고(.env) 만들기
# 강연자분 말씀으론 "copy over the environment key into your dot m file" 하셨는데,
# 보통 관례는 .env.example -> .env 복사입니다. README 확인하세요.
# 맥/리눅스:
cp .env.example .env
# 윈도우 (cmd):
copy .env.example .env
# 윈도우 (파워셸):
Copy-Item .env.example .env

# 2. 이제 .env 파일을 열어서 내 API 키 붙여넣기
# 터미널에서 열려면: (맥) open -e .env  / (윈도우) notepad .env
# 아니면 그냥 VS Code나 메모장으로 폴더 열어서 .env 파일 더블클릭하세요.
```

### 📝 `.env` 파일 내용 수정하기

파일 열면 아마 이렇게 되어 있을 겁니다:
```text
ANTHROPIC_API_KEY=your_api_key_here
```
이 `your_api_key_here` 부분을 **지우고, QR 코드로 받은 본인의 실제 API Key(보통 `sk-ant-...`로 시작)를 붙여넣기** 하세요. **따옴표 필요 없습니다.** 저장(Ctrl+S / Cmd+S) 하고 닫으세요.

> **💡 개념 돋보기: 왜 `.env` 파일이 안전한가? (원리)**
>
> > 1.  **`.gitignore` 파일에 `.env`가 적혀 있음** → `git add .` 해도 `.env`는 스테이징 영역에 안 올라감 → `git push` 해도 GitHub에 안 올라감.
> > 2.  **`python-dotenv` 라이브러리**가 프로그램 시작 시 `load_dotenv()` 호출하면 → 현재 폴더 `.env` 파일 읽어서 → `os.environ` (환경 변수) 에 주입해줌.
> > 3.  코드에선 `os.getenv("ANTHROPIC_API_KEY")`로 안전하게 꺼내 씀. **비밀이 코드에 안 적힘!**

## 6. 드디어 요리 시작! `streamlit run app.py` 실행하기

모든 준비 끝났습니다. 이제 **"요리 시작(앱 실행)"** 버튼만 누르면 됩니다.

### 🚀 비유: 주방에 불 다 켜지고, 손님 맞을 준비 완료된 상태에서 "영업 개시!" 외치기

*   **`streamlit`**: 데이터 앱을 웹 페이지로 뚝딱 만들어주는 **마법의 웹 서버 프레임워크**.
*   **`run app.py`**: `app.py`라는 **메인 레시피(진입점)** 대로 웹 서버 띄워줘.
*   **결과**: 터미널에 **로컬 URL(`http://localhost:8501` 등)**이 뜸 → 브라우저에서 그 주소 치면 **우리의 에이전트 UI 화면**이 짠! 하고 나타남.

### 🖥️ 실전 터미널 명령어

```bash
# (venv) 가상환경 켜진 상태에서 꼭 실행하세요!
streamlit run app.py
```

### 👀 실행 후 터미널에서 볼 수 있는 것들 (성공 시)

```text
  You can now view your Streamlit app in your browser.

  Local URL: http://localhost:8501
  Network URL: http://192.168.x.x:8501
```
*   **Local URL**: 내 컴퓨터 브라우저에서 열 주소. **이거 클릭하거나 복사해서 크롬/사파리 주소창에 붙여넣기 하세요!**
*   **Network URL**: 같은 와이파이 쓰는 다른 기기(핸드폰, 태블릿)에서 테스트할 때 쓰는 주소.

브라우저가 자동으로 열리거나, 직접 `http://localhost:8501` 접속하면 **사건 대응(Incident Response) 시뮬레이션 화면**이 나타날 겁니다. 강연자분 말씀대로 **"새벽 3시에 서버 다운됐을 때 깨워지는 엔지니어의 고통을 에이전트가 대신 겪어주는"** 그 화면입니다!
