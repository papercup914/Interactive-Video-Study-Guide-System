# 📖 챕터 3. 기능 추가에 따른 프롬프트 길이 증가 (수백 줄 이상) - 에이전트의 '뇌'가 비대해질 때

---

안녕하세요! 지난 시간에는 에이전트가 **'브레인(두뇌)'**과 **'핸드(손)'**로 나뉘어 동작한다는 아키텍처적 설계를 살펴봤습니다. 오늘은 이 **'브레인'에 해당하는 에이전트 정의(Agent Definition)** 부분에 기능을 하나둘 붙여나가다 보면 필연적으로 마주치게 되는 **'프롬프트 비만(Prompt Obesity)'** 현상에 대해 아주 깊게 파헤쳐 보겠습니다.

영상에서는 강사님이 `agent.py` 파일을 열어서 **"이게 바로 에이전트의 페르소나와 능력을 정의하는 곳이야"**라고 말씀하시며, **모델(Model), MCP 서버, 스킬(Skills)** 같은 요소들을 하나씩 복사해 넣는 모습을 보여주셨죠? 바로 이 **'복사해 넣는 행위' 하나하나가 프롬프트라는 풍선에 바람을 불어넣는 행위**가 됩니다.

## 1. 🍳 비유로 이해하기: "주방장에게 주는 주문서가 책 두께가 되었다고 상상해 보세요"

여러분이 **미슐랭 3스타 레스토랑의 총괄 셰프(Claude 모델)**라고 가정해 봅시다. 여러분은 주방에서 요리만 하면 됩니다. 그런데 지배인(개발자)이 주문서를 갖다 줍니다.

### **초기 버전 (가벼운 프롬프트)**
> **"손님 1번 테이블: 스테이크 미디엄 레어로 하나 구워주세요. 소금, 후추만 뿌려서."**
> *   **상태:** 주문서 한 장. 셰프는 즉시 파악하고 요리 시작. **속도 빠름, 실수 적음.**

### **기능 추가 버전 (비대해진 프롬프트 - 수백 줄)**
> **"손님 1번 테이블: 스테이크 미디엄 레어. **단, 소고기는 호주산 청정우만 사용하고, 굽기 전 30분간 실온 보관 필수. 팬은 주물 팬만 사용, 버터는 프랑스 이즈니 버터 20g, 허브는 타임과 로즈마리만. 굽는 중 온도계로 심부 온도 55도 확인 시 뒤집기. 플레이팅은 흰 접시 왼쪽에 퓌레, 오른쪽에 구운 아스파라거스, 소스는 레드와인 리덕션으로 별도 그릇에 담아 서빙. 알러지 정보: 견과류 없음, 유제품 괜찮음. 와인 페어링은 보르도 2015 빈티지 추천.** ... (이하 200줄 생략) ... **아, 그리고 화장실 가는 길도 알려주고, 계산서 출력할 때 영수증 프린터 드라이버 버전 2.3 이상인지 확인하고..."**
> *   **상태:** 주문서가 **책 한 권(수백 페이지)**.
> *   **문제점:**
>     1.  **읽는 데만 10분 걸림 (지연 시간/Latency 증가 → TTFT 악화)**
>     2.  **중요한 내용(알러지, 굽기 온도)이 뒤로 밀려 셰프가 놓칠 수 있음 (지시 사항 준수율 저하 / Lost in the Middle)**
>     3.  **종이값(토큰 비용) 엄청남.**
>     4.  **주문서 수정하려면 책 전체를 다시 인쇄해야 함 (유지보수 지옥).**

## 2. 🔍 영상 속 코드가 보여주는 '프롬프트 비만'의 현장

영상 00:06:00 부근, 강사님이 **`agent.py` (왼쪽, 미완성)** 와 **`agent_complete.py` (오른쪽, 완성본)** 을 나란히 띄워놓고 **"이 프리미티브(구성 요소)들을 하나씩 복사해 넣으며 에이전트를 구성해 보자"**고 하신 부분, 기억나시나요?

```python
# agent.py (초기 상태 - 빈 껍데기)
agent = Agent(
    name="incident-responder",
    # 여긴 아직 아무것도 없음. 가벼움.
)

# agent_complete.py (완성본 - 수백 줄 짜리 설정 덩어리)
agent = Agent(
    name="incident-responder",
    model="claude-3-5-sonnet-20241022",      # 1. 모델 지정
    instructions="""당신은 시니어 SRE 엔지니어입니다... 
    (여기에 페르소나, 행동 지침, 출력 포맷 규칙 등 
     100줄 이상의 긴 지시사항이 들어감)""",    # 2. 시스템 프롬프트 (Instructions)
    mcp_servers=[                               # 3. MCP 서버들 (외부 도구 연결 창구)
        mcp_server_github,
        mcp_server_datadog,
        mcp_server_k8s,
        mcp_server_pagerduty,
        # ... 각 서버마다 툴 정의가 수십 개씩 딸려옴
    ],
    skills=[                                    # 4. 스킬들 (재사용 가능한 프롬프트 모듈)
        skill_investigate_latency,
        skill_check_recent_deploys,
        skill_analyze_logs,
        skill_create_postmortem,
        # ... 각 스킬마다 내부 프롬프트가 또 수십 줄
    ],
    tools=[                                     # 5. 기본 제공 툴들
        tool_bash,
        tool_read_file,
        tool_write_file,
        ...
    ]
)
```

> **💡 개념 돋보기**
> > **프롬프트 비만(Prompt Obesity)이란?**
> > 에이전트에게 **역할(페르소나), 도구 사용법(Tool Schemas), 작업 절차(Skills), 외부 연동 정보(MCP Servers)** 를 모두 **시스템 프롬프트(System Prompt) 영역에 텍스트로 욱여넣다 보니**, 모델이 실제 사용자 요청(User Query)을 보기 전에 읽어야 할 **'선행 컨텍스트(Prefix Context)'가 수백~수천 줄(수만 토큰)** 으로 불어나는 현상.
> > 
> > **영상 속 키워드 매핑:**
> > *   `instructions` → **페르소나/규칙서** (수십 줄)
> > *   `mcp_servers` → **도구 카탈로그** (서버당 툴 10개 × 5개 서버 = 툴 정의만 50개 분량)
> > *   `skills` → **업무 매뉴얼** (스킬당 프롬프트 50줄 × 10개 = 500줄)
> > *   **합계: 모델이 매 턴마다 읽어야 할 '숙제'가 책 한 권 분량!**

## 3. ⚠️ 왜 이게 치명적인가? (비전공자가 겪을 3가지 고통)

### ① **'첫 토큰까지의 시간(Time To First Token, TTFT)' 폭증** ⏳
영상 00:10:30쯤 강사님이 **"이전에는 에이전트 루프와 툴 실행이 같은 박스에 있어서 컨테이너 띄우는 데 시간이 걸렸는데, 지금은 디커플링해서 TTFT가 90% 이상 줄었다"**고 자랑하셨죠?  
하지만 **프롬프트 자체가 수백 줄이면, 컨테이너 뜨는 시간은 줄었는데 '모델이 프롬프트 읽고 생각 시작하는 시간'이 새로 병목이 됩니다.**

*   **비유:** 주방장(모델) 앞에 주문서(프롬프트) 두께가 1cm에서 10cm가 되었어요. 주방장이 칼 들기 전까지 **주문서 읽는 시간만 10배** 걸립니다. 사용자는 화면만 멍하니 바라보게 되죠.

### ② **'중간 잃기(Lost in the Middle)' 현상** 🧠💨
대형 언어 모델(LLM)은 **긴 문맥의 처음과 끝은 잘 기억하지만, 중간에 묻힌 중요한 지시사항은 잘 놓칩니다.**

*   **시나리오:** `instructions` 맨 앞에 **"절대 프로덕션 DB 삭제 금지!"**라고 써놨는데, `mcp_servers` 툴 정의 200줄, `skills` 300줄 뒤에 사용자 요청이 오면? 모델은 **"아, DB 관련 툴이 있네? 써볼까?"** 하고 삭제 명령을 내릴 수 있습니다. **가장 중요한 안전장치가 중간에 파묻혀 작동 안 함.**

### ③ **비용 폭발 & 컨텍스트 윈도우 압박** 💸📏
*   **입력 토큰 비용:** 매 턴마다 수만 토큰을 시스템 프롬프트로 보냅니다. 대화가 10턴 오가면 **시스템 프롬프트 비용만 10배** 청구.
*   **컨텍스트 한계:** 모델마다 최대 컨텍스트 길이(예: 200k 토큰)가 있습니다. 시스템 프롬프트가 50k면, **실제 대화 기록(로그, 이전 조사 내용, 사용자 피드백) 담을 공간이 150k로 줄어듭니다.** 복잡한 인시던트 대응 중간에 "컨텍스트 초과"로 에러 나면 망함.

## 4. 🛠️ 그러면 어떻게 해결하나? (영상 속 힌트 + 실무 패턴)

영상에서는 **아키텍처 레벨(브레인/핸드 분리)**로 레이턴시 문제를 풀었지만, **프롬프트 길이 문제**는 **소프트웨어 공학 패턴**으로 풀어야 합니다.

### 패턴 1. **모듈화 & 동적 주입 (Dynamic Injection) - "필요할 때만 주문서 챕터 찢어서 주기"**
> **영상 힌트:** 강사님이 `skills` 배열에 `skill_investigate_latency`, `skill_check_recent_deploys` 등을 **배열로 넣어둔 것** 보이시죠? 이건 **'전체 주문서를 다 주는 게 아니라, 필요한 스킬만 골라 꽂는 구조'**로 만들 수 있다는 뜻입니다.

```python
# 나쁜 예: 처음부터 다 때려박음 (Static)
agent = Agent(skills=[skill_A, skill_B, skill_C, ..., skill_Z])

# 좋은 예: 런타임에 상황에 맞게 동적 주입 (Dynamic)
async def on_user_message(session, user_msg):
    if "레이턴시" in user_msg:
        # 지금 필요한 스킬만 붙여서 프롬프트 구성
        agent.skills = [skill_investigate_latency, skill_check_recent_deploys]
    elif "배포" in user_msg:
        agent.skills = [skill_analyze_deploy, skill_rollback]
    # 이렇게 하면 시스템 프롬프트 길이 1/10로 줄어듦!
```

### 패턴 2. **MCP 서버 툴 필터링 (Tool Filtering) - "주방장에게 전용 칼만 쥐여주기"**
`mcp_servers`에 연결된 툴이 100개인데, 현재 작업(인시던트 조사)엔 `datadog_query`, `k8s_get_pods` 2개만 쓴다? **나머지 98개 툴 정의(JSON Schema)는 프롬프트에서 빼버리세요.**

*   **구현:** `mcp_client.list_tools()`로 전체 목록 받은 뒤, 현재 태스크 관련 키워드로 필터링하여 `agent.tools`에만 넣기.

### 패턴 3. **지시사항 계층화 (Hierarchical Instructions) - "헌법/법률/시행령 분리"**
*   **Core System Prompt (헌법, 불변):** "너는 SRE다. 안전 최우선. 삭제 금지." (매우 짧음, 항상 포함)
*   **Task Policy (법률, 교체 가능):** "인시던트 대응 절차 1단계: 로그 확인, 2단계: 배포 확인..." (태스크별로 스왑)
*   **Tool/Schema (시행령, 자동 생성):** 툴 정의는 프롬프트 텍스트가 아닌 **구조화 데이터(Function Calling API)**로 넘기기. (최신 모델은 툴 정의를 별도 필드로 받아 토큰 절약 가능)

### 패턴 4. **RAG(Retrieval-Augmented Generation) 활용 - "도서관에 책 꽂아두고 필요할 때만 찾아보기"**
수백 줄짜리 `runbook`(운영 매뉴얼), `postmortem` 템플릿, `architecture doc`을 **벡터 DB에 임베딩해 저장**해 두고, 에이전트가 **"이 상황 관련 문서 검색해줘"**라고 툴 호출하면 **관련 3~5개 청크만 컨텍스트에 주입**.

> **💡 개념 돋보기**
> > **프롬프트 압축의 핵심 원칙: "Just-in-Time Context"**
> > 
> > > **모든 지식을 프롬프트에 선탑재(Pre-load)하지 말고, 실행 시점(Runtime)에 필요한 지식만 동적 주입(Dynamic Injection)하라.**
> > 
> > 이는 영상에서 강조한 **'브레인(에이전트 루프)은 서버사이드에서 가볍게 돌고, 무거운 컨텍스트/도구는 환경(Environment)/외부 저장소에 위임'**한다는 설계 철학과 정확히 일치합니다.

## 5. 🧪 실습 포인트: 내 코드에서 '프롬프트 다이어트' 해보기

| 체크 항목 | 확인 방법 | 위험 신호 🚨 |
| :--- | :--- | :--- |
| **1. `instructions` 길이** | `len(agent.instructions)` 출력해 보기 | **> 2,000자 (약 500토큰)** 넘으면 분할 필요 |

| **3. `skills` 총 프롬프트 길이** | 각 스킬 `prompt` 필드 길이 합산 | **> 5,000자** 면 RAG 또는 동적 로딩 전환 |
