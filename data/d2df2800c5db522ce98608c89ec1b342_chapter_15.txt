# 🧠 챕터: 캐시 압축, 컨텍스트 불안 등 기초 프리미티브를 Anthropic에 위임하기

> **"우린 '뇌(추론)'만 집중하면 돼요. '손(도구 실행)'과 '작업장(인프라)'은 Anthropic이 알아서 지어줍니다."**

---

안녕하세요! 지난 시간에는 '관리형 에이전트(Claude Managed Agents)'가 왜 필요한지, 그리고 기존 에이전트 프레임워크(LangGraph, CrewAI 등)와 무엇이 다른지 큰 그림을 봤어요. 오늘은 **"대체 Anthropic이 내 대신 무슨 일을 해주는 거지?"**라는 의문을 완벽하게 해소해 드릴게요.

이 챕터의 핵심은 단 한 문장입니다. **에이전트를 프로덕션(실제 서비스) 레벨로 올릴 때 겪는 '골치 아픈 기반 공사(인프라, 상태 관리, 지연 시간, 보안)'를 Anthropic 서버 사이드로 몽땅 위임(Delegate)해버린다는 것.**

이게 왜 혁신인지, 일상 비유로 아주 천천히, 깊게 파헤쳐 볼게요.

## 1. 🏗️ "뇌"와 "손"을 분리한 이유: 주방장과 주방 보조의 이야기

스크립트에서 강연자는 **"이전에는 에이전트 루프(사고 과정)와 도구 실행(행동)이 한 통(컨테이너) 안에 꽉 묶여 있었다"**고 했어요. 이걸 **식당 주방**에 비유해 볼게요.

### 🍳 구식 주방 (기존 에이전트 하네스: LangGraph 등)
*   **헤드 셰프(에이전트 뇌, LLM)**가 레시피를 생각하다가, **"당근 좀 다져와!"**라고 외치면
*   셰프 **본인이 직접** 창고로 뛰어가서 당근을 꺼내오고, 도마를 찾아 칼질을 하고, 다시 돌아와서 요리를 계속함.
*   **문제점:**
    1.  **셰프가 너무 바쁨:** 요리(추론)만 해도 벅찬데 재료 손질(도구 실행)까지 하려니 **생각하는 속도(첫 토큰 지연 시간, TTFT)가 느려짐**.
    2.  **주방(컨테이너) 크기 고정:** 셰프 한 명당 주방 하나(컨테이너 하나)를 통째로 빌려 써야 함. 손님(세션)이 100명 오면 주방 100개를 미리 지어놔야 함 → **비용 낭비, 스케일링 지옥**.
    3.  **보안 구멍:** 셰프가 창고(파일 시스템, 비밀 키) 열쇠를 다 갖고 있음. 셰프가 실수하거나 해킹당하면 **전체 창고 털림**.

### 🍳 신식 주방 (Claude Managed Agents: 뇌-손 분리)
Anthropic은 **"셰프는 레시피만 짜게 하고, 재료 손질은 전문 '주방 보조(Environment/환경)'에게 맡기자!"**고 설계했어요.

| 역할 | 구식 (일체형) | 신식 (분리형 - Managed Agents) |
| :--- | :--- | :--- |
| **뇌 (Agent Loop)** | 주방 안에서 직접 요리 + 재료 손질 | **Anthropic 클라우드 서버 사이드**에서만 돌아감. **순수 추론만 담당.** |
| **손 (Environment/Tools)** | 뇌 안에 포함됨 | **독립된 샌드박스 컨테이너(격리된 작업 공간)**에서 실행됨. |
| **연결** | 함수 호출(로컬) | **API 호출(원격)**로 뇌가 손에 "이거 해줘" 명령만 내림. |

> **💡 개념 돋보기: '뇌-손 분리(Decoupling)'가 주는 3가지 선물**
> 1.  **속도(지연 시간 해결):** 셰프가 주방 오가느라 시간 안 씀. 뇌만 돌아가니 **첫 토큰 생성 시간(TTFT)이 P95 기준 90% 이상 단축**됨 (스크립트 인용). "생각 시작하자마자 바로 대답 나옴".
> 2.  **보안(자격 증명/샌드박싱):** 손(Environment)이 창고 열쇠(자격 증명, 파일 시스템)를 가짐. 뇌(LLM)는 **암호화되지 않은 비밀 키를 볼 수조차 없음**. 해킹당해도 "생각"만 털림, "자산"은 안전.
> 3.  **확장성(서버리스):** 손님(세션) 오면 그제야 '손(컨테이너)' 빌려옴. 뇌는 공용으로 씀. **비용 절감, 무한 스케일링 가능.**

## 2. ☁️ "서버 사이드 에이전트 루프" = 나만의 무한 확장 가능한 '클라우드 뇌'

스크립트에서 **"Claude Managed Agent는 에이전트 루프가 서버 사이드에서 돈다"**고 강조했죠. 이 말이 왜 그렇게 달콤한지, **'내 노트북'**과 비교해 볼게요.

### 💻 내 노트북에서 에이전트 돌릴 때 (로컬/프로토타입)
```text
[내 노트북] 
  └─ Python 프로세스 실행 (에이전트 루프 while True:)
       ├─ LLM API 호출 (생각)
       ├─ 도구 실행 (파일 읽기, 쉘 명령어) -> 내 로컬 환경 오염 위험
       ├─ 상태 저장 (메모리/DB) -> 내가 구현해야 함
       ├─ 에러 처리, 재시도, 타임아웃 -> 내가 다 코딩해야 함
       └─ 내 랩탑 덮으면? -> **프로세스 죽음 = 에이전트 죽음** 💀
```
*   **고민거리:** "이걸 어떻게 24시간 띄우지?", "동시 접속 100명 처리하려면 쿠버네티스 띄워야 하나?", "메모리 터지면 어떡하지?", "컨텍스트 윈도우 꽉 차면 요약 로직 짜야 하나?"

### ☁️ Claude Managed Agents 쓸 때 (서버 사이드 루프)
```text
[내 코드 (가벼운 클라이언트)] 
  └─ Anthropic API 호출: "세션 시작해줘, 에이전트 이거 해줘"
        ↓ (HTTP 요청 한 번)
[Anthropic 클라우드 인프라 - 관리의 신(神)들이 상주]
  ├─ 🧠 **에이전트 루프 무한 실행** (내가 잠든 사이에도, 랩탑 덮어도 돌아감)
  ├─ 💾 **상태/컨텍스트/메모리 자동 영속화** (Durability 보장)
  ├─ 📦 **컨텍스트 윈도우 관리(압축, 요약, 프루닝) 자동 수행** <- 챕터 제목의 '캐시 압축, 컨텍스트 불안' 해결!
  ├─ ⚖️ **자동 스케일링, 로드 밸런싱, 장애 복구** (Reliability 보장)
  ├─ 🔒 **샌드박스 격리된 환경에서 도구 실행** (Security 보장)
  └─ 📡 **이벤트 스트리밍(SSE/WebSocket)으로 결과만 실시간 전송**
```
*   **내 코드:** 그냥 `stream_events()`로 결과 받아서 화면만 그리면 끝.

> **💡 개념 돋보기: '컨텍스트 불안(Context Anxiety)'과 '캐시 압축'을 위임받다**
> 긴 대화나 복잡한 작업을 하다 보면 LLM의 **컨텍스트 창(Context Window)이 꽉 차서** "이거 이상 못 넣어!" 에러 나거나, 앞 내용 까먹어서 헛소리(할루시네이션) 하는 게 **'컨텍스트 불안'**이에요.
> 기존엔 개발자가 `summarize_history()`, `trim_messages()`, `vector_store_search()` 같은 **'캐시 압축/관리 로직'을 직접 짜야 했음.**
> **Managed Agents에선 이 '기초 프리미티브(기본 부품)'를 Anthropic이 서버 단에서 알아서 최적화해줌.** 우린 "그냥 무한히 대화해줘"라고만 말하면 됨.

## 3. 🧩 3대 핵심 프리미티브: Agent(Primitive) - 뇌, 손, 그리고 연결고리

스크립트에서 코드 뜯어보며 설명한 **Agent(에이전트), Environment(환경), Session(세션)** 이 세 가지가 바로 Anthropic이 우리에게 추상화해준 **'레고 블록 3개'**예요. 이 3개만 알면 프로덕션 에이전트 완성.

### ① Agent (에이전트) = **"페르소나 & 두뇌 스펙 정의서"**
> 스크립트: *"Agent is the one that defines the persona and capabilities... model, MCP servers, skills..."*

*   **비유:** **채용 공고문 + 직원 매뉴얼**
*   **구성 요소:**
    *   `model`: 어떤 뇌 쓸지 (claude-3-5-sonnet 등)
    *   `instructions`: "넌 사고 대응 전문가야. 로그 보고 원인 찾아라" (시스템 프롬프트)
    *   `skills` / `mcp_servers`: "이 툴들 쓸 수 있어" (권한 부여)
*   **핵심:** **상태 없음(Stateless).** 그냥 "이런 직원 뽑을래"라는 **설계도**일 뿐. 실행 중인 인스턴스가 아님.

### ② Environment (환경) = **"격리된 전용 작업실 (손 + 작업장)"**
> 스크립트: *"You can think of this as the hands of the agent... a space and a container to actually take action on your behalf."*

*   **비유:** **보안 검색대 통과한 '개인 전용 클린룸'**
*   **특징:**
    *   **샌드박스(Sandboxed):** 내 로컬 PC, 프로덕션 DB와 **완전 격리**. 여기서 `rm -rf /` 해도 내 컴퓨터 안전.
    *   **자격 증명 주입:** 이 방에만 API 키, DB 비밀번호, SSH 키 넣어줌. 뇌(에이전트)는 이 키를 **모름(암호화됨)**. 그냥 "그 방에 가서 디플로이 해"라고만 시킴.
    *   **상태 유지 가능:** 파일 시스템, 설치된 라이브러리, 실행 중인 프로세스 등이 세션 동안 유지됨.
*   **종류:** 일회용(요청 시 생성 후 삭제), 영구적(항상 켜둔 개발 서버 스타일) 선택 가능.

### ③ Session (세션) = **"뇌와 손을 잇는 '근무 계약' + '업무 일지'"**
> 스크립트: *"Sessions are the way to tie together agents and environments... stream events back to your user."*

*   **비유:** **"김철수(에이전트) 씨가 3번 방(환경)에서 2024-05-20 14:00~15:00까지 일함"이라는 근무 기록표**
*   **하는 일:**
    1.  **매칭:** `Agent A` + `Environment B` = `Session 1` 생성.
    2.  **실행 컨텍스트 제공:** 이 세션 안에서만 대화 기록, 도구 호출 히스토리, 파일 상태가 공유됨.
    3.  **이벤트 스트리밍:** "생각 중...", "도구 호출함", "결과 받음", "최종 답변" → **실시간 UI 업데이트 가능**.
    4.  **생명주기 관리:** `create` → `stream` → `close` (끝나면 방 반납, 뇌는 대기).

> **💡 개념 돋보기: 왜 '세션'이 별도 객체인가? (핵심 설계 포인트)**
> *   **한 에이전트(뇌) = 여러 세션 동시 가능:** "사고 대응 전문가" 뇌 하나 두고, 사건 A 처리용 세션, 사건 B 처리용 세션 동시에 돌림. 뇌는 공유, 손(환경/상태)은 격리.
> *   **한 환경(손) = 여러 에이전트 순차 사용 가능:** "프로덕션 서버 환경" 하나 두고, 아침엔 "배포 에이전트"가 쓰고, 밤엔 "모니터링 에이전트"가 씀.
> *   **이게 '디커플링(Decoupling)'의 완성.** 뇌와 손을 **런타임에 조립(Composition)**함. 하드코딩된 결합 아님.

## 4. 🛠️ 실습 코드(`agent.py`)로 보는 '위임의 마법'

스크립트에서 `agent.py`(미완성) -> `agent_complete.py`(완성) 복사하며 설명하죠? 이 과정이 바로 **"우린 설계도만 그리면 된다"**는 걸 보여주는 의식이에요.

### 우리가 쓰는 코드 (클라이언트 사이드) - 엄청 가벼움
```python
# agent.py 에서 우리가 채워넣을 핵심 3줄 (나머진 Anthropic SDK가 알아서)

# 1. 뇌 정의 (Agent Primitive)
agent = anthropic.agents.create(
    name="incident-responder",
    model="claude-3-5-sonnet-20241022",
    instructions="당신은 3시에도 깨어있는 온콜 엔지니어입니다...",
    tools=[...], # MCP 서버나 스킬 연결
)

# 2. 손 정의 (Environment Primitive) 
# 예: "도커 컨테이너 하나 띄워줘, 파이썬 있고 kubectl 깔려있게"
env = anthropic.environments.create(
    name="prod-k8s-env",
    docker_image="my-company/oncall-tools:latest",
    secrets=["KUBECONFIG", "PAGERDUTY_KEY"] # 뇌는 모름, 환경만 앎
)

# 3. 계약 체결 & 실행 (Session Primitive)
session = anthropic.sessions.create(
    agent_id=agent.id,
    environment_id=env.id,
)

# 4. 그냥 지켜보기만 하면 됨 (이벤트 스트리밍)
for event in anthropic.sessions.stream(session.id, input="서버 다운됨 ㅠㅠ"):
    print(event) # UI에 뿌리면 끝
```

### 우리가 **안 짜도 되는 코드** (Anthropic 서버 사이드에서 자동 실행 중)
> 이거 다 직접 짜려면 최소 수개월, 팀 단위 프로젝트예요.

```text
[Anthropic Managed Infrastructure 내부에서 돌아가는 것들]

CLASS AgentLoopManager:
    WHILE session.active:
        # 1. 컨텍스트 윈도우 체크 & 자동 압축 (캐시 관리)
        IF context_tokens > 90%_limit:
            auto_summarize_old_turns()      # <- '컨텍스트 불안' 해결
            apply_prompt_caching()          # <- '캐시 압축' 해결
        
        # 2. LLM 추론 호출 (뇌 작동)
        thought = call_llm(agent.instructions + session.history)
        
        # 3. 도구 호출 파싱 -> 환경으로 원격 전송 (RPC)
        IF thought.has_tool_calls:
            # 보안: 자격 증명 없이 도구 이름/인자만 전송
            result = environment_rpc.execute(tool_name, args) 
            
            # 4. 결과 수신 -> 히스토리 추가 -> 루프 계속
            session.history.append(result)
        
        # 5. 내구성: 매 턴마다 DB에 상태 자동 저장 (체크포인트)
        #    -> 랩탑 닫아도, 네트워크 끊겨도, 서버 터져도 복구 가능
        session.persist_state()             
        
        # 6. 이벤트 실시간 스트리밍 푸시 (SSE)
        yield Event(thought, tool_call, result)
```

## 5. 🎯 시나리오: "새벽 3시, 내 대신 일해줘" (Incident Response)

스크립트의 실습 시나리오가 이거죠? **"온콜(On-call) 엔지니어의 고통"**.

### 기존 방식 (내가 직접)
1.  📞 페이저 울림 (새벽 3시)
2.  😵 눈 비비며 노트북 오픈 -> VPN -> 쿠버네티스 대시보드 -> 로그 클러스터 -> 깃허브 액션 -> 데이터독...
3.  🤯 수십 개 탭 전환하며 "이 배포 때문인가? 아님 트래픽 폭주? 디비 락 걸렸나?"
4.  ⏱️ **MTTR(평균 복구 시간) 30분~수시간** (사람이 찾기 힘드니까)

### Managed Agent 방식 (위임)
1.  📞 페이저 울림 (또는 Agent가 미리 감지하고 알림)
2.  🛌 **나는 계속 잠듦 (또는 커피 마시며 감독만 함)**
3.  🤖 Agent Session 시작:
    *   **뇌(서버):** "알람 내용 보니 `payment-service` 500 에러네. 최근 배포 내역 뽑아주고, 로그 1시간 치 줘, 디비 커넥션 풀 상태 봐줘." (병렬 도구 호출 계획)
    *   **손(환경):** `kubectl logs`, `gh run list`, `psql "show locks"` **동시 실행** (격리된 방에서 안전하게)
    *   **뇌(서버):** 결과 종합 -> "원인: 3분 전 배포된 커밋 `abc123`에서 DB 커넥션 누수 발생. 롤백 실행함. 복구 확인됨."
    *   **손(환경):** `kubectl rollout undo` 실행 -> 헬스체크 통과 확인.
4.  📝 **자동으로 인시던트 리포트(포스트모텀 초안) 작성해서 슬랙/노션에 올려줌.**
5.  ☕ **내가 일어났을 땐 이미 해결되고, 보고서만 읽으면 됨.**

> **이게 가능한 이유:** 뇌(추론)는 Anthropic 클라우드에서 **무한 컨텍스트, 무중단, 고가용성**으로 돌고, 손(실행)은 내 프로덕션 환경 **바로 옆(또는 내부 네트워크)** 격리된 컨테이너에서 **내 권한으로** 돌기 때문. **난 '설계도(Agent 정의)'만 잘 그려놓으면 됨.**

| **"내 랩탑 덮으면 에이전트 멈춤."** | **"세션은 클라우드에서 영속. 랩탑 덮어도, 재부팅해도, 여행 가도 계속 일함."** |

자, 이제 **"왜 Anthropic에 위임하는가?(Why)"**와 **"무엇을 위임하는가(What: 뇌/손/계약, 인프라/상태/보안/지연시간)"**는 완벽하게 이해하셨어요.

다음 챕터(실습 파트)에서는 **"어떻게 위임하는가(How)"**를 실제로 `agent.py` 파일에 코드로 박아 넣으며 체험할 거예요.
*   `anthropic.agents.create()`로 **뇌(페르소나)** 심기
*   `anthropic.environments.create()`로 **손(샌드박스)** 만들기
*   `anthropic.sessions.create()` + `stream()`로 **일 시키고 실시간 감시하기**

이 세 줄(정도)의 코드가 **수개월 치 인프라/백엔드 코드**를 대체하는 마법을 직접 보게 될 겁니다. 기대하셔도 좋아요! 🧙‍♂️✨
