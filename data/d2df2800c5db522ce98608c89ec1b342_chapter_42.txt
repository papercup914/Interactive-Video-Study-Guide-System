## 1. 🧠 설계 철학: "머리(두뇌)와 손(도구)은 분리해야 안전하다"

영상 초반, 강연자분은 **Claude Managed Agents(이하 CMA)**의 핵심 설계 결정 하나가 **"에이전트 루프(생각하는 머리)"와 "도구 실행(일하는 손)을 분리했다(Decoupling)"**는 점을 강조합니다. 이게 왜 이리 중요할까요?

### 🍳 비유: "요리사(에이전트)와 주방(실행 환경)의 분리"

상상해 보세요. **아주 똑똑한 천재 요리사(에이전트/뇌)**가 있습니다. 이 요리사에게 **"냉장고 가서 재료 꺼내와", "칼로 썰어", "불 조절해"**라고 명령만 내리면 척척 해냅니다.

*   **구식 방식 (Coupled - 머리와 손이 붙박이):**
    요리사 방 안에 **주방(도구, 파일시스템, DB, 비밀번호)**을 통째로 넣어둔 격입니다. 요리사가 생각이 나서 칼을 쓰려면 자기 방 안에 있는 칼을 쓰면 됩니다. 편하죠? **하지만** 요리사가 실수로(또는 해킹당해) "냉장고 다 비워", "가스밸브 열어놔" 같은 위험한 명령을 내려도 막을 길이 없습니다. 게다가 **요리사 방마다 주방을 다 차려놔야 하니** 방 만드는 데 시간도 오래 걸리고(레이턴시/지연 시간 증가), 공간도 엄청 낭비됩니다.

*   **CMA 방식 (Decoupled - 머리와 손 분리):**
    요리사(뇌)는 **깨끗한 사무실(서버 사이드 에이전트 루프)**에만 앉아서 레시피만 생각합니다. **"이제 칼 필요해", "이제 냉장고 열어야 해"**라고 **주문서(명령/Tool Call)**만 바깥으로 던집니다.
    별도의 **독립된 주방(실행 컨테이너/Environment)**이 주문서를 받아 **실제로 칼질을 하고 냉장고를 엽니다.**
    
    **이게 왜 대박이냐면요:**
    1.  **보안 (Credential/Sandboxing):** 요리사 사무실에는 **칼(도구/비밀번호)이 전혀 없습니다.** 주문서만 던질 뿐이죠. 진짜 칼과 비밀 재료(자격 증명)는 안전한 주방(샌드박스)에만 있습니다. 요리사가 미쳐도, 해킹당해도 사무실엔 훔칠 게 없어요!
    2.  **속도 (TTFT - Time To First Token):** 요리사 방마다 주방 짓느라 시간 끌 필요 없습니다. 요리사(뇌)는 가볍게 띄워두고, 주방(손)만 필요할 때 딱 띄우면 되니까 **첫 응답 속도가 90% 이상 빨라졌대요(P95 기준).** 이건 마치 "식당 열기 전에 주방 다 짓고 기다리는 게 아니라, 주문 들어오면 팝업 주방이 바로 짜잔 나타나는 격"이죠.
    3.  **신뢰성/관리:** 주방에 불나면(컨테이너 에러) 요리사(뇌)는 멀쩡히 앉아서 "아, 주방 좀 갈아줘"라고만 하면 됩니다. 요리사까지 재부팅할 필요 없어요.

> **💡 개념 돋보기: 디커플링(Decoupling) & 샌드박싱(Sandboxing)**
> *   **디커플링(Decoupling):** 서로 꽉 붙어 의존하던 것들을 **'느슨하게 연결'**시키는 것. 여기서는 **'생각하는 로직(에이전트 루프)'**과 **'실제 행동(툴 실행/컨테이너)'**을 분리했습니다. 마치 **'리모컨(뇌)'과 'TV 본체(손)'**을 분리한 것과 같습니다. 리모컨이 고장 나도 TV는 괜찮고, TV가 바뀌어도 리모컨은 그대로 쓸 수 있죠.
> *   **샌드박싱(Sandboxing):** 아이들이 모래놀이터(샌드박스)에서 노는 것처럼, **프로그램이 마음껏 뛰놀되(실행되되) 바깥(시스템 핵심, 비밀번호, 다른 파일)엔 절대 영향 못 미치게 격리된 공간**을 만드는 보안 기술입니다. CMA에서는 '실행 컨테이너'가 바로 이 모래놀이터 역할을 합니다.

### Step 3. 파이썬 가상환경 만들기 & 활성화 (가장 중요! 🌟)

> **강연자 말:** *"Python and the source... command there for Windows as well."*

**비유:** **'나만의 깨끗한 개인 주방(가상환경) 만들기'**입니다. 내 컴퓨터 전역(글로벌) 주방엔 온갖 재료(라이브러리)가 뒤섞여 있어 사고 나기 쉽습니다. 이 프로젝트 전용으로 **격리된 깨끗한 주방**을 하나 만들고, **그 주방으로 들어가는 문(활성화)**을 여는 과정입니다.

#### 🪟 Windows (PowerShell / CMD) 사용자
```powershell
# 1. 가상환경 생성 (이름은 .venv 로 통일 추천)
python -m venv .venv

# 2. 가상환경 활성화 (들어가기)
.venv\Scripts\activate
# 성공하면 터미널 앞줄에 (.venv) 라고 뜹니다!
```

#### 🍎 Mac / 🐧 Linux (Terminal / zsh / bash) 사용자
```bash
# 1. 가상환경 생성
python3 -m venv .venv

# 2. 가상환경 활성화
source .venv/bin/activate
# 성공하면 터미널 앞줄에 (.venv) 라고 뜹니다!
```

> **💡 개념 돋보기: 왜 `venv`(가상환경)를 써야 할까?**
> 파이썬 패키지(라이브러리)는 버전 충돌이 잦습니다. 프로젝트 A는 `requests 2.28`이 필요하고, 프로젝트 B는 `requests 2.31`이 필요할 수 있죠. 전역에 하나만 깔리면 둘 중 하나는 망가집니다. **가상환경은 프로젝트마다 독립된 `site-packages`(라이브러리 보관함) 폴더를 만들어 주는 '마법의 격리 주머니'입니다.** 활성화(`activate`)하면 `pip install`이 이 주머니로 가고, `python` 실행 시 이 주머니의 라이브러리를 봅니다. **항상 습관처럼 켜두세요!**

### Step 5. 환경 변수 설정 (비밀 열쇠 넣기 🔑)

> **강연자 말:** *"Copy over the environment key into your dot m file... put in the Anthropic API key..."*

**비유:** **'비서 출입증(API Key)을 보안 금고(.env 파일)에 넣어주기'**입니다. 우리 비서(Claude)가 일하려면 Anthropic 서버에 "나야, 나"라고 인증할 열쇠가 필요합니다. 이 열쇠를 코드에 직접 적으면 **깃허브에 올렸을 때 털립니다(대참사).** 그래서 **`.env`라는 비밀 파일에만 담아두고, 프로그램은 이 파일을 읽어 열쇠를 꺼내 씁니다.**

#### 1) 샘플 파일 복사/생성
보통 `.env.example` 또는 `.env.template` 파일이 있습니다. 이를 복사해 `.env`를 만듭니다.

```bash
# Mac/Linux
cp .env.example .env

# Windows (PowerShell)
Copy-Item .env.example .env
# Windows (CMD)
copy .env.example .env
```
*   만약 샘플 파일이 없다면 직접 만드세요: `touch .env` (Win: `type nul > .env`)

#### 2) `.env` 파일 열어서 키 입력하기
이제 **텍스트 에디터(VS Code, 메모장, vim 등)**로 `.env` 파일을 여세요. 내용은 대충 이렇게 생겼을 겁니다.

```text
# .env 파일 내용 예시
ANTHROPIC_API_KEY="여기에_발급받은_키_붙여넣기"
# 다른 설정들도 있을 수 있어요 (MODEL_NAME 등)
```

*   **강연장에서 QR 코드로 받은 Anthropic API Key**를 `" "` 안에 **따옴표 포함해서** 붙여넣기 하세요. (`sk-ant-...`로 시작하는 긴 문자열)
*   **저장(Ctrl+S / Cmd+S) 필수!**

> **💡 개념 돋보기: `.env` 파일과 `python-dotenv` 라이브러리**
> 파이썬 코드에서 `os.environ.get("ANTHROPIC_API_KEY")`라고 치면 운영체제 환경변수를 보는데, 매번 터미널에 `export KEY=...` 치기 귀찮죠. **`python-dotenv` 라이브러리(요구사항에 포함돼 있음)**가 프로젝트 루트의 `.env` 파일을 자동으로 읽어서 `os.environ`에 주입해 줍니다. 덕분에 코드엔 `os.getenv("KEY")`만 쓰면 되고, **비밀키는 코드 밖(.env)에 안전하게 격리**됩니다. **절대 `.env`를 Git에 올리지 마세요!** (`.gitignore`에 기본 등록돼 있어야 함)

## 3. 🧩 코드 구조 엿보기: `agent.py` vs `agent_complete.py`

강연자분이 **"왼쪽엔 빈 껍데기(`agent.py`), 오른쪽엔 정답(`agent_complete.py`)을 두고 하나씩 복사하며 배워보자"**고 하셨죠? 이 구조가 바로 **'에이전트 구성의 3대 핵심 프리미티브(Primitive, 기본 구성 요소)'**를 시각적으로 보여줍니다.

나중에 코드 채워 넣을 때 헤매지 않게, **각 파일이 어떤 '역할'을 하는 부품인지** 미리 개념만 잡아두고 가세요.

### ① `Agent` (에이전트) = **"두뇌 + 이력서 + 도구 가방"**
*   **정의:** `agent = Agent(...)` 이렇게 만듭니다.
*   **역할:** **"누구냐?(Persona), 뭘 쓸 수 있냐?(Capabilities), 어떻게 생각하냐?(Model/Loop)"**를 정의합니다.
*   **구성 요소:**
    *   `model`: 어떤 LLM 쓸까? (예: `claude-3-5-sonnet`)
    *   `mcp_servers`: **MCP(Model Context Protocol) 서버들**. 외부 도구(슬랙, 깃허브, DB 등)와 표준어로 대화하게 해주는 **'통역사/어댑터'** 역할.
    *   `skills`: 에이전트가 가진 **특수 기술(함수/프롬프트 템플릿)**. "인시던트 분석 스킬", "로그 요약 스킬" 등.
*   **비유:** **'비서 채용 공고 + 고용 계약서'**. "당신은 OO모델 기반 비서야, 슬랙이랑 깃허브 쓸 줄 알고( MCP), 인시던트 대응 스킬 가졌어(Skills)"라고 정의하는 것.

### ② `Environment` (환경) = **"손(실행 컨테이너) + 작업대(파일시스템/네트워크)"**
*   **정의:** `env = Environment(...)` 또는 `DockerEnvironment(...)` 등.
*   **역할:** 에이전트가 **"실제로 명령 내린 걸 수행하는 물리/논리적 공간"**. 앞서 배운 **'분리된 주방(샌드박스)'**이 바로 이겁니다.
*   **핵심:** **에이전트 루프(두뇌)는 서버 사이드(CMA 관리 인프라)에서 돌고, 이 Environment(손)만 내 로컬 도커나 원격에 띄워서 연결**합니다.
*   **비유:** **'완비된 주방 렌탈 계약서'**. "칼, 도마, 가스레인지(툴/바이너리), 냉장고(파일시스템), 외부 통신망(네트워크) 다 갖춘 주방이야. 비서(에이전트)가 주문서 던지면 여기서 요리해"라고 정의하는 것.

### ③ `Session` (세션) = **"두뇌와 손을 잇는 다리(실행 단위)"**
*   **정의:** `session = Session(agent=my_agent, environment=my_env)`
*   **역할:** **"이 비서(Agent)가 이 주방(Environment)에서 일하게 묶어주고, 대화 기록/상태/이벤트 스트림을 관리하는 단위"**.
*   **비유:** **'오늘 하루 근무 배정표'**. "김비서(Agent)가 1번 주방(Environment)에서 오전 9시부터 일함. 주문 들어오면 김비서한테 전달하고, 김비서가 주문서 던지면 1번 주방으로 보내고, 결과물은 손님(유저)한테 서빙함."

> **💡 개념 돋보기: 서버 사이드 에이전트 루프 (Server-side Agent Loop)**
> 강연자분이 *"Claude Managed Agent has the agent loop run server side"*라고 했죠?
> 기존 방식(예: 로컬에서 `while True: llm.call()` 돌리는 것)은 **내 노트북이 두뇌 역할**을 했습니다. 내 노트북 켜져 있어야 하고, 배터리 닳고, 네트워크 끊기면 끝장이죠.
> **CMA 방식:** **'생각하는 루프(while 문, 상태 관리, 도구 호출 파싱, 재시도 로직...)'를 Anthropic 관리 클라우드 서버에서 돌려줍니다.** 내 로컬(`app.py`)은 그냥 **"세션 만들어줘", "메시지 보내줘", "이벤트 받아줘"** 같은 **가벼운 API 호출만** 하면 됩니다. 그래서 **내 로컬 환경이 가벼워지고, 확장성/신뢰성이 보장**됩니다. **내 노트북은 '리모컨'만 쥐고 있는 셈**이죠.
