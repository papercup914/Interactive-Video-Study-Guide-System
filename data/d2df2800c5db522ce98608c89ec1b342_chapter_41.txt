# 챕터 3. 에이전트 정의: 모델, MCP 서버, 스킬 - 우리 에이전트의 '두뇌'와 '성격' 설계하기

자, 드디어 우리가 만들 에이전트의 **'설계도(Blueprint)'**를 그리는 시간입니다. 앞선 챕터에서 에이전트가 '자율적으로 일하는 비서'라는 큰 그림을 보았다면, 이제는 **"이 비서가 어떤 머리를 가졌고, 어떤 도구를 쓰며, 어떤 말투로 일할 것인가?"**를 아주 구체적으로 정해주는 단계예요.

영상에서는 이 과정을 **`agent.py`**라는 파일을 채워나가는 실습으로 보여주는데, 코드 한 줄 한 줄이 사실은 우리 에이전트의 **DNA**를 심어주는 아주 중요한 의식과 같습니다. 자, 그러면 이 '두뇌 설계도'의 핵심 3요소인 **모델(Model), MCP 서버(MCP Server), 스킬(Skill)**을 일상적인 비유로 하나씩 아주 느긋하게 뜯어보겠습니다.

---

## 1. 모델(Model): 에이전트의 '뇌(Brain)'이자 '성격(Persona)'

가장 첫 번째로 정해야 할 것은 **"누가 생각을 할 것인가?"**입니다. 영상에서는 `model="claude-3-5-sonnet-latest"`라고 적혀 있었죠. 이게 바로 우리 에이전트의 **두뇌**를 뭘로 쓸지 정하는 스위치입니다.

### 🍳 개념 돋보기: 모델 = "주방장(Head Chef)의 경력과 스타일"
> **비유:** 상상해보세요. 여러분이 레스토랑을 열었는데, 주방장을 뽑아야 합니다.
> - **Claude 3.5 Sonnet (최신 버전):** 미슐랭 3스타 경력의 **베테랑 셰프**입니다. 복잡한 코스 요리(복잡한 추론, 코딩, 긴 문맥 이해)도 척척 해내고, 손님(사용자)의 모호한 주문("입맛 돋우는 거 좀 줘")도 의도를 정확히 파악해 멋진 요리로 내놓습니다. 단, 월급(비용)이 좀 비쌉니다.
> - **Haiku (경량 모델):** 일 잘하는 **주니어 셰프**입니다. 정해진 레시피(단순 작업, 요약, 분류)대로 빠르게 뚝딱 만듭니다. 월급이 싸고 손도 빠르지만, 창의적인 신메뉴 개발이나 예외 상황 대처는 좀 버거워할 수 있습니다.
> - **GPT-4o, Gemini 등 타사 모델:** **경쟁 식당의 스타 셰프**를 스카우트해 오는 것과 같습니다. 각자 특기 요리(강점 분야)가 다릅니다.

**코드에서의 의미:**
```python
# agent.py 안의 설정
model = "claude-3-5-sonnet-latest"
```
이 한 줄이 **"우리 에이전트는 미슐랭 3스타 셰프 수준의 사고력을 가진다"**고 선언하는 겁니다. 만약 비용을 아끼고 싶다면 `"claude-3-haiku-latest"`로 바꾸면 되지만, 이번 실습처럼 '인시던트 대응(사고 수습)'같이 복잡한 추론이 필요할 땐 무조건 좋은 머리를 써야 합니다.

> **💡 튜터의 팁:** "모델을 고른다"는 건 단순히 AI 버전을 고르는 게 아닙니다. **"우리 에이전트의 IQ와 EQ, 그리고 월급(토큰 비용)을 동시에 결정한다"**는 뜻이에요. 프로덕션 레벨에서는 이 모델 선택이 서비스의 품질과 비용을 가르는 가장 중요한 레버(Lever)가 됩니다.

---

## 2. MCP 서버(MCP Server): 에이전트의 '전문 도구 가방(Tool Belt)'

모델이 아무리 똑똑해도 **'맨손'**으로는 아무것도 못 합니다. 영상에서 강연자는 **"MCP 서버를 추가한다"**고 했죠. MCP(Model Context Protocol)는 요즘 AI 업계의 **'만능 어댑터(Universal Adapter)'** 표준입니다.

### 🔧 개념 돋보기: MCP 서버 = "주방에 들여놓는 '전문 장비실' 또는 '외주 전문가 네트워크'"
> **비유:** 우리 셰프(모델)가 요리만 잘하면 끝일까요? 아니요.
> - **GitHub MCP 서버:** **"깃허브 전문 비서팀"**을 고용한 겁니다. 셰프가 "이 레포지토리 최신 커밋 좀 봐줘"라고 말하면, 비서팀이 즉시 깃허브 API를 호출해서 결과를 예쁘게 정리해 셰프 식탁 위에 올려줍니다. 셰프는 복잡한 API 문서 볼 필요 없이 "가져와" 한 마디면 끝.
> - **Filesystem MCP 서버:** **"자료실 관리인"**입니다. 셰프가 "저장소 3번 선반에 있는 레시피 좀 찾아줘"라고 하면 바로 찾아옵니다.
> - **Slack/Notion/Jira MCP 서버:** **"메신저 담당 비서", "기록 담당 비서", "일정 담당 비서"**를 각각 둔 셈입니다.

**코드에서의 의미:**
```python
# agent.py 안의 mcp_servers 설정 예시
mcp_servers = [
    {"name": "github", "config": {"token": "..."}},  # 깃허브 비서 고용
    {"name": "filesystem", "config": {"path": "/workspace"}}, # 자료실 관리인 고용
]
```
이렇게 `mcp_servers` 리스트에 이름을 적어넣는 순간, **우리 에이전트는 "나 깃허브 쓸 줄 알아", "나 파일 읽을 줄 알아"**라고 당당히 말할 수 있게 됩니다. 모델이 "아, 이 상황엔 깃허브 비서 불러야지"라고 판단하면, 시스템이 자동으로 해당 MCP 서버를 호출해 결과를 가져다주는 거죠.

> **💡 튜터의 팁:** MCP가 왜 대단하냐고요? 예전엔 개발자가 **"깃허브 API 연동 코드 짜고, 에러 처리하고, 토큰 관리하고..."** 이걸 다 직접 짜야 했습니다. 이제 MCP 서버 주소만 딱 적으면 **'표준화된 인터페이스'**로 바로 연결돼요. **"도구 추가 = 설정 한 줄"** 시대가 열린 겁니다. 이걸 '플러그 앤 플레이(Plug & Play)'라고 부르죠.

## 3. 스킬(Skill): 에이전트의 '전용 레시피북(Playbook)' 또는 '업무 매뉴얼'

자, 좋은 셰프(모델)와 최신 장비(MCP 서버)가 준비됐습니다. 그런데 **"우리 식당만의 시그니처 요리(특화된 업무 프로세스)"**를 어떻게 가르칠까요? 그게 바로 **스킬(Skill)**입니다.

영상에서는 `skills = ["incident-response"]` 같은 식으로 추가하던데, 이건 **"이 상황을 만나면 이 순서대로 행동해라"**라고 적힌 **상세 매뉴얼**을 쥐여주는 것과 같습니다.

### 📋 개념 돋보기: 스킬 = "신입 사원에게 주는 '업무 인수인계 문서' + '체크리스트'"
> **비유:** 경력 좋은 셰프(모델)라도 **우리 식당만의 '비법 소스 레시피'**는 모릅니다. 그래서 주방 벽에 붙여두는 **'매뉴얼 북'**
> - **일반적인 지식 (모델 내장):** "소고기는 중불에 구워야 한다", "파이썬 문법은 이러하다" -> **모델이 이미 알고 있음.**
> - **우리만의 노하우 (스킬):** "우리 식당 스테이크는 **반드시 1분 30초씩 뒤집고, 마지막에 버터 바르기**" / "인시던트 나면 **1) 슬랙 알림 채널 확인 -> 2) 데이터독 대시보드 스크린샷 -> 3) 온콜 엔지니어 호출 -> 4) 사후 보고서 초안 작성**" -> **이건 반드시 '스킬'로 가르쳐야 함.**

**코드에서의 의미:**
```python
# agent.py
skills = ["incident-response"]  # '인시던트 대응 매뉴얼' 스킬 장착
```
이 스킬 안에는 프롬프트(지시문)가 들어있습니다.
> *"너는 지금부터 시니어 SRE야. 알람이 오면 패닉하지 말고 순서대로 해. 먼저 깃허브 MCP로 최근 배포 내역 뽑고, 데이터독 MCP로 메트릭 찍고..."*

이렇게 **스킬 = "특정 도메인에서 '어떻게 생각하고, 어떤 도구를 어떤 순서로 쓸지' 정의한 프롬프트 템플릿 + 워크플로우"**입니다. 모델이 똑똑해도 "우리 회사 스타일대로 일해"를 모르면 사고 칩니다. 스킬이 그걸 막아주는 **가드레일(Guardrail)**이자 **네비게이션** 역할을 합니다.

> **💡 튜터의 팁:** 스킬을 **"에이전트에게 주는 시스템 프롬프트(System Prompt)의 확장판"**이라고 생각하시면 편합니다. 단순히 "착하게 굴어"가 아니라, **"이 도구(MCP) 써서, 이 단계대로, 이 포맷으로 출력해"**라는 **실행 가능한 지시서**예요. 나중에 실무에서는 `incident-response`, `code-review`, `sql-optimization`, `customer-support-triage` 등 팀마다 수십 개의 스킬을 만들어 에이전트에게 "오늘은 이 모드야"라고 스위칭하며 씁니다.

## 4. 종합: `agent.py` - 에이전트의 '이력서'이자 '장비 명세서'

영상에서 강연자가 `agent.py` 파일에 이 세 가지를 차곡차곡 복사해 넣던 장면, 기억나시나요? 그게 바로 **에이전트의 '출생 신고서'**를 쓰는 과정이었습니다.

```python
# agent.py (완성본 예시)
agent = Agent(
    name="oncall-copilot",           # 이름: "야근 도우미"
    model="claude-3-5-sonnet-latest",# 뇌: 미슐랭 3스타 셰프
    mcp_servers=[                    # 도구 가방: 전문 비서들 고용
        github_mcp,
        datadog_mcp,
        slack_mcp,
        kubernetes_mcp,
    ],
    skills=[                         # 매뉴얼: 우리 팀 방식대로 일해
        "incident-response",
        "postmortem-writing",
    ],
    # ... 기타 설정들
)
```

이 코드 한 덩어리가 **"이 에이전트는 누구이며, 무엇을 알고, 무엇을 할 수 있는가?"**를 정의하는 **완전한 명세서(Spec)**가 됩니다. 이 파일을 클로드 매니지드 에이전트 서버에 올리는 순간, **"준비된 프로 비서"**가 클라우드 어딘가에서 대기하기 시작하는 거죠.

## 5. 심화 이해: 왜 '두뇌(에이전트)'와 '손(환경/Environment)'을 뗐나? (영상의 핵심 인사이트)

영상 중반, 강연자가 아주 중요한 이야기를 했습니다. **"예전엔 에이전트 루프(생각)와 도구 실행(행동)이 한 통(컨테이너) 안에 있었는데, 이제는 뗐다(Decoupling)."** 왜 그랬을까요? 이걸 이해하면 아키텍처가 보입니다.

### 🏗️ 개념 돋보기: '두뇌-손 분리' = "본사 전략실(두뇌) vs 현장 지점(손)" 구조
> **비유 (구버전 - 결합됨):**
> - **상황:** 매번 새 프로젝트(세션)마다 **"전략실장(뇌) + 현장 작업자(손) + 공구창고(도구) + 자재창고(파일시스템)"**을 **한 트럭에 싣고 현장으로 파견 보냄(컨테이너 띄움).**
> - **문제점:**
>   1.  **느림(TTFT 지연):** 트럭 싣고 이동하고 세팅하느라 **첫 삽 뜨기까지 30분(토큰 생성 지연)** 걸림.
>   2.  **위험(보안):** 전략실장이 **현장 금고(자격 증명, 키)** 바로 옆에 있으니, 해킹당하거나 실수로 금고 열리면 대참사.
>   3.  **낭비:** 1분짜리 심부름에도 트럭 통째로 띄워야 함.

> **비유 (신버전 - 분리됨, Claude Managed Agents 방식):**
> - **두뇌(본사 전략실 - Server-side Agent Loop):** **보안 철통같은 본사 지하 벙커**에 상주. **자격 증명(키, 비밀번호)도 여기만 있음.** 절대 밖으로 안 나감. 생각만 함. **"가서 파일 좀 봐와"**라고 명령만 내림.
> - **손(현장 환경 - Environment):** **가벼운 지점 사무실(샌드박스 컨테이너).** 본사에서 "이거 해" 시키면 **자기 권한 범위 안에서만** 파일 읽고, 명령어 치고, 결과만 본사로 쏴줌. **금고 모름. 키 모름. 그냥 심부름만 함.**
> - **효과:**
>   1.  **초고속(90% 지연 감소):** 본사(두뇌)는 이미 켜져 있음. 세션 시작 = 지점(손)만 띄우면 끝. **첫 토큰까지 1초 컷.**
>   2.  **철통 보안:** 두뇌가 키를 쥐고 있음. 손(환경)은 키 없이 샌드박스에서만 놀다 감. 해커가 손 털어도 키는 본사에 있음.
>   3.  **지속성/신뢰성:** 내 노트북 덮어도(클라이언트 끊겨도) 본사(서버 사이드 루프)는 계속 생각함. "잠깐 화장실 다녀올게" 해도 작업 이어짐.

**이게 바로 `Agent`(두뇌 정의)와 `Environment`(손 정의)를 코드에서 **분리해서 정의**하게 만든 근본 이유입니다.** `agent.py`에는 **"어떻게 생각할지(모델, 스킬, MCP 리스트)"**만 적고, 실제 **"어디서 실행할지(컨테이너 스펙, 네트워크, 볼륨)"**는 `environment.py`에서 따로 적는 구조가 된 거죠.

## 6. 실습 포인트 정리: `agent.py` 채우기 (Step-by-Step)

영상에서는 `agent.py` (빈 파일) 옆에 `agent_complete.py` (정답 파일)를 두고 하나씩 복사해 넣으며 실습하죠. 여러분도 나중에 직접 해보실 때, **무작정 복사하지 말고 "이 줄이 무슨 뜻인지 중얼거리며" 복사**해보세요.

1.  **`model = "..."`** -> *"좋아, 우리 비서 머리는 소넷 3.5로 확정."*
2.  **`mcp_servers = [...]`** -> *"깃허브 비서, 데이터독 비서, 슬랙 비서... 팀원 모집 완료."*
3.  **`skills = [...]`** -> *"인시던트 대응 매뉴얼, 사후 보고서 매뉴얼... 교육 자료 지급 완료."*
4.  **`Agent(...)` 객체 생성** -> *"자, 명함(이름) 파고, 계약서(설정) 싸인 완료. 입사 처리!"*

이 과정이 끝나면 우리 에이전트는 **"누구냐? 넌 뭐 할 수 있냐?"**라는 질문에 **"저는 온콜 코파일럿이고, 소넷 뇌에 깃허브/데이터독 도구 쓰고, 인시던트 대응 매뉴얼 숙지했습니다!"**라고 당당히 답할 수 있는 상태가 됩니다.

## 🎓 챕터 마무리: 튜터의 한 마디

> **"에이전트를 정의한다"는 건, 단순히 파라미터 몇 개 채우는 게 아닙니다. **"이 AI에게 우리 회사의 어떤 권한을 줄까?(MCP), 어떤 판단 기준을 줄까?(Model), 어떤 업무 스타일을 강제할까?(Skill)"**를 **아키텍트(Architect)** 관점에서 설계하는 일이에요.**
>
> 이번 챕터에서 `agent.py`를 보며 **"아, 여기 모델이 뇌고, 여기가 도구 가방이고, 여기가 매뉴얼이구나"**라는 **구조적 이해**를 확실히 가져가셨기를 바랍니다. 다음 챕터에서는 이렇게 정의된 '두뇌'가 실제로 '손(Environment)'을 만나 **'세션(Session)'**이라는 이름으로 살아 숨 쉬는 과정을 볼 거예요. 그때 **"아, `agent.py`에서 정의한 MCP 서버가 여기서 실제로 호출되는구나!"** 하고 연결이 되실 겁니다.
>
> 자, 이제 우리 에이전트 **'입사 서류'(`agent.py`)는 완벽하게 준비됐습니다. 다음은 '근무지(Environment)'를 마련해줄 차례네요!**
