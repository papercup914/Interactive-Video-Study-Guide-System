# Chapter 1. Agent (에이전트): 페르소나와 역량 정의 - 모델, MCP 서버, 스킬, 에이전트 루프에서 활용할 구성 요소

안녕하세요! 오늘은 **'에이전트(Agent)'**라는 친구를 제대로 파헤쳐 보는 시간을 가져볼게요. 앞서 영상에서 강사님이 **"에이전트는 페르소나(Persona)와 역량(Capabilities)을 정의하는 것"**이라고 말씀하셨죠? 이 말이 무슨 뜻인지, 왜 이 작은 정의 하나가 '그저 그런 챗봇'과 '내 일을 대신해 주는 똑똑한 비서'를 가르는지 아주 쉽고 깊게, 그리고 길게 풀어드릴게요.

## 1. 프롤로그: 왜 새벽 3시에 잠을 깨우는가? (에이전트가 필요한 이유)

강의 초반에 강사님이 이런 말씀을 하셨어요.

> *"소프트웨어 엔지니어라면 새벽 2시, 3시에 온콜(On-call) 당번 때문에 잠을 깬 경험이 있을 거예요. 서버가 죽었는지, 로그는 왜 찍히는지, 배포는 잘 됐는지 메트릭과 로그를 뒤지며 조사해야 하죠."*

여러분, 상상해 보세요. **새벽 3시, 눈도 채 뜨이지 않은 상태에서 모니터 앞에서 수천 줄의 로그를 보며 "이게 왜 에러지?"라고 중얼거리는 개발자의 모습.** 이건 단순히 피곤한 문제가 아니에요. **'인지 부하(Cognitive Load)'**가 최고조에 달한 상태에서 실수하기 딱 좋은 상황이죠.

이때 우리가 원하는 건 뭐예요? **"너 대신 좀 봐줘. 그리고 요약해서 알려줘. 혹시 고칠 수 있으면 고쳐줘."** 라는 **믿음직한 파트너**잖아요? 그게 바로 **'에이전트(Agent)'**가 존재하는 이유입니다. 단순한 질문-답변 봇(Chatbot)을 넘어, **목표(Goal)를 주고 "알아서 해줘(Autonomy)"라고 시킬 수 있는 주체적인 존재** 말이죠.

## 2. 에이전트의 해부도: 뇌(Brain)와 손(Hands), 그리고 연결고리(Session)

강사님이 코드(`agent.py`)를 보여주시며 세 가지 핵심 구성 요소를 짚어주셨어요. 이건 **에이전트라는 '로봇'을 만들 때 꼭 필요한 설계도**와 같습니다.

### ① 에이전트 (Agent) = **뇌 (Brain) + 페르소나 + 역량**
> *"에이전트는 페르소나와 역량을 정의합니다. 모델, MCP 서버, 스킬, 에이전트 루프에서 활용할 구성 요소들이죠."*

**🍳 일상 비유: '요리사 채용 공고' 내기**
여러분이 레스토랑을 열었다고 쳐요. **'에이전트 정의'**는 **"어떤 요리사를 뽑을지, 그 요리사가 뭘 할 수 있는지 적는 채용 공고"**를 쓰는 것과 똑같아요.

*   **모델 (Model) = 요리사의 '두뇌 회로' (지능 수준)**
    *   "이 요리사는 미슐랭 3스타 경력자야(GPT-4o/Claude Opus)" vs "요리 학원 갓 수료한 초보야(작은 오픈소스 모델)". 어떤 두뇌를 쓸지 정하는 거예요.
*   **MCP 서버 (MCP Servers) = 요리사의 '전문 지식 서고' (도메인 지식)**
    *   "한식 전문가야", "프렌치 전문가야", "우리 식당 비밀 레시피 북이 여기 있어". 모델이 기본적으로 아는 것 외에 **'참고해야 할 외부 지식 창고'**를 연결해 주는 겁니다. (나중에 자세히 다룰게요!)
*   **스킬 (Skills) = 요리사가 가진 '특기 요리/도구 사용법' (함수/툴)**
    *   "칼질 잘함", "오븐 다룸", "재료 주문함", "손님 응대함". 즉, **'함수 호출(Function Calling)'**로 구현되는 **구체적인 행동 레퍼토리**예요. "로그 조회하기", "배포 롤백하기" 같은 거요.
*   **페르소나 (Persona) = 요리사의 '태도와 말투' (시스템 프롬프트)**
    *   "친절하고 차분하게 설명해줘", "군더더기 없이 핵심만 말해줘", "에러 나면 당황하지 말고 단계적으로 디버깅해". **어떤 성격으로 임무를 수행할지** 정하는 거예요.

> **💡 개념 돋보기: 에이전트 정의의 4대 요소**
> > **에이전트 = 모델(두뇌) + MCP 서버(외부 지식) + 스킬(도구/행동) + 페르소나(성격/지시문)**
> >
> > 이 네 가지를 `agent.py`에서 **클래스나 설정 객체로 딱 정의**해두면, 나중에 "이 에이전트 좀 써줘"라고 호출할 때마다 이 설정대로 '똑같은 성격, 똑같은 능력을 가진 인스턴스'가 뚝딱 생성됩니다. 이게 바로 **'페르소나와 역량의 정의'**라는 말의 정체예요.

---

### ② 환경 (Environment) = **손 (Hands) + 작업실 (Workspace)**
> *"환경은 에이전트의 손입니다. 에이전트(뇌)가 무엇을 실행할지 생각하면, 환경(손)은 실제로 행동할 공간과 컨테이너를 제공하죠."*

**🍳 일상 비유: '주방(작업실)과 조리도구(손)'**
아무리 천재 요리사(에이전트/뇌)가 있어도, **주방(환경)이 없으면 요리를 못 해요.**
*   **컨테이너/샌드박스:** 격리된 안전한 주방. 여기서 불내도(에러) 밖으로 안 나가요.
*   **파일 시스템/터미널/브라우저:** 칼, 도마, 오븐, 주문 전화기 같은 **실제 행동 도구**들.
*   **상태 유지 (Statefulness):** "아까 다진 마늘 어디 뒀지?" 기억하며 이어서 요리하는 것. 세션이 살아있는 동안 환경도 계속 켜져 있어요.

> **💡 개념 돋보기: 왜 뇌와 손을 분리했나요? (핵심 설계 철학)**
> > 예전 방식(예: Claude Code 등)은 **'뇌(에이전트 루프) + 손(툴 실행)'이 한 몸(같은 컨테이너)**이었어요.
> > *   **문제 1 (보안):** 요리사(뇌)에게 "내 집 열쇠(자격증명/크리덴셜)"를 다 줘야 함. 요리사가 마음만 먹으면 금고도 열 수 있음. 샌드박싱(격리)이 어려움.
> > *   **문제 2 (속도/비용):** 손님 한 명 올 때마다(세션 하나 생성될 때마다) **뇌가 든 무거운 컨테이너를 통째로 띄워야 함**. 컨테이너 뜨는 데만 수초~수십 초 걸림 (Time To First Token 지연).
> >
> > **Claude Managed Agents의 혁신: 뇌(서버 사이드) ✂️ 손(환경/컨테이너)**
> > *   **뇌는 클라우드 중앙에서 하나로 돌려쓰고 (서버리스, 무상태),** 손(환경)만 필요할 때 가볍게 띄워서 연결.
> > *   **결과:** 보안 굿(뇌가 자격증명 모름), 속도 굿(TTFT 90% 이상 단축), 신뢰성 굿(내 랩탑 닫아도 뇌는 클라우드에서 계속 돔).

---

### ③ 세션 (Session) = **뇌와 손을 잇는 '작업 지시서' + '생중계 줄'**
> *"세션은 에이전트와 환경을 엮는 방식입니다. 단일 세션은 환경 위에서 에이전트 인스턴스를 띄워 연결하고, 이벤트를 사용자에게 스트리밍하죠."*

**🍳 일상 비유: '오늘의 주문서 + 주방과의 무전기'**
*   손님(유저)이 "된장찌개 1인분 추가요"라고 주문하면 -> **세션 생성**.
*   이 세션은 **"요리사(에이전트)야, 3번 주방(환경)으로 가서 된장찌개 끓여"**라고 **뇌와 손을 매핑**해줘요.
*   요리 중 "물 끓었음", "된장 풀었음", "완성됨" 같은 **진행 상황(이벤트/스트림)**을 실시간으로 홀(유저 인터페이스)로 중계해 주는 **통신선** 역할도 해요.
*   세션이 끝나면(손님 나감) -> 주방(환경) 정리하고, 요리사(에이전트 인스턴스)도 대기실로 돌려보냄.

## 3. 코드 속으로: `agent.py`에서 이뤄지는 '정의의 마법'

강사님이 `agent.py` (빈 파일)와 `agent_complete.py` (완성 파일)를 나란히 두고 하나씩 복사해오며 설명하셨죠? 이 과정이 바로 **'추상적인 설계를 구체적인 코드로 심는 과정'**입니다.

### 단계 1: 에이전트 클래스 정의하기 (뇌와 페르소나 심기)

```python
# agent.py 에서 우리가 채워야 할 핵심 부분
from agent_framework import Agent, Model, MCPServers, Skills # 가상의 임포트

# 1. 모델 선택: "우리 요리사는 클로드 3.5 소네트(지능)로 할게요"
my_model = Model(name="claude-3-5-sonnet-20241022")

# 2. MCP 서버 연결: "우리 식당 비밀 레시피북(내부 위키, DB) 여기서 봐요"
my_mcp_servers = MCPServers([
    "internal-wiki-server", 
    "incident-runbook-server" # 장애 대응 매뉴얼 서버
])

# 3. 스킬 장착: "칼질(로그 조회), 오븐(배포 롤백), 주문받기(알림 전송) 할 줄 알아요"
my_skills = Skills([
    "query_logs",        # 로그 조회 스킬
    "check_metrics",     # 메트릭 확인 스킬
    "rollback_deploy",   # 배포 롤백 스킬
    "send_slack_alert"   # 슬랙 알림 스킬
])

# 4. 페르소나 부여 (시스템 프롬프트로 성격 주입)
system_prompt = """
당신은 새벽 3시에도 당황하지 않는 베테랑 사이버네틱스(SRE) 엔지니어입니다.
사건(Incident)이 들어오면:
1. 침착하게 로그와 메트릭을 확인하세요.
2. 원인을 가설로 세우고 검증하세요.
3. 사용자에게 현재 상황을 3줄 요약으로 보고하세요.
4. 권한 내에서는 자동 복구(롤백 등)를 시도하세요.
절대 추측으로 말하지 말고 데이터로 말하세요.
"""

# 5. 에이전트 객체 생성 (이게 바로 '채용 공고' 완성본!)
incident_agent = Agent(
    name="NightWatch-SRE",
    model=my_model,
    mcp_servers=my_mcp_servers,
    skills=my_skills,
    system_prompt=system_prompt
)
```

> **💡 개념 돋보기: `Agent` 클래스 하나면 끝?**
> > 네, 이 `incident_agent` 객체 하나에 **'누가(모델), 무엇을 알고(MCP), 무엇을 할 수 있고(스킬), 어떻게 행동할지(페르소나)'**가 **모두 캡슐화**되어 있습니다.
> > 이제 우리는 이 객체를 세션에 넣고 "돌려!"라고만 하면 됩니다. **복잡한 프롬프트 엔지니어링, 툴 스키마 정의, 루프 로직 짜기... 이걸 프레임워크가 다 떠안아 준 거예요.** 우리가 `agent.py`에 저 코드만 쓰면 되는 이유죠.

### 단계 2: 환경 정의하기 (손과 작업장 준비)

```python
# 환경 정의: "이 요리사가 쓸 주방은 '도커 컨테이너'이고, 리눅스야"
from agent_framework import Environment, DockerEnvironment

# 격리된 도커 컨테이너 환경 정의
# 여기서 실제 kubectl, aws cli, python 스크립트 등이 돌아감
prod_env = DockerEnvironment(
    image="my-company/sre-agent-env:latest", # 미리 깔린 도구들
    env_vars={"KUBECONFIG": "/etc/kube/config"}, # 환경변수 주입
    network="internal-vpc" # 내부망 접근 권한
)
```

### 단계 3: 세션으로 엮고 실행하기 (뇌 + 손 = 동작)

```python
# 세션 생성: "NightWatch 요리사, prod_env 주방으로 가서 일해"
session = Session.create(
    agent=incident_agent,
    environment=prod_env,
    user_id="user-123" # 누가 시켰는지 추적
)

# 이벤트 스트리밍 받기 (실시간 중계)
async for event in session.stream_events(user_input="서버 500 에러 났어요! 원인 찾아줘"):
    print(f"[{event.type}] {event.content}")
    # 출력 예시:
    # [thinking] "로그부터 확인해야겠군. query_logs 스킬 호출..."
    # [tool_call] query_logs(service="payment", since="5m")
    # [tool_result] "Error: Connection timeout at DB pool..."
    # [thinking] "DB 커넥션 풀 고갈이네. 최근 배포 내역 확인..."
    # [final_answer] "원인: 배포 v1.2.3에서 커넥션 누수 발생. 롤백 권장함."
```

## 4. '서버 사이드 에이전트 루프'의 마법: 내 랩탑을 닫아도 된다?

강사님이 **"Claude Managed Agent는 에이전트 루프가 서버 사이드에서 돈다"**고 강조하셨죠? 이게 왜 대박인지, 비전공자 관점에서 **'클라우드 저장소 vs USB'**에 비유해 볼게요.

### 기존 방식 (로컬/클라이언트 사이드 루프) = **USB에 작업 파일 담아 다니기**
*   내 랩탑에서 `python agent.py`를 돌리면, **에이전트가 생각하는 루프(생각 -> 도구 호출 -> 결과 보기 -> 다시 생각...)가 내 랩탑 CPU/램에서 돔**.
*   **치명적 단점:**
    1.  **내 랩탑 꺼지면 끝:** 새벽 3시에 에이전트 돌려놓고 "이제 자야지" 하고 랩탑 덮으면? **에이전트도 잠듦(중단).** 아침에 보면 반만 해놓고 멈춰있음.
    2.  **확장 안 됨:** 동시 접속자 100명이 에이전트 쓰면? 내 랩탑 100대 필요하거나, 내 랩탑 터짐.
    3.  **상태 관리 내 몫:** "어제 어디서 멈췄지?" 세션 상태, 대화 기록, 툴 실행 히스토리... 다 내가 DB에 저장하고 불러오게 코드 짜야 함. **프로토타입 -> 프로덕션 갈 때 여기서 다 죽음.**

### Claude Managed Agents (서버 사이드 루프) = **구글 독스(클라우드)에서 작업하기**
*   **에이전트 루프(뇌)가 Anthropic 클라우드 서버에서 돔.**
*   **마법 같은 이점:**
    1.  **내 랩탑 닫아도 됨 (Durability):** 세션 ID만 있으면, 일주일 뒤에 다른 컴퓨터에서 로그인해도 **"어? 그때 그 에이전트 아직 일하고 있네? 결과 나왔네?"** 이어서 볼 수 있음. 상태가 서버에 영속 저장됨.
    2.  **무한 확장 (Scalability):** 사용자 100만 명이 동시에 써도 내 코드 한 줄 안 바꿔도 서버 측에서 알아서 처리함.
    3.  **신뢰성 (Reliability):** 네트워크 끊겨도, 서버 재시작해도 에이전트 상태는 안전함. **"프로토타입을 프로덕션으로 옮기는 지옥(Productionization Hell)"에서 탈출**시켜 주는 핵심 키예요.

> **💡 개념 돋보기: "서버 사이드 루프" = 상태 관리의 외주화**
> > 여러분이 `session.stream_events()`를 호출하는 건 그저 **'결과 구경하러 가는 관람객'**일 뿐입니다. **감독(에이전트 루프)은 무대 뒤(서버)에서 연극을 계속하고 있어요.** 여러분이 관람을 그만두러 가도(브라우저 닫아도), 연극은 끝나고 결과물이 창고(세션 스토어)에 고이 저장됩니다. 이게 바로 **'내구성(Durability)'**과 **'신뢰성(Reliability)'**을 공짜로 얻는 비결입니다.

## 5. 심화: 왜 '뇌(루프)'와 '손(환경/툴)'을 칼로 베듯 분리했나? (Decoupling)

이 부분은 강의에서 **가장 중요하게 다뤄진 아키텍처 결정**입니다. 면접 가서 "에이전트 아키텍처 설계해 보세요" 하면 무조건 나와야 하는 레벨이에요. 아주 꼼꼼히 씹어 드릴게요.

### 상황 A: 일체형 (Monolithic) - 구형 자동차 (엔진+바퀴 용접)
*   **구조:** 에이전트 루프(생각) + 툴 실행(행동) = **같은 컨테이너/프로세스**에서 실행.
*   **예시:** `Claude Code` (내 로컬 파일 시스템 접근 필요), 로컬에서 도는 LangGraph 에이전트 등.
*   **장점:** 레이턴시 낮음(프로세스 간 통신 없음), 로컬 자원(파일, GPU) 직접 접근 편함.
*   **치명적 단점 1: 보안 (Credential Leakage)**
    *   에이전트가 "AWS 키 좀 줘봐" 해서 환경 변수에 넣어두면? **에이전트 코드(프롬프트 인젝션 등) 해킹당하는 순간 키 유출.**
    *   에이전트가 내 로컬 `~/.ssh/id_rsa` 읽을 수 있으면? **내 서버 다 털림.**
    *   **해결:** 뇌와 손을 분리해서, **뇌(서버)에는 절대 키를 안 줌.** 손(격리된 컨테이너)에만 최소 권한으로 키 주입. 뇌는 "손야, `kubectl get pods` 해줘"라고만 시킴. 손이 결과를 텍스트로 뇌에 던져줌. **자격 증명 완전 격리 성공.**
*   **치명적 단점 2: 지연 시간 (Cold Start / TTFT)**
    *   세션 1개 만들 때마다 **무거운 에이전트 컨테이너(파이썬, 라이브러리, 모델 캐시 등) 띄워야 함.**
    *   "안녕?" 한 마디 하는데 컨테이너 뜨는 10초 기다려야 함. **Time To First Token (TTFT) 폭망.**
    *   **해결:** 뇌(에이전트 루프)는 **항상 켜진 서버리스 함수/워커 풀**로 둠. **초경량.** 손(환경 컨테이너)만 필요할 때 띄우거나 풀링(Pooling)해둠.
    *   **결과:** 강사님 말씀대로 **P95 기준 TTFT 90% 이상 단축.** "즉각 반응하는 에이전트" 체감 가능.

### 상황 B: 분리형 (Decoupled) - 테슬라 모델 S (자율주행 컴퓨터 + 구동 모듈 분리)
*   **뇌 (Control Plane / Server-side Loop):**
    *   상태 없음(Stateless), 확장 용이, 보안 안전(자격 증명 모름), 지능만 담당.
    *   Anthropic 관리형 서비스에서 돌려줌. (우린 API만 호출)
*   **손 (Data Plane / Environments):**
    *   상태 있음(Stateful), 격리된 샌드박스, 실제 작업 수행(파일, 네트워크, CLI).
    *   우리가 `Environment` 객체로 정의해서 연결함.
*   **세션 (Session Manager):**
    *   뇌와 손을 매칭, 이벤트 스트리밍, 수명 주기 관리.

> **💡 개념 돋보기: "뇌-손 분리"가 주는 3대 선물**
> > 1.  **안전성 (Safety/Security):** "최소 권한 원칙(Least Privilege)" 실현. 뇌는 몰라도 됨. 손만 알면 됨.
> > 2.  **속도 (Latency/TTFT):** 무거운 뇌 컨테이너 안 띄워도 됨. 뇌는 상시 대기 중.
> > 3.  **유연성 (Flexibility):** 같은 뇌(에이전트 정의)로 **다른 손(로컬 환경, 클라우드 환경, 모바일 환경)** 갈아 끼우기 가능. "테스트할 땐 로컬 손, 배포땐 프로덕션 손" 이렇게 스위칭 가능.

| **Environment (손)** | Docker 컨테이너: `kubectl`, `aws cli`, `python`, 내부망 접근 권한 장착 | **프로덕션 서버에 SSH 접속 가능한 관리자 워크스테이션** |

| **Server-side Loop** | Anthropic 클라우드에서 돌아감. 내 랩탑은 그냥 브라우저만 켜두면 됨. | **나는 집에서 자고, 클라우드 슈퍼컴이 일함** |

## 7. 마무리하며: "정의(Definition)"의 힘을 믿으세요

여러분, 오늘 배운 **`Agent` 클래스 정의(모델, MCP, 스킬, 페르소나)**가 별거 아닌 코드 몇 줄로 보일 수 있어요. 하지만 이 **'선언적 정의(Declarative Definition)'** 하나가 갖는 힘은 어마어마합니다.

1.  **재현성:** "그 에이전트 누구야?" -> `Agent(name="SRE")` 객체 하나면 **완벽히 똑같은 놈** 소환 가능.
2.  **버전 관리:** `agent.py`를 Git으로 관리하면? **"어제 버전 에이전트가 더 똑똑했네? 롤백하자"** 가능. 프롬프트 엔지니어링이 코드가 됨.
3.  **테스트/평가:** "이 에이전트 성능 어때?" -> 정의된 객체 그대로 평가 데이터셋 돌려서 **자동 채점** 가능.
4.  **공유/협업:** 동료에게 "이 에이전트 써봐" -> `pip install` 하고 `from agent import incident_agent` 한 줄이면 끝.

**에이전트를 '만드는 것(코딩)'에서 '정의하는 것(설계)'으로 패러다임이 바뀐 순간입니다.**

자, 이제 터미널 열어서 `git clone` 하고, `cd ship-your-first-managed-agent`, `python -m venv venv`, `source venv/bin/activate`, `pip install -r requirements.txt`, `.env`에 API 키 넣고, `streamlit run app.py` 칩시다.

**여러분의 첫 번째 '관리형 에이전트'가 브라우저에서 "안녕하세요, 무엇을 도와드릴까요?"라고 인사하는 순간, 여러분은 공식적으로 '에이전트 엔지니어'가 되는 겁니다.** 화이팅입니다! 🚀
