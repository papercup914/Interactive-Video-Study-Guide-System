# 📚 챕터 3. 에이전트 아키텍처의 세 가지 주요 패턴: 본격적인 패턴 탐험 전, '에이전트'라는 친구의 정체부터 파악하기

안녕하세요! 지난 시간까지 우리는 AI 에이전트가 왜 지금 뜨거운 감자인지, 그리고 단순한 챗봇과는 무엇이 다른지에 대한 큰 그림을 그려보았습니다. 이제 본격적으로 **"에이전트 아키텍처의 세 가지 주요 패턴"**이라는, 마치 집의 설계도면 같은 핵심 주제로 들어가 보려 합니다.

하지만 잠깐! 설계도면을 보려면 일단 **'이 집(에이전트)'이 어떤 재료로 지어졌고, 어떤 원리로 돌아가는지**부터 알아야겠죠? 제공된 영상 스크립트는 바로 이 **'에이전트의 정의'와 '작동의 핵심 엔진(ReAct 패턴)'**에 대한 설명으로 세 가지 패턴 이야기를 시작하기 직전에서 끊겨 있습니다.

이번 챕터에서는 영상 앞부분에 해당하는 **'에이전트란 무엇인가?', 'ReAct라는 생각의 엔진', '자율성이란 무엇인가?'** 이 세 가지 기초 체력을 탄탄히 다지는 시간으로 꾸며보겠습니다. 세 가지 패턴은 이 기초 위에서 비로소 이해가 되니까요. 자, 그럼 일상적인 비유와 함께 아주 천천히, 깊게 파고들어 볼까요?

## 1. 에이전트, 넌 누구냐? - "대답만 하는 비서 vs 일 처리하는 매니저"

영상에서는 **"가장 단순한 수준에서 에이전트는 단순히 대답만 하는 소프트웨어가 아니라, 결정하고 행동할 수 있는 소프트웨어다"**라고 정의합니다.

> **💡 개념 돋보기: 챗봇 vs 에이전트 (식당 비유)**
>
> > **전통적인 챗봇 = '메뉴판만 읽어주는 홀 직원'**
> > 손님: "여기 김치찌개 어때요?"
> > 직원: "김치찌개는 8,000원입니다. (메뉴판 정보만 읽어줌)"
> > 손님: "그럼 주문해줘."
> > 직원: "죄송해요, 저는 메뉴판만 읽을 수 있어요. 직접 주문하셔야 해요." 👉 **행동 불가, 수동적 응답만 함**
> >
> > **AI 에이전트 = '주문받고 주방에 전달하고 반찬까지 챙겨주는 유능한 매니저'**
> > 손님: "김치찌개 하나 주세요. 아, 계란말이도 추가하고, 밥은 잡곡밥으로 바꿔주세요."
> > 매니저: (생각: 김치찌개 + 계란말이 + 잡곡밥 변경) → **주방에 주문 넣음(도구 호출/API 호출)** → (주방에서 "잡곡밥 다 떨어졌는데요?"라고 알림 옴) → **상황 파악 후 대안 제시** → "사장님, 잡곡밥이 다 떨어졌대요. 흰쌀밥으로 할까요, 아니면 보리밥으로 할까요?" → 손님 결정 후 **최종 서빙 완료**. 👉 **이유 추론 → 행동 → 관찰 → 다시 판단(적응)**의 사이클 수행

이 차이는 엄청납니다. 챗봇은 **'지식 검색기'**에 가깝지만, 에이전트는 **'업무 수행자'**입니다. 영상에서는 이를 **"단일 응답 생성이 아니라, 요청을 보고 필요한 단계가 무엇인지 파악하고, API를 호출하거나 코드를 실행하고, 결과를 보고 다음 할 일을 결정한다"**고 표현했습니다.

## 2. 현대 에이전트의 심장, 'ReAct(리액트) 패턴' - "생각하고, 행동하고, 보고, 고치는 요리사의 레시피"

영상에서 **"가장 명확한 설명 중 하나는 'ReAct: 언어 모델에서 추론과 행동의 시너지'라는 연구 논문에서 나온다"**고 소개합니다. 이 **ReAct(Reasoning + Acting)**는 현재 거의 모든 최신 AI 에이전트의 **기본 골격(백본)**이 되는 사고 회로입니다.

이게 도대체 무슨 말일까요? **'요리사'**에 비유해 보겠습니다.

### 🍳 ReAct 사이클: 요리사의 4단계 작업 루프

| 단계 | 영상 용어 | 요리사 비유 | 상세 설명 |
| :--- | :--- | :--- | :--- |
| **1. 추론 (Reasoning)** | `Reason` / `Step-by-step reasoning` | **"어떤 요리를 할까? 재료는 뭐가 필요하지? 순서는 어떻게 하지?"** | LLM이 머릿속으로 생각을 정리하는 단계. "사용자가 '여행 계획 짜줘'라고 했으니, 날짜/예산/취향을 물어봐야 하고, 항공권/숙소 API를 써야겠다"는 **계획 수립** 과정입니다. |
| **2. 행동 (Acting)** | `Act` / `Call a tool or API` | **"냉장고에서 재료 꺼내기(도구 사용), 불 켜기, 팬 달구기"** | 생각만 해서는 요리가 안 됩니다. **외부 도구(Tool)를 실제로 호출**하는 단계입니다. 파이썬 코드 실행, 구글 검색 API 호출, 데이터베이스 조회, 이메일 발송 등이 여기에 해당합니다. |
| **3. 관찰 (Observing)** | `Observe` / `Look at the results` | **"음... 간을 보니 싱겁네? 고기가 탔네? 국물이 끓어넘치네?"** | 행동의 **결과(피드백)를 눈으로 확인**하는 단계. API가 에러를 뱉었는지, 데이터가 잘 왔는지, 사용자가 추가 질문을 던졌는지 등을 '관찰'합니다. |
| **4. 조정/적응 (Adapting/Adjusting)** | `Adjust` / `Decide what to do next` | **"그럼 소금 더 넣자 / 불 줄이자 / 물 더 붓자 / 아님 이 요리 포기하고 라면 끼이자"** | 관찰한 결과를 바탕으로 **다음 행동을 결정**하는 단계. "검색 결과가 부족하네? 그러면 검색어를 바꿔서 다시 검색하자(Act → Observe)"거나, "사용자 질문에 답할 만큼 정보가 모였으니 이제 최종 답변을 생성하자"는 식의 **동적 의사결정**입니다. |

> **💡 개념 돋보기: ReAct가 왜 혁신적인가? (내비게이션 비유)**
>
> > **기존 LLM (Chain-of-Thought만 있는 경우) = '출발 전 지도만 보고 경로 외우기'**
> > "서울에서 부산까지 가려면 경부고속도로 타고 4시간 30분 걸립니다." (중간에 사고 나면? 모름. 그냥 처음 계획대로만 말함)
> >
> > **ReAct 에이전트 = '실시간 내비게이션 (티맵/카카오내비)'**
> > 1. **추론**: "목적지 부산, 현재 서울, 최적 경로 계산."
> > 2. **행동**: "출발! (차 몰고 감)"
> > 3. **관찰**: "어? 50km 지점에서 사고 나서 정체 발생! (실시간 교통 정보 수신)"
> > 4. **조정**: "그럼 중부내륙고속도로로 우회하는 게 30분 빠르네? 경로 재탐색 후 안내 변경."
> > 5. **반복**: 목적지 도착할 때까지 이 사이클 무한 반복.
> >
> > **핵심:** **"한 번에 텍스트를 쭉 생성하는 게 아니라, 행동하고 결과를 보며 끊임없이 생각을 고쳐나간다(Iterative)."** 이게 바로 에이전트가 '자율적'일 수 있는 비결입니다.

영상에서는 이 사이클을 **"추론, 행동, 관찰, 조정이 반복되는 사이클이 현대 AI 에이전트가 작동하는 기반이다(The cycle of reasoning, acting, observing, and adjusting is the foundation of how modern AI agents work)"**라고 단언합니다. 이 문장, 꼭 기억해 두세요. 뒤에서 배울 **세 가지 아키텍처 패턴(ReAct, Plan-and-Execute, Multi-agent 등)**은 결국 이 **ReAct 루프를 어떻게 배치하고, 누가 주도하고, 어떻게 협업하게 할 것인가**에 대한 설계도의 변주곡입니다.

## 3. 에이전트의 정의서: "추론, 계획, 기억, 그리고 자율성"

영상 후반부에서는 에이전트를 좀 더 학문적으로 정의합니다.
> **"시스템에 추론(Reasoning), 계획(Planning), 기억(Memory)이 탑재되어 있고, 사용자를 대신해 적응(Adapt)하고 결정(Decide)할 만큼 충분한 자율성(Autonomy)을 가진 시스템"**

이 네 가지 키워드(**추론, 계획, 기억, 자율성**)는 에이전트 아키텍처를 평가하는 **'성능표'**이자 **'설계 체크리스트'**입니다. 하나씩 비유로 뜯어봅시다.

### ① 추론 (Reasoning) - "뇌, 논리 엔진"
*   **역할:** 복잡한 문제를 쪼개고(Decomposition), 논리적으로 연결하고, 예외 상황을 처리하는 능력.
*   **비유:** **셜록 홈즈의 두뇌**. 단서(관찰 결과)를 보고 "범인은 왼손잡이여야 해"라고 논리적으로 도출해내는 과정. ReAct의 'Reason' 단계가 바로 이것입니다.

### ② 계획 (Planning) - "설계도, 프로젝트 매니저"
*   **역할:** 목표(사용자 요청)를 달성하기 위한 **단계별 로드맵**을 미리 짜는 능력. "먼저 A하고, 그 결과로 B하고, 마지막으로 C하자."
*   **비유:** **건축가의 청사진**. 벽돌 하나 쌓기 전에 "기초 공사 → 기둥 세우기 → 지붕 올리기 → 내부 인테리어" 순서를 정해두는 것. 계획이 없으면 ReAct 루프가 무한 루프에 빠지거나 엉뚱한 짓만 하게 됩니다.

### ③ 기억 (Memory) - "일기장, 하드디스크, 근무 수첩"
*   **역할:** 과거의 대화 맥락, 이전 작업의 결과, 사용자 선호도, 습득한 지식 등을 **저장하고 필요할 때 꺼내 쓰는 능력**.
*   **비유:**
    *   **단기 기억 (Short-term/Working Memory):** 요리 중 "방금 소금 한 스푼 넣었지?" 기억하는 것 (컨텍스트 윈도우).
    *   **장기 기억 (Long-term Memory):** "이 손님은 매운 거 싫어해", "지난주에 검색한 항공권 가격은 이렇더라"를 DB에 저장해두고 다음에 쓰는 것 (Vector DB, Knowledge Graph 등).
*   **중요성:** 기억 없는 에이전트는 **'금붕어'**입니다. 매번 처음부터 설명해야 하죠.

### ④ 자율성 (Autonomy) - "운전대, 결정권"
*   **역할:** 인간의 일일 지시(Step-by-step guiding) 없이, **주어진 목표 안에서 스스로 판단하여 다음 행동을 선택하고 실행하는 자유도**.
*   **비유:**
    *   **자율성 낮음 (워크플로우/오토메이션):** "1번 버튼 누르세요 → 2번 버튼 누르세요 → 3번..." (인간이 핸들 잡고 있음)
    *   **자율성 높음 (진정한 에이전트):** "집에 안전하게 데려다줘." → 자율주행차가 **알아서** 차선 유지, 신호 대기, 끼어들기 대응, 주차까지 다 함. (인간은 목적지만 줌)
*   **영상 포인트:** **"사용자를 대신해(On behalf of the user) 적응하고 결정할 만큼 충분한 자율성"**. 여기서 '충분한(Enough)'이 중요합니다. 완전 무인 자율주행(레벨 5)처럼 완벽할 필요는 없지만, 중간에 인간이 "이렇게 저렇게 해"라고 일일이 시키지 않아도 될 정도는 되어야 '에이전트'라 부릅니다.

## 4. 이제 진짜 '세 가지 패턴'을 만날 준비가 되었습니다.

자, 여기까지가 영상 스크립트 앞부분이 우리에게 전해준 **에이전트의 '해부학 교과서'** 같은 내용입니다.

*   **에이전트 = 결정하고 행동하는 소프트웨어** (챗봇과 다름)
*   **작동 원리 = ReAct 루프 (추론 → 행동 → 관찰 → 조정의 무한 반복)**
*   **필수 4대 장착품 = 추론, 계획, 기억, 자율성**

이제 우리는 **"그렇다면 이 ReAct 루프와 4대 장착품을 실제 코드와 시스템 구조로 어떻게 조립할 것인가?"**라는 질문에 답할 준비가 되었습니다. 다음 섹션(또는 다음 영상 파트)에서 다룰 **'에이전트 아키텍처의 세 가지 주요 패턴(Three Broad Patterns)'**은 바로 이 질문에 대한 세 가지 다른 **'조립 설명서'**입니다.

> **💡 학습 포인트 정리 (이 챕터의 핵심만 콕!)**
>
> > 1.  **에이전트 ≠ 챗봇**: 에이전트는 '대답'이 아니라 '행동(Action)'하고 '결정(Decision)'한다.
> > 2.  **ReAct는 심장박동**: Reason(생각) → Act(도구사용) → Observe(결과확인) → Adjust(다음판단) 사이클이 에이전트의 생명을 유지한다.
> > 3.  **4대 필수 요소**: 추론(두뇌), 계획(설계도), 기억(데이터베이스), 자율성(운전대) 이 네 가지가 갖춰져야 '진짜 에이전트'다.
> > 4.  **패턴의 의미**: 곧 배울 '세 가지 패턴'은 이 ReAct 루프와 4대 요소를 **어떤 구조로 배치하느냐(단일 루프? 계층 구조? 다중 에이전트?)**에 따른 아키텍처 스타일이다.
