# 🧑‍💻 챕터: 완성된 코드 참고하며 미완성 파일 채워넣기 방식 - '요리 레시피 보며 실습하기' 학습법

자, 이제 본격적으로 우리 손으로 직접 에이전트를 만들어볼 시간입니다! 강연자분께서 "이제 랩탑을 열고 URL로 가서 레포지토리를 복제(clone)하자"라고 하셨죠? 이 부분은 **'직접 요리하며 배우는 쿠킹 클래스'**의 시작을 알리는 신호탄과 같습니다.

---

## 1. 개발 환경 구축: '나만의 주방' 세팅하기

가장 먼저 해야 할 일은 **'주방(개발 환경)'을 내 컴퓨터에 차리는 것**입니다. 강연장에서 알려준 순서대로 따라 해 볼게요. 겁먹지 마세요! 이건 그냥 **'재료 손질하고 도구 꺼내놓기'** 과정일 뿐입니다.

### 📋 단계별 주방 세팅 가이드

> **💡 개념 돋보기: `git clone`이란?**
> 
> > **비유: 유명 셰프의 '비법 레시피 노트' 통째로 내 주방으로 가져오기**
> > 
> > 인터넷 어딘가(GitHub)에 있는 완성된 프로젝트 폴더를 **내 컴퓨터 로컬로 그대로 복사해 오는 명령어**입니다. `git clone [주소]`라고 치면, 원격 저장소에 있는 모든 파일(코드, 설정, 히스토리)이 내 폴더 안에 `쏙` 하고 들어옵니다. "이 레시피대로 한번 해보자!" 하고 노트를 빌려오는 거라고 생각하시면 됩니다.

1.  **레포지토리 복제 (`git clone`)**
    *   화면에 띄워준 URL로 가서 `git clone` 명령어를 터미널(명령창)에 칩니다.
    *   **비유:** 셰프의 레시피 북을 내 책상에 펼쳐놓은 상태입니다.

2.  **프로젝트 폴더로 이동 (`cd Ship Your First Manage Agent`)**
    *   `cd`는 **Change Directory(폴더 바꾸기)**의 약자예요.
    *   **비유:** 큰 서재(컴퓨터) 안에서 '오늘 실습할 요리방'이라는 특정 방으로 **발을 들여놓는 행위**입니다. 이 방 안으로 들어가야 비로소 요리(코딩)를 시작할 수 있어요.

3.  **가상 환경 만들기 및 활성화 (Mac: `python -m venv venv` → `source venv/bin/activate` / Windows: `venv\Scripts\activate`)**
    *   **비유: '나만의 깨끗한 조리대' 만들기**
    *   내 컴퓨터엔 이미 여러 파이썬 라이브러리(양념)가 깔려 있을 수 있어요. 이것들이 서로 섞이면 맛(코드 실행 결과)이 이상해질 수 있죠. 그래서 **이 프로젝트 전용으로만 쓸 깨끗한 빈 조리대(가상 환경)**를 하나 만드는 겁니다. `activate`는 "자, 이제부터 이 조리대 위에서만 요리할게!"라고 선포하는 스위치 같은 거예요.

4.  **필수 재료 설치 (`pip install -r requirements.txt`)**
    *   **비유: 레시피에 적힌 '필수 양념 리스트' 보고 장 봐오기**
    *   `requirements.txt`에는 이 요리(프로젝트)에 꼭 필요한 라이브러리 이름과 버전이 적혀 있어요. `pip install`은 마트에서 장 봐와서 내 조리대(가상 환경) 위에 쫙 깔아놓는 작업입니다.

5.  **비밀 열쇠 꽂기 (`.env` 파일에 Anthropic API Key 넣기)**
    *   **비유: '특급 비밀 소스(클로드 모델 사용 권한)' 병에 라벨 붙여 냉장고에 넣기**
    *   QR 코드로 받은 무료 크레딧 키(API Key)는 **내 지갑(코드 안)에 현금 그대로 두면 안 되는 비밀 열쇠**예요. 그래서 `.env`라는 **'비밀 금고 파일'**에 따로 보관하고, 코드에서는 "금고에서 열쇠 꺼내 써"라고만 시키는 거예요. 이건 보안의 기본 중의 기본! 절대 GitHub에 올리면 안 돼요.

6.  **불 켜기 (`streamlit run app.py`)**
    *   드디어 웹 페이지가 열립니다! 로컬호스트 주소(보통 `http://localhost:8501`)가 뜨면 성공.
    *   **비유: 주방 문 열고 손님(사용자) 맞을 준비 완료!** 이제 브라우저라는 '홀'에서 우리 에이전트가 서빙할 준비가 된 겁니다.

## 2. 실습 시나리오: '새벽 3시의 악몽' 해결하기 - 인시던트 대응 에이전트

강연자분이 보여주신 화면, 기억나시나요? **"인시던트(Incident)가 떴어요!"** 하는 시뮬레이션 화면이요.

> **💡 개념 돋보기: 인시던트(Incident) & 온콜(On-call)이란?**
> 
> > **비유: 식당 영업 중 '가스불이 안 켜지거나', '냉장고가 고장 난' 긴급 상황**
> > 
> > 소프트웨어 엔지니어에게 **'인시던트'**는 **"서비스가 터졌다(장애 발생)"**는 비상벨입니다. **'온콜(On-call)'**은 **"이번 주에는 너가 비상벨 당번이야"**라고 정해진 당번 제도예요. 새벽 3시, 휴가 중, 결혼식 중에도 전화가 오면 뛰어가야 하는... 엔지니어들의 **'악몽 같은 당번'**이죠. 로그 보며 "왜 안 되지?", 메트릭 보며 "CPU 왜 100%지?", 배포 내역 보며 "누가 뭘 배포했나?" 정신없이 조사해야 합니다.

오늘 우리가 만들 에이전트는 **이 '새벽 3시의 악몽'을 대신 해결해 주는 '슈퍼 야간 당번 알바생'**입니다. 클로드(Claude)라는 똑똑한 두뇌에게 "너가 로그 보고, 메트릭 보고, 원인 찾아서 보고해줘"라고 시키는 거죠. 우리가 잠든 사이, 혹은 우리가 커피 마시는 사이 에이전트가 일해주는 그림입니다.

## 3. 핵심 학습 전략: '완성본(정답지) 보며 빈칸 채우기' - `agent.py` vs `agent_complete.py`

자, 이제 코드 에디터(VS Code 등)를 여셨다면 왼쪽과 오른쪽에 두 파일이 나란히 떠 있을 거예요.

*   **왼쪽: `agent.py` (우리가 채워야 할 '빈칸 문제지')** - 텅 비어 있거나 뼈대만 있는 파일.
*   **오른쪽: `agent_complete.py` (정답지이자 '완성된 요리')** - 모든 로직이 다 짜여 있는 완성본.

> **💡 개념 돋보기: 왜 '빈칸 채우기' 방식인가? (학습 설계 의도)**
> 
> > **비유: '요리 교실에서 완성된 요리 보며 내 접시 채우기'**
> > 
> > 처음부터 "자, 밀가루 반죽해, 불 조절해, 소스 만들어" 다 시키면 초보자는 멘붕 옵니다. **중요한 건 '어떤 순서로 어떤 재료가 들어가는가(아키텍처의 구성 요소)'**예요. 그래서 강연자는 **"완성된 요리(오른쪽)를 보고, 내 접시(왼쪽)에 한 입씩 옮겨 담으며 '아, 여긴 소스가 들어가는구나', '여긴 고기가 들어가는구나' 몸으로 익히라"**고 하신 겁니다. **한 조각씩 복사해 붙여넣기(Copy & Paste)하며 실행해보는 것**, 이게 이 실습의 핵심 학습법입니다.

### 🧩 우리가 채워 넣을 4가지 핵심 '레고 블록' (Primitive Components)

강연자께서 왼쪽 파일(`agent.py`)에 순서대로 복사해 넣으라고 한 4가지 구성 요소를 **'에이전트라는 로봇을 만드는 4대 부품'**으로 비유해 드릴게요.

#### 1. `Agent` (에이전트) - **"로봇의 두뇌 🧠 + 이력서 📄"**
*   **역할:** "너는 누구야? 뭘 할 줄 알아? 어떤 모델(뇌) 쓸 거야? 어떤 도구(기술) 쓸 거야?"를 **정의**하는 곳.
*   **구성 요소:** 모델(클로드), MCP 서버(도구 상자 연결 통로), 스킬(특기), 시스템 프롬프트(성격/지시사항).
*   **비유:** **"이 로봇은 '클로드 3.5 소넷'이라는 최신형 두뇌를 썼고, '인시던트 해결사'라는 직함을 가졌으며, '로그 조회', '메트릭 확인'이라는 자격증을 땄고, '너는 친절하고 정확하게 답해야 해'라는 교육을 받은 상태다"**라고 **스펙시트(명세서) 적어놓는 곳**입니다.

#### 2. `Environment` (환경) - **"로봇의 손과 발 🤲, 작업실 🏭"**
*   **역할:** 두뇌가 "이거 해!"라고 명령하면, **실제로 명령이 실행되는 물리적(가상) 공간** 제공.
*   **비유:** 두뇌(에이전트)가 "냉장고 좀 열어봐"라고 생각만 해선 안 열리죠? **냉장고가 있는 주방(환경)**, **칼과 도마가 있는 조리대(환경)**가 있어야 실제로 '행동'할 수 있습니다. 여기는 **컨테이너(격리된 공간)**로 돌아가며, 에이전트가 파일 읽고, 명령어 치고, API 호출하는 **'실행의 장'**입니다.

#### 3. `Session` (세션) - **"두뇌와 손을 이어주는 '신경계' 🔗 + '작업 일지' 📝"**
*   **역할:** 특정 **에이전트 인스턴스(두뇌 하나)**와 특정 **환경 인스턴스(손 하나)**를 **1:1로 묶어주는 연결 고리**.
*   **기능:** 이 둘을 묶어서 **"자, 이제 일 시작해!"**라고 이벤트 스트림(명령/응답 흐름)을 타고 사용자(나)에게 결과를 실시간으로 보여줌.
*   **비유:** **"철수(에이전트)야, 이 주방(환경)에서 일해라"**라고 **파트너 매칭** 시켜주고, 철수가 주방에서 뭘 하는지 CCTV(이벤트 스트림)로 중계해주는 **'현장 감독관'** 같은 존재입니다.

#### 4. `Server-side Agent Loop` (서버 사이드 에이전트 루프) - **"관제탑 ☁️, 무거운 건 클라우드가 다 함"**
*   **핵심:** **"에이전트가 '생각(추론) -> 도구 호출 -> 결과 관찰 -> 다시 생각' 하는 루프(반복)를 내 랩탑이 아닌 클로드 서버에서 돌린다!"**
*   **비유:** **"로봇의 복잡한 생각 회로(루프)를 내 집(로컬)에 두지 않고, 튼튼한 클라우드 데이터 센터(클로드 서버)에 맡겨버리는 것."**
*   **장점 (강연자 강조):**
    *   내 랩탑 덮어도(절전 모드/종료) **로봇은 클라우드에서 계속 일함(내구성/Durability)**.
    *   내 인터넷 끊겨도, 브라우저 새로고침 해도 **상태가 안 날아감(신뢰성/Reliability)**.
    *   복잡한 컨테이너 띄우기, 스케일링(확장) 고민 **안 해도 됨(운영 편의성)**.
    *   **"프로토타입 -> 프로덕션(실서비스) 갈 때 골치 아픈 인프라 걱정을 싹 덜어줌."**

## 4. 심화 이해: 왜 '두뇌(에이전트)'와 '손(환경/도구)'을 분리했나? - 아키텍처의 비하인드 스토리

강연자분이 **"이게 핵심 디자인 결정(Design Decision)인데..."** 하며 길게 설명하신 부분, 놓치지 마세요! 이건 **'좋은 아키텍처란 무엇인가'**를 보여주는 교과서 같은 사례입니다.

### 📖 과거 방식 (Coupled: 두뇌+손 한몸) - "클로드 코드(Claude Code) 스타일"
*   **구조:** 에이전트 루프(생각)와 도구 실행(파일 읽기/쓰기, 터미널 명령)이 **같은 컨테이너(상자) 안에 같이 들어있음**.
*   **비유: **"요리사(두뇌)가 자기 주방(손/도구)을 통째로 들고 다니며, 식당 테이블 옆에서 바로 요리하는 1인 푸드트럭"**
*   **장점:** 빠르고 강력함. 내 컴퓨터 파일 시스템에 바로 접근해서 코드 고치기엔 최고.
*   **단점 (치명적):**
    1.  **보안/자격 증명(Credentials) 문제:** 요리사가 내 집 냉장고(비밀 키, DB 비밀번호)를 마음껏 뒤질 수 있음. 샌드박스(격리)가 약함.
    2.  **지연 시간(Latency/TTFT - Time To First Token) 문제:** 손님(세션) 한 명 올 때마다 **푸드트럭(컨테이너) 한 대를 새로 뽑아서(Spin up) 주차해야 함**. 트럭 뽑는 시간에 손님은 기다림. (P95 기준 **90% 이상 느림**)

### 🚀 클로드 매니지드 에이전트 방식 (Decoupled: 두뇌↔손 분리) - "레스토랑 분업화"
*   **구조:** **두뇌(에이전트 루프)는 클라우드 중앙 관제탑(서버 사이드)에 두고**, **손(환경/도구 실행)은 별도의 격리된 샌드박스(컨테이너)에서만 돌림**. 둘은 API로만 대화.
*   **비유: **"두뇌는 본사 '셰프 총괄 본부'에 앉아서 레시피만 짜고, 손(조리)은 각 지점 '격리된 주방'에서만 수행. 본부는 주방 키(비밀번호) 모름. 주문 오면 본부가 주방에 '이거 해' 지시만 내림."**
*   **획기적 이점:**
    1.  **보안/샌드박싱 완벽:** 두뇌(에이전트)가 **절대 직접 비밀 키(자격 증명)를 만질 수 없음**. 손(환경)만 암호화된 채로 접근 가능. "두뇌는 손이 무슨 재료 쓰는지만 알지, 창고 열쇠는 모름."
    2.  **지연 시간 혁신적 단축 (TTFT 90% 감소!):** 세션이 생겨도 **무거운 두뇌 컨테이너(루프)를 안 띄워도 됨**. 이미 떠 있는 중앙 두뇌가 바로 생각 시작. 손(환경)만 가볍게 띄우면 되니 **'첫 응답 속도'가 압도적으로 빠름**.
    3.  **확장성:** 두뇌는 하나(또는 풀)로 공유하고, 손(환경)만 필요할 때마다 팍팍 늘리면 됨.

> **💡 개념 돋보기: TTFT (Time To First Token) & P95**
> 
> > **비유: 손님이 "주문요!" 하고 첫 입 먹기까지 걸리는 시간**
> > 
> > *   **TTFT:** 사용자가 "해줘"라고 요청 보낸 뒤, 에이전트가 **"네, 알겠어요"**라고 **첫 마디(첫 토큰) 내뱉기까지 걸린 시간**. 이거 길면 사용자 답답해함.
> > *   **P95 (Percentile 95):** "상위 5% 최악의 경우를 뺀, **평소 95% 상황에 해당하는 성능 지표**". 평균은 이상치에 휘둘리니, **'실제 체감 성능'을 보려면 P95를 봐야 함**.
> > *   **결과:** 두뇌/손 분리 덕분에 **"컨테이너 뜨는 시간"이 사라져서, 95%의 상황에서 첫 마디 튀어나오는 속도가 10배 이상 빨라짐.** 이건 사용자 경험(UX) 차원에서 '마법' 같은 차이예요.

## 5. 실습 로드맵: 이제 복사-붙여넣기 여정 시작! 🚗

강연자 말씀대로 **"단순히 복사만 하지 말고, 한 조각씩 옮길 때마다 '이게 두뇌야, 이게 손이야, 이게 연결고리야'라고 중얼거리며 하세요."**

1.  **1단계: `Agent` 정의 복사** → "두뇌 스펙 정했어."
2.  **2단계: `Environment` 정의 복사** → "작업실(손) 준비했어."
3.  **3단계: `Session` 생성/연결 복사** → "두뇌랑 손이랑 이어줬어. 이제 일 시킬 수 있어."
4.  **4단계: 실행 (`streamlit run app.py`)** → 브라우저에서 "인시던트 발생!" 버튼 누르며 에이전트 일하는 거 구경.
