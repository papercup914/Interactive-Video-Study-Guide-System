# 📚 챕터 1: 워크숍 개요 및 강사 소개 — "우리가 만들 '슈퍼 인턴'의 설계도 들여다보기"

안녕하세요! 오늘 워크숍에 오신 여러분, 진심으로 환영합니다. 저는 오늘 여러분과 함께 **'클로드 매니지드 에이전트(Claude Managed Agents)'**라는, 요즘 가장 핫한 AI 에이전트 개발 플랫폼을 이용해 **'내 대신 야근해 주는 슈퍼 인턴(에이전트)'**을 직접 만들어 볼 강사입니다.

평소에 "AI가 내 코드도 짜주고, 서버 장애도 대신 처리해 주면 얼마나 좋을까?" 생각만 하셨죠? 오늘 그 상상을 현실로 만드는 **마법 같은 3시간**이 될 겁니다. 자, 그럼 본격적으로 실습에 들어가기 전에, **오늘 우리가 만들 '슈퍼 인턴'이 도대체 어떻게 생겼는지(아키텍처), 왜 이렇게 똑똑한지(설계 철학)**를 일상적인 비유로 아주 천천히, 꼼꼼히 뜯어보겠습니다.

---

## 1. 오늘 워크숍의 큰 그림: "뇌(브레인)와 손(핸즈)을 분리하라"

여러분, 요리사(셰프)와 주방 보조(수셰프/주방 도구)를 떠올려 보세요.

*   **셰프(에이전트의 뇌, LLM):** "이 재료로 파스타를 만들어야지, 면 삶고, 소스 만들고, 플레이팅해." → **생각하고 계획만 함.**
*   **주방 보조 & 도구들(에이전트의 손, 환경/툴):** 실제로 칼질을 하고, 불을 켜고, 면을 삶고, 접시에 담음. → **몸으로 행동함.**

기존의 많은 AI 에이전트 프레임워크는 이 **셰프와 주방 보조를 한 몸(같은 컨테이너/박스)**에 욱여넣었습니다. 셰프가 "칼 줘"라고 하면 바로 옆에서 칼을 건네주는 식이죠. 이게 처음에는 편해 보입니다. **클로드 코드(Claude Code)**처럼 내 컴퓨터 파일 시스템을 직접 뒤적여야 하는 에이전트라면, 뇌와 손이 붙어 있는 게 훨씬 빠르고 직관적이니까요.

> **💡 개념 돋보기: '뇌와 손의 결합(Coupled Architecture)'이란?**
> > **쉽게 말해 '만능 로봇 팔' 하나만 있는 상태예요.**
> > 뇌(LLM)가 "파일 읽어줘"라고 생각하자마자, उसी 프로세스 안에서 손(툴 실행기)이 바로 `read_file` 함수를 실행하는 구조죠. 초기 프로토타입 만들 땐 최고로 편합니다. 설치도 간단하고, 지연 시간(Latency)도 없으니까요.

## 2. 하지만 '프로덕션(실전)'에서는 이야기가 다릅니다: "보안과 신뢰성, 그리고 속도"

여러분이 만든 에이전트를 **회사 실제 서비스(프로덕션)**에 올린다고 상상해 보세요. 갑자기 무시무시한 문제들이 튀어나옵니다.

### 문제 1: "셰프에게 금고 열쇠까지 줄 순 없잖아?" (보안 & 자격 증명 분리)
뇌(셰프)가 "DB 비밀번호 좀 알려줘"라고 할 때, 뇌와 손이 붙어 있으면 뇌가 **실제 비밀번호(자격 증명)**를 다 볼 수 있습니다. 해킹당하면 끝장이죠.
> **💡 개념 돋보기: '샌드박싱(Sandboxing)과 손-뇌 분리(Decoupling)'의 마법**
> > **비유: '셰프는 레시피만 보고, 주방 보조는 금고에서 재료만 꺼내온다.'**
> > 클로드 매니지드 에이전트는 **뇌(에이전트 루프)와 손(환경/컨테이너)을 철저히 분리**합니다.
> > 1.  뇌(서버 사이드): "이 작업 하려면 DB 접속 필요해" → **의도만 전달**.
> > 2.  손(격리된 샌드박스 환경): 암호화된 자격 증명을 이용해 **실제 DB 접속 실행**.
> > 3.  결과만 뇌에게 "성공했어(또는 데이터 여기 있어)"라고 **안전하게 반환**.
> > 이렇게 하면 **뇌는 절대 실제 비밀번호(자격 증명)를 볼 수 없습니다.** 이게 바로 '샌드박싱'이고, '손과 뇌의 분리'가 주는 최고의 선물입니다.

### 문제 2: "매번 주방 새로 짓고 셰프 불러오느라 3시 퇴근 못 해" (지연 시간 & 확장성)
기존 방식(뇌+손 결합)은 **사용자 세션마다 컨테이너(주방)를 새로 띄워야** 했습니다.
*   사용자 A 접속 → 컨테이너 생성(수초~수십 초) → 에이전트 로드 → 실행.
*   사용자 100명 동시 접속? → 컨테이너 100개 동시 생성 → **서버 다운/지연 폭주**.

> **💡 개념 돋보기: '서버 사이드 에이전트 루프(Server-side Agent Loop)'의 위력**
> > **비유: '거대한 중앙 주방(서버) 하나에 슈퍼 셰프들이 대기 중이다.'**
> > 클로드 매니지드 에이전트는 **에이전트의 생각 루프(뇌)를 서버 측에서 중앙 관리**합니다.
> > *   사용자가 접속하면? → **이미 떠 있는 뇌 세션에 바로 연결만 하면 끝.** (컨테이너 생성 대기 시간 0초)
> > *   내 노트북 덮어도? → **서버에서 뇌가 계속 생각 중.** (내 로컬 환경과 무관하게 지속성/내구성 보장)
> > *   브라우저 새로고침해도? → **세션 그대로 유지.**
> >
> > **실제 수치로 증명된 속도:** 이 구조 덕분에 **첫 토큰 생성 시간(TTFT, Time To First Token)이 P95 기준 90% 이상 단축**되었습니다. 프로토타입이 '실전용'이 되는 순간입니다.

## 3. 오늘 실습 시나리오: "새벽 3시, 온콜(On-call) 악몽에서 해방되자"

자, 이제 아키텍처 이야기는 이쯤 하고, **우리가 오늘 만들 구체적인 '슈퍼 인턴'의 임무**를 공개합니다.

### 상황극: 여러분은 지금 '온콜(당직) 엔지니어'입니다.
*   시간: **새벽 3시** (또는 휴가 중 해변에서 칵테일 마시는 중)
*   사건: **서버 다운 알람(페이저듀티/슬랙 알림) 울림!**
*   기존 인간 엔지니어의 고통:
    1.  눈 비비며 노트북 켬.
    2.  대시보드(메트릭스) 보고, 로그 뒤지고, 최근 배포 내역 확인.
    3.  원인 찾고, 롤백하거나 핫픽스 배포.
    4.  사고 리포트(Postmortem) 작성.
    5.  **결과: 수면 부족, 번아웃, 다음 날 회의 졸음.**

### 오늘의 미션: **이 모든 걸 에이전트에게 위임하자!**
우리는 **스트림릿(Streamlit) 웹 앱** 위에서 돌아가는 **'인시던트 대응 에이전트'**를 만듭니다.
1.  **사건 발생** → 에이전트에게 "이 인시던트 좀 봐줘" 요청.
2.  **에이전트(뇌)**가 계획 수립: "메트릭스 확인 → 로그 분석 → 배포 이력 대조 → 근본 원인 추론 → 해결 방안 제안".
3.  **환경(손, 샌드박스)**에서 안전하게 도구 실행: 데이터독(Datadog) API 호출, 쿠버네티스 로그 조회, 깃헙 배포 이력 확인.
4.  **결과 리포트** 자동 생성: "원인은 3시간 전 배포된 버전의 메모리 릭입니다. 롤백 권장합니다."

> **💡 개념 돋보기: 'MCP 서버(Model Context Protocol)'가 뭐길래?**
> > **비유: '만능 리모컨(표준 인터페이스)'**
> > 에이전트가 "데이터독 메트릭스 줘"라고 했을 때, 데이터독 API 문서 읽고, 인증 토큰 넣고, HTTP 요청 짜고... 이거 에이전트가 매번 하기 귀찮고 복잡하죠?
> > **MCP 서버**가 **"데이터독 메트릭스 조회"라는 버튼 하나**로 추상화해 줍니다. 에이전트는 그냥 버튼만 누르면 됩니다. 오늘 실습에서는 이 MCP 서버들을 에이전트의 '스킬(Skill)'로 장착해 줄 겁니다.

## 4. 실습 환경 세팅: "내 노트북에 주방 차리기" (Step-by-Step)

자, 이제 진짜 손을 움직일 차례입니다. 강사 화면을 보며 따라오셔도 되고, 아래 가이드를 보며 본인 속도대로 하셔도 됩니다. **중간에 안 되더라도 절대 당황하지 마세요!** 화면 공유로 다 보여드릴 거고, 나중에 저장소 클론해서 천천히 복습하시면 됩니다.

### ① 저장소 클론 (소스 코드 가져오기)
제공된 URL(또는 QR 코드)로 들어가서 `git clone` 하세요.
```bash
# 터미널(명령 프롬프트)에서 실행
git clone <제공된_저장소_URL>
cd <저장소_폴더명>/Ship_Your_First_Managed_Agent  # 오늘 실습 폴더로 이동
```
> **💡 꿀팁:** 폴더 이름에 공백 있으면 따옴표(`" "`)로 감싸세요!

### ② 파이썬 가상 환경 만들기 (나만의 깨끗한 주방 만들기)
시스템 파이썬 더럽히지 말고, 전용 방(가상환경) 만드세요.

**Mac / Linux:**
```bash
python3 -m venv venv        # 'venv'라는 폴더에 가상환경 생성
source venv/bin/activate    # 가상환경 진입 (프롬프트 앞에 (venv) 뜸)
```

**Windows (Command Prompt):**
```cmd
python -m venv venv
venv\Scripts\activate.bat
```
**Windows (PowerShell):**
```powershell
python -m venv venv
venv\Scripts\Activate.ps1
# 실행 정책 오류 나면: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### ③ 필수 라이브러리 설치 (재료 채우기)
```bash
pip install -r requirements.txt
```
*   `anthropic`, `streamlit`, `mcp` 관련 라이브러리 등이 쫙 깔립니다. 커피 한 잔 마시며 기다리세요.

### ④ 환경 변수 설정 (비밀 열쇠 넣기)
이게 **가장 중요**합니다! 에이전트가 클로드(LLM)랑 대화하려면 API 키가 필요하죠.
1.  폴더 안에 `.env.example` 파일이 있을 겁니다. 복사해서 `.env` 파일 만드세요.
    *   Mac/Linux: `cp .env.example .env`
    *   Windows: `copy .env.example .env`
2.  `.env` 파일을 열어서 `ANTHROPIC_API_KEY=여기에_키_붙여넣기` 하세요.
    *   **무료 크레딧 QR 코드** 찍으셨죠? 거기서 발급받은 키 넣으시면 됩니다. (없어도 강사 키로 시연 가능하니 걱정 마세요!)

### ⑤ 앱 실행! (주방 오픈)
```bash
streamlit run app.py
```
*   터미널에 `Local URL: http://localhost:8501` 같은 주소 뜹니다.
*   브라우저에서 열면 **오늘의 메인 무대(UI)**가 나타납니다.

## 5. 코드 구조 미리보기: "레시피북(agent.py) 해부하기"

앱이 떴다면, 이제 **VS Code(또는 에디터)**로 `agent.py` 파일을 열어보세요. 좌측은 **빈 껍데기(우리가 채울 파일)**, 우측은 **완성본(답안지)**입니다. 우리는 답안지에서 한 조각씩 떼어다 내 파일로 붙여넣으며 **'기초 체력(Primitive) 쌓기'**를 할 겁니다.

오늘 우리가 조립할 **핵심 4대 컴포넌트(Primitive)**입니다. 이건 외우지 마시고, **역할만 확실히 아시면 됩니다.**

| 컴포넌트 | 비유 | 역할 | 핵심 키워드 |
| :--- | :--- | :--- | :--- |
| **1. Agent (에이전트)** | **셰프(뇌)** | **페르소나(성격)와 능력 정의.** "너는 SRE 전문가야. 쓸 수 있는 도구(MCP 서버)는 이것들이야." | `model`, `mcp_servers`, `skills` |
| **2. Environment (환경)** | **주방/작업장(손)** | **코드가 실제 실행되는 격리된 공간(컨테이너/샌드박스).** 파일 시스템, 네트워크, OS 자원 여기서 씀. | `docker`, `sandbox`, `tool_execution` |
| **3. Session (세션)** | **근무 교대표/작업 티켓** | **뇌(에이전트 인스턴스)와 손(환경)을 1:1로 묶는 연결고리.** 이벤트 스트리밍, 상태 관리 담당. | `agent_instance + environment`, `stream_events` |
| **4. Server-side Loop (서버 루프)** | **중앙 관제탑** | **에이전트 생각 루프를 클라우드(서버)에서 돌림.** 내 로컬 꺼져도 지속, 확장성, 신뢰성 보장. | `managed`, `durability`, `scaling` |

> **💡 개념 돋보기: 왜 'Agent.py'를 조각조각 채우는 방식으로 실습하나요?**
> > **비유: '레고 조립 설명서 없이 통짜 성곽 주기 vs 브릭 하나씩 설명하며 쌓기'**
> > 완성된 코드 `agent_complete.py`를 통째로 복사하면 "돌아간다"는 사실만 압니다. 하지만 **`agent.py`에 한 줄씩 추가하며 "아, 이 줄이 뇌를 만드는 거구나", "이 줄이 손을 붙이는 거구나"** 체감해야 나중에 내 서비스에 맞춰 **응용/수정/디버깅**할 수 있습니다. 오늘은 **'이해'가 목표**입니다.

## 6. 강사 마무리 인사 & 마음가짐

자, 여러분. 지금까지 **워크숍 개요(우리가 뭐 만들지, 왜 이 구조지?)**와 **강사 소개(저는 여러분의 '에이전트 개발 입문 가이드'입니다)**를 마쳤습니다.

오늘 3시간 동안 우리는:
1.  **이론:** 뇌/손 분리 아키텍처가 왜 '보안/속도/신뢰성'의 열쇠인지 체감하고,
2.  **실습:** 직접 `agent.py`를 채워 넣으며 **에이전트=셰프, 환경=주방, 세션=근무표**라는 추상화를 내 손끝에 새기고,
