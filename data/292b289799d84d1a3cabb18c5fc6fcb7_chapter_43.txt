# 전체 파이프라인 실행 흐름 이해: 계획 → 작성 → 검증 → 최종 산출물 생성

자, 이제 우리가 만들었던 모든 조각들이 어떻게 하나로 연결되어 **'똑똑한 블로그 작가 에이전트'**로 탄생하는지, 그 거대한 전체 그림을 들여다볼 시간이에요. 마치 레스토랑의 주방 시스템이 어떻게 손님의 주문 한 번에 완벽한 코스 요리를 내어놓는지, 그 비하인드 스토리를 엿보는 것과 같아요. 자, 앞치마를 단단히 매고 주방으로 들어가 볼까요?

---

## 1. 두 개의 '전문 주방'을 도구(Tool)로 포장하기: 캡슐화의 마법

지난 시간까지 우리는 **'강력한 플래너(Robust Blog Planner)'**와 **'강력한 라이터(Robust Blog Writer)'**라는 두 개의 복잡한 루프(Loop) 시스템을 만들었어요. 
- 플래너는 "개요가 완벽해질 때까지 최대 3번 다시 쓴다"는 고집 센 수석 셰프이고요.
- 라이터는 "본문 품질이 합격할 때까지 최대 3번 다시 쓴다"는 깐깐한 조리장이에요.

이 두 친구는 내부가 **엄청나게 복잡**해요. "생각하고, 검사하고, 고치고, 다시 검사하고..." 하는 과정이 루프 속에 숨겨져 있죠. 그런데 이 복잡한 과정을 **매번(root agent가) 직접 지휘하려 하면 어떨까요?** 총지배인(루트 에이전트)이 주방 안으로 들어가 "자, 이제 다시 써! 자, 이제 검사해!"라고 일일이 지시해야 한다면, 총지배인은 정작 손님 맞이와 메뉴 기획이라는 본연의 일을 못 하게 돼요.

그래서 우리는 **'도구(Tool)라는 멋진 포장 상자'**를 준비했어요.

> **💡 개념 돋보기: 도구(Tool)화와 캡슐화 (Encapsulation)**
> 
> > **비유: '자판기' 혹은 '전문 외주 업체'**
> > 
> > 여러분이 커피가 마시고 싶을 때, 원두를 고르고, 로스팅하고, 그라인더로 갈고, 탬핑하고, 에스프레소 머신으로 추출하는 **모든 과정을 직접 하나하나 명령하시나요?** 아니죠. 그냥 **자판기 버튼(도구 인터페이스)**만 누르면 됩니다. 자판기 안쪽(내부 구현)이 얼마나 복잡하든, 고장 나든, 청소하든 **여러분은 알 필요가 없어요.** 그냥 "입력(돈, 버튼)"하면 "출력(커피)"이 나옵니다.
> > 
> > 우리가 플래너와 라이터를 `FunctionTool`(함수 도구)로 감싼 것도 바로 이겁니다. **"주제만 주면, 알아서 검증까지 다 끝낸 완성된 개요를 돌려주는 검은 상자(플래너 도구)"**와 **"개요만 주면, 알아서 퇴고까지 다 끝낸 완성된 본문을 돌려주는 검은 상자(라이터 도구)"**를 만든 거예요. 이제 총지배인은 이 상자들에 **'입력'만 넣으면 '완벽한 출력'이 나온다**는 것만 알면 됩니다. 이게 바로 **캡슐화(Encapsulation)**의 힘이에요.

## 2. 총지배인 '블로거(Blogger)'의 등장: 오케스트라 지휘자

자, 이제 두 개의 완벽한 도구(자판기)가 준비됐어요. 이제 이 도구들을 **누가, 언제, 어떤 순서로 누를 것인가?**를 결정하는 **'두뇌'**가 필요하죠. 그게 바로 **루트 에이전트(Root Agent), 이름하여 '블로거(Blogger)'**입니다.

스크립트에서는 이렇게 말해요: *"The instructions for Blogger are simple."* (블로거의 지시사항은 단순하다.)

단순하다니, 정말 단순할까요? 네, **내부 로직을 도구로 다 숨겨놨기 때문에** 밖에서 보는 지시사항은 믿을 수 없을 만큼 단순하고 우아해집니다. 마치 오케스트라 지휘자가 악보 한 장만 보고 "자, 바이올린 파트(플래너) 시작, 첼로 파트(라이터) 시작, 이제 피날레(최종 다듬기)!"라고 지휘하는 것과 똑같아요.

블로거의 **작업 지시서(Instruction/프롬프트)**는 대략 이런 느낌이에요.

> **📋 블로거의 업무 매뉴얼 (시스템 프롬프트 예시)**
> 
> > **역할:** 너는 전문 블로그 콘텐츠 디렉터 '블로거'다.
> > 
> > **보유 도구:**
> > 1. `robust_blog_planner`: 주제를 받으면 [검증 완료된 상세 개요]를 반환함.
> > 2. `robust_blog_writer`: 개요를 받으면 [검증 완료된 완성 본문]을 반환함.
> > 
> > **실행 순서 (Workflow):**
> > 1. 사용자로부터 **'주제(Topic)'**를 받는다.
> > 2. **1단계 (계획):** `robust_blog_planner` 도구를 호출하여 **'완벽한 개요'**를 받아온다. (내부에서 3번 퇴고하는 건 내 알 바 아님)
> > 3. **2단계 (작성):** 받아온 개요를 들고 `robust_blog_writer` 도구를 호출하여 **'완벽한 본문'**을 받아온다. (내부에서 3번 퇴고하는 건 내 알 바 아님)
> > 4. **3단계 (마무리 - 내 손으로 직접):** 받은 본문을 바탕으로 **'대체 제목 3개'**와 **'트윗용 훅 2개'**를 창작하여 붙인다.
> > 5. 최종 결과물(본문 + 제목들 + 훅들)을 사용자에게 전달한다.

보세요. 블로거는 **'어떻게(How)'**를 전혀 모릅니다. **'무엇을(What)'**만 알아요. "플래너 불러서 개요 받아오고, 라이터 불러서 본문 받아오고, 나 마무리 좀 하고 끝." 이게 다예요. 이게 바로 **'제어된 워크플로우(Controlled Workflow)'**의 아름다움입니다.

## 3. 파이프라인의 흐름: 주문부터 서빙까지 (데이터의 여정)

자, 이제 사용자가 "요즘 뜨는 '생성형 AI로 돈 버는 법'에 대해 블로그 글 써줘"라고 말했다고 쳐볼까요? 데이터가 파이프라인을 타고 흐르는 여정을 **택배 배송 추적**처럼 하나씩 따라가 볼게요.

### 📦 Step 1: 입력 (사용자 → 루트 에이전트 '블로거')
- **사용자:** "주제: 생성형 AI로 돈 버는 법"
- **블로거 (생각):** "좋아, 일단 기획팀(플래너 도구)부터 불러야지."

### 📦 Step 2: 계획 단계 - 플래너 도구 호출 (블로거 → 플래너 도구)
- **블로거:** `planner_tool.run(topic="생성형 AI로 돈 버는 법")` 실행!
- **플래너 도구 내부 (블랙박스 안에서 벌어지는 일):**
  1.  **초안 작성:** "1. 서론, 2. 툴 소개, 3. 사례, 4. 결론" 대충 씀.
  2.  **비평가 등장:** "어이, 2번이 너무 뻔해. '프롬프트 엔지니어링 알바' 같은 구체적 사례 넣어. 3번은 최신 트렌드 'GPTs 스토어 수익화'로 바꿔."
  3.  **수정:** 비평 반영해 개요 수정.
  4.  **재검사:** (최대 3회 반복) "오케이, 이제 완벽해. 합격!"
- **플래너 도구 출력 (Return):** 📄 **<최종 확정 개요 JSON>** (블로거에게 전달됨)

### 📦 Step 3: 작성 단계 - 라이터 도구 호출 (블로거 → 라이터 도구)
- **블로거:** (개요 받아 들고) `writer_tool.run(outline=최종_개요)` 실행!
- **라이터 도구 내부 (또 다른 블랙박스):**
  1.  **초안 작성:** 개요 보고 2000자짜리 글 막 씀.
  2.  **비평가 등장:** "이거 톤이 너무 딱딱해. '여러분' 대신 '독자님' 써주고, 3번 문단 예시가 약해. 구체적 수치(월 300만 원) 넣어줘."
  3.  **수정:** 비평 반영해 본문 수정.
  4.  **재검사:** (최대 3회 반복) "좋아, 출판해도 되겠어. 합격!"
- **라이터 도구 출력 (Return):** ✍️ **<최종 확정 본문 Markdown>** (블로거에게 전달됨)

### 📦 Step 4: 최종 가공 - 블로거의 직접 작업 (블로거 내부 로직)
- **블로거:** "자, 본문 다 왔네. 이제 내 솜씨 좀 보여줄까? 도구 안 쓰고 **내가 직접** 마무리 짓자."
  - **작업 A:** 본문 읽고 **'클릭을 유도하는 대체 제목 3개'** 생성.
    - (예: "월급 외 수익 300만 원, AI로 가능한 이유", "직장인 투잡 1순위, 생성형 AI 시작법" ...)
  - **작업 B:** 본문 핵심 요약해서 **'트위터/X용 훅(Hook) 2개'** 생성.
    - (예: "퇴근 후 1시간, AI로 월세 벌기 시작했다면 믿으시겠어요? 🧵👇", "챗GPT로 글만 쓰지 마세요. '이렇게' 써야 돈이 됩니다. #AI수익화 #부업")

### 📦 Step 5: 최종 산출물 전달 (블로거 → 사용자)
- **블로거:** (본문 + 제목 3개 + 훅 2개)를 예쁘게 포장해서 사용자 채팅창에 **짜잔!** 하고 내놓습니다.

## 4. 왜 이렇게 복잡하게 '도구'로 나눴을까? (아키텍처의 지혜)

초보자들은 "그냥 블로거 하나한테 '알아서 계획하고, 쓰고, 검사하고, 제목 달고 다 해'라고 한 번에 시키면 안 돼요?"라고 묻곤 해요. 이론상으론 가능하지만, **'만능 천재 직원 1명' vs '전문가 2명 + 관리자 1명'**의 차이는 엄청나요.

> **💡 개념 돋보기: 단일 에이전트 vs 멀티 에이전트(도구 기반) 아키텍처**
> 
> > **비유: '슈퍼맨 알바생' vs '전문 레스토랑 팀'**
> > 
> > **🦸 슈퍼맨 알바생 (단일 거대 프롬프트/에이전트):**
> > "너는 기획자이자 작가이자 비평가이자 편집장이야. 주제 주면 다 알아서 해."
> > - **장점:** 구조 단순함. 처음 만들기 쉬움.
> > - **단점:** 프롬프트가 **수천 줄**로 길어짐. "기획 잘해"랑 "글 잘 써"랑 "검사해"가 서로 부딪혀서 **망각하거나 헛소리(Hallucination) 할 확률 급증**. 수정하려면 거대한 프롬프트 전체를 다시 뜯어고쳐야 함. 디버깅 지옥.
> > 
> > **👨‍🍳👨‍🍳🧑‍💼 전문 레스토랑 팀 (도구 기반 멀티 에이전트):**
> > - **수석 셰프(플래너):** 기획만 전담. "개요 품질"만 신경 쓰면 됨. 프롬프트 짧고 명확.
> > - **조리장(라이터):** 집필만 전담. "본문 품질"만 신경 쓰면 됨.
> > - **총지배인(블로거):** 흐름만 관리. "순서"만 신경 쓰면 됨.
> > - **장점:**
> >     1. **관심사 분리(Separation of Concerns):** 각자 자기 일에만 집중 → **성능 최상.**
> >     2. **독립적 테스트/디버깅:** "개요가 이상해?" → 플래너만 고치면 됨. 라이터 건들 필요 없음.
> >     3. **재사용성:** 이 '플래너 도구'는 나중에 '유튜브 대본 짜기 에이전트'에서도 그대로 갖다 씀!
> >     4. **확장성:** 나중에 '이미지 생성 도구', 'SEO 키워드 분석 도구'만 총지배인한테 새 도구로 쥐여주면 기능 추가 끝.
> > 
> > **결론:** 처음엔 귀찮아도 **'도구로 쪼개기(Modularization)'**가 정석입니다. 이게 진짜 '엔지니어링'이에요.

## 5. 실행의 순간: 터미널에서 `adk web` 치기

자, 코드 다 짜놨으니 이제 **'시동 걸기'**만 남았어요. 스크립트에서 말한 그대로 따라 해 봅시다.

1.  **터미널(명령 프롬프트/파워쉘/터미널)**을 여세요. (VS Code 하단 터미널 탭 써도 돼요)
2.  프로젝트 폴더( `agent.py` 가 있는 곳)로 이동했는지 확인하세요 (`cd 내_프로젝트_폴더`).
3.  **마법의 주문**을 치세요:
    ```bash
    adk web
    ```
    *(참고: `adk` 명령어가 안 먹히면 `python -m adk web` 으로 시도해 보세요. 가상환경이 활성화되어 있어야 해요!)*

4.  엔터 치면 뭔가 로그들이 쭉 뜨면서 마지막에 이런 게 보일 거예요:
    > `INFO: Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)`
    > `INFO: ADK Web UI available at http://127.0.0.1:8000/dev-ui/`

5.  **웹 브라우저(크롬/엣지 등)를 열고** 주소창에 **`http://127.0.0.1:8000/dev-ui/`** 를 붙여넣고 엔터!

> **💡 개념 돋보기: ADK Web UI (개발자용 플레이그라운드)**
> 
> > **비유: '주방 CCTV 모니터 + 주문 키오스크'**
> > 
> > 이 화면은 그냥 채팅창이 아니에요. **우리가 만든 에이전트의 뇌 속을 실시간으로 들여다보는 투명 창**이에요.
> > - **좌측 채팅창:** 손님(사용자) 역할. "주제: AI 부업" 입력.
> > - **우측/하단 이벤트 로그(Events/Traces):** **주방 CCTV.** 블로거가 플래너 도구 호출했네? → 플래너 내부에서 루프 돌고 있네? → 비평가가 "다시 써"라고 했네? → 라이터 도구 호출했네? → 블로거가 제목 달고 있네? **이 모든 과정이 타임라인별로 다 찍혀요.**
> > 
> > 이걸 봐야 **"어? 왜 개요가 이상하지?"** 할 때, 플래너 탓인지 라이터 탓인지, 프롬프트 탓인지 **즉각 진단**할 수 있어요. 콘솔 창에 `print` 찍어보며 디버깅하던 원시 시절과 작별하세요!

## 6. 첫 상호작용: "안녕, 블로거야?"

브라우저 창이 떴다면, 이제 우리 에이전트에게 첫 말을 걸어볼 차례예요. 스크립트에서는 *"To kick things off, I'm going to ask..."*라고 하며 시연을 시작하죠.

여러분도 채팅 입력창에 이렇게 쳐보세요.

> **사용자:** `안녕? 너는 누구야?`

블로거가 어떻게 답할까요? 아마 이렇게 답할 거예요.
> **블로거:** "안녕하세요! 저는 블로그 글 작성을 도와드리는 **'블로거(Blogger)'** 에이전트입니다. 작성하고 싶은 **주제(Topic)**를 주시면, 체계적인 기획부터 검증된 집필, 매력적인 제목과 홍보용 훅까지 **완성도 높은 블로그 포스트 한 편**을 통째로 만들어 드립니다. 어떤 주제로 글을 써드릴까요?"

자, 이제 **진짜 주제**를 던져볼까요?
> **사용자:** `생성형 AI를 활용해 직장인이 부업으로 월 100만 원 버는 현실적인 방법`

이제 **우측 이벤트 로그(Event/Trace 탭)**를 **눈을 떼지 말고 지켜보세요.**

1.  **`Function Call: robust_blog_planner`** 뜸 → **플래너 일 시작!**
2.  내부 이벤트들(`Model Response`, `Function Call: critique` 등) 주르륵 지나감 → **루프 도는 중!**
3.  **`Function Response: robust_blog_planner`** 뜸 → **개요 완성! (JSON 형태 확인 가능)**
4.  **`Function Call: robust_blog_writer`** 뜸 → **라이터 일 시작!**
5.  또 내부 이벤트들 주르륵 → **본문 쓰는 중!**
6.  **`Function Response: robust_blog_writer`** 뜸 → **본문 완성! (Markdown 확인 가능)**
7.  블로거 모델 응답(Model Response) 뜸 → **제목 3개, 훅 2개 직접 생성 중!**
8.  **최종 답변 완성!** 화면에 예쁘게 렌더링되어 나타남.

## 7. 마무리하며: 여러분은 이제 '에이전트 아키텍트'입니다.

자, 여기까지 오느라 정말 수고하셨어요. 방금 우리가 한 일을 정리해 볼게요.

1.  **문제 정의:** "블로그 글 쓰기"를 **계획/작성/검증/마무리** 단계로 분해함.
2.  **하위 에이전트 설계:** 각 단계를 맡을 **전문가(플래너, 라이터)**를 만들되, **자가 검증 루프(비평가 + 재시도 최대 3회)**를 심어 **'믿을 만한 도구'**로 만듦.
3.  **캡슐화:** 복잡한 루프를 **`FunctionTool`**로 감싸 **입력/출력만 깔끔한 인터페이스**로 제공.
4.  **오케스트레이션:** **루트 에이전트(블로거)**에게 도구 사용 순서만 지시하는 **단순하고 명확한 프롬프트** 부여.
5.  **실행 및 관찰:** `adk web`으로 런칭하고, **UI 트레이스**로 내부 동작을 검증하며 완성도 확인.

이게 바로 **'프롬프트 엔지니어링'을 넘어선 '에이전트 엔지니어링(Agent Engineering)'**의 첫걸음입니다. 더 이상 "프롬프트 잘 짜서 한 방에 되게 하기"가 아니라, **"신뢰할 수 있는 부품(도구)을 만들고, 조립 설명서(오케스트레이션)를 써서 시스템을 완성하기"**를 배운 거예요.

이제 이 파이프라인에 **'이미지 생성 도구'**, **'SEO 키워드 분석 도구'**, **'워드프레스 자동 발행 도구'**만 붙이면? **완전 자동화 콘텐츠 팩토리**가 되는 거죠.

**축하합니다! 여러분은 이제 첫 번째 프로덕션 레디(Production-ready) 에이전트 시스템을 설계하고 실행한 겁니다.** 🎉

다음 챕터에서는 이 시스템을 더 똑똑하게, 더 멋지게 확장하는 방법들(메모리 추가, 사람 피드백 루프(HITL) 넣기, 평가 시스템 구축 등)을 알아보러 갈게요. 그때까지 이 `adk web` 창 켜놓고 이것저것 주제 던져보면서 "아, 여기서 플래너가 저렇게 개요를 짜는구나", "라이터가 저 비평을 듣고 고쳤구나" 하며 **트레이스 읽는 눈**을 키워두세요. 그게 실력입니다!
