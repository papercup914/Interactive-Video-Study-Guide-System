# 챕터 2. 에이전트 이름 지정(BlogPlanner) 및 모델 설정(환경 변수 활용) - 나만의 AI 작가팀 채용하기

자, 지난 챕터에서 우리는 **UV라는 초고속 패키지 매니저**를 설치하고, 파이썬 가상환경이라는 '깨끗한 작업실'을 마련해 두었습니다. 이제 본격적으로 **'블로그 글쓰기 에이전트 팀'**을 꾸려볼 차례입니다.

가장 먼저 해야 할 일은 무엇일까요? 바로 **'팀장님(에이전트)께 명찰을 달아드리고, 어떤 두뇌(모델)를 쓸지 정해주는 일'**입니다. 사람으로 치면 입사 첫 날, 사원증을 받고 업무용 노트북(두뇌)을 지급받는 과정이죠.

## 1. 에이전트에게 '이름'을 지어주자: `name="BlogPlanner"`

코드상으로 가장 먼저 만나는 친구는 `LlmAgent` 클래스입니다. ADK에서 **LLM Agent(대언어모델 에이전트)**는 "생각하고 말하고 쓰는 역할"을 맡은 핵심 인력입니다. 우리가 만들 첫 번째 에이전트는 **'블로그 플래너(BlogPlanner)'**라는 역할을 맡을 친구예요.

```python
# agents/planner_agent.py
from google.adk.agents import LlmAgent

# 1. 에이전트 인스턴스 생성 (명찰 달아주기)
planner_agent = LlmAgent(
    name="BlogPlanner",  # <--- 바로 여기! 이 친구의 공식 이름입니다.
    model="gemini-2.0-flash", # 두뇌 모델 (나중에 환경변수로 분리할 거예요)
    description="블로그 주제를 받아 목차(아웃라인)를 짜는 기획자 에이전트",
    instruction="""
    당신은 전문 블로그 기획자입니다. 사용자가 준 주제를 분석하여 
    독자의 흥미를 끌 수 있는 논리적인 목차(Outline)를 5단계 내외로 작성하세요.
    """,
)
```

### 💡 개념 돋보기: 왜 `name`이 그렇게 중요할까?

> **📌 비유: 회사 조직도와 슬랙(Slack) 멘션(@이름)**
> 
> 여러분이 100명짜리 회사에 입사했다고 상상해 보세요. 여러분의 책상 위에 **'사원증(이름)'**이 없다면? 누가 여러분을 부르겠습니까? "저기요~" 하고 부르면 열 명이 돌아봅니다.
> 
> ADK 세계에서도 마찬가지입니다. **`name="BlogPlanner"`**는 이 에이전트의 **고유한 사원증이자, 다른 에이전트나 시스템이 이 친구를 호출할 때 쓰는 '핸들(Handle)'**입니다.
> 
> - **다른 에이전트가 위임할 때:** "야, **BlogPlanner**! 이 주제로 목차 좀 짜줘." (이름으로 지목)
> - **로그/디버깅할 때:** `[BlogPlanner] 작업 시작...` (누가 일했는지 식별)
> - **상태 저장/조회 시:** 세션 DB에 `BlogPlanner`의 작업 내역이 별도 저장됨.
> 
> **이름은 중복되면 안 됩니다.** `WriterAgent`라는 친구도 나중에 만들 텐데, 둘 다 `name="Agent"`로 해두면 시스템은 "누가 플래너고 누가 라이터야?" 하며 멘붕에 빠집니다. **역할이 곧 이름이 되게 짓는 것, 그게 정석입니다.**

## 2. 모델(Model) 설정: 에이전트의 '두뇌' 교체하기

위 코드에서 `model="gemini-2.0-flash"` 부분을 보셨나요? 이게 바로 에이전트의 **'두뇌'**입니다. LLM Agent는 스스로 지식을 가진 게 아니라, 지정된 거대 언어 모델(LLM)에게 "이거 생각해봐"라고 물어보고 답을 받아옵니다.

ADK에서는 이 모델을 문자열 하나로 뚝딱 갈아끼울 수 있습니다.
- `"gemini-2.0-flash"`: 구글 제미나이 최신 경량 모델 (빠르고 저렴)
- `"gemini-1.5-pro"`: 더 복잡한 추론 필요 시 (비쌈, 느림)
- `"gpt-4o"`: 오픈AI 모델 쓰고 싶다면? (ADK가 멀티모달 지원하며 연동 가능)

### 💡 개념 돋보기: 모델은 '셰프', 에이전트는 '레스토랑 매니저'

> **📌 비유: 주방장(모델) vs 매니저(에이전트)**
> 
> - **모델(LLM)**: **미슐랭 3스타 주방장**입니다. 재료(프롬프트/데이터)만 주면 세계 최고의 요리(텍스트 생성)를 해냅니다. 하지만 주방장은 **'손님 응대', '예약 관리', '재료 주문', '플레이팅 규칙'** 모릅니다. 그냥 요리만 잘해요.
> - **에이전트(LlmAgent)**: **능숙한 레스토랑 매니저**입니다. 주방장(모델)을 **고용(`model="..."`)**했습니다. 매니저는 손님(유저)을 맞이하고(`instruction`), 주문서(`input`)를 정리해서 주방장에게 넘기고, 나온 요리를 검수(`output_parser` 등)해서 손님에게 내줍니다.
> 
> **`model` 파라미터**는 **"우리 식당에 어떤 주방장을 모실까?"** 결정하는 인사 명령서와 같습니다. 오늘은 가성비 좋은 '제미나이 플래시' 셰프를 모셨네요!

## 3. 하드코딩은 이제 그만! 환경 변수(Environment Variables)로 모델 관리하기

그런데 위 코드처럼 `model="gemini-2.0-flash"`를 **코드 안에 박제(하드코딩)**해두면 큰일 납니다.

1.  **배포 환경 차이:** 로컬에서는 `flash` 쓰다가, 실제 서비스 올릴 땐 `pro`로 바꾸고 싶을 수 있음.
2.  **보안/키 관리:** 모델 이름 자체는 비밀이 아니지만, 이 모델을 쓰기 위한 **API Key**는 절대 코드에 적으면 안 됨 (깃허브 올렸다가 해킹당함).
3.  **유연성:** 코드 한 줄 안 고치고 `.env` 파일만 바꿔서 모델을 갈아치우고 싶음.

그래서 **환경 변수(.env 파일)**를 쓰는 게 정석입니다.

### 3-1. 프로젝트 루트에 `.env` 파일 만들기 (절대 Git에 올리지 마세요!)

```text
# .env (프로젝트 최상위 폴더에 생성)

# 사용할 LLM 모델 이름 지정
DEFAULT_MODEL="gemini-2.0-flash"

# 구글 AI 스튜디오나 Vertex AI에서 발급받은 API 키 (이건 진짜 비밀!)
GOOGLE_API_KEY="AIzaSyXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"

# 혹시 오픈AI 쓸 일 있으면 대비
# OPENAI_API_KEY="sk-XXXXXXXXXXXXXXXXXXXXXXXX"
```

> ⚠️ **중요 경고: `.gitignore`에 `.env` 반드시 추가하세요!**
> ```text
> # .gitignore
> .env
> __pycache__/
> *.pyc
> .venv/
> ```
> 이거 안 하면 API 키가 전 세계에 공개됩니다. **진짜로요.**

### 3-2. 파이썬에서 `python-dotenv`로 불러오기

이제 코드에서 이 값을 읽어와야겠죠? 파이썬 표준 라이브러리 `os` 모듈과, `.env` 파일을 자동으로 읽어주는 **`python-dotenv`** 패키지를 씁니다.

**먼저 패키지 설치 (UV로!):**
```bash
uv add python-dotenv
```
> **비유:** `uv add`는 **"우리 식당 창고에 '환경변수 읽기 도구'라는 신상 장비 하나 사다 놔"**라는 뜻입니다.

**코드 수정 (`agents/planner_agent.py`):**

```python
# agents/planner_agent.py
import os
from dotenv import load_dotenv
from google.adk.agents import LlmAgent

# 1. .env 파일 로드 (가장 위쪽에서 한 번만 호출하면 됨)
# 이렇게 하면 os.environ 에 .env 안의 키-값 쌍이 다 들어감
load_dotenv()

# 2. 환경 변수에서 모델 이름 꺼내오기 (없으면 기본값 fallback)
# os.getenv("키이름", "기본값")
model_name = os.getenv("DEFAULT_MODEL", "gemini-2.0-flash")

# 3. 에이전트 생성 시 변수 주입
planner_agent = LlmAgent(
    name="BlogPlanner",
    model=model_name,  # <--- 하드코딩된 문자열 대신 변수 사용!
    description="블로그 주제를 받아 목차(아웃라인)를 짜는 기획자 에이전트",
    instruction="""
    당신은 전문 블로그 기획자입니다. 사용자가 준 주제를 분석하여 
    독자의 흥미를 끌 수 있는 논리적인 목차(Outline)를 5단계 내외로 작성하세요.
    출력 형식은 마크다운 리스트로 해주세요.
    """,
)

# 테스트용: 이 파일을 직접 실행하면 모델 이름 찍히게 해두기
if __name__ == "__main__":
    print(f"✅ BlogPlanner 에이전트 로드 완료! 사용 모델: {model_name}")
```

### 💡 개념 돋보기: `load_dotenv()`와 `os.getenv()`의 동작 원리

> **📌 비유: 비서에게 '비밀 수첩' 건네주기**
> 
> 1.  **`.env` 파일** = **사장님만 보는 '비밀 수첩'**. (모델 이름, API 키 적혀 있음)
> 2.  **`load_dotenv()`** = **비서(파이썬 런타임)에게 "이 수첩 내용 좀 외워둬"라고 시키는 것.** 프로그램 시작 시 딱 한 번 실행하면, 비서가 수첩 내용을 **`os.environ`이라는 '머릿속 메모장'**에 다 적어둡니다.
> 3.  **`os.getenv("DEFAULT_MODEL")`** = **"비서야, 수첩에 'DEFAULT_MODEL'이라고 적힌 거 뭐야?"라고 묻는 것.** 비서가 메모장 보고 `"gemini-2.0-flash"`라고 알려줍니다.
> 4.  **두 번째 인자 `"gemini-2.0-flash"`** = **"수첩에 없으면 이거 기본으로 써"라고 비상용 지침 내리는 것.** (Fail-safe)
> 
> 이렇게 하면 **코드(로직)**와 **설정(값)**이 완벽히 분리됩니다. 나중에 모델 바꾸고 싶으면? 코드 건들일 필요 없이 `.env` 파일 열어서 `DEFAULT_MODEL="gemini-1.5-pro"`로 한 글자만 고치면 끝. **이게 바로 '설정의 외부화(Externalized Configuration)'라는 고급 아키텍처 패턴의 기초**입니다.

## 4. API 키는 어디에 쓰이나요? (ADK의 자동 처리)

여러분, `GOOGLE_API_KEY`는 `.env`에 넣었는데 **코드 어디에도 안 썼네요?** 이상하죠?

ADK(그리고 LangChain, LlamaIndex 같은 프레임워크들)은 **구글 제미나이 모델을 쓸 때, 자동으로 환경 변수 `GOOGLE_API_KEY` (또는 `GEMINI_API_KEY`)를 뒤져서 인증 헤더에 붙여줍니다.**

```text
[우리가 한 일]           [ADK 내부에서 일어난 일]
1. .env에 키 저장    -->  2. load_dotenv()로 os.environ에 적재
                      -->  3. LlmAgent(model="gemini...") 생성 시
                      -->  4. ADK 클라이언트 라이브러리가 
                          "어? 구글 모델이네? 그럼 os.environ['GOOGLE_API_KEY'] 
                          꺼내서 Authorization 헤더에 붙여야지!" 하고 자동 처리
```

> **📌 비유: 멤버십 카드 자동 인식**
> 
> 여러분이 헬스장(ADK)에 회원권(API Key)을 맡겨뒀다고 칩시다. `.env`에 넣어둔 건 **락커에 회원권 넣어둔 것**과 같습니다. `load_dotenv()`는 **락커 열어서 회원권 꺼내 목에 거는 행위**입니다.
> 
> 이제 여러분이 `LlmAgent`라는 **러닝머신(모델)**을 타려고 하면, 헬스장 시스템(ADK 런타임)이 **목에 걸린 회원권(API Key)을 자동으로 스캔**하고 "회원님 입장하세요~" 하고 돌려줍니다. 우리가 매번 "제 회원권 여기 있습니다" 하고 코드에 적을 필요가 없는 거죠.

## 5. 실전 팁: 에이전트별로 다른 모델 쓰기 (고급)

블로그 팀을 꾸리다 보면 **'기획자(Planner)'**는 빠르고 저렴한 `flash` 모델로 충분하지만, **'작가(Writer)'**는 문장력이 좋아야 하니 `pro` 모델을 쓰고 싶을 수 있습니다. 이럴 땐 `.env`에 모델 이름을 여러 개 정의해두면 됩니다.

**`.env` 확장:**
```text
# .env
PLANNER_MODEL="gemini-2.0-flash"   # 기획: 빠르고 싼 거
WRITER_MODEL="gemini-1.5-pro"      # 집필: 똑똑한 거
REVIEWER_MODEL="gemini-2.0-flash"  # 검수: 다시 싼 거
```

**코드에서 골라 쓰기:**
```python
# agents/planner_agent.py
planner_model = os.getenv("PLANNER_MODEL", "gemini-2.0-flash")
planner_agent = LlmAgent(name="BlogPlanner", model=planner_model, ...)

# agents/writer_agent.py
writer_model = os.getenv("WRITER_MODEL", "gemini-1.5-pro")
writer_agent = LlmAgent(name="BlogWriter", model=writer_model, ...)
```

이렇게 해두면 **운영 비용 최적화**가 코드 수정 없이 `.env` 한 줄로 가능해집니다. "이번 달 예산 빠듯하네? Writer도 flash로 돌려!"라고 `.env`만 바꿔서 내리면 끝이죠.

## 6. 요약 및 체크리스트: 이 챕터에서 우리가 한 일

이번 챕터는 화려한 기능 구현은 아니었지만, **'제대로 된 소프트웨어 공학의 기초 공사'**를 한 가장 중요한 시간이었습니다.

| 작업 | 코드/파일 | 비유 | 왜 중요한가? |
| :--- | :--- | :--- | :--- |
| **에이전트 명명** | `name="BlogPlanner"` | 사원증 발급 | 시스템 내 식별, 디버깅, 라우팅의 기준 |
| **모델 지정(하드코딩 지양)** | `model=model_name` | 주방장 고용 계약서 | 역할에 맞는 성능/비용의 두뇌 선택 가능 |
| **환경 변수 파일 생성** | `.env` | 비밀 수첩/락커 | 보안(API Key), 환경별 설정 분리, 배포 용이성 |
| **dotenv 로드 및 주입** | `load_dotenv()`, `os.getenv()` | 비서에게 수첩 암기시키기 | 코드와 설정 분리 (Clean Architecture 기초) |
| **Git 무시 설정** | `.gitignore` | 금고 잠그기 | **필수!** 키 유출 방지 |

## 💬 튜터의 한 마디

> **"이름 없고, 설정 하드코딩된 에이전트는 '프로토타입'일 뿐 '제품'이 될 수 없습니다."**
> 
> 지금 당장은 `print("Hello")`만 찍어도 신나지만, 나중에 에이전트가 10개, 20개로 늘어나고 팀원들과 협업하고 서버에 올릴 때가 되면 **"이 에이전트 이름이 뭐였더라?", "API 키 왜 코드에 박혀있어?"** 같은 사소한 것들이 **치명적인 버그와 보안 사고**로 돌아옵니다.
