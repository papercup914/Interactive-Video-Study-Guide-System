# 루트 에이전트 지시사항(Instruction) 작성: 지휘자, 주방장, 그리고 완성된 요리

자, 드디어 우리 '블로그 글쓰기 공장'의 마지막 퍼즐 조각, **'루트 에이전트(Root Agent)'**를 맞이할 시간이 왔습니다. 앞서 우리는 **'설계도(플래너)'**를 그리는 부서와 **'글쓰기(라이터)'**와 **'검수(체커)'**를 반복하는 부서를 각각 **'견고한 플래너 도구'**와 **'견고한 라이터 도구'**라는 멋진 자동 기계로 포장해 두었습니다.

이제 이 두 기계를 다루며 전체 오케스트라를 지휘할 **'총지배인(루트 에이전트)'**을 고용하고, 이 분에게 줄 **'업무 매뉴얼(Instruction)'**을 작성해 볼 차례입니다. 이 매뉴얼만 있으면 총지배인은 내부에서 어떤 복잡한 일이 벌어지는지 몰라도, 그저 버튼만 눌러 완벽한 블로그 글을 받아볼 수 있게 됩니다.

---

## 1. 총지배인의 책상 위에 놓인 두 개의 '마법 버튼'

가장 먼저, 우리 루트 에이전트(이름을 **'블로거(Blogger)'**라고 짓기로 했죠?)의 책상 위에는 **단 두 개의 버튼(도구)**만 놓여 있습니다.

1.  **플래너 도구 (Planner Tool):** "설계도 좀 뽑아줘!"라고 누르면, 내부에서 기획자와 검수자가 티격태격하며(루프 돌며) 완성된 **완벽한 목차(아웃라인)**를 뱉어주는 기계.
2.  **라이터 도구 (Writer Tool):** "본문 좀 써줘!"라고 누르면, 내부에서 작가와 교정자가 실랑이하며(루프 돌며) **검수 통과된 완성본 원고**를 뱉어주는 기계.

> **💡 개념 돋보기: 캡슐화(Encapsulation) - "블랙박스"의 마법**
>
> > **식당 주방의 비유로 이해해 보세요.**
> > 손님(사용자)이나 홀 매니저(루트 에이전트)는 주방 안에서 **'셰프가 재료를 다듬는지', '불 조절을 몇 번 하는지', '접시에 예쁘게 담는지'** 전혀 알 필요가 없습니다. 그저 **"김치찌개 하나 주세요(플래너 도구 호출)"**, **"공깃밥 추가요(라이터 도구 호출)"**라고 주문만 넣으면, 주방(내부 루프 시스템)이 알아서 복잡한 과정을 거쳐 **'맛있는 결과물'**만 서빙해 줍니다.
> >
> > 이렇게 **내부의 복잡한 로직(루프, 재시도, 검수)을 감추고, '입력 → 출력'이라는 단순 인터페이스만 바깥에 노출하는 것**을 프로그래밍에서는 **'캡슐화'**라고 부릅니다. 덕분에 루트 에이전트는 "플래너 내부에서 최대 3번 재시도한다"는 사실을 몰라도 됩니다. 그냥 "도구야, 일해라"라고만 시키면 되는 거죠.

## 2. '블로거' 총지배인의 업무 매뉴얼 (Instruction) 상세 해설

이제 이 총지배인에게 줄 **'지시사항(Instruction)'**을 한 줄 한 줄, 아주 구체적으로 작성해 보겠습니다. 이 지시사항이 곧 루트 에이전트의 **'뇌'**가 됩니다.

### 📋 매뉴얼 1단계: "손님(사용자)이 주제를 말하면, 일단 설계도부터 뽑아라!"

> **지시 문구 예시:** *"When a user gives it a topic, first it calls the planner tool to make an outline..."*
> (사용자가 주제를 주면, 가장 먼저 플래너 도구를 호출해서 아웃라인을 만드세요.)

*   **상황:** 사용자가 "요즘 뜨는 '생성형 AI로 여행 계획 짜기'에 대해 블로그 글 써줘"라고 말을 겁니다.
*   **행동:** 총지배인은 메모장에 '생성형 AI 여행 계획'이라고 적고, 바로 책상 왼쪽의 **<플래너 도구> 버튼**을 꾹 누릅니다.
*   **내부 동작 (총지배인은 모름):** 플래너 도구 내부에서는 기획자 에이전트가 목차를 짜고, 검수자 에이전트가 "이 목차는 1번이 빠져서 안 돼요, 다시 짜세요"라고 퇴짜 놓는 과정이 최대 3번 반복됩니다.
*   **결과:** 잠시 후, 플래너 도구에서 **"검수 완료된 깔끔한 목차(아웃라인)"**가 슉 하고 튀어 나옵니다.

> **💡 개념 돋보기: 순차적 작업 흐름 (Sequential Workflow) - "코스 요리처럼"**
>
> > **코스 요리 비유로 이해해 보세요.**
> > 식당에서 **에피타이저(목차) → 메인 요리(본문) → 디저트(제목/훅)** 순서로 나오는 것처럼, 에이전트도 **절대 동시에 하지 않고 순서대로** 처리합니다.
> > 만약 본문을 먼저 쓰라고 시키면? "목차도 없는데 무슨 내용으로 쓰냐"며 엉뚱한 글이 나옵니다. 그래서 **'먼저 플래너, 그다음 라이터'**라는 순서(Sequence)를 지시사항에 **명시적으로 못 박아주는 것**이 매우 중요합니다.

---

### 📋 매뉴얼 2단계: "설계도 나왔으니, 이제 본문 써라!"

> **지시 문구 예시:** *"...then it calls the writer tool to draft the full post..."*
> *(그러면 라이터 도구를 호출해서 전체 포스트 초안을 작성하세요.)*

*   **행동:** 총지배인은 방금 받은 **'완성된 목차(아웃라인)'**를 손에 쥐고, 책상 오른쪽의 **<라이터 도구> 버튼**을 누르며 말합니다. "이 설계도대로 본문 꽉 채워서 써줘."
*   **내부 동작 (총지배인은 모름):** 라이터 도구 내부에서는 작가 에이전트가 목차의 각 섹션별로 글을 쓰고, 체커 에이전트가 "여긴 설명이 부족해", "여기 사실 관계 틀렸어"라며 고치라고 돌려보내는 과정이 최대 3번 반복됩니다.
*   **결과:** 잠시 후, 라이터 도구에서 **"검수까지 다 끝난, 출판 직전의 완성된 본문"**이 뚝 하고 떨어집니다.

---

### 📋 매뉴얼 3단계: "다 썼으니, 이제 포장(마케팅) 좀 하자! 대체 제목 3개, 트윗 훅 2개"

> **지시 문구 예시:** *"...and finally it adds three alternative titles and two tweet-length hooks."*
> *(그리고 마지막으로 대체 제목 3개와 트윗 길이의 훅 2개를 추가하세요.)*

*   **상황:** 본문은 다 나왔습니다. 하지만 블로그 글의 생명은 **'클릭을 유도하는 제목'**과 **'공유를 부르는 한 줄 요약'**이죠.
*   **행동:** 총지배인은 완성된 본문을 쭉 읽어본 뒤, **자신이 직접**(별도 도구 호출 없이) 창의력을 발휘해 다음과 산출물을 만듭니다.
    1.  **대체 제목 3개:** 본 제목 말고, 다른 각도에서 끌리는 제목 3개 (예: "초보자를 위한...", "실패 없는...", "5분이면 끝내는...")
    2.  **트윗 훅 2개:** 트위터(X)나 스레드에 올렸을 때 280자 이내로 "이 글 꼭 읽어봐야 해!"라고 느끼게 할 매력적인 한 줄 요약 2개.
*   **최종 산출물:** 사용자에게 전달될 **'완성 패키지(본문 + 대체 제목 3개 + 트윗 훅 2개)'**가 준비됩니다.

## 3. 왜 루트 에이전트는 '두 개의 도구'만 알까? (통제의 미학)

스크립트에서는 이렇게 강조합니다.
> *"The root agent only has access to the two tools we exposed... So its workflow is clear and controlled."*

**총지배인(루트 에이전트)에게는 '플래너 도구'와 '라이터 도구' 딱 두 개만 보입니다.**
내부에 **'플래너 에이전트', '플래너 체커', '라이터 에이전트', '라이터 체커', '루프 에이전트(자동 재시도기)'** 등등 수많은 직원들이 바쁘게 움직이고 있지만, 총지배인은 그들의 존재조차 모릅니다.

### 이게 왜 좋을까요? (비전공자를 위한 3가지 이유)

> **💡 개념 돋보기: 관심사 분리(Separation of Concerns) - "각자 할 일만 하자"**
>
> > **회사 조직도 비유로 이해해 보세요.**
> > **사장님(루트 에이전트):** "기획팀장(플래너 도구)님, 기획안 뽑아주세요." → "제작팀장(라이터 도구)님, 기획안대로 제작해주세요." → "마무리 제가 할게요." (끝)
> > **기획팀장(플래너 도구):** 내부에서 팀원들(에이전트, 체커) 시켜서 검수하고, 재시도하고, 싸우고... 사장님은 모릅니다. 그냥 "완성본"만 줍니다.
> > **제작팀장(라이터 도구):** 마찬가지.
> >
> > 만약 사장님이 "기획팀 김 대리, 체커 박 대리, 너네 지금 몇 번째 싸우고 있어?"라고 일일이 간섭하면? **사장님 일이 너무 복잡해져서 망합니다.**
> > **도구(Tool)로 감싸서 추상화(Abstraction)하면, 사장님은 '복잡한 내부'를 몰라도 '단순한 외부 명령'만으로 거대한 시스템을 굴릴 수 있습니다.** 이게 바로 **'명확하고 통제된 워크플로우(Clear and Controlled Workflow)'**의 핵심입니다.

## 4. 전체 흐름 한눈에 보기: "주문 → 요리 → 서빙" 풀 스토리

자, 이제 우리가 만든 **'블로거(Blogger) 시스템'**이 사용자 요청을 받아 처리하는 全 과정을 영화 한 장면처럼 그려보겠습니다.

### 🎬 Scene 1: 주문 접수 (User Input)
> **사용자:** "챗GPT로 엑셀 업무 자동화하는 법 좀 써줘."

### 🎬 Scene 2: 총지배인 출동 (Root Agent: Blogger)
> **블로거(내부 독백):** "좋아, 내 매뉴얼(Instruction) 1번: 플래너 도구 호출!"

### 🎬 Scene 3: 주방 1 - 설계도 제작소 (Planner Tool 내부)
> *   **플래너 에이전트:** (급하게 목차 작성) "1. 도입, 2. 준비물, 3. 실습, 4. 마무리"
> *   **플래너 체커:** (꼼꼼히 검수) "음, 2번에 'API 키 발급'이 빠져있네. 3번 예시가 너무 어려워. **재시도 1회!**"
> *   **플래너 에이전트:** (수정) "1. 도입, 2. 준비물(API 키 포함), 3. 실습(초보 예시), 4. 마무리, 5. 꿀팁"
> *   **플래너 체커:** "오케이! 합격." (최대 3번까지 반복 가능)
> *   **결과물:** ✨ **완벽한 아웃라인** ✨ → 루트 에이전트에게 전달.

### 🎬 Scene 4: 총지배인 2차 지시
> **블로거(내부 독백):** "설계도 받았어. 매뉴얼 2번: 라이터 도구 호출! (설계도 넘기며) 이대로 써줘."

### 🎬 Scene 5: 주방 2 - 글쓰기 공장 (Writer Tool 내부)
> *   **라이터 에이전트:** (본문 작성 중...) "챗GPT로 엑셀 자동화하려면 일단 파이썬 깔고... (쭉쭉 작성)"
> *   **라이터 체커:** (빨간 펜으로) "여기 '파이썬 설치' 부분, 윈도우/맥 구분 안 했네. 코드 예시가 에러 나. **재시도 1회!**"
> *   **라이터 에이전트:** (수정) "윈도우는 이렇게, 맥은 저렇게... 수정된 코드 블록 넣음."
> *   **라이터 체커:** "좋아, 합격." (최대 3번 반복)
> *   **결과물:** ✨ **검수 완료된 풀 본문** ✨ → 루트 에이전트에게 전달.

### 🎬 Scene 6: 총지배인의 마무리 손질 (Root Agent: Final Touch)
> **블로거:** "본문 다 왔다. 이제 매뉴얼 3번: 나만의 센스로 포장하자."
> *   **대체 제목 3개 생성:**
>     1. "코딩 몰라도 된다! 챗GPT로 엑셀 노가다 10초 만에 끝내기"
>     2. "직장인 필수템: 챗GPT + 엑셀 자동화 입문 가이드"
>     3. "파이썬? 몰라도 돼요. 챗GPT가 대신 짜주는 엑셀 매크로"
> *   **트윗 훅 2개 생성:**
>     1. "칼퇴하고 싶다면? 이 글 하나로 엑셀 지옥 탈출하세요. 👇 [링크] #챗GPT #엑셀자동화 #직장인꿀팁"
>     2. "코딩 1도 모르는 제가 챗GPT로 주 3시간 야근을 0시간으로 만들었습니다. 비법 공유합니다. 🧵"

### 🎬 Scene 7: 최종 서빙 (Final Output)
> **사용자 화면에 표시:**
> **[본문 전문]** + **[대체 제목 3개]** + **[트윗 훅 2개]**
> **"자, 완성된 블로그 글 패키지입니다. 바로 발행하시면 됩니다!"**

## 5. 마무리하며: 당신이 작성한 첫 번째 '에이전트 스크립트'

자, 이렇게 해서 우리는 **단순한 챗봇을 넘어, '계획하고 → 검수하고 → 다시 쓰고 → 포장까지 하는' 자율적인 AI 워크플로우(에이전트 시스템)**를 하나 완성했습니다.

*   **Loop Agent**로 **"실패하면 다시 해"**라는 끈기를 심어줬고,
*   **Tool(도구)화**로 **"복잡한 건 내부에서 알아서 해, 난 결과만 쓸게"**라는 모듈화(부품화)를 이뤘고,
*   **Root Agent Instruction**으로 **"너는 1번, 2번, 3번 순서대로만 해"**라는 명확한 지휘 체계를 세웠습니다.

이것이 바로 **'에이전트 개발의 정석'**이자, 여러분이 방금 써내려간 **첫 번째 에이전트 스크립트**의 완결편입니다.

> **💡 튜터의 한 마디**
> > 처음에는 "왜 이렇게 복잡하게 도구로 감싸고, 루프 돌리고, 지시사항 적고... 그냥 한 번에 시키면 안 되나?" 싶으실 수 있어요. 하지만 **'신뢰할 수 있는 자동화'**를 만들려면 **"한 번에 완벽하게 되는 건 없다"**는 전제 하에, **실패를 감지하고(Checker), 자동으로 고치고(Retry), 큰 단위는 부품처럼 분리해서(Tool), 전체 흐름은 단순하게(Instruction)** 설계하는 이 과정이 **필수**입니다.
> >
> > 이제 이 틀(플래너-라이터-루트 구조)만 익혀두시면, **'블로그 글쓰기'뿐만 아니라 '코드 리뷰 봇', '여행 일정 짜기 봇', '쇼핑몰 상품 설명 작성 봇'** 등 무엇이든 이 위에 살만 붙여서 만드실 수 있습니다. 축하합니다! 당신은 이제 에이전트 아키텍트의 첫 발을 내디뎠습니다. 🎉
