# 📚 챕터 3: 검증 에이전트 구현의 기초 다지기 - 환경 설정과 '기획자(Planner)' 에이전트 탄생기

> **안내:** 요청하신 **'아웃라인 검증 체커(Outline Validation Checker)'**는 보통 **'기획자(Planner)가 작성한 초안을 검토하고, 합격할 때까지 되돌려 보내는 감독관 역할'**을 합니다. 하지만 제공해주신 영상 스크립트 구간은 이 검증 에이전트가 등장하기 직전, **'주방 오픈 준비(환경 설정)'와 '메뉴 기획자(Blog Planner) 채용'** 과정까지밖에 담고 있지 않습니다.
>
> 따라서 이번 가이드에서는 **검증 에이전트를 맞이하기 위해 반드시 갖춰야 할 '주방 인프라(ADK 구조 이해, UV 설치, 첫 번째 에이전트 생성)'**를 아주 상세하게 다뤄보겠습니다. 검증 에이전트는 "이 기획안이 합격한 건가?"라고 판단할 **'기준(기획안)'**이 있어야 비로소 일을 시작할 수 있기 때문입니다. 자, 튼튼한 기초 공사부터 시작해 볼까요?

---

## 1. ADK라는 '대형 레스토랑 주방'의 조직도 이해하기

코드를 한 줄도 쓰기 전에, 우리가 일하게 될 **Google ADK(Agent Development Kit)**라는 주방이 어떻게 돌아가는지 조직도부터 파악해야 합니다. 무작정 칼질(코딩)부터 하면 재료(데이터)가 어디 있는지, 누가 설거지(에러 처리)하는지 몰라 헤매게 되거든요.

영상에서는 ADK의 에이전트들을 **네 가지 직책**으로 나눠 설명합니다. 이걸 **'레스토랑 주방의 역할'**에 비유해 볼게요.

### 🍳 ADK 4대 직책, 주방에서는 이렇게 일합니다

| ADK 전문 용어 | 주방 비유 | 하는 일 | 핵심 특징 |
| :--- | :--- | :--- | :--- |
| **LLM Agent** | **수석 셰프 (Creative Chef)** | "김치찌개 레시피 짜줘", "블로그 글 써줘" 같은 **창의적 작업** 수행 | 거대 언어 모델(LLM)의 두뇌를 빌려 씀. **`model` 파라미터 필수** |
| **Workflow Agent** | **주방 총괄 매니저 (Flow Manager)** | "셰프 → 검수 → 플레이팅" **작업 순서(플로우)** 설계 및 관리 | 로직(코드)으로 흐름 제어. LLM 안 씀. **순차(Sequential), 병렬(Parallel), 반복(Loop)** 있음 |
| **Loop Agent** (Workflow의 일종) | **꼼꼼한 품질 검사관 (QC Manager)** | **"합격할 때까지 무한 반복"** 시키는 매니저 | 검증 실패 시 자동으로 이전 단계(셰프)에게 **"다시 해!"** 명령 |
| **Custom Agent** | **특수 임무 전담반 (Special Ops)** | 기존 도구로 안 되는 **완전 새로운 도구/로직** 직접 만듦 | `BaseAgent` 상속받아 파이썬 클래스로 직접 구현. 최후의 보루 |

> **💡 개념 돋보기: 왜 'Loop Agent'가 검증의 핵심인가?**
> > **여러분, 식당에서 요리 나갈 때 셰프가 한 번에 완벽하게 내나요?**
> > 아닙니다. 주방장이 "간 맞춰!", "불 조절해!" 하며 **접시가 완벽해질 때까지 되돌려 보냅니다.** 
> > ADK에서 **`Loop Agent`**가 바로 이 **'주방장'** 역할입니다. 안에 **`Planner Agent`(셰프)**와 **`Validation Agent`(검사관)**을 넣어두고, 검사관이 "불합격!"이라고 외치면 Loop Agent가 "자, 다시 기획해!"라고 플래너에게 시킵니다. **이 '자동 재시도 루프'가 ADK의 꽃**입니다.

## 2. 개발 환경 구축: '요리 도구(UV)'와 '식재료(ADK)' 준비하기

주방 조직도를 알았으니, 이제 실제 요리를 할 **개발 환경(IDE)**이라는 조리대에 도구를 깔아봅시다. 영상에서는 최신 파이썬 패키지 매니저인 **`uv`**를 강력 추천합니다.

### 🛠️ Step 1: `uv` 설치하기 (초고속 파이썬 도우미)

> **비유: `pip`가 '손수레'라면, `uv`는 '전동 지게차'입니다.**
> 파이썬 라이브러리 설치 속도가 **10~100배 빠르고**, 가상환경 생성/관리까지 자동으로 해줍니다. 요즘 파이썬 개발자 필수템이죠.

**터미널(명령 프롬프트)에 딱 한 줄만 복사해 넣으세요.**

```bash
# macOS / Linux (Homebrew 있는 경우)
brew install uv

# Windows (PowerShell 관리자 권한으로 실행)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 혹은 파이썬으로 설치 (어디서든 통함)
pip install uv
```
> **💡 꿀팁:** 설치 후 터미널을 **재시작**해야 `uv` 명령어가 먹힙니다. `uv --version` 치고 버전 번호 뜨면 성공!

### 📦 Step 2: Google ADK 설치하기 (주방 핵심 장비 반입)

이제 우리 주방에 **ADK라는 핵심 장비**를 들여놓습니다. `uv`를 쓰면 가상환경 만들기 -> 활성화 -> 설치가 **한 방**에 끝납니다.

프로젝트 폴더를 하나 만들고(예: `blog_agent_project`), 터미널에서 그 폴더로 이동(`cd blog_agent_project`)한 뒤 실행하세요.

```bash
# 1. 프로젝트 초기화 (pyproject.toml, .venv 폴더 자동 생성)
uv init

# 2. Google ADK 설치 (의존성 자동 해결되며 초고속 설치)
uv add google-adk

# 3. (선택) 환경 변수 관리용 라이브러리도 같이 깔아두면 편함
uv add python-dotenv
```
> **💡 개념 돋보기: `uv init`과 `uv add`의 마법**
> > 예전엔 `python -m venv venv` -> `source venv/bin/activate` -> `pip install ...` 세 단계였죠?
> > **`uv init`** 한 방이면 **가상환경 생성(`.venv`) + `pyproject.toml`(레시피 장부) 생성** 끝.
> > **`uv add 패키지명`** 한 방이면 **가상환경 활성화 + 설치 + 의존성 기록** 끝.
> > **이제 `source .venv/bin/activate` 치지 마세요!** `uv run python agent.py` 처럼 **`uv run` 앞에 붙이면 자동으로 그 환경에서 실행**됩니다.

## 3. 첫 번째 에이전트 생성: '블로그 기획자(Blog Planner)' 채용하기

자, 주방도 차렸고 도구도 들어왔습니다. 이제 **첫 번째 직원**을 뽑아볼까요? 영상에서는 `agent.py` 파일을 만들고 **`BlogPlanner`**라는 에이전트를 정의합니다.

### 📝 `agent.py` 파일 생성 및 중요 임포트

IDE(VS Code 추천)에서 프로젝트 폴더 안에 `agent.py` 파일을 만드세요. 그리고 맨 위에 이 친구들을 불러옵니다.

```python
# agent.py 최상단
import os
from dotenv import load_dotenv
from google.adk.agents import LlmAgent  # ★ 핵심: LLM 에이전트(수석 셰프) 클래스
from google.adk.tools import google_search  # (나중에 쓸 수 있는 도구 예시)

# .env 파일에서 API 키 등 환경 변수 로드
load_dotenv()
```

> **💡 개념 돋보기: `LlmAgent` vs `Agent` (구버전 주의!)**
> > 예전 ADK 튜토리얼 보면 `from google.adk.agents import Agent` 라고 된 게 많습니다.
> > **최신 ADK(0.3.0 이상)에서는 `LlmAgent`가 정식 명칭**입니다. `Agent`는 베이스 클래스고, 우리가 모델을 끼워 쓰는 실무용은 **`LlmAgent`**예요. 이거 틀리면 "모델이 없다" 에러 나니 꼭 `LlmAgent`로 임포트하세요!

---

### 🧑‍🍳 '블로그 기획자(Blog Planner)' 에이전트 정의하기

이제 영상 코드대로 **첫 번째 에이전트 객체**를 만듭니다. 이 친구의 임무는 **["사용자 주제" -> "구조화된 아웃라인(개요)"]** 변환입니다.

```python
# agent.py 이어서 작성

# 1. 사용할 모델 이름 가져오기 (보통 .env에 GEMINI_MODEL="gemini-1.5-flash" 등으로 저장)
MODEL_NAME = os.getenv("GEMINI_MODEL", "gemini-1.5-flash")

# 2. 블로그 기획자 에이전트 인스턴스 생성
blog_planner = LlmAgent(
    name="BlogPlanner",                    # 🏷️ 이름표 (로그/디버깅용 식별자)
    model=MODEL_NAME,                      # 🧠 뇌 (어떤 LLM 쓸지)
    description="사용자 주제를 받아 블로그 글의 구조화된 아웃라인을 작성하는 기획자", # 📋 인사말/용도 설명
    instruction="""                        # 📜 레시피 (가장 중요! 프롬프트 엔지니어링 영역)
    당신은 전문 블로그 기획자입니다.
    사용자가 준 '주제'를 분석하여, 독자가 읽기 좋은 논리적 구조의 **아웃라인(개요)**을 만들어주세요.
    
    **출력 형식 (마크다운):**
    ## 📌 블로그 제목 후보 (3가지)
    1. ...
    2. ...
    3. ...
    
    ## 🎯 타겟 독자 및 핵심 메시지
    - 타겟: ...
    - 핵심 메시지: ...
    
    ## 📖 상세 목차 (H2, H3 구조)
    ### 1. 서론: ...
       - 소주제 1-1
       - 소주제 1-2
    ### 2. 본론 1: ...
       ...
    ### 3. 결론: ...
    
    ## 💡 추천 키워드 (SEO용)
    - 키워드1, 키워드2, ...
    """,
    # tools=[google_search], # 필요시 검색 도구 장착 가능 (주석 처리됨)
)
```

## 4. 코드 라인별 '비하인드 스토리' 완전 해부

비전공자 입장에서 **"이게 왜 필요하지?"** 싶은 부분들을 일상 비유로 꽉꽉 채워 설명해 드립니다.

### ① `name="BlogPlanner"`: **'이름표 달기'**
> **비유: 주방에 '김셰프', '박셰프' 이름표 붙이는 거랑 똑같습니다.**
> 나중에 로그 찍히거나, Loop Agent가 "야, BlogPlanner 너 다시 해!"라고 부를 때 이 이름으로 찾습니다. **중복 안 되게, 역할 명확하게** 짓는 게 국룰입니다.

### ② `model=MODEL_NAME`: **'뇌 이식하기'**
> **비유: 셰프한테 '미슐랭 3스타 두뇌' vs '요리 학원 수료생 두뇌' 중 뭘 줄지 정하는 겁니다.**
> - `gemini-1.5-flash`: 빠르고 싼, **일 잘하는 주니어 셰프** (개발/테스트용 강추)
> - `gemini-1.5-pro`: 느리고 비싸지만 **천재 시니어 셰프** (복잡한 추론 필요할 때)
> 이걸 `.env` 파일(`GEMINI_MODEL=gemini-1.5-flash`)에 빼둔 건, **코드 안 고치고 모델만 갈아끼우게 하려고**입니다. 나중엔 `uv run python agent.py` 할 때 환경변수로 덮어쓰기도 쉽죠.

### ③ `description="..."`: **'채용 공고/소개글'**
> **비유: 이력서 맨 위에 한 줄 요약 **"블로그 기획 10년 차, 아웃라인 장인"** 쓰는 거랑 같습니다.**
> 이 에이전트를 **다른 에이전트(예: 감독관 에이전트)가 "누구 쓸까?" 둘러볼 때 읽는 메타데이터**입니다. 사람이 읽는 용도도 있지만, **에이전트 간 위임(Delegation) 시 LMT가 이 설명 보고 "아, 기획은 얘한테 맡기면 되겠네?" 판단**합니다. **대충 쓰지 마세요!**

### ④ `instruction="..."`: **'비밀 레시피 장부 (시스템 프롬프트)'**
> **💡 개념 돋보기: 여기가 '프롬프트 엔지니어링'의 전장입니다**
> > **이 문자열 하나가 이 에이전트의 '성격', '실력', '출력 포맷'을 100% 결정합니다.**
> > - **역할 부여(Role):** "당신은 전문 블로그 기획자입니다." -> 페르소나 심기
> > - **작업 정의(Task):** "주제를 분석하여 아웃라인 만들기" -> 뭘 할지 명확히
> > - **출력 강제(Format):** "마크다운, H2/H3 구조, 제목 후보 3개..." -> **파싱(후처리) 쉽게 하려고 틀 고정**
> > - **제약 조건(Constraints):** "SEO 키워드 포함", "타겟 독자 명시" -> 품질 올리기
> 
> **💡 실전 팁:** 이 `instruction`은 **외부 파일(`prompt.txt`)로 빼서 읽어오게** 짜는 게 유지보수에 최고입니다. 코드랑 프롬프트 섞이면 나중에 수정하다 코드 망가뜨려요.

## 5. 지금까지 만든 것의 '위치'와 '다음 단계' 예고

자, 지금까지 우리는 **`agent.py`** 안에 **`blog_planner`**라는 **'훌륭한 기획자 한 명'**을 고용했습니다.

```text
[현재 우리 주방 상태]
┌─────────────────────────────────────┐
│  agent.py                           │
│  ┌───────────────────────────────┐  │
│  │ blog_planner (LlmAgent)       │  │  ← "주제 줘봐, 아웃라인 뽑아줄게"
│  │  - name: "BlogPlanner"        │  │
│  │  - model: gemini-1.5-flash    │  │
│  │  - instruction: (비밀 레시피)  │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

**하지만 아직 검증 에이전트(Outline Validation Checker)는 없습니다!**
지금 상태론 기획자가 **"이상한 아웃라인"**을 내놔도 **"그래, 수고했어"** 하고 끝납니다. 

> **다음 챕터(다음 영상 구간)에서 우리가 할 일:**
> 1. **`OutlineValidator` 에이전트 만들기** (검사관 채용: "이 아웃라인 합격/불합격 판단해!")
> 2. **`LoopAgent`로 둘 묶기** (주방장 임명: "불합격이면 기획자한테 다시 시켜!")
> 3. **실행 테스트하기** (`uv run python agent.py`로 주문 넣기)
