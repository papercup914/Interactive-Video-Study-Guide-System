# 챕터 4. 터미널 실행 명령어 숙지 및 로컬 웹 UI 접속 방법: 내 에이전트에게 날개를 달아주자

자, 드디어 우리가 직접 코드로 작성한 '블로거(Blogger) 에이전트'라는 멋진 로봇 직원을 완성했습니다. 플래너(기획자)와 라이터(작가)라는 두 명의 유능한 팀원도 채용했고, 루트 에이전트(총괄 매니저)가 이들을 지휘하는 시스템도 완벽하게 갖췄습니다. 그런데 이 로봇 직원이 책상 서랍 속에만 들어있다면 아무 소용이 없겠죠? 이제 **'전원 버튼'을 누르고, '사무실 문'을 열어서 실제로 일하게 만들어야 합니다.**

이번 챕터에서는 우리가 작성한 파이썬 코드를 **터미널(명령 프롬프트)**이라는 콘솔 창에서 실행시키는 마법의 주문(명령어)을 배우고, 실행된 에이전트와 대화할 수 있는 **로컬 웹 UI(관리자 페이지)**에 접속하는 방법까지 아주 세세하게 알아보겠습니다. 컴퓨터를 잘 모른다고요? 걱정 마세요. 우리가 매일 쓰는 '식당'과 '주방'에 비유해서 하나하나 차근차근 설명해 드릴게요.

## 1. 터미널이란? - '주방으로 통하는 직통 인터폰'

가장 먼저 **터미널(Terminal)** 혹은 **명령 프롬프트(Command Prompt)**, **쉘(Shell)**이라는 낯선 단어를 마주하게 됩니다. 비전공자분들께는 검은 화면에 하얀 글씨만 깜빡이는 이 화면이 가장 무섭고 어려운 장애물일 수 있어요.

> **💡 개념 돋보기: 터미널(Terminal) = 주방장(컴퓨터)에게 직접 주문하는 인터폰**
> 
> 우리가 평소에 쓰는 윈도우나 맥의 예쁜 화면(GUI, 그래픽 사용자 인터페이스)은 **'홀 서빙 직원'**과 같습니다. "메뉴판 좀 주세요", "물 한 잔 주세요" 같은 쉬운 말로 시키면 직원이 주방에 가서 음식을 가져다주죠. 편하지만, 메뉴판에 없는 특별 주문("양파 빼주세요, 매운 소스 두 배로 해주세요")을 하려면 복잡해집니다.
> 
> 반면 **터미널(CLI, 명령줄 인터페이스)**은 **'주방장(운영체제/컴퓨터)에게 직접 대면해서 주문하는 직통 인터폰'**입니다. "파일 복사해", "프로그램 실행해", "폴더 만들어" 같은 **명령어(Command)**를 텍스트로 정확하게 말하면, 주방장이 군말 없이 바로 실행해 줍니다. 서빙 직원을 거치지 않으니 훨씬 빠르고, 정교한 제어가 가능하죠. 우리가 에이전트를 실행하는 건 "메뉴판에 없는 스페셜 요리(내가 만든 코드 실행)"를 주방장에게 직접 시키는 일이기 때문에, 이 터미널이라는 인터폰을 반드시 사용해야 합니다.

**윈도우에서는?** 시작 메뉴에서 `cmd` 또는 `PowerShell`을 검색해서 실행하세요. (관리자 권한으로 실행하면 더 좋습니다.)
**맥(Mac)에서는?** `Command + Space`를 눌러 `터미널(Terminal)`을 검색해서 실행하세요.

## 2. '작업 폴더'로 이동하기 - "주방장, 오늘 일할 식당으로 가자!"

터미널을 켜면 보통 `C:\Users\내이름>` 또는 `/Users/내이름 ~ %` 같은 프롬프트가 뜹니다. 이건 **'현재 내 위치가 집(홈 디렉토리)'**이라는 뜻이에요. 하지만 우리 에이전트 코드(레시피)와 재료들(파일들)은 **'프로젝트 식당(프로젝트 폴더)'**에 차려져 있습니다. 주방장에게 "일해!"라고 시키려면, 먼저 주방장이 그 식당 앞에 서 있어야겠죠?

> **💡 개념 돋보기: `cd` 명령어 = 택시 타고 목적지(폴더)로 이동하기**
> 
> `cd`는 **Change Directory(디렉토리 변경)**의 약자입니다. 터미널에서 `cd 폴더경로`를 치고 엔터를 치면, 현재 위치를 그 폴더로 순간이동시킵니다.
> 
> **예시 상황:**
> 내 문서 폴더 안에 `my_adk_project`라는 폴더를 만들었다면?
> ```bash
> # 윈도우의 경우
> cd Documents\my_adk_project
> 
> # 맥/리눅스의 경우
> cd Documents/my_adk_project
> ```
> **꿀팁 (Tab 키의 마법):** `cd Doc`까지만 치고 **Tab 키**를 눌러보세요. 자동으로 `Documents\`가 완성됩니다. `cd my_a` 치고 Tab -> `my_adk_project\` 완성. 오타 없이 빠르게 이동하는 필수 기술이니 꼭 익히세요!

제대로 이동했는지 확인하려면 `dir`(윈도우) 또는 `ls`(맥/리눅스)를 쳐서 파일 목록을 보세요. 우리가 만든 `agent.py`나 `__main__.py` 같은 파일이 보이면 **출근 완료**입니다.

## 3. ADK 웹 서버 실행 명령어 - "영업 개시! 손님 맞을 준비 해!"

이제 가장 중요한 순간입니다. 우리가 만든 에이전트 코드를 실행해서 **웹 서버(Web Server)**를 띄워야 합니다. 이 웹 서버가 바로 **'에이전트와 대화할 수 있는 웹 페이지(UI)'**를 우리 컴퓨터 안에서 만들어주는 역할을 합니다.

스크립트에서 언급된 명령어는 바로 이겁니다.

```bash
adk web
```

> **💡 개념 돋보기: `adk web` = "임시 식당 오픈 및 웹사이트 개설" 한 방에 끝내기**
> 
> 이 명령어 한 줄이 뒤에서 엄청난 일을 벌입니다. 비유하자면:
> 1.  **건물 짓기:** 내 컴퓨터 안에 임시로 웹 서버라는 건물을 세웁니다. (보통 `http://localhost:8000` 또는 `http://127.0.0.1:8000` 주소로 열림)
> 2.  **주방 세팅:** 우리가 작성한 파이썬 코드(`agent.py` 등)를 읽어서, 플래너와 라이터 에이전트를 메모리에 올리고 초기화합니다. (로봇 직원들 대기시킴)
> 3.  **홀 준비:** 브라우저에서 접속했을 때 볼 수 있는 예쁜 관리자 페이지(UI) 파일을 서빙할 준비를 합니다.
> 4.  **영업 시작:** "손님(나) 오면 바로 응대할게!" 하고 대기 상태로 들어갑니다.
> 
> **중요!** 이 명령어를 치고 엔터를 치면 **커서가 깜빡거리며 멈춰 있습니다.** 에러가 난 게 아닙니다! **"서버가 정상적으로 돌아가고 있으니 꺼지지 말고 기다려달라"**는 뜻이에요. 이 창은 **절대 끄지 마세요!** 이 창을 끄면 서버가 멈추고 웹 페이지도 닫힙니다. 이 터미널 창은 **'서버 엔진 실린더'** 같은 역할이라 계속 켜둬야 합니다.

실행 후 터미널에 대략 이런 메시지가 뜨면 성공입니다.
```text
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started server process [12345]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
```
*   `http://127.0.0.1:8000` 또는 `http://localhost:8000`이 바로 **우리 식당의 주소**입니다.
*   `Press CTRL+C to quit`은 "일 다 끝났으면 Ctrl+C 눌러서 서버 꺼"라고 알려주는 친절한 안내문입니다.

## 4. 로컬 웹 UI 접속하기 - "손님(나)이 식당에 입장하다"

서버가 돌아가는 터미널 창은 **그대로 둔 채**, 이제 **웹 브라우저(크롬, 엣지, 사파리 등)**를 여세요. 주소창에 터미널에 뜬 주소를 칩니다.

> **💡 개념 돋보기: `localhost` (127.0.0.1) = "내 컴퓨터 자신" = "내 방 안의 비밀 아지트"**
> 
> 인터넷 주소(`naver.com`, `google.com`)는 **'남의 집 주소'**입니다. 하지만 `localhost` 또는 `127.0.0.1`은 **'우리 집(내 컴퓨터) 주소'**입니다. 인터넷이 연결 안 되어도, 와이파이가 터지지 않는 깊은 산속에서도 **내 컴퓨터 안에서만 돌아가는 서비스**에 접속할 수 있는 마법의 주소예요.
> 
> *   **Port 8000 (`:8000`)**: 집 안에 문이 여러 개 있는데, 8000번 방 문을 두드려서 들어가겠다는 뜻입니다. (보통 웹은 80번, 개발용은 3000, 8000, 8080번 등을 씁니다.)

브라우저에 `http://localhost:8000`을 치고 엔터를 누르면... 짠! **Google ADK의 공식 웹 관리자 페이지(ADK Web UI)**가 나타납니다.

## 5. ADK 웹 UI 화면 뜯어보기 - "최첨단 주방 관제실"

처음 보는 화면이라 당황스러울 수 있어요. 하지만 차근차근 보면 우리가 설계한 구조와 똑같이 생겼습니다.

1.  **왼쪽 사이드바 (에이전트 선택창):**
    *   여기서 실행할 에이전트를 고릅니다. 우리가 만든 `Blogger` (또는 프로젝트명/루트 에이전트 이름)가 목록에 떠 있을 겁니다. 클릭해서 선택하세요.
    *   *비유: "오늘 일할 총괄 매니저(Blogger) 호출하기"*

2.  **중앙 채팅 창 (대화 영역):**
    *   하단에 `Type a message...` 입력창이 있습니다. 여기가 **사용자(나)가 에이전트에게 지시하는 곳**입니다.
    *   *비유: "매니저에게 주문서(프롬프트) 내밀기"*

3.  **우측/하단 패널 (이벤트/로그/상태 창 - 매우 중요!):**
    *   ADK 웹 UI의 꽃입니다. 에이전트가 **생각하는 과정(Planning)**, **툴을 호출하는 순간(Tool Call)**, **결과를 받는 순간(Tool Response)**이 **실시간 로그(Event Stream)**로 뜹니다.
    *   *비유: "주방 CCTV로 요리 과정 실시간 중계 보기"*

## 6. 첫 미션 실행: "AI 에이전트 탑 10 유즈케이스 블로그 써줘"

자, 이제 스크립트에서 했던 것처럼 첫 주문을 넣어봅시다. 채팅 입력창에 이렇게 타이핑하고 엔터를 치세요.

> **"AI 에이전트의 탑 10 유즈케이스(활용 사례)에 대한 블로그 글을 써줘."**

그럼 화면에서 어떤 일이 벌어질까요? 눈 크게 뜨고 보세요. 이게 바로 **에이전틱 워크플로우(Agentic Workflow)**의 실체입니다.

### 단계 1: 플래너(기획자) 호출 - 🧠 "생각 중..."
*   우측 로그 창에 `function_call: planner` 같은 로그가 뜹니다.
*   루트 에이전트(총괄)가 **"일단 기획부터 해야지"**라며 `planner` 툴(도구)을 호출한 겁니다.
*   잠시 후 `function_response: planner`가 뜨고, **목차(Outline)**가 짜인 게 보입니다. "1. 서론, 2. 고객 서비스 자동화, 3. 코드 생성..." 식으로요.

### 단계 2: 라이터(작가) 호출 - ✍️ "초안 작성 중..."
*   플래너가 짠 목차를 들고 루트 에이전트가 **"자, 작가야 이 목차대로 써"**라며 `writer` 툴을 호출합니다.
*   `function_call: writer` 로그 확인.
*   스트리밍(Streaming) 방식으로 글이 **토큰 단위로 쭉쭉 써지는 모습**이 중앙 채팅창에 실시간으로 나타납니다. (타자기 치듯 한 글자씩 나오는 그 맛!)

### 단계 3: 후처리(제목/훅 생성) - ✨ "마무리 작업 중..."
*   스크립트 설명대로, 작성이 끝나면 루트 에이전트는 **"좋아, 이제 제목 3개랑 트윗 훅 2개만 뽑으면 끝"**이라며 내부 로직(또는 추가 툴 호출)을 돌립니다.
*   최종 결과물로 **본문 + 대체 제목 3개 + 트윗용 훅 2개**가 깔끔하게 포장되어 화면에 출력됩니다.

## 7. 트러블슈팅: "왜 안 되지?" 대표 케이스 3가지

처음엔 당연히 안 되는 게 정상입니다. 당황하지 말고 아래 체크리스트를 확인하세요.

| 증상 | 원인 (비유) | 해결 방법 |
| :--- | :--- | :--- |
| **`'adk' is not recognized...`** <br> (명령어를 찾을 수 없음) | **주방장(OS)이 'adk'라는 도구(명령어)를 모름.** <br> ADK 라이브러리 설치 안 했거나, PATH 설정 안 됨. | 1. `pip install google-adk` 로 설치 확인.<br>2. 파이썬 가상환경(venv) 켜져 있는지 확인 (터미널 앞에 `(venv)` 떠야 함). |
| **`Error: Could not find agent...`** <br> (에이전트 못 찾음) | **식당(프로젝트 폴더) 위치를 못 찾음.** <br> `cd`로 프로젝트 루트 폴더(agent.py 있는 곳) 안 들어감. | `cd` 명령어로 `agent.py` 또는 `__main__.py`가 있는 **최상위 폴더**로 이동 후 다시 `adk web` 실행. |
| **브라우저에서 `localhost:8000` 안 열림 / 흰 화면** | **문(포트) 막힘 / 서버 안 뜸.** <br> 백신/방화벽 차단, 또는 다른 프로그램이 8000번 포트 사용 중. | 1. 터미널 에러 로그 확인 (빨간 글씨).<br>2. `adk web --port 8080` 처럼 다른 포트 지정해보기.<br>3. 크롬 시크릿 모드(캐시 없음)로 접속 시도. |
| **에이전트가 "모르겠다"거나 엉뚱한 소리 함** | **레시피(프롬프트/코드) 오류.** <br> `instruction` 지시문이 약하거나, 툴 등록(`tools=[planner, writer]`) 누락. | 코드 열어서 `root_agent` 정의 부분, `tools` 리스트, `instruction` 문자열 다시 확인. |

## 8. 마무리하며: 당신은 이제 '에이전트 운영자'입니다

축하합니다! 방금 당신은:
1.  **터미널**이라는 강력한 인터폰으로 주방장(컴퓨터)에게 직접 명령을 내렸고,
2.  `adk web` 한 줄로 **웹 서버 구축 + 에이전트 로딩 + UI 제공**이라는 복잡한 인프라를 순식간에 세웠고,
3.  **브라우저**라는 프라우저**로 접속해 **눈에 보이지 않는 에이전트들의 협업 과정(기획 -> 작성 -> 검수)**을 CCTV 보듯 지켜보며,
4.  **"AI 에이전트 탑 10 유즈케이스"라는 완성도 높은 블로그 글**을 자동으로 뽑아냈습니다.

이게 바로 **Google ADK(Agent Development Kit)**가 주는 마법 같은 개발자 경험(DX)입니다. 복잡한 랭체인(LangChain) 체인 구성, 메모리 관리, 스트리밍 처리, 툴 바인딩... 이런 골치 아픈 보일러플레이트 코드 **한 줄도 안 짜고** 말이죠.

이제 이 `adk web` 터미널 창은 **당신의 '에이전트 관제탑'**입니다. 여기에 새로운 에이전트 코드를 짜서 넣기만 하면, 즉시 웹에서 테스트하고 디버깅하고 배포할 준비가 끝납니다.
