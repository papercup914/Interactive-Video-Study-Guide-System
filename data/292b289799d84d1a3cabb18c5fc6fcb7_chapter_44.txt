# 챕터 5: ADK 웹(ADK Web)을 활용한 에이전트 실행 및 테스트 - 내 에이전트에게 날개를 달아주자

자, 드디어 우리가 직접 작성한 첫 번째 에이전트 스크립트, **'블로거(Blogger)'**가 완성되었습니다. 이전 챕터에서 우리는 '기획자(플래너)'와 '작가(라이터)'라는 두 명의 유능한 직원을 고용하고, 그들을 지휘할 '팀장(루트 에이전트)'을 임명했었죠. 팀장에게는 "사용자가 주제를 주면 -> 기획자에게 개요를 시키고 -> 작가에게 초안을 시키고 -> 마지막으로 제목 3개와 트윗용 훅 2개를 덧붙여라"라는 아주 명확한 업무 매뉴얼(Instruction)도 넘겨주었습니다.

이제 잘 짜여진 이 설계도가 종이 위에서만 존재하는 게 아니라, **실제로 움직이게 만드는 순간**이 왔습니다. 이 챕터에서는 우리가 만든 에이전트를 **터미널(명령 프롬프트)에서 깨워서**, **웹 브라우저라는 편리한 창을 통해 직접 눈으로 확인하고 대화하는 방법**을 배워보겠습니다.

---

## 1. 에이전트 실행, 어렵게 생각하지 마세요: "식당 오픈 준비하기"

프로그래밍을 처음 접하는 분들에게 '터미널에서 명령어를 친다'는 건 마치 주방에 처음 들어가 칼을 쥐는 것처럼 두렵게 느껴질 수 있습니다. 하지만 걱정 마세요. 이건 그저 **식당 오픈 전에 전등 켜고, 간판 불 밝히고, 손님 맞을 준비하는 과정**과 똑같습니다.

우리가 작성한 파이썬 코드(스크립트)는 아직 **'레시피 북(설계도)'**일 뿐입니다. 이 레시피 북을 실제 요리(에이전트 작동)로 만들기 위해 주방(컴퓨터)에 "자, 이제 요리 시작해!"라고 신호를 보내는 명령어가 바로 `adk web`입니다.

### 💡 개념 돋보기: `adk web` 명령어란?
> **비유: 식당의 '자동 문 열기 버튼' + '홀 매니저 고용'**
>
> *   **`adk`**: 구글이 만든 에이전트 개발 도구 키트(ADK)라는 도구 상자 이름입니다.
> *   **`web`**: "이 에이전트를 웹 브라우저에서 볼 수 있게 띄워줘"라는 뜻입니다.
> *   이 한 줄을 치면, 내 컴퓨터 안에서 에이전트가 돌아가기 위한 임시 서버(식당 주방)가 켜지고, 내가 웹 브라우저(손님 입장)로 들어가서 에이전트와 채팅할 수 있는 예쁜 화면(홀)이 자동으로 차려집니다. 복잡한 서버 설정, 포트 포워딩, 프론트엔드 코딩... 이 모든 걸 이 명령어 하나가 **'원클릭'**으로 해결해 줍니다.

## 2. 실전: 터미널에서 마법의 주문 외우기

자, 이제 직접 해봅시다. 맥(Mac)을 쓰시면 '터미널(Terminal)' 앱을, 윈도우(Windows)를 쓰시면 '명령 프롬프트(cmd)'나 '파워셸(PowerShell)', 아니면 VS Code 하단의 **터미널 탭**을 여세요.

### 단계 1: 내 프로젝트 폴더로 이동하기 (식당 위치로 가기)
가장 먼저, 우리가 코드를 저장해둔 폴더(디렉토리)로 들어가야 합니다. 터미널은 기본적으로 '내 문서'나 '사용자 폴더'에 있는데, 우리 코드는 아마 `my_agent_project` 같은 폴더 안에 있을 겁니다.

```bash
cd 내_프로젝트_폴더_경로
```
*예시: `cd Documents/my_adk_agent`*

> **💡 팁 (초보자를 위한 꿀팁):**
> 폴더 경로 외우기 힘드시죠? 폴더를 터미널 창으로 **드래그 앤 드롭**하세요! `cd `라고 치고 스페이스바 한 번 누른 뒤, 탐색기(파인더)에서 폴더를 터미널 창으로 끌어서 놓으면 경로가 자동으로 입력됩니다. 엔터만 치면 끝!

### 단계 2: 가상 환경 활성화하기 (위생 장갑 끼기)
이전 챕터에서 `python -m venv .venv`로 만든 가상 환경, 기억나시죠? 아직 켜져 있지 않다면 꼭 켜주세요. 이게 내 프로젝트만의 깨끗한 주방 환경을 만드는 겁니다.

*   **맥/리눅스:** `source .venv/bin/activate`
*   **윈도우 (파워셸):** `.venv\Scripts\Activate.ps1`
*   **윈도우 (CMD):** `.venv\Scripts\activate.bat`

터미널 맨 앞에 `(.venv)`라고 뜨면 성공입니다!

### 단계 3. 대망의 실행 명령어: `adk web` (오픈 간판 켜기)

자, 드디어 주인공이 등장합니다. 터미널에 딱 이 한 줄을 치고 엔터를 누르세요.

```bash
adk web
```

## 3. 실행 화면 읽기: "주방에서 들려오는 소리들"

엔터를 치자마자 화면에 뭔가 주르륵 글자가 뜰 겁니다. 당황하지 마세요. 이건 에이전트가 "나 지금 일어나고 있어!", "도구들 챙겼어!", "서버 켰어!"라고 보고하는 **시동 로그**입니다.

### 주요 로그 해석해보기

```text
INFO:     Started server process [12345]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

*   **`Started server process`**: 웹 서버 프로세스가 시작되었어요. (가스불 켬)
*   **`Application startup complete`**: 내 에이전트 코드(블로거, 플래너, 라이터)가 메모리에 다 올라갔어요. (재료 손질 완료)
*   **`Uvicorn running on http://127.0.0.1:8000`**: **이게 제일 중요합니다!** 내 컴퓨터(`127.0.0.1` = localhost)의 **8000번 문(port)**으로 손님을 받겠다는 뜻입니다.

> **💡 개념 돋보기: `127.0.0.1:8000` (로컬호스트와 포트)**
>
> *   **`127.0.0.1` (Localhost)**: **"내 집(내 컴퓨터)"**을 가리키는 약속된 주소입니다. 인터넷이 끊겨도 내 컴퓨터 안에서는 통합니다.
> *   **`:8000` (Port)**: 집 현관문 번호입니다. 80번은 일반 웹사이트, 443번은 보안 사이트, **8000번은 개발용 임시 문**으로 많이 씁니다.
> *   즉, **"내 컴퓨터 8000번 문으로 오세요, 거기 식당 열려있어요"**라는 뜻입니다.

## 4. 브라우저에서 에이전트 만나기: "손님 입장하기"

이제 터미널은 그대로 둔 채(끄지 마세요! 서버가 꺼집니다), **크롬(Chrome)이나 엣지(Edge), 사파리(Safari) 같은 웹 브라우저**를 여세요.

주소창에 방금 본 주소를 똑같이 칩니다.

> **`http://127.0.0.1:8000`**
> *(또는 `http://localhost:8000` 도 똑같이 작동합니다)*

엔터를 치면... 짠! **ADK 웹 UI(사용자 인터페이스)**라는 깔끔한 채팅 화면이 나타납니다. 별도의 HTML/CSS/자바스크립트 코드 한 줄 안 쓰고, 우리가 `adk web` 한 번 쳤을 뿐인데 말이죠.

### 화면 구성 뜯어보기 (식당 내부 구경)

1.  **왼쪽 사이드바 (메뉴판/직원 명부):**
    *   **Agents 드롭다운**: 현재 실행 중인 에이전트 목록입니다. 우리는 `Blogger`(루트 에이전트) 하나만 보일 겁니다. 나중에 서브 에이전트들이 여기 목록에 뜨기도 합니다.
    *   **Sessions**: 대화 히스토리입니다. "새 대화(New Session)"를 누르면 깨끗한 상태에서 시작할 수 있습니다.
2.  **가운데 큰 화면 (홀/식탁):**
    *   에이전트와 주고받는 **대화 내역**이 실시간으로 뜹니다.
    *   사용자(나) 말풍선, 에이전트 말풍선이 카카오톡처럼 보입니다.
3.  **아래쪽 입력창 (주문서):**
    *   여기에 내용을 입력하고 엔터(또는 전송 버튼)를 치면 에이전트에게 전달됩니다.

## 6. 눈앞에서 펼쳐지는 마법: "주방 오픈 키친 구경하기"

이게 ADK Web의 **킬러 기능(Killer Feature)**입니다. 단순히 "답변이 나왔다"만 보여주는 게 아니라, **에이전트 머릿속에서 무슨 일이 벌어지는지 단계별로 다 보여줍니다.**

화면을 유심히 보세요. 다음과 같은 흐름으로 **'생각의 과정(Thought)'**과 **'도구 호출(Tool Call)'**이 실시간으로 뜹니다.

### 단계 1: 루트 에이전트(Blogger)의 판단 (생각)
> **💭 Blogger (Thought):**
> *"사용자가 'AI 에이전트 활용 사례 10가지' 블로그를 원하네. 내 매뉴얼(Instruction)에 따르면 먼저 플래너(Planner) 도구를 호출해서 개요를 짜야지."*

### 단계 2: 플래너 도구 호출 (행동 - Function Call)
화면에 **파란색 박스**나 **기어 아이콘** 같은 게 뜨면서 `planner` 도구가 실행되는 게 보입니다.
> **🔧 Tool Call: `planner`**
> **Input (입력):** `{"topic": "AI 에이전트의 활용 사례 10가지"}`
> *(잠시 로딩... 생각 중...)*
> **Output (출력):**
> ```json
> {
>   "outline": [
>     "1. 서론: AI 에이전트의 부상",
>     "2. 사례 1: 고객 지원 자동화",
>     "3. 사례 2: 코드 생성 및 리뷰",
>     ...
>     "11. 결론"
>   ]
> }
> ```

> **💡 개념 돋보기: Function Calling (함수 호출/도구 사용)**
> **비유: 팀장이 직원에게 '업무 지시서'를 건네는 순간**
>
> *   LLM(거대 언어 모델)은 기본적으로 **'말만 잘하는 입'**입니다. 계산도 못 하고, 파일도 못 만들고, 인터넷 검색도 못 합니다.
> *   하지만 **Function Calling** 능력을 얻으면, **"나 이거 못 해. 대신 이 계산기(도구) 좀 써줘"** 혹은 **"내 밑에 기획자(서브 에이전트/도구) 있으니까 걔한테 시켜서 결과 받아올게"**라고 **자신의 한계를 도구로 극복**합니다.
> *   화면에 뜨는 `Tool Call` 로그는 **"팀장이 기획자에게 '이 주제로 개요 짜와'라고 메모를 던지는 장면"**을 실시간 중계해 주는 것입니다.

### 단계 3: 루트 에이전트의 다음 판단 (생각)
> **💭 Blogger (Thought):**
> *"좋아, 개요 나왔네. 이제 라이터(Writer) 도구한테 이 개요 넘겨서 본문 쓰라고 해야지."*

### 단계 4: 라이터 도구 호출 (행동)
> **🔧 Tool Call: `writer`**
> **Input (입력):** `{"outline": "...방금 받은 개요 내용...", "topic": "AI 에이전트 활용 사례 10가지"}`
> *(잠시 로딩... 글 쓰는 중...)*
> **Output (출력):** 마크다운 형식의 긴 블로그 본문 초안이 텍스트로 주르륵 나옵니다.

### 단계 5: 마무리 작업 (후처리)
스크립트 지시사항에 있던 *"마지막으로 대체 제목 3개와 트윗용 훅 2개 추가해"* 부분을 에이전트 자신이 직접 수행합니다. (이건 별도 도구 호출 없이 루트 에이전트 자신의 LLM 능력으로 처리합니다.)

### 단계 6: 최종 답변 전달 (서빙)
화면에 **최종 결과물**이 예쁘게 렌더링되어 나타납니다.
*   완성된 블로그 글 (마크다운이라 제목, 굵은 글씨, 리스트가 다 예쁘게 보임)
*   **대체 제목 3개** (예: "AI 에이전트, 내 일을 바꿀 10가지 방법", "이제 사람 대신 일하는 AI 비서들..." 등)
*   **트윗용 훅 2개** (예: "🤖 AI 에이전트가 내 코드 리뷰를? 10가지 충격적 활용법 공개! #AI #자동화" 등)

## 7. 디버깅의 기술: "왜 내 말 안 들어?" - 로그 보며 대화하기

테스트하다 보면 에이전트가 이상한 소리를 하거나, 도구를 안 쓰고 자기가 다 하려고 들거나, 도구 호출 형식이 틀려서 에러가 날 수 있습니다. 이때 ADK Web은 **최고의 디버깅 도구**가 됩니다.

### 시나리오 A: 에이전트가 플래너 안 부르고 자기가 대충 개요 짜버림
*   **원인**: Instruction(지시문)이 약하거나, "반드시 도구를 써라"는 강제성이 부족함.
*   **해결**: 코드의 `instruction` 부분을 `"반드시 planner 도구를 먼저 호출하여 개요를 생성한 후..."` 식으로 더 단호하게 수정 후 `adk web` 재실행(터미널에서 `Ctrl+C`로 끄고 다시 `adk web`).

### 시나리오 B: 플래너 도구 호출 시 에러 발생 (빨간 글씨 뜸)
*   **화면에서 확인**: `Tool Call` 박스에 **Error** 혹은 `Exception`.traceback이 뜹니다.
*   **원인**: 입력값(`Input`) 형식이 안 맞음. 예: 플래너는 `topic` 문자열 하나만 받는데, `{"topic": "...", "extra": "..."}`처럼 딴걸 보냄.
*   **해결**: 루트 에이전트의 지시사항이나, 도구 정의(`FunctionTool` 감쌀 때) 매개변수 스키마를 수정.

### 시나리오 C: 세션 초기화 (새로 시작하고 싶을 때)
*   왼쪽 사이드바 **`+ New Session`** 버튼 누르면 대화 기록이 싹 지워지고 깨끗한 상태에서 다시 테스트 가능합니다. **"손님 나갔으니 식탁 치우고 새 손님 맞이하기"**와 같습니다.

## 8. 터미널 로그도 놓치지 마세요: "주방 뒤 CCTV 확인하기"

브라우저 화면(UI)에 안 뜨고 **터미널(콘솔) 창에만 찍히는 로그**도 있습니다. 이건 개발자(우리를 위한) 전용 CCTV입니다.

*   **HTTP 요청 로그**: `INFO: 127.0.0.1:12345 - "POST /run HTTP/1.1" 200 OK`
    *   내 브라우저가 서버에게 요청 보냈고, 서버가 200(성공) 응답 줬다는 뜻.
*   **Python `print()` 디버깅**: 만약 코드 안에 `print("지금 플래너 호출함")` 이렇게 심어두면 **터미널에만** 찍힙니다. UI에는 안 떠요. 복잡한 변수 값 확인할 때 터미널 보세요.

> **⚠️ 중요: 종료할 때**
> 테스트 다 끝났으면 **터미널에서 `Ctrl + C` (맥/윈도우 공통)**를 눌러 서버를 끄세요. 그냥 브라우저 탭만 닫으면 서버가 백그라운드에서 계속 돌면서 포트(8000)를 잡고 있어, 나중에 다시 `adk web` 칠 때 "주소 이미 사용 중(Address already in use)" 에러가 납니다.

## 9. 요약 및 다음 단계 예고

자, 오늘 우리는 무엇을 했나요?

1.  **터미널**이라는 주방에 들어가 **`adk web`**이라는 오픈 버튼을 눌렀습니다.
2.  **`http://127.0.0.1:8000`** 주소로 브라우저라는 손님 입장에서 식당에 들어갔습니다.
3.  **"AI 에이전트 10가지 활용 사례"**라는 주문을 넣었습니다.
4.  **ADK Web UI**라는 오픈 키친 창을 통해, **루트 에이전트(팀장)가 플래너(기획자) 도구 호출 -> 결과 수신 -> 라이터(작가) 도구 호출 -> 결과 수신 -> 최종 가공 -> 서빙**하는 **전 과정을 실시간 생중계**로 확인했습니다.
5.  에러가 나면 UI의 빨간 로그와 터미널의 파이썬 로그를 보며 **디버깅(수정)**하는 방법까지 익혔습니다.

이제 여러분은 **"코드만 짜는 개발자"가 아니라, "에이전트를 운영하고 검증하는 오케스트라 지휘자"**가 되셨습니다.
