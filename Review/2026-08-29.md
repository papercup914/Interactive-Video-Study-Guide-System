# Interactive Video Study Guide System — 유지보수 관점 코드 리뷰

> 리뷰 일자: 2026-08-29

## 0. 시스템 개요

이 프로젝트는 실제로 3개의 독립적인 애플리케이션이 공존하는 상태입니다:

1. **`app.py` (Streamlit)** — 초기 프로토타입. 단일 파일 339줄, UI+비즈니스 로직 혼재
2. **`backend/` (FastAPI + Celery)** — 현재 주력 프로덕션 API
3. **`frontend/` (Next.js 16 + React 19)** — 관리자 대시보드 및 학습 뷰어

이 세 레이어가 **병렬로 존재하며 서로 다른 저장소를 쓴다**는 것이 유지보수 관점 최대의 구조적 리스크입니다.

## 1. 🔴 Critical — 즉시 수정 필요

### 1-1. 존재하지 않는 함수 호출 (실행 시 NameError)
- **`backend/services/evaluator.py:36`** 에서 `clean_json_string(raw)` 를 호출하지만, 이 함수는 **어디에도 정의되어 있지 않습니다.**
- `evaluate_learning_profile()` 이 호출되는 순간 `NameError` 발생 → 예외 처리로 `fallback_evaluation()` 이 반환되므로 **기능 전체가 항상 폴백으로만 동작**합니다. (사일런트 실패)

### 1-2. 데드 코드 (unreachable)
- **`backend/services/llm.py:289-294`**: `return transcript` 뒤에 또 한 번의 `with open(...)` 과 `return transcript` 가 있습니다. 두 번째 블록은 **절대 실행되지 않는 데드 코드**. 리팩토링 흔적.
- **`backend/routers/guide.py:184-186`**: `process_latest_note_evaluation()` 은 본문이 `pass` 뿐인 빈 함수("Evaluation feature disabled (Option B Rollback)"). 호출부(`guide.py:203`)에서 `background_tasks.add_task` 로 등록되지만 아무 일도 안 함.

### 1-3. 동기 DB 세션을 비동기 컨텍스트에서 잘못 사용
- `job_manager.py` 의 모든 함수는 `SessionLocal()` (동기 SQLAlchemy) 을 사용합니다.
- 이들은 Celery worker (동기) 에서는 문제없지만, **FastAPI async 라우터** (`admin.py` 의 `start_batch_pregeneration` 등) 에서 직접 호출되면 이벤트 루프를 블로킹합니다. 특히 `asyncio.create_task(run_batch_pregeneration_pipeline(batch_id))` (admin.py:309) 로 비동기 태스크를 만들고 그 안에서 동기 DB + 동기 LLM 호출을 `run_in_executor` 없이 실행합니다.

### 1-4. `create_task` 누수 (Fire-and-forget)
- **`backend/routers/admin.py:307-309`**:
  ```python
  asyncio.create_task(run_batch_pregeneration_pipeline(batch_id))
  ```
  이 태스크는 **저장되지 않고 참조도 없이** 생성됩니다. 요청이 끝나면 GC가 수거할 수 있어 작업이 중간에 죽을 수 있고, 예외도 무시됩니다. Celery task (`celery_batch_pregenerate_task`) 가 이미 있는데 사용하지 않고 직접 create_task로 우회한 것도 일관성 문제입니다.

### 1-5. `profile_result` 미정의 변수 참조 위험
- **`backend/services/tasks.py:186`**:
  ```python
  pm = profile_result.get("profile_message", "") if 'profile_result' in locals() else ""
  ```
  `profile_result` 는 document가 아닐 때(elif 분기)만 정의됩니다. `'profile_result' in locals()` 가드가 있긴 하지만, `profile_result` 가 **정의는 됐지만 `None`** 일 수 있는 경로는 방어되지 않습니다. 취약한 패턴입니다.

## 2. 🟠 High — 보안 / 데이터 무결성

### 2-1. CORS 기본값 `"*"` + `allow_credentials=True`
- `backend/main.py:17-29`: `CORS_ORIGINS` 미설정 시 `allow_origins=["*"]`, 동시에 `allow_credentials=True`.
- 이 조합은 Starlette에서 브라우저가 credentials를 보내지 못하게 하는 보호가 있긴 하나, 의도대로 동작하지 않는 환경 차이가 있을 수 있고 **프로덕션에서 자격 증명 허용 + 와일드카드**는 표준 위반입니다. 명시적 origin 목록 필수.

### 2-2. 배치 작업 인증 부재 (전역적으로)
- `guide.py`, `admin.py` 의 모든 배치/가이드 엔드포인트에 **`Depends(get_current_user)` 가 없습니다.**
- `main.py`에 정의된 `get_current_user` 는 `/api/auth/me` 에만 사용되고, 실제 가이드 생성/조회/삭제/배치/동기화 API는 **전부 인증 없이 노출**되어 있습니다. 배치 작업에 `sync_key`(운영 서버 시크릿)가 평문으로 DB에 저장되고(`models.py` BatchJob.sync_key), 목록 API(`/batch/list/all`)가 인증 없이 그 키를 반환합니다(`get_all_batch_jobs` 포함 필드).

### 2-3. 수동 스키마 마이그레이션 (취약)
- `job_manager.py:12-31`: `Base.metadata.create_all()` 이후 `ALTER TABLE ... ADD COLUMN` 을 `try/except: pass` 로 감싸 실행.
- 이는 **마이그레이션 도구(Alembic) 없이 임시방편**으로 컬럼을 추가하는 안티패턴입니다. SQLite/PostgreSQL 분기, 오류 무시로 인해 컬럼 추가가 부분 실패해도 silently 넘어갑니다.

### 2-4. 비밀/경로 하드코딩
- `video.py` 의 `COOKIE_PATHS` 에 `/app/backend/...` 등 배포 환경 경로가 하드코딩. `guide.py:48` 의 `backend/tmp` 상대경로, `llm.py` 의 `backend/data` 캐시 경로 등이 **현재 작업 디렉토리에 의존**하여 어디서 실행되느냐에 따라 동작이 달라집니다.

### 2-5. SSRF 위험
- `admin.py` 의 `BatchStartRequest.url` 을 검증 없이 `collect_videos_from_source` → yt-dlp에 전달. 내부 네트워크 주소 등 임의 URL을 넣을 수 있습니다. 최소한 youtube/channel/playlist 도메인 화이트리스트 필요.

## 3. 🟡 Medium — 유지보수성 / 설계

### 3-1. 중복된 코드베이스 3중 구조
- 루트에 `services/llm.py`, `services/video.py` (백엔드와 **별도 복사본**), `summary.py`, `summary2.py`, `patch_history.py`, `test_models.py` 등 잔존 파일이 프로토타입 잔재로 남아 있습니다.
- `backend/data/` 안에 `debug.py`, `debug_mermaid.py`, `fix_mermaid.py`, `debug_innertube_step.py`, `test_debug.py`, `test_invidious_live.py` 등 **디버그/테스트 스크립트가 프로덕션 패키지 내부에 혼재**.
- `scratch/` 디렉토리도 존재. 어느 파일이 실제 실행되는지 불분명해 신규 개발자의 진입장벽이 높습니다.

### 3-2. God 함수 / 초대형 파일
- `backend/services/llm.py` 는 **921줄**, 여러 책임(오디오 처리, 아웃라인 생성, 챕터 생성, 번역, 프로파일링, 키워드 추출, 프롬프트)이 한 파일에 집약.
- `job_manager.py` 572줄, `app.py` 339줄. 함수당 응집도가 낮고, 프롬프트 문자열(수십~수백 줄)이 함수 안에 인라인으로 박혀 있어 **프롬프트만 수정해도 코드 리뷰가 어렵습니다**.

### 3-3. 중복된 클라이언트/폴백 로직
- `get_openai_client`, `get_gemini_client` 를 매 함수 호출마다 새로 생성. `safe_gemini_generate_content` 내부에 모델 폴백 루프가 있고, 이를 감싸는 각 함수(`generate_answer`, `translate_title`, `profile_content` 등)에도 **별도의 Gemini↔OpenAI 폴백 try/except** 가 반복 구현 → 6곳 이상 중복.

### 3-4. 마법 숫자/문자열
- `concurrency_limit = 3`, 재시도 5회, `await asyncio.sleep(65)`(429 대기), `time.sleep(3)`(폴링), `semaphore(3)`, `max_size_mb=20`, 캐시 TTL `"3600s"` 등이 모두 인라인 산재. 상수화 필요.
- 프리셋 명칭/슬러그 매핑(`batch_generator.py:38-46`)과 `llm.py`의 `preset_suffix` 로직이 서로 독립적으로 존재해 **동기화 위험**.

### 3-5. 예외 처리 일관성 결여
- `except Exception` / `except:` (bare) 혼용. `json.loads` 실패 시 `except: pass` 로 무시(job_manager.py 여러 곳) → 데이터 손상이 silent.
- 한국어/영어 에러 메시지 혼용, print() 기반 로깅 (로거 미사용).

### 3-6. 타입 힌트 부족
- 핵심 public 함수들에 반환 타입/파라미터 타입 누락 다수. `get_youtube_transcript` 는 `str | None` 으로 명시했지만 나머지는 대부분 미흡.
